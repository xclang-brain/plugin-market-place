# まとめて任せる

条件に合う警告を、エージェントに最後まで処置させます。処置の間、質問はありません。終わると[一覧](decide.md)が1つ表示されます。

## どちらを使うか

| | エージェント1つ（2段階目） | 複数のエージェント（3段階目） |
| --- | --- | --- |
| 起動 | `copilot --agent coverity-triage-kit:triage-worker` | `copilot --agent coverity-triage-kit:triage-orchestrator` |
| 処置 | 1件ずつ順に | 設定の `parallel`（最初は3）の数だけ同時に |
| 加わること | ― | 同じ原因の CID を1つにまとめる<br>別のエージェントがすべての結果を検証し、問題があれば1回作り直す |
| 見本の警告での時間 | 6件で約2分<br>18件で約3.5分 | 6件で約3〜4分<br>18件で約6分 |

見本の警告は、1件の処置が約10秒で終わるものです。統合と検証の時間が加わるため、3段階目のほうが長くかかりました。処置に時間がかかるコードでの比較は、測定していません。

まず2段階目を使い、結果の検証が欲しいときに3段階目を使います。

## 手順

1. リポジトリの最上位のフォルダーで、上の表のコマンドでエージェントを起動します。
2. 次の文を入力します。

    ```text title="チャットに入力"
    条件に合う警告をすべて処置して
    ```

3. 最初に許可を確認されたら、「このセッションでは許可」を選びます。

    ```text title="表示の例"
    条件に合う警告は 137 件あります。設定の上限（20 件）まで取得しました。ブランチ main の最新のコードで処置します
    ```

4. 一覧が表示されたら、[一覧で決める](decide.md)のとおりに答えます。

3段階目の一覧には、次の行が加わります。

- 同じ原因の CID は「20004（同じ原因: 20005, 20006）」の1行になり、1つの修正と1つの逸脱コメントで処理されます。
- 備考が「検証で要確認のため」の CID は、`summary.md` の「検証の指摘」を読んでから決めます。

## 続き・中断・やり直し

| したいこと | 方法 |
| --- | --- |
| 次の警告を処置する | OK の後に、同じ文をもう一度入力します。処理済みの CID は外れ、その分だけ新しい警告が入ります |
| 中断した処置を続ける | 同じエージェントで起動し、同じ文を入力します。「前回の続きから進めます（残り 7 件）」と表示されます |
| 最初から取得し直す | 「取得し直して」と入力します |
| 1件の結果を直す | 処置が終わってから、エージェントを指定せずに `copilot` を起動し、「CID 20003 を処置して。呼び出し元は admin.c にもある」のように依頼します。新しい結果で、一覧がもう一度表示されます |
| 1回の件数を増やす | [設定](settings.md)の `limit` を変えます |

## 席を離れて実行する

許可の確認で止まらないように、必要な許可を付けて起動します。`<結果フォルダーの場所>` は、設定の `output_dir` のフォルダー（最初は、リポジトリと同じ階層の `coverity-triage-out`）です。

```shell title="ターミナル"
copilot --agent coverity-triage-kit:triage-worker --add-dir "<結果フォルダーの場所>" --allow-tool 'shell(uv:*)' --allow-tool write --allow-tool 'coverity-connect(coverity_search_issues)' --allow-tool 'coverity-connect(coverity_get_issue_details)'
```

3段階目では、エージェントの名前を `triage-orchestrator` に変えます。

Coverity に書き込むツールは含めていないので、OK の後の登録の前には、必ず許可の確認が出ます。

!!! note "実機では未確認"
    この起動方法で許可の確認が出なくなることは、実機の Copilot CLI ではまだ確認していません。
