# エージェントによる一括処置

条件に合う警告を、エージェントに最後まで処置させます。処置の間に質問はなく、終わると[一覧](decide.md)が1つ表示されます。

## 使い分け

| | エージェント1つ | 複数のエージェント |
| --- | --- | --- |
| 起動コマンド | `copilot --agent coverity-triage-kit:triage-worker` | `copilot --agent coverity-triage-kit:triage-orchestrator` |
| 処置の進め方 | 1件ずつ順に | 設定の `parallel`（初期値 3）の数だけ同時に |
| 追加の処理 | なし | 同じ原因の CID を1つにまとめる<br>別のエージェントがすべての結果を検証し、問題があれば1回作り直す |
| 所要時間（実測） | 6件で約2分<br>18件で約3.5分 | 6件で約3〜4分<br>18件で約6分 |

時間は、1件の処置が約10秒で終わるサンプルの警告での実測です。処置に時間がかかるコードでは測っていません。

通常はエージェント1つで処置し、結果を別のエージェントに検証させたい場合に、複数のエージェントを使います。

## 手順

1. リポジトリの最上位のフォルダーで、上の表のコマンドを実行します。
2. 次の文を入力します。

    ```text title="チャットに入力"
    条件に合う警告をすべて処置して
    ```

3. 許可を求められたら、「このセッションでは許可」を選びます。

    ```text title="表示の例"
    条件に合う警告は 137 件あります。設定の上限（20 件）まで取得しました。ブランチ main の最新のコードで処置します
    ```

4. 一覧が表示されたら、[一覧の確認と承認](decide.md)のとおりに答えます。

複数のエージェントで処置した一覧では、次の2点が異なります。

- 同じ原因の CID は「20004（同じ原因: 20005, 20006）」の1行にまとまり、1つの修正と1つの逸脱コメントで処理されます。
- 備考が「検証で要確認のため」の CID は、`summary.md` の「検証の指摘」を読んでから決めます。

## 再開とやり直し

| 目的 | 方法 |
| --- | --- |
| 次の警告の処置 | OK の後に、同じ文をもう一度入力します。処理済みの CID は外れ、その分だけ新しい警告が入ります |
| 中断した処置の再開 | 同じコマンドで起動し、同じ文を入力します。「前回の続きから進めます（残り 7 件）」と表示されます |
| 警告の再取得 | 「取得し直して」と入力します |
| 1件の結果の修正 | 処置が終わってから、エージェントを指定せずに `copilot` を起動し、「CID 20003 を処置して。呼び出し元は admin.c にもある」のように依頼します。新しい結果で、一覧がもう一度表示されます |
| 1回あたりの件数の変更 | [設定](settings.md)の `limit` を変えます |

## 許可の事前指定

許可を求められて処置が止まらないように、必要な許可を付けて起動します。`<結果フォルダーの場所>` は、設定の `output_dir` のフォルダー（初期値は、リポジトリと同じ階層の `coverity-triage-out`）です。

```shell title="ターミナル"
copilot --agent coverity-triage-kit:triage-worker --add-dir "<結果フォルダーの場所>" --allow-tool 'shell(uv:*)' --allow-tool write --allow-tool 'coverity-connect(coverity_search_issues)' --allow-tool 'coverity-connect(coverity_get_issue_details)'
```

複数のエージェントのときは、エージェントの名前を `triage-orchestrator` に変えます。

Coverity に書き込むツールは含めていないので、OK の後の登録の前には、必ず許可を求められます。

!!! note "実機では未確認"
    この起動方法で許可を求められなくなることは、実機の Copilot CLI ではまだ確認していません。
