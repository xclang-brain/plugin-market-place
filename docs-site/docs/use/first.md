# 1件ずつの処置

チャットで CID を指定して、1件ずつ処置します。出力の形と、OK までの流れをつかむのに向いています。

## チャットへの入力

リポジトリの最上位のフォルダーで `copilot` を起動し、次の文を入力します。

| 入力 | 動作 |
| --- | --- |
| 条件に合う警告を取得して | 設定の条件（初期値は、未分類の警告を20件まで）で警告を取得し、CID の一覧を表示します |
| CID 20002 を処置して | その CID を調べ、修正コードと逸脱コメントを作ります |
| 次を処置して | 未処置の CID を1件処置します |
| まとめを見せて | 処置した CID の一覧を表示します。ここで OK を出します（[一覧の確認と承認](decide.md)） |
| 取得し直して | 新しい結果フォルダーを作り、警告を取得し直します |

許可を求められたら、「このセッションでは許可」を選びます。

## 処置の結果

CID ごとに、次の形で表示されます。

```text title="表示の例"
CID 20002（FORWARD_NULL、src/reader.c:15）
判定：誤検知（確信度：高。経路を唯一の呼び出し元までコードで確認できたため）　推奨：逸脱コメントを登録する
根拠：
- src/reader.c:32 read_config() は、path が NULL なら open_and_read() を呼び出す前に返る
- src/reader.c:36 open_and_read() の呼び出し元は、ここだけ

修正コード：open_and_read() の先頭に NULL チェックを追加する（現在の呼び出し元では通らない分岐）
  （差分）

逸脱コメント（89文字）：
誤検知。唯一の呼び出し元 read_config()（src/reader.c:32〜36）が path の NULL を除外してから渡しており、NULL を参照することはない。
```

- 逸脱コメントは、どの CID にも作られます。1行・200文字以内で、判定（「誤検知。」など）から始まります。
- 修正の必要がないとき（最新のコードで修正済みなど）は、修正コードの代わりに理由が表示されます。
- この時点では、リポジトリも Coverity も変わっていません。

## 結果の修正

指摘を添えて、同じ CID をもう一度依頼します。

```text title="チャットに入力"
CID 20002 を処置して。呼び出し元は admin.c にもある
```

## 中断後の再開

新しい会話でも、「次を処置して」と入力すれば続きから進みます。

!!! tip "プロジェクト固有の知識"
    「fatal_error() は戻らない」のような事実を `.coverity-triage/knowledge.md` に書いておくと、処置の前に読み込まれます（[設定](settings.md#プロジェクト固有の知識)）。
