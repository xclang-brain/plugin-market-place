# 一覧で決める

どの方法で処置しても、最後に一覧が1つ表示されます。CID ごとの「選択」を確認して「OK」と答えると、選択のとおりに処理されます。**リポジトリと Coverity が変わるのは、この OK の後だけです。**

## 一覧の例

| CID | 判定 | 確信度 | 修正コード | 逸脱コメント | 選択 | 備考 |
| --- | --- | --- | --- | --- | --- | --- |
| 20001 | 本物のバグ | 高 | src/reader.c | 本物のバグ。open_and_read()（src/reader.c:19〜20）は… | 修正を取り込む | |
| 20002 | 誤検知 | 高 | src/reader.c | 誤検知。唯一の呼び出し元 read_config()（src/reader.c:32〜36）が…（False Positive／Ignore／Unspecified） | 逸脱コメントを登録する | |
| 20003 | 判定不能 | 低 | src/reader.c | 本物のバグ。… | 保留にする | 確信度が低いため |

一覧の下に、差分と根拠をまとめた `summary.md` の場所が表示されます。

## 読み方

=== "判定"

    | 判定 | 意味 |
    | --- | --- |
    | 本物のバグ | 警告の経路が成立し、実際に問題が起きる |
    | 誤検知 | 経路が成立しない（Coverity が認識していない条件がある） |
    | 意図的 | 経路は成立するが、設計どおりの動作で問題にならない |
    | 判定不能 | 実行時の値や外部の仕様で決まり、コードからは判定できない |

=== "確信度"

    | 確信度 | 意味 |
    | --- | --- |
    | 高 | 警告の経路をコードで最後まで追跡でき、根拠がすべてコードにある |
    | 中 | 根拠の一部が推定（呼び出し元がリポジトリにない、など） |
    | 低 | コードから判定できない前提に依存している |

=== "選択と備考"

    選択の初期値は、AI の推奨です。ただし、次の CID は最初から「保留にする」になり、理由が備考に出ます。

    | 備考 | 当てはまる CID |
    | --- | --- |
    | 確信度が低いため | 確信度が「低」 |
    | 検証で要確認のため | 検証で、人の確認が必要とされた |
    | 未検証のため | 検証が終わらなかった |
    | ビルドに失敗したため | オプションのビルド確認で、その修正のファイルにエラーが出た |

    検証は、複数のエージェントに任せたときだけ行われます。

    そのほか、選択を変えた CID には「チャットで指定」「画面で選択」、前の OK で処理した CID には「取り込み済み」「登録済み」と出ます。「処置に失敗」「未処置」の CID は選べないので、「CID 20003 を処置して」で処置します。

## OK の前に見るところ

1. 「保留にする」の行の備考
2. 確信度が「中」の行の根拠（`summary.md`）
3. 「修正を取り込む」の行の差分（`summary.md`）

## 答え方

| 答え | 結果 |
| --- | --- |
| OK | 一覧の選択のとおりに処理します |
| 20002 は修正、ほかは OK | 20002 の選択を変えてから、処理します |
| 20001 は保留 | 選択を変えた一覧を、もう一度表示します（まだ処理しません） |

選択は「修正」「逸脱」「保留」の語で指定します。

## OK の後に行われること

| 選択 | リポジトリ | Coverity |
| --- | --- | --- |
| 修正を取り込む | **git**：ブランチ `coverity-fix/<結果フォルダー名>` に修正1件を1コミットとして積み、push して、プルリクエスト作成用の URL を表示します<br>**svn**：作業コピーに差分を適用します | 「Bug／Fix Required」と修正の概要 |
| 逸脱コメントを登録する | 変わりません | 逸脱コメント |
| 保留にする | 変わりません | 「Pending」と保留の理由 |

- Coverity に書き込む前に、Copilot CLI が許可を求めます。
- git では、表示された URL を開いてプルリクエストを作ります。svn では、作業コピーの変更を確認してコミットします。
- どの選択でも、CID は Coverity で分類済みになり、次の取得から外れます。保留にした CID をもう一度処置するときは、[設定](settings.md)の `classification` に `Pending` を加えます。

??? info "Coverity に登録される Classification・Action・Severity"

    | 選択 | Classification | Action | Severity |
    | --- | --- | --- | --- |
    | 逸脱（誤検知） | False Positive | Ignore | Unspecified |
    | 逸脱（意図的） | Intentional | Ignore | Unspecified |
    | 逸脱（本物のバグ） | Bug | Ignore。最新のコードで修正済みのときは Fix Submitted | Impact から（High → Major、Medium → Moderate、Low → Minor） |
    | 修正を取り込む | Bug | Fix Required | 逸脱コメントが「本物のバグ。」で始まるときは Impact から。それ以外は Unspecified |
    | 保留にする | Pending | Undecided | Unspecified |
