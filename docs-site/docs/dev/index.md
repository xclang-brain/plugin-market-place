# 概要と原則

coverity-triage-kit は、GitHub Copilot CLI 用のプラグインです。構成要素は、スキル4つ、エージェント4つ、Coverity Connect と通信する MCP サーバー、ローカルの Web 画面です。スクリプトは Python で記述し、uv で実行します。動作環境は Windows を想定し、Linux でも動作します。

## 利用形態

利用形態は4段階あり、どの段階も単独で利用できます。

| 段階 | 形態 | 主な構成要素 |
| --- | --- | --- |
| 1 | チャットで CID を1件ずつ処置 | スキル、MCP サーバー |
| 2 | エージェント1つで一括処置 | `triage-worker` |
| 3 | 複数のエージェントで並列処置・統合・検証 | `triage-orchestrator`、`triage-reviewer`、`triage-integrator` |
| 4 | Web 画面での確認と選択 | スキル `coverity-gui` |

## 設計原則

変更の際は、次の原則に反していないことを確認してください。テスト欄に記載のある原則は、違反すると該当するテストが失敗します。

| 原則 | 担保の方法 | テスト |
| --- | --- | --- |
| 目的を1つに限定する（条件に合う警告を取得し、CID ごとに修正コードと逸脱コメントを出力する） | 目的外の機能は追加しない。規模に上限を設ける | `budget` |
| リポジトリと Coverity への変更は、利用者の OK の後に限る | 取り込みのコマンドは、応答の `next` ではなく `after_ok` で返す。Coverity への書き込みツールは事前に許可しない | `flow`、EVAL |
| 認証キーを、チャット、ログ、結果フォルダー、設定ファイルに残さない | 環境変数からのみ読み込む。スクリプトは値の有無だけを判定し、MCP サーバーは応答とエラー内の値をマスクする | ― |
| 4つの段階を、それぞれ単独で利用できるようにする | 下位の段階のファイルに、上位の段階の構成要素名を含めない | `stages` |
| 規模に上限を設ける | コード、テスト、文書、ファイル、コマンド、設定キー、MCP ツールの数の上限を、仕様書8章で定める | `budget` |
| 文書と画面の文言は、利用者の言葉で書く | 禁止語と開発ツール名の混入を検出する | `docs` |
| 確認済みの事実のみを記載する | 実環境で確認していない事項は、未確認と明記する | ― |

各原則の詳細は[憲章](gh:docs/constitution.md)を参照してください。

## 未検証事項

本バージョンは、実環境の GitHub Copilot CLI と Coverity Connect では動作を検証していません。検証済みなのは、モデルを使わない自動テストと、開発用の定義（Claude Code 用）を使った実際のモデルでの実行のみです。特に次の点は、実環境での確認が必要です。

- `uv run --native-tls`：現行の uv では非推奨。後継の `--system-certs` は古い uv では使用できない。廃止された場合は、このオプションを含むコマンド（`mcp.json`、スキル、エージェントの定義など）の置き換えが必要
- Copilot CLI が許可を求める回数と、`--allow-tool` を指定した場合に許可を求めなくなるかどうか
- サブエージェントの起動と、統括エージェントの委任先を制限するフックの動作
- Coverity Connect のバージョンによる API 応答の違い
- 3段階目が2段階目より短時間で完了する条件
