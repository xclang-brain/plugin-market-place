# 始める前に

coverity-triage-kit は、GitHub Copilot CLI のプラグインです。スキル4つ、エージェント4つ、Coverity Connect と通信する MCP サーバー、ローカルの画面でできていて、スクリプトは Python（uv で実行）です。利用者の PC は Windows を想定し、Linux でも動きます。

使い方には4つの段階があります。1段階目はチャットとスキル、2段階目はエージェント1つ、3段階目は複数のエージェント、4段階目は画面です。

## 守る決まり

変更のたびに、次の決まりを守れているかを確認します。右の列にテスト名があるものは、破るとそのテストが失敗します。

| 決まり | 守る仕組み |
| --- | --- |
| 行うことは1つ。条件に合う警告を取得し、CID ごとに修正コードと逸脱コメントを出力する | 目的に必要のない機能は足しません。規模の上限（`budget`） |
| リポジトリと Coverity が変わるのは、利用者の OK の後だけ | 取り込みのコマンドは、応答の `next` ではなく `after_ok` に入れます。Coverity に書き込むツールは、事前に許可しません（`flow`、EVAL） |
| 認証キーを、チャット、ログ、結果フォルダー、設定ファイルに残さない | 環境変数からだけ読みます。スクリプトは値の有無だけを見て、MCP サーバーは応答とエラーの中の値を伏せ字にします |
| 4つの段階は、どれも単独で使える | 下の段階のファイルに、上の段階の構成要素の名前を書きません（`stages`） |
| 規模に上限がある | コード、テスト、文書、ファイル、コマンド、設定キー、MCP のツールの数に、仕様書8章で上限を決めています（`budget`） |
| 文書と画面の文は、利用者の言葉で書く | 使わない言葉と、開発に使うツールの名前がないことを確認します（`docs`） |
| 確認した事実だけを書く | 実機で確認していないことは、確認していないと書きます（テストなし） |

決まりの原文は[憲章](gh:docs/constitution.md)です。

## 実機で確認していないこと

このバージョンは、実機の GitHub Copilot CLI と Coverity Connect では動作を確認していません。確認したのは、モデルを使わないテストと、開発用のファイルで実際のモデルを動かした結果だけです。特に次の点は、実機での確認が必要です。

- `uv run --native-tls`：現在の uv では非推奨です。後継の `--system-certs` は、古い uv では使えません。uv がこのオプションを廃止したら、コマンドを置き換えます
- Copilot CLI が許可を求める回数と、`--allow-tool` で求められなくなること
- サブエージェントの起動と、統括エージェントの依頼先を制限するフック
- 実機の Coverity Connect の API の応答（バージョンによる違い）
- 3段階目が2段階目より早く終わる条件
