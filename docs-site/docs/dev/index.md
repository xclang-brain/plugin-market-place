# 概要と原則

coverity-triage-kit は、GitHub Copilot CLI 用のプラグインです。スクリプトは Python で記述し、uv で実行します。動作環境は Windows を想定し、Linux でも動作します。

## 利用形態

| 段階 | 形態 | 主な構成要素 |
| --- | --- | --- |
| 1 | チャットで CID を1件ずつ処置 | スキル、MCP サーバー |
| 2 | エージェント1つで一括処置 | `triage-worker` |
| 3 | 複数のエージェントで並列処置・統合・検証 | `triage-orchestrator`、`triage-reviewer`、`triage-integrator` |
| 4 | Web 画面での確認と選択 | スキル `coverity-gui` |

## 設計原則

変更の際は、次の原則に反していないことを確認してください。テスト欄のテストは、違反を検出します。

| 原則 | 担保の方法 | テスト |
| --- | --- | --- |
| 目的の限定（条件に合う警告の取得と、CID ごとの修正コード・逸脱コメントの出力）と規模の上限 | 目的外の機能は追加しない。コード、テスト、文書、ファイル、コマンド、設定キー、MCP ツールの数の上限を、仕様書8章で定める | `budget` |
| リポジトリと Coverity への変更は、利用者の OK 後に限定 | 取り込みのコマンドは、応答の `next` ではなく `after_ok` で返す。Coverity への書き込みツールは事前に許可しない | `flow`、EVAL |
| チャット、ログ、結果フォルダー、設定ファイルへの認証キーの記録禁止 | 環境変数からのみ読み込む。スクリプトは値の有無だけを判定し、MCP サーバーは応答とエラー内の値をマスクする | ― |
| 各段階の独立性（単独で利用可能） | 下位の段階のファイルに、上位の段階の構成要素名を含めない | `stages` |
| 文書と画面における利用者の言葉の使用 | 禁止語と開発ツール名の混入を検出する | `docs` |
| 確認済みの事実のみの記載 | 未検証事項を、本ページと設計書に明記する | ― |

## 未検証事項

本バージョンは、実環境の GitHub Copilot CLI と Coverity Connect では動作を検証していません。検証済みなのは、モデルを使わない自動テストと、開発用の定義（Claude Code 用）を使った実際のモデルでの実行のみです。特に次の点は、実環境での確認が必要です。

- `uv run --native-tls`：現行の uv では非推奨。後継の `--system-certs` は古い uv では使用できない。廃止された場合は、このオプションを含むコマンド（`mcp.json`、スキル、エージェントの定義など）の置き換えが必要
- Copilot CLI が許可を求める回数と、`--allow-tool` を指定した場合に許可を求めなくなるかどうか
- サブエージェントの起動と、統括エージェントの委任先を制限するフックの動作
- Coverity Connect のバージョンによる API 応答の違い
- 3段階目が2段階目より短時間で完了する条件
