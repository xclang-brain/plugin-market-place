# 始める前に

coverity-triage-kit は、GitHub Copilot CLI のプラグインです。スキル4つ、エージェント4つ、Coverity Connect と通信する MCP サーバー、ローカルの画面からなり、スクリプトは Python（uv で実行）です。利用者の PC は Windows を想定し、Linux でも動きます。

## 変えてはいけない決まり

変更のたびに、次を壊していないかを確認します。テストで守られているものは、テストが落ちます。

| 決まり | 守っている仕組み・テスト |
| --- | --- |
| 行うことは1つ：条件に合う警告を取得し、CID ごとに修正コードと逸脱コメントを出力する | 規模の上限（`budget`）。目的に要らない機能は足しません |
| リポジトリと Coverity が変わるのは、利用者の OK の後だけ | 取り込みのコマンドは応答の `next` ではなく `after_ok` に入れます。書き込むツールは事前に許可しません（`flow`、EVAL） |
| 認証キーを、チャット、ログ、結果フォルダー、設定ファイルに残さない | 環境変数だけから読みます。スクリプトは有無だけを確認し、MCP サーバーは応答とエラーから伏せます |
| 4つの段階は、どれも単独で使える | 下の段階のファイルに上の段階の名前を書きません（`stages`） |
| 規模に上限がある | コード 5,500 行、テスト 6,000 行、利用者向けの文書 15,000 字、ファイル 160、コマンド 6、設定キー 13、MCP のツール 4（`budget`）。足すときは、先に同じだけ削れないかを考えます |
| 文書と画面の文は、利用者の言葉で書く | 使わない言葉と、開発ツールの名前を確認します（`docs`） |
| 確認した事実だけを書く | 実機で確認していないことは、確認していないと書きます |

決まりの原文は[憲章](gh:docs/constitution.md)です。

## 実機で確認していないこと

このバージョンは、実機の GitHub Copilot CLI と実機の Coverity Connect では動作を確認していません。確認したのは、モデルを使わないテストと、開発用の形での実際のモデルによる実行です。特に次の点は、実機で確認が必要です。

- `uv run --native-tls`：現在の uv では非推奨です。後継の `--system-certs` は古い uv で使えません。uv が廃止したときは、コマンドの置き換えが必要です
- Copilot CLI の許可の確認の回数と、`--allow-tool` で確認が出なくなること
- サブエージェントの起動と、統括エージェントの依頼先を制限するフック
- 実機の Coverity Connect の API の応答（バージョンによる違い）
- 3段階目が2段階目より早く終わる条件

## 開発に必要なもの

| もの | ないとき |
| --- | --- |
| Python 3.10 以上と PyYAML、uv、git | テストを実行できません |
| svn（`svn` と `svnadmin`） | svn のテストがスキップされます |
| Node.js と Playwright（Chromium） | 画面をブラウザーで操作するテストがスキップされます |
