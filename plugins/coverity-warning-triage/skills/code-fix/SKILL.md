# 修正案の作り方

修正は、指示ファイル（`brief.md`）の「修正するコード」のフォルダのファイルだけを、ふだんのファイルの編集の機能で直します。差分やブランチは、あとでスクリプトが作ります。

指示ファイルがないとき（チャットで直接頼まれたとき）は、最後の「指示ファイルがないとき」の節に従います。

## 決まり

1. **最小限の修正**：警告をなくすのに必要な箇所だけを変える。リファクタリング、整形、関係のない改善はしない。（K-36）
2. **関数の外から見た動き（外部仕様）を変えない**：引数、戻り値、公開ヘッダ、グローバル変数のインタフェースを変えない。（K-37）
3. **まわりの書き方に合わせる**：インデント（タブ / 空白）、名前の付け方、括弧の位置、エラー処理の書き方（`goto` での後片付け、戻り値のエラーコードなど）を、まわりのコードに合わせる。（K-38）
4. 修正によって、MISRA / CERT の別の規則に新しく違反しないようにする（暗黙の型変換を増やさない、関数の出口を増やすなら既存の書き方に従う など）。（K-39）
5. 修正するコードのフォルダの外のファイル（調べるコード、利用者の作業中のファイル）は変えない。（K-65）

## 決まりの中で直せないとき

- 決まりを超えた修正案を作る（例：関数の戻り値を変える）。
- 結果ファイルの `fix.exceeded_constraints` に、超えた決まりと理由を書く（例「関数の外部仕様：エラーを戻り値で返す必要がある」）。
- `fix.impact` に、影響を受ける呼び出し元をすべて挙げる。（K-40）

## 手順

1. 修正するコードのフォルダで、直す箇所を読む（最新のリビジョンなので、調べたときと行番号がずれていることがある）。
2. ファイルを編集して直す。
   - 日本語のコメントを足してよいが、ファイルの文字コードで表せる文字だけを使う。
3. 直したあと読み直し、意図どおりかを確かめる。
4. 結果ファイルに、`fix.summary`（直した内容を 1 行で）と `fix.impact`（どの条件で何が変わるか、影響の範囲）を書く。

最新のリビジョンでもう直っているときは、何も変えずに `fix.already_fixed_on_latest` を true にします。（K-34）

## アノテーション（オプション）

指示ファイルに「アノテーションを入れるコード」のフォルダがあるときだけ行います。そのフォルダのファイルに、逸脱案として Coverity の注釈を入れます。

- 警告の行の**すぐ上の行**に、ブロックコメントで入れる。理由は逸脱コメントと同じ文にする（スキル `deviation-comment`）。
- `[...]` の中は、★ のイベントのタグにする。判定で書き分ける（Coverity は `:FALSE` が無い注釈を「意図的」として扱うため）。

  | 判定（`verdict.judgement`） | 書き方 |
  |---|---|
  | `false_positive`（誤検知） | `/* coverity[<タグ>:FALSE] 誤検知。... */` |
  | それ以外 | `/* coverity[<タグ>] 意図的。... */` |

- インデントは警告の行に合わせる。注釈のほかは何も変えない。（K-41）

## 指示ファイルがないとき（チャットで直接頼まれたとき）

人がチャットで、警告を示して「この警告を直して」と頼んだときの進め方です。決まりの 1〜4 と「決まりの中で直せないとき」は上と同じで、次だけが違います。

- 警告の情報は、頼んだ人が示したもの（CID、チェッカー、ファイルと行、警告経路）を使う。
  - 警告経路が示されていなくて、MCP サーバー coverity-triage の `get_issues` が使えれば、ツールの説明のとおりに `output_dir` を渡さずに呼び、警告経路を取る。
  - それでも足りないもの（警告経路、CID、ファイルと行、ストリーム名など）は、頼んだ人に聞く。推測で補わない。
- プロジェクトの知識は、`<リポジトリ>/.coverity-triage/knowledge.md` があれば読む。
- 修正するコードのフォルダはないので、直すのは利用者の作業中のファイルです。ただし、すぐには直さない（決まりの 5 の代わりに、次の順で進める）。
  1. 直す箇所を読み、上の決まりで修正を考える。
  2. 修正の差分（ファイルのパスはリポジトリの一番上からの相対パス）と、直した内容の 1 行と、影響（どの条件で何が変わるか、影響の範囲）をチャットに示し、この差分で直してよいかを聞く。決まりを超えるときは、超えた決まりと理由、影響を受ける呼び出し元も示す。
  3. 同意を得たら、示した差分のとおりに作業中のファイルを直す。示した差分のほかは変えない。
  4. 同意を得られなければ、何も変えない。直す点を言われたら、差分を直して、もう一度示す。
- 作業中のファイルで、もう直っているときは、何も変えずに、そのことと場所を伝える。
- 結果ファイルは書かない。Coverity にも書き込まない。
