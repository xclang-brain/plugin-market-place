# embedded-debug-kit 設計書

- 版：0.1.0
- 上位の文書：[仕様書](../specs/requirements.md) 0.1.0

## 1. 全体の構成

```text
4段階目  Web管理画面（debug-dashboard スキル ＋ CLI のフック）
           │ フックで記録と停止をするだけ。エージェントには頼まない
3段階目  統括エージェント ──頼みの文──▶ 作業エージェント（2段階目）
           │                └─頼みの文──▶ 検証エージェント
2段階目  作業エージェント（device-worker）
           │ スキルの名前で使う
1段階目  スキル：cross-compile・ftp-deploy・serial-console・skill-setup
           │ FTP とシリアル
         組み込み機器
```

- 上の段階は、下の段階を名前だけで使う（REQ-002）。下の段階は、上の段階を知らない。
- 4段階目は、3段階目のエージェントに頼みも指示もしない。CLI のフックで、エージェントの動きを記録し、止めるときはツールの呼び出しを断る（REQ-407）。

## 2. ファイルの置き場所

1つのフォルダで、Claude Code と Copilot CLI の両方に対応する。スキルは両方で共有し、エージェントとフックは CLI ごとに置く。

| 置き場所 | 中身 | 読む CLI |
| --- | --- | --- |
| `.claude-plugin/plugin.json` | Claude Code のマニフェスト | Claude Code |
| `plugin.json` | Copilot CLI のマニフェスト（Agent Plugins 1.0.0） | Copilot CLI |
| `skills/<名前>/` | スキル（1段階目と、4段階目の debug-dashboard） | 両方 |
| `agents/*.md` | エージェント（2・3段階目） | Claude Code |
| `hooks/hooks.json` | フック（4段階目） | Claude Code |
| `com.github.copilot/agents/*.agent.md` | エージェント（2・3段階目） | Copilot CLI |
| `com.github.copilot/hooks/hooks.json` | フック（4段階目） | Copilot CLI |
| `docs/` | 憲章・仕様書・設計書・使い方のガイド | 人 |
| `tests/` | プラグイン全体のテスト | 人・CI |

確かめた事実（2026年11月9日。Claude Code 2.1.319 での実測と公式文書、@github/copilot 1.0.107 の配布物と公式文書）：

- Claude Code は `.claude-plugin/plugin.json` を読み、`agents/`・`skills/`・`hooks/hooks.json` を既定の場所から読む。
- Copilot CLI は、Agent Plugins 1.0.0 の `$schema` を持つルートの `plugin.json` を、`.claude-plugin/plugin.json` より優先して読む。この形式では、スキルは `skills/`、Copilot だけの部品は `com.github.copilot/` の下に置く。
- どちらも、フックとプラグインの中のプロセスに、環境変数 `CLAUDE_PLUGIN_ROOT`（プラグインのフォルダ）を渡す。

## 3. スキルの共通の決まり

| 項目 | 決まり |
| --- | --- |
| 名前 | フォルダの名前と SKILL.md の `name` を同じにする。役割が分かる名前にし、ほかのスキルとぶつかりにくくする |
| SKILL.md | description は「何をするか」と「いつ使うか」だけ。本文は、コマンドの表と結果の読み方だけ。詳しいことは `reference/` に分ける |
| スクリプト | `scripts/` に置く。Python 3.8 以上の標準ライブラリだけを使う。ほかのものは `scripts/vendor/` に同梱する |
| 呼び方 | Windows は `py -3`、ほかは `python3`。パスは `<このスキルのフォルダ>/scripts/…` と書く（どちらの CLI も、スキルのフォルダの場所を示す） |
| サブコマンド | `run`（作業）、`check`（設定を確かめる。ファイルを作らない）、`init`（設定ファイルをひな形から作る）。`--workdir` で作業フォルダを指定できる |
| 結果 | 標準出力に JSON を1つ。ASCII だけで書く（日本語は `\uXXXX` にする）。これで、PowerShell でも bash でも文字が化けない。共通の項目は `ok`・`message`・`problems`・`log` |
| 終了コード | 0：成功、1：作業の失敗、2：設定や引数の問題 |
| 設定ファイル | `<作業フォルダ>/.<スキルの名前>/config.ini`。INI の形式（標準ライブラリの configparser で読む）。各項目のすぐ上に `#` のコメントで説明を書く |
| ログ | `<作業フォルダ>/.<スキルの名前>/logs/` に UTF-8 で書く。フォルダには、中身が `*` の `.gitignore` を置く |
| パスワード | `password` と `password_env`（環境変数の名前）の2つの項目で受け取る。環境変数があれば、そちらを使う。結果とログでは伏せる |

INI にしたのは、標準ライブラリで読めて、自前の読み取り処理が要らないからである。

設定のコメントの書き方（skill-setup が読む）：

| コメントに書くこと | 意味 |
| --- | --- |
| 「（必須）」 | 必須の項目 |
| `例：` で始まる行 | 値の例。何行でも書ける |
| `選べる値：a / b / c` の行 | 書ける値をこの中に限る |

## 4. 各スキル

| スキル | すること | 主な設定 |
| --- | --- | --- |
| cross-compile | ビルドのコマンドを動かし、結果と、できたファイル（ある・新しい・大きさ・ELF の種類）を返す。時間切れでは、子のプロセスまで止める | `source_dir`、`sdk_env`、`build_command`、`outputs`、`timeout_seconds` |
| ftp-deploy | ファイルを FTP で機器に送る。一時的な名前で送り、大きさを確かめてから名前を変える（REQ-107）。必要なら権限を付ける | `host`、`port`、`user`、`password`、`files`、`remote_dir`、`file_mode` |
| serial-console | シリアルで機器のシェルにつなぎ、必要ならログインして、コマンドを順に動かし、出力と終了コードを返す | `port`、`baud`、`login_user`、`login_password`、`prompt`、`commands` |
| skill-setup | 指定されたスキルの SKILL.md から設定ファイルの場所と作り方を知り、コメントを読みながら、利用者に質問して値を書き込む | なし |
| debug-dashboard | Web管理画面の起動・停止と、フックからの記録と停止（4段階目、7章） | なし |

serial-console は、シリアルの読み書きに pyserial 3.5（BSD ライセンス）を `scripts/vendor/` に同梱する。

## 5. エージェント

| エージェント | 段階 | 動かし方 | 使うツール |
| --- | --- | --- | --- |
| device-worker | 2 | メインの会話として動かすか、統括エージェントから頼まれる | ファイルの読み書き、検索、コマンド、スキル、利用者への質問 |
| orchestrator | 3 | メインの会話として動かす | エージェントへの依頼、ファイルの読み取り、検索、利用者への質問 |
| verifier | 3 | 統括エージェントから頼まれる | ファイルの読み取り、検索 |

- 統括エージェントは、メインの会話として動かす。サブエージェントは利用者に質問できず、環境によってはほかのサブエージェントを呼べないためである（Claude Code の公式文書と、この環境での実測）。Claude Code では `claude --agent embedded-debug-kit:orchestrator`、Copilot CLI では `/agent` で選ぶ。
- 統括エージェントのツールに、ファイルの編集とコマンドを入れない（REQ-303）。
- 作業エージェントの定義は、使うスキルの名前だけを並べる（REQ-202）。
- 統括エージェントは、既定の作業エージェントの名前（device-worker）だけを知る。作業エージェントを替えるときは、その1か所を直す。
- description は「何をするか」と「いつ使うか」だけを書く。CLI は、これを見て任せる相手を決める（両方の CLI の公式文書）。

### 5.1 統括エージェントの頼みの文

統括エージェントと、作業・検証エージェントの間の取り決めは、統括エージェントの頼みの文のひな形だけで決める。作業エージェントと検証エージェントの定義には、統括エージェントとの決まりを書かない。

| 頼み | 相手 | 返事の形 |
| --- | --- | --- |
| 準備の確認 | 作業エージェント | 1行目が「準備：できている」か「準備：できていない」。続けて、設定の要約と足りないもの |
| 作業（1回だけ試す。合否は決めない） | 作業エージェント | 変えたこと、手順ごとの結果、判断に要るログの行、ログの場所 |
| 評価 | 検証エージェント | 条件ごとに「C1：合格／不合格／判断できない。理由」の1行。最後に「次に試すとよいこと」 |

- 作業の頼みには、計画（何を直し、何を確かめるか）を必ず入れる。4段階目は、この頼みの文から計画を読む。
- 合否は、検証エージェントの返事のとおりに扱う（REQ-307）。4段階目も、検証エージェントの返事から合否を読む。

### 5.2 Issue

振り返りで改善点があれば、統括エージェントは、Issue にするかを利用者に聞く（REQ-309）。
作る場合は、題と本文を入れた作成ページの URL（`https://github.com/xclang-brain/plugin-market-place/issues/new?title=…&body=…`）を示す。利用者が開いて「作成」を押すので、毎回、利用者の承認を得たことになる（憲章 第24条）。

## 6. CLI ごとの違い

| 項目 | Claude Code | Copilot CLI |
| --- | --- | --- |
| エージェントの定義 | `agents/<名前>.md` | `com.github.copilot/agents/<名前>.agent.md` |
| 利用者への質問 | AskUserQuestion | ask_user |
| エージェントへの依頼 | Agent | task |
| ツールの書き方 | `Read, Edit, Bash` など | `read, edit, execute` など（Claude の名前も別名として通る） |
| フックの形式 | `{"hooks":{"PreToolUse":[{"matcher":…,"hooks":[…]}]}}` | `{"version":1,"hooks":{…}}`。PascalCase のイベント名を使うと、Claude Code と同じ形の入力が来る |

- Copilot CLI 版のエージェントとフックは、Claude Code 版をもとに作る。本文は、上の表の名前だけを替え、ほかは同じにする。
- Copilot CLI の対応は、Claude Code 版のテストを終えてから行う。

## 7. 4段階目：Web管理画面

### 7.1 動き

1. 利用者が debug-dashboard スキルで画面を起動する。スキルは、作業フォルダの `.debug-dashboard/` に「記録中」の印を置き、サーバーを裏で起動して URL を返す。
2. 利用者は、画面の「設定」で頼みの文を作り、統括エージェントを選んだチャットに送る（REQ-402）。
3. CLI のフックが、ツールの呼び出し、エージェントの開始と終了、最後の返事を `.debug-dashboard/sessions/<セッション>/events.jsonl` に書く。
4. 画面は、その記録を読んで、進み具合と結果を見せる。
5. 「止める」を押すと、画面が止める印を置く。フックは、印があればツールの呼び出しを断り、作業を終えるよう伝える。次の頼みが送られたら、フックが印を消す（REQ-404）。
6. スキルで画面を止めると、「記録中」の印を消す。印のない作業フォルダでは、フックは何もしない（REQ-406）。

### 7.2 フック

| イベント | すること |
| --- | --- |
| UserPromptSubmit | 新しい頼みとして記録する。止める印を消す |
| PreToolUse | 止める印があれば断る。なければ、ツールの名前と入力の要約を記録する |
| PostToolUse | 成否を記録する |
| SubagentStart・SubagentStop | 開始と終了を記録する。終了では、エージェントの最後の返事も記録する |
| Stop | メインの会話の最後の返事を記録する |

- 入力の `agent_type` で、どのエージェントの動きかを見分ける。ないものはメインの会話とする。
- フックのスクリプトは `skills/debug-dashboard/scripts/` に置き、両方の CLI のフックの設定から呼ぶ。
- 記録に失敗しても、ツールの呼び出しは止めない（止める印を読むときだけ断る）。

### 7.3 画面のサーバー

- Python の標準ライブラリだけで書く。127.0.0.1 の、OS が選ぶポートで待ち受ける（REQ-401）。
- 起動ごとに乱数の鍵を作り、URL に付ける。最初に開いたときにクッキーに移し、アドレスバーからは消す。
- Host ヘッダーを確かめ、POST は同じオリジンからの JSON だけを受ける。CSP で、外のスクリプトを読ませない。
- 返すファイルは、決まった一覧のものだけにする。

### 7.4 画面

| タブ | 中身 |
| --- | --- |
| 設定 | 頼む作業・合格の条件・試行の上限・作業エージェントの名前。入れると、頼みの文と「コピー」ボタンが出る |
| 実行のようす | 動いているエージェント、試行ごとの計画・作業の報告・評価、使われたツール（新しい順）、「止める」ボタン |
| 結果 | 統括エージェントの最後の報告、条件ごとの最後の評価、前の実行の一覧 |

## 8. テスト

| 種類 | 置き場所 | 中身 |
| --- | --- | --- |
| スキルの単体テスト | `skills/<名前>/tests/` | スクリプトの動き。偽のビルド、FTP のテスト用サーバー、偽のシリアルの機器を使う。フォルダだけをコピーしても動く |
| フックと画面 | `skills/debug-dashboard/tests/` | 記録、止める、サーバーの守り（鍵・Host・オリジン） |
| 独立性 | `tests/independence/` | スキルのフォルダが外を参照しない。上の段階が下の段階の中身を書かない。作業エージェントがスキルの名前だけを持つ |
| 文書 | `tests/docs/` | 版の一致と、要求の追跡 |
| 通しの試験 | `tests/e2e/` | 模擬の機器と `claude -p` で、2段階目と3段階目が不具合を直せるか。AI の利用料がかかるので CI では動かさない |

プラグインの検証には、`claude plugin validate`、plugin-dev の plugin-validator・skill-reviewer・検証スクリプト、skill-creator の評価を使う。
