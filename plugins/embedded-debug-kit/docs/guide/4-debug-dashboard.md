# Web管理画面（4段階目）

統括エージェント（3段階目）への依頼文を作り、進み具合と結果をブラウザーで見る画面です。
debug-dashboard スキルで画面を起動すると、CLI のフックが、依頼・ツールの呼び出し・報告を記録します。画面から実行を止めることもできます。

この文書は、GitHub Copilot CLI での使い方を書きます。Claude Code で違うところは、「[Claude Code での違い](#claude-code-での違い)」にまとめてあります。

## 必要なもの

- Claude Code か GitHub Copilot CLI
- Python 3.8 以上（Windows は `py -3` か `python`、ほかは `python3` で動くもの）。追加の Python パッケージは不要です。
- Windows では PowerShell、ほかでは bash（どちらも、OS に初めからあるもので足ります）
- ブラウザー
- 3段階目が使える状態（[統括エージェントと検証エージェント](3-debug-orchestrator.md)）

## インストール

プラグインをインストールすれば、何もしなくても使えます。スキルとフックの両方がインストールされます。
フックは、画面を起動していないときは何もしません。
スキルのフォルダをコピーするだけでは、記録できません。

## 依頼のしかた

このスキルは、利用者が呼んだときだけ動きます。

1. 直したいソースのフォルダで CLI を起動し、`/embedded-debug-kit:debug-dashboard` と入力します。画面が起動し、URL が出ます。
2. URL をブラウザーで開きます。
3. 「設定」のタブで、直したいこと・合格の条件・試行の上限を入力します。依頼文ができたら「コピー」を押します。
4. 同じ PC の別のターミナルで、同じフォルダから統括エージェントを起動し（[始め方](3-debug-orchestrator.md#始め方)）、依頼文を貼り付けて送ります。
5. 「進み具合」のタブで、今のフェーズ（計画・作業・評価）、依頼と報告（届いた順）、使われたツール（新しいほうから 300 件まで）を見ます。
6. 終わったら、「結果」のタブで、統括エージェントの最後の報告と、検証エージェントの最後の判定を見ます。前のセッションも選べます。
7. 使い終わったら、`/embedded-debug-kit:debug-dashboard stop` と入力して画面を終了します。動いているかは、`stop` の代わりに `status` と書いて確かめられます。

画面が動いている間は、CLI のセッション（CLI を起動してから終えるまでの、1つの会話）をすべて記録します。
記録するのは、同じ作業フォルダのセッションです。作業フォルダは、Git のリポジトリの中で起動すると、リポジトリのいちばん上のフォルダになります。そのため、同じリポジトリの中なら、どのフォルダで起動したセッションも記録します。
ブラウザーや CLI を閉じても、画面は動き続けます。
画面は、エージェントに依頼したセッションのうち、いちばん新しいものを表示します。

## 実行を止める

「進み具合」のタブの「実行を止める」を押すと、そのセッションのツールの呼び出しを断り、作業を終えて報告するよう AI に伝えます。

- 押す前に、上の「セッション：」が統括エージェントのセッションか確かめます。
- 効くのは、次のツールの呼び出しからです。すでに動いているコマンドは、終わるまで止まりません。
- そのセッションで次の依頼を送ると、止めた状態は解除されます。画面を終了しても解除されます。

## 設定

画面の「設定」のタブの項目です。入力した値は、作業フォルダの `.debug-dashboard/settings.json` に残ります。

| 項目 | 意味 | 初めの値 |
| --- | --- | --- |
| 直したいこと | 起きている症状と、正しい結果 | 空 |
| 合格の条件 | 直ったと判断する条件。1行に1つ書く | 空 |
| 試行の上限 | 計画・作業・評価を繰り返す回数の上限（1〜20） | 5 |

条件の扱いは、[統括エージェントの依頼のしかた](3-debug-orchestrator.md#依頼のしかた)にあります。

## 結果とログ

記録は、作業フォルダ（Git のリポジトリの中なら、いちばん上のフォルダ）の `.debug-dashboard/` に置きます。中身が `*` の `.gitignore` を置くので、Git に入りません。
Linux では、本人だけが読み書きできるフォルダにします。Windows では、作業フォルダの権限をそのまま受け継ぎます。

| 場所 | 中身 |
| --- | --- |
| `sessions/<セッションの ID>/events.jsonl` | 依頼・依頼文・報告・ツールの呼び出しの記録（1行に1件、UTF-8） |
| `logs/server.log` | 画面のサーバーの起動・終了と、断った要求 |
| `logs/hook.log` | フックが記録に失敗したときのエラー |

記録する内容は次のとおりです。

| もの | 記録する内容 |
| --- | --- |
| 利用者の依頼、エージェントへの依頼文、エージェントの最後の報告 | そのまま（1件 8 KB まで） |
| コマンド | 先頭の 1,000 字 |
| ファイルの読み書き・検索 | ツールの名前とファイルのパスだけ |
| 利用者への質問 | 質問だけ |
| ツールの結果 | 記録しない |

名前に pass・token・secret・key を含む項目の値（`password=…`、`token: …` など）は、`***` に替えます。URL や `-u 利用者:パスワード` に書いたパスワードも `***` に替えます。
記録を残すのは、新しいほうから 30 のセッションまでです。1つのセッションの記録が 20 MB を超えると、そこから後は記録せず、「お知らせ」が1件出ます。

## Claude Code での違い

| 項目 | Claude Code での動き |
| --- | --- |
| スキルの呼び方 | `/debug-dashboard` と短く入力できる（`stop`・`status` も同じ）。ほかのプラグインと名前がぶつかるときは、Copilot CLI と同じ形で入力する |
| 作業フォルダ | CLI を起動したフォルダ。そのフォルダで起動したセッションだけを記録する |
| フックを動かすシェル | bash。Windows では、Git for Windows の bash が必要 |
| Python | Windows は `py -3`、ほかは `python3` で動くもの |
| プラグインなしで使う | できる（下の手順） |

プラグインなしで使うときは、次の2つをしてから、CLI を起動し直します。

1. `skills/debug-dashboard/` フォルダを、`<プロジェクト>/.claude/skills/debug-dashboard/` にコピーします。フォルダの名前は `debug-dashboard` のままにします（フックの設定が、この名前を使います）。`tests/` はコピーしなくてもかまいません。
2. プラグインの `com.anthropic.claude-code/hooks/hooks.json` の `hooks` の中身を、`<プロジェクト>/.claude/settings.json` の `hooks` に写します。すでに同じイベントのフックがあれば、その配列の後ろに足します。写したら、`${CLAUDE_PLUGIN_ROOT}/skills` を `${CLAUDE_PROJECT_DIR}/.claude/skills` に書き換えます。

## 困ったとき

画面が開かないとき：

| 起きること | 確かめること |
| --- | --- |
| 画面が起動しない | `.debug-dashboard/logs/server.log`。Python 3.8 以上がインストールされているか |
| 「応答しません」と出る | PC が混んでいれば、しばらく待ってからもう一度。続くときは、出たプロセス番号のプロセスを止める |
| 「トークンが違います」と出る | スキルが出した URL を開き直す。画面を起動し直すと URL は変わる |
| 「画面のサーバーにつながりません」と出る | `/embedded-debug-kit:debug-dashboard status` で確かめ、止まっていれば起動し直す |
| `/debug-dashboard` と入力すると「Unknown command」と出る | `/embedded-debug-kit:debug-dashboard` と入力する |

進み具合や結果が正しく出ないとき：

| 起きること | 確かめること |
| --- | --- |
| 進み具合に何も出ない | 統括エージェントを、画面を起動したのと同じフォルダ（Git のリポジトリなら、同じリポジトリの中）で起動したか。Python（Windows は `py -3` か `python`、ほかは `python3`）が動くか。`.debug-dashboard/logs/hook.log` |
| 「結果」のタブに、統括エージェントの最後の報告が出ない | CLI の会話の記録が遅れて書かれ、読めなかった。最後の報告は、チャットで見る |
| Windows の Claude Code で、進み具合に何も出ない | `where bash` の最初が `C:\Windows\System32\bash.exe` なら、Git for Windows の bash を PATH の前に置く |
| 統括エージェントでないセッションが出る | 統括エージェントが作業エージェントか検証エージェントに依頼すると、画面は統括エージェントのセッションに移る。待てなければ「結果」のタブの「前のセッション」で選ぶ |
| 今のフェーズが「作業」や「評価」のまま変わらない | エージェントが途中で止まると起きる。そのセッションで次の依頼を送ると戻る |

止まらないとき、片づけたいとき：

| 起きること | 確かめること |
| --- | --- |
| 「実行を止める」を押しても止まらない | 動いているコマンドが終わるのを待つ。待てなければ、CLI で Esc を押す |
| PC の再起動などで、画面のサーバーが落ちた | `/embedded-debug-kit:debug-dashboard stop` で、残ったファイルを片づける。残っていると、ツールを呼ぶたびにフックが Python を起動する |

## テストの動かし方

スキルのフォルダで、次を動かします（Windows では `python3` を `py -3` に替えます）。

```sh
python3 -m unittest discover -s tests
```

テストは、PC の上で画面のサーバーを動かし、フックに偽の入力を渡して確かめます。外のネットワークは使いません。ほかにインストールするものはありません。
プラグインのフックの設定を使うテストは、bash（Windows では Git Bash）で動かします。PowerShell（`pwsh` か `powershell`）があれば、Copilot CLI 用の `powershell` の欄のコマンドも試します。スキルのフォルダだけをコピーしたときは、これらのテストを飛ばします。

## してはいけないこと

- 画面の URL を、ほかの人に渡さないでください。トークンが入っていて、開くと実行を止められます。
- `.debug-dashboard/` の `.gitignore` を消さないでください。記録には、依頼や報告がそのまま入ります。
- パスワードを、依頼文やチャットに書かないでください。`***` に替えるのは、決まった形のものだけです。
