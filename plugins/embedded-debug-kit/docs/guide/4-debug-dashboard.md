# Web管理画面（4段階目）

統括エージェント（3段階目）への依頼文づくり、進み具合、結果を、ブラウザーで見る画面です。
debug-dashboard スキルで画面を起動すると、CLI のフックが、依頼・ツールの呼び出し・報告を記録します。画面から実行を止めることもできます。

## 要るもの

- Claude Code
- Python 3.8 以上（Windows は `py -3`、ほかは `python3` で動くもの）。ほかに入れるものはありません。
- bash（Windows では、Claude Code が使う Git Bash）
- ブラウザー
- 3段階目が使える状態（[統括エージェントと検証エージェント](3-debug-orchestrator.md)）

## 入れ方

プラグインとして入れたときは、何もしなくても使えます。スキルとフックの両方が入ります。

プラグインなしで使うときは、次の2つをして、CLI を起動し直します。

1. `skills/debug-dashboard/` フォルダを、`<プロジェクト>/.claude/skills/debug-dashboard/` にコピーします。`tests/` はコピーしなくてもかまいません。
2. プラグインの `com.anthropic.claude-code/hooks/hooks.json` の `hooks` の中身を、`<プロジェクト>/.claude/settings.json` の `hooks` に写します。そのとき、`${CLAUDE_PLUGIN_ROOT}/skills` を `${CLAUDE_PROJECT_DIR}/.claude/skills` に書き換えます。

フックは、画面を起動していないときは何もしません。

## 頼み方

このスキルは、利用者が呼んだときだけ動きます。AI が自分から画面を起動することはありません。

1. 直したいソースのフォルダで CLI を起動し、`/debug-dashboard` と入力します。画面が起動し、URL が出ます。
2. URL をブラウザーで開きます。
3. 「設定」のタブで、直したいこと・合格の条件・試行の上限を入れます。依頼文ができたら「コピー」を押します。
4. 別の端末の同じフォルダで、統括エージェントを起動し（[始め方](3-debug-orchestrator.md#始め方)）、依頼文を貼り付けて送ります。
5. 「進み具合」のタブで、今の段（計画・作業・評価）、依頼と報告（届いた順）、使われたツール（新しい順）を見ます。
6. 終わったら、「結果」のタブで、統括エージェントの最後の報告と、検証エージェントの最後の判定を見ます。前の実行も選べます。
7. 画面を閉じるときは、`/debug-dashboard stop` と入力します。動いているかは `/debug-dashboard status` で確かめられます。

ほかのプラグインと名前がぶつかるときは、`/embedded-debug-kit:debug-dashboard` と入力します。

「進み具合」のタブの「実行を止める」を押すと、そのチャットのツールの呼び出しを断り、作業を終えて報告するよう AI に伝えます。

- 効くのは、次のツールの呼び出しからです。すでに動いているコマンドは、終わるまで止まりません。
- そのチャットで次の依頼を送ると、止めた状態は解けます。

## 設定

画面の「設定」のタブの項目です。入れた値は、作業フォルダの `.debug-dashboard/settings.json` に残ります。

| 項目 | 意味 | 初めの値 |
| --- | --- | --- |
| 直したいこと | 起きている症状と、正しい結果 | 空 |
| 合格の条件 | 直ったと判断する条件。1行に1つ書く | 空 |
| 試行の上限 | 計画・作業・評価を繰り返す回数の上限（1〜20） | 5 |

合格の条件を書かなければ、統括エージェントが聞きます。

## 結果とログ

記録は、作業フォルダの `.debug-dashboard/` に置きます。本人だけが読み書きできるフォルダで、中身が `*` の `.gitignore` を置くので、Git に入りません。

| 場所 | 中身 |
| --- | --- |
| `sessions/<セッション>/events.jsonl` | 依頼・依頼文・報告・ツールの呼び出しの記録（1行に1件、UTF-8） |
| `logs/server.log` | 画面のサーバーの起動・終了と、断った要求 |
| `logs/hook.log` | フックが記録に失敗したときのエラー |

記録する内容は次のとおりです。

| もの | 記録する内容 |
| --- | --- |
| 利用者の依頼、エージェントへの依頼文、エージェントの最後の報告 | そのまま（1件 8 KB まで） |
| コマンド | 先頭の 1,000 字 |
| ファイルの読み書き・検索 | ツールの名前とファイルのパスだけ |
| 利用者への質問 | 質問だけ |
| ツールの結果 | 記録しない |

名前に pass・token・secret・key を含む項目の値（`password=…`、`token: …` など）と、URL に書いたパスワードは `***` に替えます。
1つのチャットの記録は 20 MB まで、残すのは新しい 30 件までです。

## 困ったとき

| 起きること | 確かめること |
| --- | --- |
| 画面が起動しない | `.debug-dashboard/logs/server.log`。Python 3.8 以上が入っているか |
| 「トークンが違います」と出る | スキルが出した URL を開き直す。画面を起動し直すと URL は変わる |
| 「画面のサーバーにつながりません」と出る | `/debug-dashboard status` で確かめ、止まっていれば起動し直す |
| 進み具合に何も出ない | 統括エージェントを、画面を起動したのと同じフォルダで起動したか。`py -3` か `python3` が動くか。`.debug-dashboard/logs/hook.log` |
| 「実行を止める」を押しても止まらない | 動いているコマンドが終わるのを待つ。待てなければ、CLI で Esc を押す |
| 今の段が「作業」や「評価」のまま変わらない | エージェントが途中で止まると起きる。そのチャットで次の依頼を送ると戻る |

## テストの動かし方

スキルのフォルダで、次を動かします（Windows では `python3` を `py -3` に替えます）。

```sh
python3 -m unittest discover -s tests
```

テストは、PC の上で画面のサーバーを動かし、フックに偽の入力を渡して確かめます。外のネットワークは使いません。ほかに入れるものはありません。
スキルのフォルダだけをコピーしたときは、プラグインのフックの設定を使うテストを飛ばします。

## してはいけないこと

- 画面の URL を、ほかの人に渡さないでください。トークンが入っていて、開くと実行を止められます。
- `.debug-dashboard/` の `.gitignore` を消さないでください。記録には、依頼や報告がそのまま入ります。
- パスワードを、依頼文やチャットに書かないでください。`***` に替えるのは、決まった形のものだけです。
