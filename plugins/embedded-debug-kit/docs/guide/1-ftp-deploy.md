# ftp-deploy の使い方

PC のファイルを、FTP で組み込み機器のフォルダに送るスキルです。
一時的な名前で送り、サイズを確かめてから置き換えます。途中で失敗したら、送りかけのファイルを消します。それまでに送り終えたファイルは、機器に残ります。
必要なら、送ったあとに権限（755 など）も変えます。

## 必要なもの

- Python 3.8 以上。
- 機器の FTP サーバー。サイズの問い合わせ（SIZE）、名前の変更（RNFR・RNTO）、削除（DELE）に対応していること。送り先のフォルダを作るなら MKD に、権限を変えるなら SITE CHMOD にも対応していること。
- PC から機器に FTP でつながること。

## 依頼のしかた

1. 「ftp-deploy の設定ファイルを作って」と依頼します。`<作業フォルダ>/.ftp-deploy/config.ini` ができます。
2. 設定ファイルに値を書きます（[設定](#設定)）。
3. 「ftp-deploy の設定を確かめて」と依頼します。機器にログインし、送り先のフォルダの一覧だけを取ります。ビルドの前や、送り先のフォルダがまだないときでも確かめられます。
4. 「機器に送って」と依頼します。設定の `files` に書いたファイルを送ります。

作業フォルダは、CLI を起動したフォルダです。

スキルを指定して呼ぶときは、スラッシュコマンドを使います。後ろに、依頼を続けて書けます。

```text
/embedded-debug-kit:ftp-deploy 機器に送って
```

## 設定

設定ファイルは `<作業フォルダ>/.ftp-deploy/config.ini` です。各項目の意味は、ファイルの中のコメントにもあります。

| 項目 | 意味 | ひな形の値 |
| --- | --- | --- |
| `host` | 機器の IP アドレスかホスト名（必須） | 空 |
| `port` | FTP のポート番号 | `21` |
| `user` | ユーザー名。空なら anonymous でログインする | `root` |
| `password` | パスワード | 空 |
| `password_env` | パスワードを入れた環境変数の名前。その環境変数があれば、`password` より優先する | 空 |
| `passive` | パッシブモードを使うか（`true` / `false`） | `true` |
| `tls` | FTPS を使うか（`true` / `false`）。機器の証明書は確かめない（盗み見は防ぐが、なりすましは防がない） | `false` |
| `files` | 送るファイル（必須）。作業フォルダからの相対パスか、絶対パス。機器では、どれも `remote_dir` の直下に同じ名前で置く | 空 |
| `remote_dir` | 機器の送り先のフォルダ（必須）。なければ作る | 空 |
| `file_mode` | 送ったファイルの権限（8 進数。例：`755`）。空なら変えない | 空 |
| `timeout_seconds` | 機器の応答を待つ秒数 | `30` |

`files` は、次の行から1行に1つずつ、行頭に空白を入れて書きます。

```ini
files =
    build/my_app
    conf/my_app.conf
```

パスワードを環境変数で渡すときは、`password_env` に環境変数の名前を書きます。CLI を起動する前に、同じ端末でその環境変数を設定します。

`.ftp-deploy/` には、設定とログを Git から外すための `.gitignore` を置きます。

## 結果とログ

送れたら、AI が、送ったファイル、機器の送り先、変えた権限を伝えます。
失敗したら、起きたことと、確かめることを伝えます。それまでに送ったファイルがあれば、それも伝えます。

送るたびに、`.ftp-deploy/logs/` にログ（UTF-8）が1つできます。機器の FTP サーバーの答えも残ります。パスワードは `***` に替えてあります。

## 困ったとき

| AI が伝えたこと | 確かめること |
| --- | --- |
| ホスト名が見つからない | `host` |
| 接続を断られた（FTP サーバーが動いていない） | 機器で FTP サーバーが動いているか。`port` |
| 機器が応答しない | 機器の電源とケーブル。`host` |
| 機器までの経路がない | ケーブル、`host`、PC のネットワークの設定 |
| ユーザー名かパスワードが違う | `user`、`password`、`password_env` の環境変数 |
| 権限がないか、場所がない | `user` が `remote_dir` に書き込めるか |
| 確かめたときに、送り先のフォルダに入れない | `remote_dir` がフォルダか。そこに入る権限が `user` にあるか |
| 空き容量が足りない | 機器の空き容量 |
| サイズが合わない | 機器の空き容量とケーブル |
| 送る途中で止まる | `passive` を変えてみる |
| 途中で接続が切れた | 機器の電源とケーブル |
| このコマンドに対応していない | SITE CHMOD なら `file_mode` を空にする。SIZE などなら、機器の FTP サーバーを替える |
| 暗号化の手続きに失敗した | 機器の FTP サーバーが FTPS に対応しているか。`tls` |
| 機器の答えを UTF-8 で読めない | 機器の FTP サーバーの文字コードの設定 |
| 機器に `<名前>.part` が残っているかもしれない | 接続が切れたか、消す権限がなくて消せなかった。次に送れば上書きされる |
| 古い `<名前>` は消した。送ったファイルは `<名前>.part` にある | もう一度送るか、機器で名前を `<名前>` に変える |
| 機器の答えの一部が `***` になる | パスワードと同じ文字列を伏せている。パスワードが `root` などの短い単語だと起きやすい |
| 送ったプログラムを、機器で実行できない | `file_mode` に `755` などを書く |

## してはいけないこと

- パスワードをチャットに書かないでください。
- `.ftp-deploy/` の `.gitignore` を消さないでください。
- `remote_dir` を、機器のシステムのフォルダ（`/bin` など）にしないでください。同じ名前のファイルが置き換わります。
