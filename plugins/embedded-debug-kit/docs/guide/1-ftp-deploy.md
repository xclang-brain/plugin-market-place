# ftp-deploy の使い方

PC のファイルを、FTP で組み込み機器のフォルダに送るスキルです。
一時的な名前で送り、サイズを確かめてから置き換えます。途中で失敗したら、途中までのファイルを消します。
必要なら、送ったあとに権限（755 など）も変えます。

## 要るもの

- Python 3.8 以上。ほかに入れるものはありません。
- 機器の FTP サーバー。サイズの問い合わせ（SIZE）と名前の変更（RNFR・RNTO）に対応していること。権限を変えるなら、SITE CHMOD にも。
- PC から機器に FTP でつながること。

## 入れ方

プラグインとして入れたときは、何もしなくても使えます。

プラグインなしで使うときは、`skills/ftp-deploy/` フォルダを次のどれかにコピーし、CLI を起動し直します。`tests/` はコピーしなくてもかまいません。

| CLI | 1つのプロジェクトで使う | どのプロジェクトでも使う |
| --- | --- | --- |
| Claude Code | `<プロジェクト>/.claude/skills/ftp-deploy/` | `~/.claude/skills/ftp-deploy/` |
| GitHub Copilot CLI | `<プロジェクト>/.github/skills/ftp-deploy/` | `~/.copilot/skills/ftp-deploy/` |

`~` は、Windows では `%USERPROFILE%` です。

## 頼み方

1. 「ftp-deploy の設定ファイルを作って」と頼みます。`<作業フォルダ>/.ftp-deploy/config.ini` ができます。
2. 設定ファイルに値を書きます（[設定](#設定)）。
3. 「ftp-deploy の設定を確かめて」と頼みます。機器にログインし、送り先のフォルダがあるかを見ます。何も送らず、ファイルも作りません。
4. 「build/my_app を機器に送って」と頼みます。

作業フォルダは、CLI を起動したフォルダです。

## 設定

設定ファイルは `<作業フォルダ>/.ftp-deploy/config.ini` です。各項目の意味は、ファイルの中のコメントにもあります。

| 項目 | 意味 | ひな形の値 |
| --- | --- | --- |
| `host` | 機器の IP アドレスかホスト名（必須） | 空 |
| `port` | FTP のポート番号 | `21` |
| `user` | ユーザー名。空なら anonymous でログインする | `root` |
| `password` | パスワード | 空 |
| `password_env` | パスワードを入れた環境変数の名前。その環境変数があれば、`password` より優先する | 空 |
| `passive` | パッシブモードを使うか（`true` / `false`） | `true` |
| `tls` | FTPS を使うか（`no` / `yes`） | `no` |
| `files` | 送るファイル（必須）。作業フォルダからの相対パスか、絶対パス | 空 |
| `remote_dir` | 機器の送り先のフォルダ（必須）。なければ作る | 空 |
| `file_mode` | 送ったファイルの権限（8 進数。例：`755`）。空なら変えない | 空 |
| `timeout_seconds` | 機器の応答を待つ秒数 | `30` |

`files` が2つ以上なら、次の行から1行に1つずつ、行頭に空白を入れて書きます。

```ini
files =
    build/my_app
    conf/my_app.conf
```

パスワードを環境変数で渡すときは、`password_env` に名前（例：`DEVICE_FTP_PASSWORD`）を書き、CLI を起動する前に、同じ端末でその環境変数を設定します。

- PowerShell：`$env:DEVICE_FTP_PASSWORD = '機器のパスワード'`
- bash：`export DEVICE_FTP_PASSWORD='機器のパスワード'`

`.ftp-deploy/` には、中身が `*` の `.gitignore` を置きます。設定とログは Git に入りません。

## 結果とログ

送れたら、AI が、送ったファイル、機器の送り先、変えた権限を伝えます。
失敗したら、起きたことと、確かめることを伝えます。

送るたびに、`.ftp-deploy/logs/` にログ（UTF-8）が1つできます。機器の FTP サーバーの答えも残ります。パスワードは `***` に替えてあります。
設定を確かめたときは、ログを作りません。

## 困ったとき

| 言われたこと | 確かめること |
| --- | --- |
| ホスト名が見つからない | `host` |
| 接続を断られた（FTP サーバーが動いていない） | 機器で FTP サーバーが動いているか。`port` |
| 機器が応答しない | 機器の電源とケーブル。`host` |
| 機器までの経路がない | ケーブル、`host`、PC のネットワークの設定 |
| ユーザー名かパスワードが違う | `user`、`password`、`password_env` の環境変数 |
| 権限がないか、場所がない | `user` が `remote_dir` に書き込めるか |
| 空き容量が足りない | 機器の空き容量 |
| 送る途中で止まる | `passive` を変えてみる |
| 途中で接続が切れた | 機器の電源とケーブル |
| 機器に `<名前>.part` が残っているかもしれない | 接続が切れて消せなかった。次に送れば上書きされる |
| 送ったプログラムを、機器で実行できない | `file_mode` に `755` などを書く |

## テストの動かし方

スキルのフォルダで、次を動かします（Windows では `python3` を `py -3` に替えます）。

```sh
python3 -m pip install -r tests/requirements.txt
python3 -m unittest discover -s tests
```

テストは、PC の上で FTP サーバー（pyftpdlib）を動かし、それを機器の代わりにします。外のネットワークは使いません。
pyftpdlib がなければ、FTP サーバーを使うテストは飛ばします。

## してはいけないこと

- パスワードをチャットに書かない。
- `.ftp-deploy/` の `.gitignore` を消さない。
- `remote_dir` を、機器のシステムのフォルダ（`/bin` など）にしない。同じ名前のファイルは置き換わる。
