# 部品を交換する

スキルや作業エージェントを、自分で作ったものに置き換える手順です。

## スキルを置き換える

1. 自分のスキルのフォルダの名前と、SKILL.md の `name` を、置き換えるスキルと同じ名前にします。
2. プラグインの `skills/` の中の、置き換えるスキルのフォルダを、自分のスキルのフォルダと入れ替えます。

自分のスキルは、置き換えるスキルと同じ作業をするように作ります。

| 置き換えるスキル | 自分のスキルがする作業 |
| --- | --- |
| cross-build | プログラムをビルドする |
| ftp-deploy | ビルドしたファイルを、機器に送る |
| serial-console | 機器でコマンドを動かし、その出力を返す |

作業のたびに、コマンドの出力をテキストのファイルに保存し、保存した場所を AI に伝えます。
検証エージェントが、このファイルを読んで合否を判定します。ファイルの名前と、中身の書き方は、自由です。

ftp-deploy を、scp で送るスキルに置き換えるなら、SKILL.md に次のように書きます。

```markdown
1. `scp build/my_app root@192.168.1.50:/opt/my_app/` を実行する。
2. コマンドの出力を、`.ftp-deploy/logs/` の中のファイルに保存する。
3. 成功したかと、保存したファイルの場所を伝える。
```

## 自分のスキルの設定を、skill-config で書けるようにする

1. 設定ファイルを、`<CLI を起動したフォルダ>/.<スキルの名前>/config.yaml` に置きます。
2. 設定ファイルは、`項目: 値` の形で書きます。各項目のすぐ上に、コメントで説明を書きます。

skill-config は、コメントの説明を添えて、項目を1つずつ質問します。コメントに次の語を書くと、質問のしかたが変わります。

| コメントに書く語 | skill-config の質問 |
| --- | --- |
| （必須） | 値が空なら、最初に質問する |
| （秘密） | 値の代わりに、値を入れた環境変数の名前を質問する。答えは `<項目>_env` に書く |
| 例： | 続けて書いた値を、選択肢に出す |
| 選べる値： | `/` で区切って書いた値から、選んでもらう |

```yaml
# 機器の IP アドレスかホスト名（必須）。
# 例：192.168.1.50
host:

# ログインのパスワード（秘密）。
password:

# パスワードを入れた環境変数の名前。
password_env:

# 暗号化して送るか。
# 選べる値：no / yes
tls: no
```

## 作業エージェントを置き換える

1. 自分のエージェントの定義のファイルの名前を `device-debugger.agent.md` に、定義の `name` を `device-debugger` にします。
2. プラグインの `com.github.copilot/agents/device-debugger.agent.md` を、自分の定義と入れ替えます。

自分の定義の本文に、次の節を入れます。統括エージェントは、作業エージェントがこのとおりに動くものとして依頼します。

```markdown
## ほかのエージェントから依頼されたとき

依頼文に書かれた手順と報告の形に従います。合否の判断と利用者への質問は、依頼したエージェントに任せます。聞きたいことは、報告に書いて返します。
```

## 名前も変えるとき

部品の名前を変えるときは、その名前を書いている定義も合わせます。場所は、[設計書](../design/design.md)の 1.1 にあります。

## してはいけないこと

- 自分のスキルから、ほかのスキルを呼んだり、ほかのスキルのファイルを読んだりしないでください。スキルを1つずつ置き換えられなくなります。
