# 部品を交換する（GitHub Copilot CLI）

1段階目のスキルと、2段階目の作業エージェントは、別のものに交換できます。
この文書は、今の実装で必要な手順を、そのまま書きます。楽にできるところも、手間がかかるところも書きます。

## 先に結論

| 交換するもの | 直す場所（Copilot CLI で動かすのに必要な分） |
| --- | --- |
| スキルの中身だけ（名前は同じ） | なし |
| スキル（名前も変える） | 作業エージェントの定義の2行 |
| 作業エージェント（2段階目だけで使う） | なし |
| 作業エージェント（3段階目でも使う） | 統括エージェントの定義の6行。うち4行は、フックのコード |

どの交換でも、プラグインを複製して直します。
インストールしたプラグインの部品を、設定だけで外から差し替える方法はありません。

## 準備：プラグインを複製する

1. このリポジトリを fork するか、clone します。
2. マーケットプレイスからインストールしてあれば、アンインストールします。同じ名前の部品が2つにならないようにするためです。

   ```shell
   copilot plugin uninstall embedded-debug-kit
   ```

3. 部品を直したら、複製したフォルダを指定して CLI を起動します。

   ```shell
   copilot --plugin-dir <複製したフォルダ>/plugins/embedded-debug-kit
   ```

   fork を GitHub に置いたときは、`copilot plugin install <所有者>/<リポジトリ>:plugins/embedded-debug-kit` でもインストールできます。

4. 読み込まれた部品は、次で確かめます。

   ```shell
   copilot --plugin-dir <複製したフォルダ>/plugins/embedded-debug-kit skill list
   ```

   エージェントは、CLI を起動してから `/agent` で確かめます。

## スキルを交換する

### 新しいスキルが守ること

どれも、定義には書かれていない決まりです。守っているかを確かめるしくみは、ありません。

| 決まり | 守らないと起きること |
| --- | --- |
| SKILL.md の description に、何をするかと、いつ使うかを書く | 作業エージェントが、どの作業に使うスキルかを選べない |
| ログをファイルに残し、その場所を結果で返す | 3段階目で、判定が「判断できない」になる。検証エージェントは、ファイルしか読まない |
| 設定ファイルを `<作業フォルダ>/.<スキルの名前>/config.ini` に置き、[設定ファイルの決まり](1-skill-config.md#設定ファイルの決まり)に沿って書く | skill-config で設定できない。設定ファイルを手で書くことになる |
| パスワードを、結果にもログにも出さない | チャットと、Web管理画面の記録に残る |
| フォルダの名前と SKILL.md の `name` を同じにする。2語以上をハイフンでつなぐ | テスト（`tests/independence`）が通らない |

### 手順

ftp-deploy を、自分で作った scp-deploy に替える例です。

1. `skills/scp-deploy/` を作り、SKILL.md とスクリプトを置きます。
2. `skills/ftp-deploy/` を消します。残すと、作業エージェントは使いませんが、スキルだけを使うときに選ばれ続けます。
3. `com.github.copilot/agents/device-debugger.agent.md` の2行を直します。

   | 場所 | 直す前 | 直した後 |
   | --- | --- | --- |
   | 先頭の `skills:` の一覧 | `- ftp-deploy` | `- scp-deploy` |
   | 本文の「使うスキル」の行 | `` `ftp-deploy` `` | `` `scp-deploy` `` |

4. CLI を起動し直します。

スキルどうしは互いを知らないので、ほかのスキルは直しません。
名前を変えずに、`skills/ftp-deploy/` の中身だけを置き換えるなら、手順 3 も要りません。

### 役割が変わるとき

作業エージェントの本文は、「ビルドし、機器に送り、機器で動かして、ログで確かめる」という進め方で書いてあります。
機器に送る手順がなくなるなど、役割が変わる交換では、作業エージェントの「進め方」も書き直します。

## 作業エージェントを交換する

### 新しい作業エージェントが守ること

これも、統括エージェントの依頼文が前提にしているだけで、確かめるしくみはありません。

| 決まり | 理由 |
| --- | --- |
| ほかのエージェントから依頼されたときは、依頼文の手順と報告の形に従う。合否を決めず、利用者に質問しない | 統括エージェントの依頼文が、そう求める |
| 報告に、変えた行の差分、手順ごとの結果、判断に必要なログの行、ファイルの絶対パスを書く | 検証エージェントが、そのファイルを読んで判定する |
| 聞きたいことや足りないものは、作業をせずに、報告に書いて返す | 統括エージェントが、利用者に聞く |
| 先頭に `disable-model-invocation: true` を書かない | 書くと、統括エージェントが依頼できない |
| ファイルの名前を `<名前>.agent.md` にし、`name` と同じにする。2語以上をハイフンでつなぐ | エージェントの名前は `embedded-debug-kit:<名前>` になる |

### 手順

device-debugger を、自分で作った board-tester に替える例です。

1. `com.github.copilot/agents/board-tester.agent.md` を作ります。`device-debugger.agent.md` を写して書き換えるのが早道です。
2. 2段階目だけで使うなら、これで終わりです。`copilot --agent embedded-debug-kit:board-tester` で起動します。
3. 3段階目でも使うなら、`com.github.copilot/agents/debug-orchestrator.agent.md` の6行で、`device-debugger` を `board-tester` に書き換えます。

   | 場所 | 行数 |
   | --- | --- |
   | フックの説明のコメント | 1 |
   | フックの `bash` の欄（通す相手の行と、断る理由の行） | 2 |
   | フックの `powershell` の欄（通す相手の行と、断る理由の行） | 2 |
   | 本文の最初の文 | 1 |

4. フックを直したら、テストで確かめます。フックを書き間違えると、統括エージェントのすべての依頼が断られます。

   ```shell
   python3 -m unittest discover -s tests/independence
   ```

5. 古い `device-debugger.agent.md` は、消しても残してもかまいません。残しても、統括エージェントからは依頼できません。

Web管理画面は直しません。画面は、作業エージェントの名前を持っていないためです。

### 組み込み機器のほかに使うとき

統括エージェントの定義には、組み込み機器向けの言葉が残っています。別の分野の作業エージェントに替えるなら、ここも直します。

- description と本文の最初の文の「組み込み機器の不具合の修正などを」
- 「終える」の手順の「デバッグ用の出力が残っていれば」
- 改善案の Issue の送り先（このリポジトリの URL に固定）

## 直さなくても動くが、古い名前が残るところ

交換した後も、次のファイルに古い名前が残ります。複製を保守するなら、直します。

| 交換したもの | 古い名前が残るファイル |
| --- | --- |
| スキル | 次の7つ。`README.md`、`docs/guide/` の3つ（古いスキルの使い方、`2-device-debugger.md`、例に名前を使う `1-skill-config.md`）、`docs/design/design.md`、`tests/e2e/run_e2e.py`、`evals/` の採点基準 |
| 作業エージェント | 次の6つ。`README.md`、`docs/guide/` の2つ（`2-device-debugger.md`、`3-debug-orchestrator.md`）、`docs/design/design.md`、`tests/e2e/run_e2e.py`、`evals/` の採点基準 |

Claude Code 用の定義（`com.anthropic.claude-code/agents/`）も、同じように直します。直さないと、両方の CLI の定義の本文が同じかを見るテストが通りません。作業エージェントを替えたときは、`.claude-plugin/plugin.json` のエージェントの一覧も直します。

## 疎結合と言えるところ、言えないところ

言えるところ：

- スキルを替えても、ほかのスキルは1行も直さない。
- 上の段階が持つのは、下の段階の名前だけである。直す行は、スキルで2行、作業エージェントで6行に収まる。
- Web管理画面は、スキルも作業エージェントも知らない。
- テスト（`tests/independence`）は、部品の名前を定義から読む。名前を替えても、テストは直さない。

言えないところ：

- 外から差し替えられない。部品の名前が定義の中に書いてあるので、プラグインの複製が必要になる。
- 作業エージェントの名前が、統括エージェントのフックのコードに、2つのシェルの分、書いてある。
- 新しい部品が守る決まり（上の2つの表）は、文章の前提でしかない。破っても、エラーにならず、判定が「判断できない」になるなどの形で現れる。
- 文書と通しのテストに、部品の名前が残る（6〜7つのファイル）。
- 検証エージェントの名前（debug-verifier）は、Web管理画面のスクリプトの2か所に書いてある。検証エージェントは、ここに書いた手順では交換できない。

## 確かめたこと

- プラグインの複製で、上の2つの例のとおりに入れ替えた。`tests/independence`、`tests/docs`、debug-dashboard のテストが通った（2026年11月10日）。
- 入れ替えたスキルが、`copilot --plugin-dir <フォルダ> skill list` に出た（Copilot CLI 1.0.108）。
- 入れ替えた後に、Copilot CLI で AI を動かして不具合を直すところまでは、確かめていない。

## してはいけないこと

- Copilot CLI がプラグインをインストールしたフォルダを、直接書き換えないでください。プラグインを更新すると、変更が消えます。
- 統括エージェントのフックを、`bash` の欄と `powershell` の欄の片方だけ直さないでください。OS によって、依頼がすべて断られます。
- 検証エージェントの名前（debug-verifier）を変えないでください。Web管理画面が、この名前で「評価」のフェーズを見分けます。
