# スキルと作業エージェントを置き換える

プラグインのスキルと作業エージェントは、自分で作ったものに置き換えられます。

## スキルを置き換える

1. 元のスキルと同じ作業をするスキルを作ります。
2. フォルダの名前と、SKILL.md の `name` を、元のスキルと同じ名前にします。
3. プラグインの `skills/` にある元のスキルのフォルダを、自分のスキルのフォルダに置き換えます。

| 元のスキル | 自分のスキルがする作業 |
| --- | --- |
| cross-build | プログラムをビルドする |
| ftp-deploy | ビルドしたファイルを、機器に送る |
| serial-console | 機器でコマンドを動かし、その出力を返す |
| skill-config | スキルの設定ファイルに、値を書く |

## 自分のスキルを、skill-config で準備できるようにする

1. 設定ファイルのひな形を、スキルのフォルダの `assets/config-template.yaml` に置きます。skill-config は、これを `<ソースのフォルダ>/.<スキルの名前>/config.yaml` に写します。自分のスキルは、写した先のファイルを読みます。
2. ひな形は、`項目: 値` の形で書きます。各項目のすぐ上に、コメントで説明を書きます。
3. Python で必要なパッケージは、スキルのフォルダの `pyproject.toml` に書きます。skill-config は、これを uv で入れます。SKILL.md には、スクリプトを `uv run --project "<スキルのフォルダ>"` で動かすと書きます。

skill-config は、コメントの説明を添えて、項目を1つずつ質問します。コメントに次の語を書くと、質問のしかたが変わります。

| コメントに書く語 | skill-config の質問 |
| --- | --- |
| （必須） | 値が空なら、最初に質問する |
| （秘密） | パスワードの代わりに、環境変数の名前を質問する |
| 例： | 「例：」の後ろに書いた値を、選択肢に出す |
| 選べる値： | 「選べる値：」の後ろに `/` で区切って書いた値から、選んでもらう |

（秘密）の項目 `password` のすぐ下に、名前に `_env` を付けた項目 `password_env` を置きます。skill-config は、ここに環境変数の名前を書きます。`password` は、空のままにします。

```yaml
# 機器の IP アドレスかホスト名（必須）。
# 例：192.168.1.50
host:

# ログインのパスワード（秘密）。
password:

# パスワードを入れた環境変数の名前。
password_env:

# 暗号化して送るか。
# 選べる値：no / yes
tls: no
```

## 作業エージェントを置き換える

1. 不具合を調べて直すエージェントを作ります。エージェントの定義ファイルの本文に、次の節を入れます。統括エージェントからの依頼を受けるために必要です。

   ```markdown
   ## ほかのエージェントから依頼されたとき

   依頼文に書かれた手順と報告の形に従います。合否の判断と利用者への質問は、依頼したエージェントに任せます。聞きたいことは、報告に書いて返します。
   判断に必要な出力（機器の出力など）は、ファイルに保存し、その場所を報告に書きます。
   ```

2. 定義のファイルを `device-debugger.agent.md` という名前にし、定義の `name` を `device-debugger` にします。
3. プラグインの `com.github.copilot/agents/device-debugger.agent.md` を、自分のファイルに置き換えます。

Claude Code では、ファイルの名前を `device-debugger.md` にし、`com.anthropic.claude-code/agents/device-debugger.md` を置き換えます。

## 名前も変えるとき

スキルや作業エージェントの名前を変えるときは、元の名前が書いてあるファイルも書き換えます。書いてある場所は、[設計書](../design/design.md)の 1.1 にあります。

## してはいけないこと

- 自分のスキルから、ほかのスキルを呼んだり、ほかのスキルのファイルを読んだりしないでください。そのスキルが置き換えられると、自分のスキルが動かなくなります。
