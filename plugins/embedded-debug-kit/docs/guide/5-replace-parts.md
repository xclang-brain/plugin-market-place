# スキルと作業エージェントを置き換える

プラグインのスキルと作業エージェントを、自分で作ったものに置き換える手順です。

## スキルを置き換える

1. 自分のスキルのフォルダの名前と、SKILL.md の `name` を、元のスキルと同じ名前にします。
2. プラグインの `skills/` にある元のスキルのフォルダを、自分のスキルのフォルダに置き換えます。

自分のスキルは、次の2つを満たすように作ります。

### 元のスキルと同じ作業をする

| 元のスキル | 自分のスキルがする作業 |
| --- | --- |
| cross-build | プログラムをビルドする |
| ftp-deploy | ビルドしたファイルを、機器に送る |
| serial-console | 機器でコマンドを動かし、その出力を返す |

### コマンドの出力を、ファイルに保存する

自分のスキルは、作業のたびに、コマンドの出力をテキストのファイルに保存し、保存した場所を報告するように作ります。
3段階目では、合否を判定する AI が、このファイルを読みます。ファイルの置き場所、名前、中身の書き方は、自由です。

ftp-deploy を、scp で送るスキルに置き換えるなら、SKILL.md に次のように書きます。

```markdown
1. `scp build/my_app root@192.168.1.50:/opt/my_app/` を実行する。
2. コマンドの出力を、`.ftp-deploy/logs/` の中のファイルに保存する。
3. 成功したかどうかと、保存したファイルの場所を報告する。
```

## 自分のスキルを、skill-config で設定できるようにする

1. 設定ファイルを、`<ソースのフォルダ>/.<スキルの名前>/config.yaml` に置きます。
2. 設定ファイルは、`項目: 値` の形で書きます。各項目のすぐ上に、コメントで説明を書きます。

skill-config は、コメントの説明を添えて、項目を1つずつ質問します。コメントに次の語を書くと、質問のしかたが変わります。

| コメントに書く語 | skill-config の質問 |
| --- | --- |
| （必須） | 値が空なら、最初に質問する |
| （秘密） | パスワードの代わりに、環境変数の名前を質問する |
| 例： | 続けて書いた値を、選択肢に出す |
| 選べる値： | `/` で区切って書いた値から、選んでもらう |

（秘密）の項目 `password` の次には、環境変数の名前を入れる項目 `password_env` を書きます。

```yaml
# 機器の IP アドレスかホスト名（必須）。
# 例：192.168.1.50
host:

# ログインのパスワード（秘密）。
password:

# パスワードを入れた環境変数の名前。
password_env:

# 暗号化して送るか。
# 選べる値：no / yes
tls: no
```

## 作業エージェントを置き換える

1. 自分のエージェントの定義を、`device-debugger.agent.md` という名前のファイルにします。定義の `name` は、`device-debugger` にします。
2. プラグインの `com.github.copilot/agents/device-debugger.agent.md` を、自分のファイルに置き換えます。

自分の定義の本文に、次の節を入れます。3段階目で、統括エージェントからの依頼を受けるために必要です。

```markdown
## ほかのエージェントから依頼されたとき

依頼文に書かれた手順と報告の形に従います。合否の判断と利用者への質問は、依頼したエージェントに任せます。聞きたいことは、報告に書いて返します。
```

## 名前も変えるとき

スキルや作業エージェントの名前を変えるときは、その名前を書いているファイルも書き換えます。書いている場所は、[設計書](../design/design.md)の 1.1 にあります。

## してはいけないこと

- 自分のスキルから、ほかのスキルを呼んだり、ほかのスキルのファイルを読んだりしないでください。スキルを1つずつ置き換えられなくなります。
