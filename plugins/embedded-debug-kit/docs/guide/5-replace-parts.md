# 部品を交換する

スキルや作業エージェントを、自分で作ったものに置き換える手順です。

## スキルを交換する

`skills/<スキルの名前>/` のフォルダを、自分のスキルのフォルダに置き換えます。
フォルダの名前と、SKILL.md の `name` は、元のスキルと同じにします。

自分のスキルは、次の2つを満たすように作ります。

| 満たすこと | 理由 |
| --- | --- |
| 元のスキルと同じ役割を持つ | 作業エージェントは、ビルド、機器への転送、機器での実行の順に作業を進める |
| 出力をファイルに残し、その場所を結果として返す | 検証エージェントは、ファイルを読んで合否を判定する |

設定ファイルを[設定ファイルの決まり](1-skill-config.md#設定ファイルの決まり)に沿って書くと、skill-config で設定できます。

## 作業エージェントを交換する

`com.github.copilot/agents/device-debugger.agent.md` を、自分のエージェントの定義に置き換えます。
ファイルの名前と、定義の `name` は、元のままにします。

自分のエージェントは、次の2つを満たすように作ります。

| 満たすこと | 理由 |
| --- | --- |
| ほかのエージェントから依頼されたら、依頼文に書かれた手順と報告の形に従う | 統括エージェントは、試行ごとに、手順と報告の形を依頼文で伝える |
| そのとき、合否の判断と利用者への質問は、依頼したエージェントに任せる。聞きたいことは、報告に書いて返す | 合否は検証エージェントが判定し、質問は統括エージェントが利用者に聞く |

## 名前も変えるとき

部品の名前を変えるときは、その名前を書いている定義も合わせます。場所は、[設計書](../design/design.md)の 1.1 にあります。

## してはいけないこと

- 自分のスキルから、ほかのスキルを呼んだり、ほかのスキルのファイルを読んだりしないでください。スキルを1つずつ交換できなくなります。
- 自分のエージェントの定義に、スキルのスクリプトや設定ファイルの場所を書かないでください。スキルを交換するたびに、定義も直すことになります。
