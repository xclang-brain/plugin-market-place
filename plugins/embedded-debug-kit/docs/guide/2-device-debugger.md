# 作業エージェントの使い方

作業エージェントは、不具合の原因を調べて直す AI です。
ソースを直し、ビルドして機器で動かし、結果を確かめます。直るまで、これを5回まで繰り返します。

## 手順

1. 機器のパスワードを、環境変数に入れます。環境変数の名前は自由です（例：`DEVICE_PASSWORD`）。
2. 同じターミナルで、ソースのフォルダから、作業エージェントを指定して CLI を起動します。

   ```shell
   copilot --agent embedded-debug-kit:device-debugger
   ```

   Copilot CLI では、起動した後に `/agent` と入力して、一覧から選ぶこともできます。Claude Code では、`claude --agent embedded-debug-kit:device-debugger` で起動します。

3. このフォルダで初めて使うときは、「スキルを設定したい」と依頼し、作業エージェントの質問に答えます。パスワードの渡し方を質問されたら、手順 1 の環境変数の名前を答えます。
4. ソースの変更を、すべてコミットします。
5. 起きている症状と、正しい結果を書いて依頼します。

   ```text
   sensor_app を機器で動かすと、AVG=3 と出ます。正しくは AVG=25 です。原因を調べて直してください。
   ```

6. 作業エージェントが、直ったかどうか、原因、変えたファイル、ログの場所を報告します。変更は、`git diff` で確かめます。

繰り返す回数は、依頼に「3回まで」と書けば変えられます。「main.c は変えない」のような条件も、依頼に書けます。

## してはいけないこと

- ソースに、コミットしていない変更を残したまま使わないでください。AI がソースを書き換えるので、AI の変更と区別できなくなります。
- パスワードをチャットに書かないでください。
