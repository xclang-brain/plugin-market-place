# serial-console の使い方

シリアルでつないだ組み込み機器のシェルで、コマンドを動かすスキルです。
必要ならログインし、コマンドを1つずつ動かして、出力と終了コードを返します。
決めた秒数で終わらないコマンドは、Ctrl-C を送って止めます。

## 要るもの

- Python 3.8 以上。Windows では、py ランチャー（python.org のインストーラーで入ります）も要ります。シリアルを扱う pyserial 3.5 はスキルに入っています（`scripts/vendor/serial/`、BSD ライセンス）。ほかに入れるものはありません。
- 機器のシリアルコンソール（シェル）と、PC につなぐケーブル（USB シリアル変換ケーブルなど）。
- Linux では、シリアルポートを開く権限（`dialout` グループ）。

## 入れ方

プラグインとして入れたときは、何もしなくても使えます。

プラグインなしで使うときは、`skills/serial-console/` フォルダを次のどれかにコピーし、CLI を起動し直します。`tests/` はコピーしなくてもかまいません。

| CLI | 1つのプロジェクトで使う | どのプロジェクトでも使う |
| --- | --- | --- |
| Claude Code | `<プロジェクト>/.claude/skills/serial-console/` | `~/.claude/skills/serial-console/` |
| GitHub Copilot CLI | `<プロジェクト>/.github/skills/serial-console/` | `~/.copilot/skills/serial-console/` |

`~` は、Windows では `%USERPROFILE%` です。
フォルダの名前を変えてコピーするときは、`SKILL.md` の `name` も同じ名前にします。設定とログのフォルダも `.<新しい名前>/` になります。

## 頼み方

1. 「serial-console の設定ファイルを作って」と頼みます。`<作業フォルダ>/.serial-console/config.ini` ができます。
2. 設定ファイルに値を書きます（[設定](#設定)）。少なくとも `port` を書き、ログインが要るならパスワードも渡します。
3. 「シリアルの設定を確かめて」と頼みます。機器につなぎ、プロンプトが出るまで進めます（必要ならログインします）。コマンドは動かさず、ファイルも作りません。
4. 「機器で uname -a を動かして」のように頼みます。設定の `commands` を動かすなら、「設定のコマンドを機器で動かして」と頼みます。

作業フォルダは、CLI を起動したフォルダです。

## 設定

設定ファイルは `<作業フォルダ>/.serial-console/config.ini` です。各項目の意味は、ファイルの中のコメントにもあります。

| 項目 | 意味 | ひな形の値 |
| --- | --- | --- |
| `port` | シリアルポート（必須）。Windows は `COM3` など、Linux は `/dev/ttyUSB0` など。`socket://ホスト:ポート` なら TCP でつなぐ | 空 |
| `baud` | 通信の速さ（ボーレート）。機器と同じにする | `115200` |
| `login_user` | ログインのユーザー名。機器がログインを求めたときに使う | `root` |
| `login_password` | ログインのパスワード | 空 |
| `login_password_env` | パスワードを入れた環境変数の名前。その環境変数があれば、`login_password` より優先する | 空 |
| `prompt` | シェルのプロンプトの終わりに合う正規表現 | `[#$] $` |
| `commands` | 上から順に動かすコマンド | 空 |
| `command_timeout_seconds` | 1つのコマンドを待つ最長の秒数。過ぎたら Ctrl-C で止め、残りは動かさない | `30` |

`commands` が2つ以上なら、`commands =` の次の行から、1行に1つずつ、行頭に空白を入れて書きます。

```ini
[settings]
port = COM3
login_password_env = DEVICE_PASSWORD
commands =
    /opt/my_app/my_app --selftest
    dmesg | tail -n 20
```

パスワードを環境変数で渡すときは、`login_password_env` に名前（例：`DEVICE_PASSWORD`）を書き、CLI を起動する前に、同じ端末でその環境変数を設定します。

- PowerShell：`$env:DEVICE_PASSWORD = '機器のパスワード'`
- bash：`read -rs DEVICE_PASSWORD && export DEVICE_PASSWORD` を動かし、パスワードを入れて Enter を押します（入れた文字は画面に出ません）。

`.serial-console/` には、中身が `*` の `.gitignore` を置きます。設定とログは Git に入りません。

## 結果とログ

動かしたら、AI が、コマンドごとの出力と終了コードを伝えます。出力は、コマンドごとに最後の 60 行・8,000 字までです。
時間切れで止めたコマンドがあれば、そのことと、動かさなかったコマンドを伝えます。
失敗したら、起きたことと、確かめることを伝えます。

動かすたびに、`.serial-console/logs/` にログ（UTF-8）が1つできます。機器からの出力が、すべて入ります（色などの制御文字と、終了コードを読むやりとりは除きます）。パスワードは `***` に替えてあります。
設定を確かめたときは、ログを作りません。

終わったあとも、機器はログインしたままです。ほかの人もつなぐ機器なら、使い終わったら端末ソフトでログアウトします。

## 困ったとき

| 言われたこと | 確かめること |
| --- | --- |
| シリアルポートが見つからない | USB ケーブル。`port`（この PC で見つかったポートの一覧が添えてある） |
| ほかのプログラムが使っている | Tera Term、PuTTY、minicom などを閉じる。前に動かしたこのスキルが、まだ動いていないか |
| 開く権限がない（Linux） | `sudo usermod -aG dialout $USER` を動かしてから、ログインし直す |
| 何も届かない | 機器の電源とケーブル。`baud` |
| 文字は届くが、プロンプトもログインの求めも出ない | `baud` と `prompt`。機器で前のプログラムが動いたままでないか |
| ログインのあと、プロンプトが出ない | `prompt` が機器のプロンプトに合っているか |
| ログインできない | `login_user`、`login_password`、`login_password_env` の環境変数 |
| 時間切れで Ctrl-C を送った | コマンドが入力を待っていないか。`command_timeout_seconds` |
| 終了コードを読めない | 機器のシェルが `$?` を使えるか |
| 途中で切れた | USB ケーブルと機器の電源 |
| つなぐたびに機器が再起動する | USB シリアル変換の DTR・RTS が、機器のリセットにつながっていないか |
| 出力の一部が `***` になる | パスワードと同じ文字列を伏せている。パスワードが `root` などの短い言葉だと起きやすい |

## テストの動かし方

スキルのフォルダで、次を動かします（Windows では `python3` を `py -3` に替えます）。

```sh
python3 -m unittest discover -s tests
```

テストは、PC の上で機器のまね（`tests/fake_device.py`）を動かし、TCP（`socket://127.0.0.1:<番号>`）でつなぎます。機器のまねは、ログインと、小さなシェル（`echo`、`$?`、多くの行を出すコマンド、Ctrl-C まで終わらないコマンドなど）をまねます。ほかに入れるものはなく、外のネットワークも使いません。
Linux では、疑似端末を使うテストもします。bash（Windows では Git Bash）と PowerShell からコマンドを渡すテストもします。これらは、使えない OS やシェルがないときは飛ばします。

## してはいけないこと

- パスワードをチャットに書かない。
- `.serial-console/` の `.gitignore` を消さない。
- スキルが動いている間に、端末ソフトで同じポートを開かない。機器から届く文字が2つに分かれ、どちらも正しく読めなくなる。
