# serial-console の使い方

シリアルでつないだ組み込み機器のシェルで、コマンドを動かすスキルです。
必要ならログインし、コマンドを1つずつ動かして、出力と終了コードを返します。
決めた秒数で終わらないコマンドは、Ctrl-C を送って止めます。

## 必要なもの

- Python 3.8 以上。Windows では、py ランチャーも使います。シリアルを扱う pyserial 3.5 は、スキルに同梱しています。
- 機器のシリアルコンソール（シェル）と、PC につなぐケーブル（USB シリアル変換ケーブルなど）。
- Linux では、シリアルポートを開く権限（`dialout` グループ）。

## 依頼のしかた

1. 「serial-console の設定ファイルを作って」と依頼します。`<作業フォルダ>/.serial-console/config.yaml` ができます。
2. 設定ファイルに値を書きます（[設定](#設定)）。少なくとも `port` を書き、ログインが必要ならパスワードも渡します。
3. 「シリアルの設定を確かめて」と依頼します。機器につなぎ、プロンプトが出るところまで進めます。
4. 「機器で uname -a を動かして」のように依頼します。設定の `commands` を動かすなら、「設定のコマンドを機器で動かして」と依頼します。

作業フォルダは、CLI を起動したフォルダです。

スキルを指定して呼ぶときは、スラッシュコマンドを使います。後ろに、依頼を続けて書けます。

```text
/embedded-debug-kit:serial-console 機器で uname -a を動かして
```

## 設定

設定ファイルは `<作業フォルダ>/.serial-console/config.yaml` です。各項目の意味は、ファイルの中のコメントにもあります。

| 項目 | 意味 | ひな形の値 |
| --- | --- | --- |
| `port` | シリアルポート（必須）。Windows は `COM3` など、Linux は `/dev/ttyUSB0` など。`socket://ホスト:ポート` なら TCP でつなぐ | 空 |
| `baud` | 通信の速さ（ボーレート）。機器と同じにする | `115200` |
| `login_user` | ログインのユーザー名。機器がログインを求めたときに使う | `root` |
| `login_password` | ログインのパスワード | 空 |
| `login_password_env` | パスワードを入れた環境変数の名前。その環境変数があれば、`login_password` より優先する | 空 |
| `prompt` | シェルのプロンプトの終わりに合う正規表現 | `'[#$] $'` |
| `commands` | 上から順に動かすコマンド | 空 |
| `command_timeout_seconds` | 1つのコマンドを待つ最長の秒数。過ぎたら Ctrl-C で止め、残りは動かさない | `30` |

`commands` が2つ以上なら、次の行から、1行に1つずつ `- ` に続けて書きます。記号で始まる値と、「: 」を含む値は、`'…'` で囲みます。

```yaml
port: COM3
login_password_env: DEVICE_PASSWORD
commands:
  - /opt/my_app/my_app --selftest
  - dmesg | tail -n 20
```

パスワードを環境変数で渡すときは、`login_password_env` に環境変数の名前を書きます。CLI を起動する前に、同じ端末でその環境変数を設定します。

`.serial-console/` には、設定とログを Git から外すための `.gitignore` を置きます。

## 結果とログ

動かしたら、AI が、コマンドごとの出力と終了コードを伝えます。出力は、コマンドごとに最後の 60 行・8,000 字までです。
時間切れで止めたコマンドがあれば、そのことと、動かさなかったコマンドを伝えます。
失敗したら、起きたことと、確かめることを伝えます。

動かすたびに、`.serial-console/logs/` にログ（UTF-8）が1つできます。機器からの出力が入ります。色などの制御文字と、終了コードを読むためのやりとりは除きます。パスワードは `***` に替えてあります。

終わったあとも、機器はログインしたままです。ほかの人もつなぐ機器なら、使い終わったら端末ソフトでログアウトします。

## 困ったとき

| AI が伝えたこと | 確かめること |
| --- | --- |
| シリアルポートが見つからない | USB ケーブル。`port`（この PC で見つかったポートの一覧が添えてある） |
| ほかのプログラムが使っている | Tera Term、PuTTY、minicom などを閉じる。前に動かしたこのスキルが、まだ動いていないか |
| 開く権限がない（Linux） | `sudo usermod -aG dialout $USER` を動かしてから、ログインし直す |
| 何も届かない | 機器の電源とケーブル。`baud` |
| 文字は届くが、プロンプトもログインの求めも出ない | `baud` と `prompt`。機器で前のプログラムが動いたままでないか |
| ログインのあと、プロンプトが出ない | `prompt` が機器のプロンプトに合っているか |
| ログインできない | `login_user`、`login_password`、`login_password_env` の環境変数 |
| 時間切れで Ctrl-C を送った | コマンドが入力を待っていないか。`command_timeout_seconds` |
| 終了コードを読めない | 機器のシェルが `$?` を使えるか |
| 途中で切れた | USB ケーブルと機器の電源 |
| つなぐたびに機器が再起動する | USB シリアル変換の DTR・RTS が、機器のリセットにつながっていないか |
| 出力の一部が `***` になる | パスワードと同じ文字列を伏せている。パスワードが `root` などの短い単語だと起きやすい |

## してはいけないこと

- パスワードをチャットに書かないでください。
- `.serial-console/` の `.gitignore` を消さないでください。
- スキルが動いている間に、端末ソフトで同じポートを開かないでください。機器から届く文字が2つに分かれ、どちらも正しく読めなくなります。
