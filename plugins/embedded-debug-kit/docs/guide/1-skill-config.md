# skill-config の使い方

ほかのスキルの設定ファイルを、利用者に質問しながら埋めるスキルです。
設定ファイル `<作業フォルダ>/.<スキルの名前>/config.ini` の各項目のコメントを読み、必須なのに空の項目から1つずつ聞いて、答えを書き込みます。
書き換えるのはその項目の行だけで、コメントや並びはそのまま残ります。パスワードは聞きません。

このプラグインの cross-build・ftp-deploy・serial-console のほか、[設定ファイルの決まり](#設定ファイルの決まり)に沿って書いた設定ファイルなら使えます。

## 要るもの

- Python 3.8 以上（Windows では `py -3`、ほかの OS では `python3` で動くもの）。ほかに入れるものはありません。
- 設定するスキルの設定ファイル。なければ、先にそのスキルに作ってもらいます（例：「ftp-deploy の設定ファイルを作って」）。

## 入れ方

プラグインとして入れたときは、何もしなくても使えます。

プラグインなしで使うときは、`skills/skill-config/` フォルダを次のどれかにコピーし、CLI を起動し直します。`tests/` はコピーしなくてもかまいません。

| CLI | 1つのプロジェクトで使う | どのプロジェクトでも使う |
| --- | --- | --- |
| Claude Code | `<プロジェクト>/.claude/skills/skill-config/` | `~/.claude/skills/skill-config/` |
| GitHub Copilot CLI | `<プロジェクト>/.github/skills/skill-config/` | `~/.copilot/skills/skill-config/` |

`~` はホームフォルダ（Windows では `C:\Users\<ユーザー名>`）です。
フォルダの名前を変えてコピーするときは、`SKILL.md` の `name` も同じ名前にします。ログのフォルダも `.<新しい名前>/` になります。

## 依頼のしかた

「ftp-deploy の設定を、質問しながら埋めて」のように、設定するスキルの名前を入れて依頼します。名前がなければ、AI が聞きます。

1. 必須なのに空の項目を、1つずつ聞かれます。選択肢から選ぶか、値を書いて答えます。リストの項目は「、」などで区切って答え、AI が分けた結果を確かめます。
2. ほかの項目と今の値の表が出て、直したい項目があるかを1回だけ聞かれます。
3. 最後に、設定ファイルの場所、書いた項目、まだ空の必須の項目が伝えられます。

「ftp-deploy の host を 192.168.1.50 にして」のように値まで書けば、その項目だけを、聞かずに書き込みます。

パスワードなどの（秘密）の項目は、値を聞かれません。代わりに、渡し方を選びます。

- 環境変数で渡す：環境変数の名前だけを答えます。値は、次のコマンドで設定します。動かしたらパスワードを入れ、Enter を押します（画面にも履歴にも残りません）。そのあと、同じ端末から CLI を起動し直します。
  - PowerShell：`$env:DEVICE_PASSWORD = [Net.NetworkCredential]::new('', (Read-Host -AsSecureString)).Password`
  - bash：`read -rs DEVICE_PASSWORD && export DEVICE_PASSWORD`
- 自分でファイルに書く：伝えられた設定ファイルを開いて、値を書きます。

ほかのエージェントから依頼されたときなど、質問できないときは、依頼の中にある値だけを書き込み、設定ファイルの場所と空の必須の項目を伝えます。

## 設定ファイルの決まり

このスキル自身の設定ファイルはありません。設定するスキルの設定ファイルを、次の決まりで読みます。

| 書き方 | 意味 |
| --- | --- |
| `[settings]` の下の `項目 = 値` | 読み書きする項目。ほかの節は読まない |
| 項目のすぐ上の `#` か `;` の行 | その項目の説明。空の行があれば、そこで切れる |
| 「（必須）」 | 必須の項目。空なら最初に聞く |
| 「（秘密）」 | パスワードなど。値を聞かず、結果では `***` と伏せる。名前が `password` や `token` などの項目も同じ |
| 「例：」で始まる行 | 値の例。選択肢に出す |
| 「選べる値：」で始まる行 | `/` で区切った、書ける値。この中からしか書けない |
| `<項目>_env` | （秘密）の項目の値を入れた環境変数の名前 |
| 行頭に空白を入れた続きの行 | リストの値（1行に1つ） |

```ini
[settings]

# 機器の IP アドレスかホスト名（必須）。
# 例：192.168.1.50
host =

# ログインのパスワード（秘密）。
password =

# パスワードを入れた環境変数の名前。
# 例：DEVICE_PASSWORD
password_env =

# FTPS を使うか。
# 選べる値：no / yes
tls = no

# 送るファイル（必須）。
files =
    build/my_app
    conf/my_app.conf
```

## 結果とログ

書き込むと、AI が、書いた項目と、まだ空の必須の項目を伝えます。
失敗したら、起きたことと確かめることを伝えます。そのとき、設定ファイルは元のままです。

書き込むたびに、`.skill-config/logs/skill-config-<日付>.log`（UTF-8）に、項目と、書き換える前と後の値を書き足します。（秘密）の値は `***` と書きます。
`.skill-config/` と `.<スキルの名前>/` には、中身が `*` の `.gitignore` を置きます。設定とログは Git に入りません。
項目を読むだけのときは、何も作りません。

## 困ったとき

| AI が伝えたこと | 確かめること |
| --- | --- |
| 設定ファイルがない | 先に、そのスキルに設定ファイルを作ってもらったか。スキルの名前の綴り |
| 項目がない | 項目の名前の綴り。その項目が `[settings]` の下にあるか |
| 選べる値のどれか1つを書く | コメントの「選べる値：」の中から選ぶ |
| （秘密）の項目なので書けない | 環境変数で渡すか、自分でファイルに書く |
| 環境変数の名前を書く | `<項目>_env` には、パスワードではなく、環境変数の名前を答える |
| 2回書かれている | 同じ項目の行を1つにする |
| その項目の行だけを書き換えられない | 空の行の後に、行頭に空白を入れた行がないか。ファイルを開いて直接直す |
| 読み取り専用・書き込めない | ファイルの権限。ほかのアプリで開いていないか |
| UTF-8 で読めない | 設定ファイルを UTF-8 で保存し直す |
| 日本語の値が `?` になった | Windows PowerShell 5.1 から渡すと起きる。PowerShell 7 を使うか、先に `$OutputEncoding` を UTF-8 にする |

## テストの動かし方

スキルのフォルダで、次を動かします（Windows では `python3` を `py -3` に替えます）。

```sh
python3 -m unittest discover -s tests
```

テストは、一時フォルダに作った設定ファイルを使います。ほかに入れるものはなく、外のネットワークも使いません。

## してはいけないこと

- パスワードをチャットに書かないでください。
- 保存していない変更がある設定ファイルを、AI に書き換えさせないでください。あとで保存すると、AI が書いた値が消えます。
- `.skill-config/` と `.<スキルの名前>/` の `.gitignore` を消さないでください。
