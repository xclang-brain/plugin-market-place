# 統括エージェントと検証エージェント（3段階目）

直してほしいことを依頼すると、統括エージェント（debug-orchestrator）が、計画・作業・評価の試行を、合格するか上限に達するまで繰り返します。
作業は作業エージェント（device-debugger）がします。合否は、直した本人ではなく、検証エージェント（debug-verifier）がログを読んで判定します。

## 始め方

1. 作業エージェントを、単体で使える状態にしておきます（[作業エージェントの使い方](2-device-debugger.md)）。
2. 直したいソースのフォルダで、統括エージェントを指定して CLI を起動します。

   ```shell
   # Claude Code
   claude --agent embedded-debug-kit:debug-orchestrator
   # GitHub Copilot CLI（起動してから /agent で選んでもかまいません）
   copilot --agent embedded-debug-kit:debug-orchestrator
   ```

## 依頼のしかた

起きている症状と、正しい結果を書きます。

```text
sensor_app を機器で動かすと AVG=3 と出ます。正しくは AVG=25 です。直してください。
```

- 合格の条件（例：ログに AVG=25 と出る）も書けます。書かなければ、統括エージェントが正しい結果から決めます。正しい結果も書かなければ、利用者に聞きます。条件には C1 から番号が付きます。
- 試行の上限も書けます。書かなければ5回です。
- 作業エージェントが設定などを確かめたいときは、統括エージェントがチャットで聞きます。

## 結果

終わると、チャットに次のことが出ます。

| 項目 | 中身 |
| --- | --- |
| 結論 | 成功（すべての条件に合格した）、失敗（上限まで試したが合格しなかった）、人の判断が必要（作業を進められなかった）のどれか |
| 条件ごとの判定 | 最後の試行での、合格・不合格・判断できない |
| 試行ごとのまとめ | 計画、作業の報告の要約、判定 |
| 変えたファイル | この実行で変えたファイル |

実行の記録は、CLI の会話の記録と、各スキルのログに残ります。
進み具合をブラウザーで見たいときは、[Web管理画面](4-debug-dashboard.md)を使います。

## 改善点を Issue にする

終わると、統括エージェントが、このプラグインの進め方を振り返ります。改善点があれば、Issue にするかを聞きます。

1. 「する」と答えると、題と本文がチャットに出ます。直したいところがあれば伝えます。
2. Issue の作成ページの URL が出ます。開いて、題と本文を確かめてから作ります。

Issue は、配布元のリポジトリ（xclang-brain/plugin-market-place）に公開されます。

## 困ったとき

| 起きること | すること |
| --- | --- |
| エージェントが見つからないと言われる | プラグインが入っていて、有効かを確かめる（`claude plugin list` か `copilot plugin list`） |
| すぐに「人の判断が必要」で終わる | 作業エージェントだけで同じ依頼を試し、設定や機器の接続に問題がないかを確かめる |
| 判定が「判断できない」になる | 合格の条件を、ログに出る文字など、ファイルを読んで確かめられる形にする |

## してはいけないこと

- ふつうの会話から「統括エージェントに任せて」と依頼しないでください。依頼できる相手が絞られず、利用者への質問もできません。「始め方」のとおりに起動します。
- コミットしていない変更があるフォルダで使わないでください。AI はソースを直接書き換え、自動では元に戻しません。始める前にコミットしておくと、`git diff` で確かめて戻せます。
- 社外に出してはいけない情報（ソース、ログ、機器のアドレスなど）を、Issue に入れないでください。
