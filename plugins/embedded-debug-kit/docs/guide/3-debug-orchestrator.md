# 統括エージェントの使い方

統括エージェントは、作業エージェントに直させ、検証エージェントに合否を判定させる AI です。
検証エージェントは、機器の出力などを読んで判定します。合格しなければ、統括エージェントは、修正と判定を最大5回繰り返します。

## 手順

1. このフォルダで初めて使うときは、[作業エージェントの使い方](2-device-debugger.md)の手順 1〜4 でスキルを設定し、その CLI を終了します。
2. ソースの変更を、すべてコミットします。
3. 機器のパスワードを、環境変数に入れます。作業エージェントの使い方の手順 2 と同じです。
4. 同じターミナルで、ソースのフォルダで、統括エージェントを指定して CLI を起動します。

   ```shell
   copilot --agent embedded-debug-kit:debug-orchestrator
   ```

   Copilot CLI では、起動した後に `/agent` と入力して、一覧から選ぶこともできます。Claude Code では、`claude --agent embedded-debug-kit:debug-orchestrator` で起動します。

5. 起きている症状と、合格の条件を書いて依頼します。合格の条件は、機器の出力に出る文字列で書きます。

   ```text
   sensor_app を機器で動かすと AVG=3 と出ます。直してください。合格の条件は、機器の出力に AVG=25 と出ることです。
   ```

6. 統括エージェントが、結論、条件ごとの判定、変えたファイルを報告します。変更は、`git diff` で確かめます。

   | 結論 | 意味 |
   | --- | --- |
   | 成功 | すべての条件に合格した |
   | 失敗 | 試行の上限まで試して、不合格の条件が残った |
   | 人の判断が必要 | 設定や機器の問題で、作業が止まった |

試行の上限は、依頼に「3回まで」と書けば変えられます。

## 改善点の Issue

終わりに、統括エージェントが、このプラグインの改善点を Issue にするかを質問します。
「する」と答えると、統括エージェントが作成ページの URL を示します。そのページで内容を確かめて、作成します。
Issue は、公開のリポジトリ（xclang-brain/plugin-market-place）に載ります。

## してはいけないこと

- ソースに、コミットしていない変更を残したまま使わないでください。AI がソースを書き換えるので、AI の変更と区別できなくなります。
- パスワードをチャットに書かないでください。
- 社外に出せない情報（ソース、機器の出力、機器のアドレスなど）が入ったまま、Issue を作成しないでください。
