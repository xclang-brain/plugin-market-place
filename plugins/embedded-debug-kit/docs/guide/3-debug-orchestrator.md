# 統括エージェントの使い方

修正と、直ったかの判定を、別々の AI に任せます。
作業エージェントが直し、検証エージェントがログを読んで合否を判定します。統括エージェントが、合格するまでこれを繰り返させます。

## 手順

1. 作業エージェントを、使える状態にします（[作業エージェントの使い方](2-device-debugger.md)の手順 2 まで）。
2. 直したいソースのフォルダで、統括エージェントを指定して CLI を起動します。

   ```shell
   copilot --agent embedded-debug-kit:debug-orchestrator
   ```

   起動した後に指定するときは、`/agent` と入力して、一覧から選びます。Claude Code では、`copilot` を `claude` に読み替えます。

3. 起きている症状と、合格の条件を書いて依頼します。合格の条件は、ログに出る文字で書きます。

   ```text
   sensor_app を機器で動かすと AVG=3 と出ます。直してください。合格の条件は、機器の出力に AVG=25 と出ることです。
   ```

4. 統括エージェントが、結論、条件ごとの判定、変えたファイルを報告します。

| 結論 | 意味 |
| --- | --- |
| 成功 | すべての条件に合格した |
| 失敗 | 上限の5回まで試して、不合格の条件が残った |
| 人の判断が必要 | 設定や機器の問題で、作業が止まった |

## 改善点の Issue

終わりに、統括エージェントが、このプラグインの改善点を挙げ、Issue にするかを質問します。
「する」と答えると、タイトルと本文と、作成ページの URL を示します。Issue は、公開のリポジトリ（xclang-brain/plugin-market-place）に載ります。

## してはいけないこと

- コミットしていない変更があるフォルダで使わないでください。AI がソースを書き換えます。コミットしておけば、`git diff` で変更を確かめて戻せます。
- 社外に出せない情報（ソース、ログ、機器のアドレスなど）を、Issue に書かないでください。
