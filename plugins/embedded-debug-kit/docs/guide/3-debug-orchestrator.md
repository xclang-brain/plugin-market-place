# 統括エージェントの使い方

直す AI と、直ったかを判定する AI を分ける使い方です。
作業エージェントが直し、検証エージェントがログを読んで合否を判定します。統括エージェントは、合格するまで、最大5回、この2つを繰り返し動かします。

## 手順

1. [作業エージェントの使い方](2-device-debugger.md)の手順 1〜3（コミット、起動、設定）を済ませます。
2. ソースのフォルダで、統括エージェントを指定して CLI を起動します。

   ```shell
   copilot --agent embedded-debug-kit:debug-orchestrator
   ```

   Copilot CLI では、起動した後に `/agent` と入力して、一覧から選ぶこともできます。Claude Code では、`claude --agent embedded-debug-kit:debug-orchestrator` で起動します。

3. 起きている症状と、合格の条件を書いて依頼します。合格の条件は、ログに出る文字で書きます。

   ```text
   sensor_app を機器で動かすと AVG=3 と出ます。直してください。合格の条件は、ログに AVG=25 と出ることです。
   ```

4. 統括エージェントが、結論、条件ごとの判定、変えたファイルを報告します。変更は、`git diff` で確かめます。

| 結論 | 意味 | 次にすること |
| --- | --- | --- |
| 成功 | すべての条件に合格した | 変更を確かめて、コミットする |
| 失敗 | 5回試して、不合格の条件が残った | 報告の原因を読み、症状を書き足して、もう一度依頼する |
| 人の判断が必要 | 設定や機器の問題で、作業が止まった | 報告に書かれた問題を直して、もう一度依頼する |

## 改善点の Issue

終わりに、統括エージェントが、このプラグインの改善点を挙げ、Issue にするかを質問します。
「する」と答えると、タイトルと本文と、作成ページの URL を示します。URL を開き、内容を確かめてから、自分で作成します。
Issue は、公開のリポジトリ（xclang-brain/plugin-market-place）に載ります。

## してはいけないこと

- コミットしていない変更があるフォルダで使わないでください。AI の変更と区別できなくなります。
- 社外に出せない情報（ソース、ログ、機器のアドレスなど）を、Issue に書かないでください。
