# 記録と止めるしくみ

## 記録のフォルダ

`<作業フォルダ>/.debug-dashboard/` は、本人だけが読み書きできる。中身が `*` の `.gitignore` を置くので、Git に入らない。

| ファイル | 中身 |
| --- | --- |
| `recording` | 記録中の目印。サーバーが 30 秒ごとに書き直し、終了するときに消す |
| `server.json` | サーバーのプロセス番号・ポート・URL（トークン入り） |
| `settings.json` | 画面の「設定」に入れた値 |
| `sessions/<セッション>/events.jsonl` | フックが書く記録。1行に1件 |
| `sessions/<セッション>/stop` | 「実行を止める」の目印。そのセッションで次の依頼が来ると消える |
| `logs/server.log` | サーバーの起動・終了と、断った要求 |
| `logs/hook.log` | フックが記録に失敗したときのエラー |

## 記録するもの

| もの | 残す内容 |
| --- | --- |
| 利用者の依頼、エージェントへの依頼文、エージェントの最後の報告 | そのまま（1件 8 KB まで） |
| コマンド | 先頭の 1,000 字 |
| ファイルの読み書き・検索 | ツールの名前とパスだけ |
| 利用者への質問 | 質問だけ |
| ツールの結果 | 残さない |

名前に pass・token・secret・key を含む項目の値と、URL のパスワードは `***` に替える。
1つのセッションの記録は 20 MB まで。セッションは新しい 30 件まで残す。

## 記録されないとき

フックは、次のときは何もしない。

- `recording` がない、2 分より古い、またはシンボリックリンクである。
- `.debug-dashboard/` か、その中のフォルダがシンボリックリンクである。
- CLI を、画面を起動したのと違うフォルダで起動した（作業フォルダは `CLAUDE_PROJECT_DIR` で決まる）。
- Python が見つからない（`py` も `python3` もない）。

## 今の段

画面の「今の段」は、動いているサブエージェントの名前で決める。名前が `debug-verifier` で終わるものが動いていれば評価、ほかのものが動いていれば作業、どれも動いていなければ計画。
依頼文や報告の中身は読まない。
