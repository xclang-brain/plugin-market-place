# 記録のしくみと画面の見せ方

## 記録のフォルダ

`<作業フォルダ>/.debug-dashboard/` に置く。Linux では、本人だけが読み書きできる権限で作る。Windows では、作業フォルダの権限をそのまま受け継ぐ。中身が `*` の `.gitignore` を置くので、Git に入らない。

| ファイル | 中身 |
| --- | --- |
| `recording` | 記録中の目印。サーバーが 30 秒ごとに書き直し、終了するときに消す |
| `server.json` | サーバーのプロセス番号・ポート・URL（トークン入り） |
| `settings.json` | 画面の「設定」に入れた値 |
| `sessions/<チャットの ID>/events.jsonl` | フックが書く記録。1行に1件 |
| `sessions/<チャットの ID>/stop` | 「実行を止める」の目印。そのチャットで次の依頼が来たときと、画面を終了・起動したときに消える |
| `sessions/<チャットの ID>/handback-<サブエージェントの ID>` | 自動モードで、サブエージェントが渡した最後の報告を記録した目印。そのサブエージェントが終わると消える |
| `logs/server.log` | サーバーの起動・終了と、断った要求 |
| `logs/hook.log` | フックが記録に失敗したときのエラー |

## 記録するもの

| もの | 残す内容 |
| --- | --- |
| 利用者の依頼、エージェントへの依頼文、エージェントの最後の報告 | そのまま（1件 8 KB まで） |
| コマンド | 先頭の 1,000 字 |
| ファイルの読み書き・検索 | ツールの名前とパスだけ |
| 利用者への質問 | 質問だけ |
| ツールの結果 | 残さない |

名前に pass・token・secret・key を含む項目の値（`名前=値`、`名前: 値`。全角の `＝`・`：` も）を `***` に替える。URL の `//利用者:パスワード@`、`-u 利用者:パスワード`、`sshpass -p パスワード` のパスワードも替える。
1つのチャットの記録は 20 MB まで。超えると、そこから後は記録せず、「お知らせ」を1件残す。記録は、新しいほうから 30 のチャットまで残す。
画面には、使われたツールを新しいほうから 300 件まで見せる。

## 記録されないとき

フックは、次のときは何もしない。

- `recording` がない、2 分より古い、またはシンボリックリンクである。
- `.debug-dashboard/` か、その中のフォルダがシンボリックリンクである。
- CLI を、画面を起動したのと違うフォルダで起動した。作業フォルダは、Claude Code では `CLAUDE_PROJECT_DIR`、Copilot CLI では `COPILOT_PROJECT_DIR` で決まる。Copilot CLI では、Git のリポジトリの中なら、そのいちばん上のフォルダになる。
- Python が見つからない（`py` も `python3` もない。Copilot CLI の Windows では、`py` も `python` も `python3` もない）。
- Claude Code の Windows で、`bash` が WSL のもの（`C:\Windows\System32\bash.exe`）になっている。
- プラグインとして入れていない。Claude Code では、フックを settings.json に写して CLI を起動し直すまで記録しない。Copilot CLI は、プラグインとして入れたときだけ記録する。

また、次のものは記録しない。

- バックグラウンドのサブエージェントが終わった知らせ（`<task-notification>` で始まる依頼）。「実行を止める」も解けない。
- バックグラウンドのサブエージェントを待っている間の、メインの会話の報告。
- Copilot CLI で、メインの会話の最後の報告を、3 秒のうちに読めなかったとき。Copilot CLI はフックに最後の報告を渡さないので、CLI の会話の記録から読む。そのターンにメインの会話の発言がなかったときも、記録しない。
- そのチャットで依頼文を記録していないエージェントの報告。CLI が中で動かすエージェント（入力の候補、`/btw` など）や、画面を起動する前に依頼したエージェントがこれにあたる。`recording` が古くなっていた間（PC のスリープ中など）に依頼したものも同じ。

## 画面が見せるチャット

画面では、1つのチャットを「実行」と呼ぶ。「進み具合」と「結果」は、エージェントに依頼したチャットのうち、いちばん新しいものを見せる。そのチャットがなければ、いちばん新しいチャットを見せる。「前の実行」でほかのチャットを選ぶと、そのチャットを見せ続ける。

## 今の段（計画・作業・評価）

画面は、依頼文や報告の中身を見ずに、エージェントの名前だけで今の段を決める。名前が `debug-verifier` で終わるエージェントが動いていれば評価、ほかのエージェントが動いていれば作業、どれも動いていなければ計画。
