# 送る手順

`run` は、機器に1回だけつなぐ。つながらなければ、やり直さずに終える。
送り先のフォルダ `remote_dir` に入り、なければ親から順に作る。そのあと、`files` のファイルを上から1つずつ、次の順に送る。

1. `<名前>.part` という名前で送る。
2. 機器のファイルのサイズ（SIZE）が、PC のファイルと同じかを確かめる。
3. `file_mode` があれば、権限を変える（SITE CHMOD）。
4. `<名前>` に名前を変える（RNFR・RNTO）。同じ名前のファイルがあると名前を変えられない機器では、古いファイルを消してから変える。

## 失敗したとき

- `<名前>.part` を消して止まる。古い `<名前>` は、そのまま残る。それまでに送ったファイルは、機器に残る（結果の `files` に入る）。
- 手順 4 で古いファイルを消したあとに名前を変えられなかったときは、`<名前>.part` を残し、`message` にそう書く。もう一度送るか、機器で名前を変えれば直る。
- `<名前>.part` を消せなかったとき（接続が切れた、消す権限がない）は、`message` にそう書く。次に送れば上書きされる。

## 送り先

- 送るのは `remote_dir` の中だけ。`remote_dir` に `..` は使えない。`/` で始めないと、ログインしたときのフォルダからの場所になる。
- 機器では、どのファイルも `remote_dir` の直下に、PC のファイルと同じ名前で置く（フォルダの構成は送らない）。名前が同じファイルは、2つ送れない。
- 名前に `\` や改行が入ったファイルは、送らずに設定の問題（終了コード 2）として返す。
- ファイルとフォルダの名前は UTF-8 で送る。

## check

- ログインし、送り先のフォルダに入って、中身の一覧を取る（NLST）。一覧は、ファイルを送るときと同じ種類の接続で取るので、`passive` や FTPS の問題もわかる。
- 送り先のフォルダがまだなければ、あるところまで入って一覧を取り、`notes` に「run のときに作る」と書く。あるのに入れなければ、失敗（終了コード 1）にする。
- 送るファイルが PC にまだなければ、`notes` に書く。run では、設定の問題（終了コード 2）になる。

## FTPS

`tls = true` のときは、FTPS（AUTH TLS）でつなぎ、ファイルも暗号化して送る（PROT P）。
ファイルを送る接続では、ログインした接続の TLS セッションを使い回す。そうしないと断る FTP サーバー（vsftpd の既定の `require_ssl_reuse=YES` など）があるためである。
機器の証明書は確かめない。盗み見は防ぐが、なりすましは防がない。
