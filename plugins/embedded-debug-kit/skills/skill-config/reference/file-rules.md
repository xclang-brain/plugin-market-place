# 設定ファイルの読み方と書き方

## コメントの読み方

項目の行のすぐ上に続く、行頭が `#` か `;` の行を、その項目のコメントとして読む。空の行があれば、そこで切れる。読むのは `[settings]` の項目だけ。

| コメント | 結果 |
| --- | --- |
| 「（必須）」を含む | `required` が `true` |
| 「（秘密）」を含む | `secret` が `true` |
| 「例：」で始まる行 | 「例：」の後ろを `examples` に足す |
| 「選べる値：a / b」の行 | `/` で区切った値を `choices` にする |
| そのほかの行 | `comment` |

- 括弧とコロンは、半角でも読む。
- 名前に `password`・`passwd`・`passphrase`・`secret`・`token`・`api_key` を含む項目も、「（秘密）」がなくても `secret` にする。
- `_env` で終わる項目は、環境変数の名前を書く項目なので、`secret` にしない。
- （秘密）の項目は、`<項目>_env` に名前があれば、空でも `missing` に入れない。

## set の決まり

- 項目の名前は、大文字と小文字を区別しない。ファイルにない項目は断る。
- 標準入力の各行の前後の空白と、空の行は除く。1行なら `項目 = 値`、2行以上なら `項目 =` の次の行から、行頭に空白を4つ入れて1行に1つずつ書く。
- 「選べる値：」のある項目には、その中の1つだけを書ける。大文字と小文字は区別せず、コメントの書き方にそろえて書く。
- （秘密）の項目は、空にすることだけができる。
- 制御文字を含む値は断る。2行以上の値で、`#` か `;` で始まる行があるときも断る（コメントとして読まれるため）。
- 書き換えるのは、その項目の行（リストの続きの行を含む）だけ。リストの中の字下げしたコメントは、値の後ろに残す。ほかの行、BOM、改行の形（CRLF か LF）は、そのまま残す。
- 書く前に、書き換えた後の中身を読み直し、ほかの項目の値とコメントが変わらないことを確かめる。変わるときは、書き換えをやめる（空の行の後に、字下げした続きの行があるときなど）。
- 同じフォルダの一時ファイルに書いてから、置き換える。途中で失敗しても、ファイルは元のまま。読み取り専用のファイルは断る。
- `.<スキルの名前>/` に `.gitignore` がなければ、書く前に、中身が `*` の `.gitignore` を置く。

## 標準入力の文字コード

UTF-8 で読む（BOM は外す）。UTF-8 で読めなければ、OS の既定の文字コード（日本語の Windows なら cp932）で読む。
Windows PowerShell 5.1 は、そのままだと日本語を `?` に変えてパイプに流す。SKILL.md の PowerShell の例は、そのために先に `$OutputEncoding` を UTF-8 にしている。

## ログ

set は、`<作業フォルダ>/.<このスキルの名前>/logs/<このスキルの名前>-<日付>.log` に、項目と、書き換える前と後の値を書き足す（UTF-8）。（秘密）の値は `＊＊＊` と書く。フォルダを作るときは、先に中身が `*` の `.gitignore` を置く。
