# 設定ファイルの読み方と書き方

## 読める書き方

設定ファイルは YAML で書く。読むのは、YAML のうち次の書き方だけ。ほかの書き方（入れ子、`[a, b]`、`|` など）は、何行目かを伝えて止まる。

- `項目: 値`。行頭から書く。値を空にするときは `項目:`。
- リストは、`項目:` の次の行から、`- 値` を1行に1つずつ書く。
- 記号で始まる値と、「: 」を含む値は、`'…'` で囲む。値の中の `'` は `''` と書く。
- `"…"` で囲んだ値も読める。中の `\` は、`\\` と `\"` だけ使える。
- 値は、数や `true` も、文字として読む。
- 行頭が `#` の行と、空白の後の `#` から行の終わりまでは、コメント。

## コメントの読み方

項目の行のすぐ上に続く、行頭が `#` の行を、その項目のコメントとして読む。空の行があれば、コメントはそこで切れる。

| コメント | 結果 |
| --- | --- |
| 「（必須）」を含む | `required` が `true` |
| 「（秘密）」を含む | `secret` が `true` |
| 「例：」で始まる行 | 「例：」の後ろを `examples` に足す |
| 「選べる値：」で始まる行 | `/` か `／` で区切った値を `choices` にする |
| そのほかの行 | `comment` |

- 括弧とコロンは、半角でも読む。
- 名前を `_`・`.`・`-` で区切った語に、`pass`・`password`・`passwd`・`passphrase`・`pwd`・`secret`・`token`・`api_key`・`apikey`・`private_key` がある項目は、「（秘密）」がなくても `secret` にする。たとえば、`login_pass` は `secret` にし、`max_tokens` は `secret` にしない。
- `_env` で終わる項目は、`secret` にしない。（秘密）の項目と対の `<項目>_env` には、環境変数の名前を書く。
- （秘密）の項目は、`<項目>_env` に名前があれば、空でも `missing` に入れない。

## set の決まり

- 項目の名前は、大文字と小文字を区別する。ファイルにない項目は断る。
- `--stdin` と `--empty` は、どちらか1つだけを付ける。
- 標準入力の各行の前後の空白と、空の行は除く。値の行が1つもなければ断る（標準入力の渡し忘れを、空にする依頼と取り違えないため）。
- 値が1つなら `項目: 値`、2つ以上なら `項目:` の次の行から、`  - 値` を1行に1つずつ書く。`--empty` なら `項目:` と書く。
- そのまま書くと YAML として別の意味になる値は、`'…'` で囲んで書く。
- 「選べる値：」のある項目には、その中の1つだけを書ける。大文字と小文字は区別せず、コメントの書き方にそろえて書く。
- （秘密）の項目は、空にしかできない。
- （秘密）の項目と対の `<項目>_env` には、環境変数の名前（英数字と `_`。数字で始めない）を1つだけ書ける。断るときも、渡された値は結果に出さない。
- 制御文字を含む値は断る。
- 書き換えるのは、その項目の行（リストの行を含む）だけ。リストの中のコメントは、値の後ろに残す。ほかの行、BOM、改行の形（CRLF か LF）は、そのまま残す。
- 書く前に、書き換えた後の中身を読み直し、ほかの項目の値とコメントが変わらないことを確かめる。変わるときは、書き換えをやめる（リストの途中に、行頭からのコメントがあるときなど）。
- 同じフォルダの一時ファイルに書いてから、置き換える。途中で失敗しても、ファイルは元のまま。読み取り専用のファイルは断る。
- `.<スキルの名前>/` に `.gitignore` がなければ、書く前に、中身が `*` の `.gitignore` を置く。

## 標準入力の文字コード

UTF-8 で読む（BOM は外す）。UTF-8 で読めなければ、OS の既定の文字コード（日本語の Windows なら cp932）で読む。
Windows PowerShell 5.1 は、そのままだと日本語を `?` に変えてパイプに流す。SKILL.md の PowerShell の例は、そのために先に `$OutputEncoding` を UTF-8 にしている。
