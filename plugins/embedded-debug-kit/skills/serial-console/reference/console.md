# 機器とのやりとり

## プロンプトが出るまで

1. ポートを 8N1、フロー制御なしで開く。Linux などでは、flock でポートに鍵をかけて開く。
2. Ctrl-U（打ちかけの文字を消す）と Enter を送り、最後の行が次のどれかになるのを待つ。
   - `login:` で終わる：`login_user` を送る。
   - `Password:` で終わる：ユーザー名を送ったあとなら、パスワードを送る。送る前なら、前に誰かが入力しかけたものなので、Enter で取り消す。
   - `prompt` に合う：シェルに着いた。
3. 3 秒たっても返事がなければ、もう一度だけ Enter を送る。

ログインしたら、そのままにする。次に動かしたときは、ログインせずにシェルが出る。

## コマンドを動かす

- コマンドを送り、最後の行が `prompt` に合って、0.2 秒続きが来なければ、終わったとみる。
- 終わったら ` echo "__rc=$?"` を送り、終了コードを読む。そのため、次のコマンドの `$?` は、前のコマンドの終了コードにならない。`./app; echo $?` のように1つのコマンドの中なら使える。
- `command_timeout_seconds` を過ぎたら Ctrl-C を送り、プロンプトが戻るのを 5 秒待つ。残りのコマンドは動かさない。
- プロンプトのすぐ後ろに機器のメッセージ（カーネルのログなど）が出てプロンプトが隠れたときは、1 秒何も届かなくなったら Enter を送り、プロンプトを出し直させる。プロンプトが `# ` のように短いときはしない（`# ` で始まる出力の行と見分けられないため）。
- `reboot` のように機器を再起動するコマンドは、プロンプトが戻らないので、時間切れで終わる。`--command` で1つだけ渡し、機器が起動し終わってから、check でシェルまで進める。

`exit_code` が `null` になるのは、時間切れのとき、機器のシェルが `$?` を使えないとき、答えが 5 秒以内に来ないとき。

## 出力とログ

- 色などの制御文字（ANSI のエスケープシーケンス）と `\r` を除き、バックスペース（`\b`）で消された文字を消す。
- 送ったコマンドのエコーと、最後のプロンプトを除く。出力が改行で終わらず、プロンプトと同じ行にあるときは、プロンプトだけを除く。
- JSON の `output` は、最後の 60 行・8,000 字まで。ログには、機器からの出力が、行ごとに `| ` を付けてすべて入る。終了コードを読むやりとりは、ログに書かない。
- パスワードと同じ文字列は、出力でもログでも `***` に替える。

## `--command` と `--stdin`

`--command` の値は `'…'` で囲む。値の中の `'` は、bash では `'\''`、PowerShell では `''` と書く。

次のときは、`--command` では値が変わってしまうので、`--stdin` で渡す。標準入力は書き換えられない。

- Windows PowerShell 5.1 と PowerShell 7.2 までは、値の中の `"` が正しく渡らない（`echo "x"` が `echo x` になる）。
- Windows の Git Bash は、`/` で始まる値を、`C:/Program Files/Git/opt/app/my_app` のような Windows のパスに書き換える。スクリプトは、書き換わった値を見つけると、終了コード 2 で止める。

`--stdin` は、標準入力を UTF-8 で読み、空でない行を1つずつコマンドにする。`--command` とは一緒に使えない。

## 設定の `commands`

- 2つ以上なら、`commands =` の次の行から、1行に1つずつ、行頭に空白を入れて書く。
- 行の頭が `#` か `;` の行は、コメントとして読み飛ばす。
