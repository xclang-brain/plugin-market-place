# 機器とのやりとり

## プロンプトが出るまで

1. ポートを 8N1、フロー制御なしで開く。Linux などでは、flock でポートに鍵をかけて開く。
2. Enter を送り、最後の行が次のどれかになるのを待つ。
   - `login:` で終わる：`login_user` を送る。
   - `Password:` で終わる：ユーザー名を送ったあとなら、パスワードを送る。送る前なら、前の人の打ちかけなので、Enter で取り消す。
   - `prompt` に合う：シェルに着いた。
3. 3 秒たっても返事がなければ、もう一度だけ Enter を送る。

ログインしたあと、ログアウトはしない。次に動かしたときは、そのままシェルが出る。

## コマンドを動かす

- コマンドを送り、最後の行が `prompt` に合って、0.2 秒続きが来なければ、終わったとみる。
- 終わったら ` echo "__rc=$?"` を送り、終了コードを読む。そのため、次のコマンドの `$?` は、前のコマンドの終了コードにならない。`./app; echo $?` のように1つのコマンドの中なら使える。
- `command_timeout_seconds` を過ぎたら Ctrl-C を送り、プロンプトが戻るのを 5 秒待つ。残りのコマンドは動かさない。
- プロンプトのすぐ後ろに機器のメッセージ（カーネルのログなど）が出てプロンプトが隠れたときは、1 秒静かになってから Enter を送り、プロンプトを出し直させる。

`exit_code` が `null` になるのは、時間切れのとき、機器のシェルが `$?` を使えないとき、答えが 5 秒以内に来ないとき。

## 出力とログ

- 色などの制御文字（ANSI のエスケープシーケンス）と `\r` を除き、後退（`\b`）を当てはめる。
- 送ったコマンドのエコーと、最後のプロンプトの行を除く。
- JSON の `output` は最後の 60 行まで。ログには、機器から届いた文字が、行ごとに `| ` を付けてすべて入る。終了コードを読むやりとりは、ログに書かない。
- パスワードと同じ文字列は、出力でもログでも `***` に替える。

## `--command` の書き方

値は `'…'` で囲む。値の中の `'` は、bash では `'\''`、PowerShell では `''` と書く。

Windows PowerShell 5.1 と PowerShell 7.2 までは、値の中の `"` が正しく渡らない。`"` を使うコマンドは、設定の `commands` に書く。

## 設定の `commands`

- 1行に1つ書く。2つ目からは、行頭に空白を入れる。
- 行の頭が `#` か `;` の行は、コメントとして読み飛ばす。
