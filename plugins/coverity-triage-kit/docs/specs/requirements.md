# coverity-triage-kit 仕様書

GitHub Copilot CLI 用のプラグインです。利用者の PC は Windows を想定し、Linux でも動作します。対象は、Coverity Connect に登録された C / C++ の警告です。

## 1. 目的

設定した条件で Coverity から警告を取得し、CID ごとに次の2つを出力します。

1. 修正コード
2. 修正しない場合の逸脱コメント

利用者が内容を確認して OK を出すと、プラグインが逸脱コメントを Coverity に登録し、修正をリポジトリに取り込みます。

## 2. 利用者の流れ

### 2.1 準備（最初の1回、3ステップ）

1. インストールします（コマンド2行）。事前に必要なものは、uv と、git（2.32 以降）または svn です。
2. Coverity のユーザー名と認証キーを、自分のターミナルで環境変数 `COV_USER` / `COV_AUTH_KEY` に設定します。
3. `/coverity-triage-kit:coverity-setup https://coverity.example.co.jp:8443 app-main` のように、URL とストリームを入力します。設定ファイルが作成され、接続の確認結果が表示されます。

### 2.2 4つの段階

どの段階も、上の段階なしで単独で使えます。

| 段階 | 利用者が入力するもの | 得られるもの |
| --- | --- | --- |
| 1 スキルと MCP | 「条件に合う警告を取得して」 | 警告の一覧 |
| | 「CID 20002 を処置して」 | その CID の修正コードと逸脱コメント（判定と根拠つき） |
| 2 エージェント1つ | エージェント `triage-worker` を選び、「条件に合う警告をすべて処置して」 | 条件に合う警告すべての修正コードと逸脱コメント。処置の間、質問はありません |
| 3 マルチエージェント | エージェント `triage-orchestrator` を選び、同じ依頼 | 2段階目と同じ出力を、より高い品質で（別のエージェントによる検証、同じ原因の CID の統合）。処置は並列に行います |
| 4 画面 | 「画面を開いて」 | ブラウザーの画面で、進捗と、CID ごとの修正コード・逸脱コメントを確認し、どちらを採用するかを選びます。選んだ後、チャットで「画面で選んだ内容で進めて」と入力します |

どの段階でも、最後は同じです。CID ごとの修正コードと逸脱コメントの一覧が1つ表示されます。確認して「OK」と答えると、プラグインが登録と取り込みを行います（4章）。

中断したときは、同じ依頼をもう一度入力すると、続きから進みます。取り込みと登録が済んだ後に同じ依頼を入力すると、次の警告を取得します。

## 3. 出力

CID ごとに、修正コード（リポジトリにそのまま適用できる差分）と、逸脱コメント（200文字以内。Coverity の Classification・Action・Severity つき）を出力します。判断の材料として、判定（本物のバグ／誤検知／意図的／判定不能）、確信度、根拠（ファイル:行）を添えます。

結果は、どの段階でも同じ形のフォルダーに保存します。画面と、OK の後の処理は、このフォルダーを読みます。

```text
<output_dir>/<年月日-時分秒>/
  issues.json            取得した警告の一覧
  cid/<CID>/result.json  判定、根拠、逸脱コメント
  cid/<CID>/fix.patch    修正コード（差分）
  summary.md             全 CID の修正コードと逸脱コメントを1つにまとめたもの
```

## 4. OK の後にプラグインが行うこと

CID ごとに、「修正を取り込む」「逸脱コメントを登録する」「何もしない」のどれかを選びます。最初は AI の推奨が選ばれています（確信度が低い CID は「何もしない」）。「20003 は逸脱、ほかは OK」のように、チャットか画面で変更できます。

| 選択 | プラグインが行うこと |
| --- | --- |
| 修正を取り込む | git：修正用のブランチを作り、修正1件を1コミットにして push し、プルリクエスト作成用の URL を表示します。svn：作業コピーに差分を適用します。どちらの場合も、Coverity に「Bug／Fix Required」と修正の概要を登録します |
| 逸脱コメントを登録する | Coverity に、Classification・Action・Severity とコメントを登録します |

Coverity に書き込む直前には、Copilot CLI の許可の確認が表示されます。

「何もしない」を選んだ CID は、Coverity では未分類のままです。次に取得したときに、もう一度対象になります。

## 5. 設定

設定ファイルは `<リポジトリ>/.coverity-triage/config.yaml` の1つです。`/coverity-triage-kit:coverity-setup` が作成します。必須は最初の2つだけです。

| キー | 既定値 | 意味 |
| --- | --- | --- |
| `coverity.url` | （必須） | Coverity Connect の URL |
| `coverity.stream` | （必須） | 対象のストリーム |
| `conditions.checkers` | すべて | チェッカー名（ワイルドカード可） |
| `conditions.impacts` | すべて | High / Medium / Low |
| `conditions.classification` | `Unclassified` | 取得する警告の分類 |
| `conditions.limit` | `20` | 取得する件数の上限 |
| `output_dir` | `../coverity-triage-out` | 結果フォルダーの場所（リポジトリの外） |
| `parallel` | `3` | 3段階目で同時に動かすエージェントの数 |
| `base_branch` | 自動判定 | git で修正を取り込む先のブランチ |
| `build.command` | 空 | ビルドのコマンド（下の2つのオプションで使用） |
| `build.check_fixes` | `false` | オプション：修正を適用した状態でビルドして確認します |
| `build.initial_analysis` | `false` | オプション：取得の前に、解析と Coverity への登録を行います |
| `build.analyze_args` | `--all` | オプションの解析で cov-analyze に渡す引数 |

## 6. 構成要素

| 段階 | 構成要素 | 役割 |
| --- | --- | --- |
| 1 | MCP サーバー `coverity-connect`（ツール4つ） | 接続の確認、警告の検索、警告の経路の取得、逸脱コメントの登録 |
| 1 | スキル `coverity-setup` | 設定ファイルの作成と接続の確認 |
| 1 | スキル `coverity-triage` | CID 1件の処置（修正コードと逸脱コメントの作成、結果の保存） |
| 1 | スキル `coverity-apply` | OK の後の、登録と取り込み |
| 2 | エージェント `triage-worker` | 取得した警告すべてを、1件ずつ最後まで処置します |
| 3 | エージェント `triage-orchestrator` | 全体の進行（並列の処置、統合、検証） |
| 3 | エージェント `triage-reviewer` | 別のエージェントによる検証 |
| 3 | エージェント `triage-integrator` | 同じ原因の CID の統合 |
| 4 | スキル `coverity-gui` | ローカルの HTML サーバーと画面 |

## 7. 品質の約束

- 取得した CID は、すべて結果に載ります。処置できなかった CID は、理由を表示します。未処置の CID が残っている間は、完了になりません。
- 3段階目では、すべての結果を別のエージェントが検証し、差し戻された結果は1回作り直します。同じ原因の CID は1つにまとめます。
- 修正コードは git または svn が作成した差分で、文字コードと改行コードをそのまま保ちます。逸脱コメントの形式は、スクリプトで確認します。
- 利用者のリポジトリと Coverity が変わるのは、OK の後だけです。処置中の編集は、リポジトリの外の作業用コピーで行います。
- 認証キーは、チャット、ログ、結果フォルダーのどこにも残しません。

## 8. 規模の上限

機能を追加するときも、次の上限を超えないようにします。上限は `tests/test_budget.py` で確認します。

| 項目 | 上限 |
| --- | --- |
| 出荷するコード（Python、JavaScript、HTML、CSS） | 5,500 行 |
| テスト | 6,000 行 |
| 利用者向けの文書（README と docs/guide） | 15,000 字 |
| ファイル | 160 |
| 利用者が使うコマンド | スキル 4、エージェント 2 |
| 設定キー | 13 |
| MCP のツール | 4 |
