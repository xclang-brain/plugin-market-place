# coverity-triage-kit 憲章

このプラグインを変更するときに、判断の基準にする原則です。仕様書と設計書は、この原則に従います。

1. **利用者のために作ります。** 導入しやすいこと、分かりやすいこと、出力の質が良いこと、早いことを優先します。機能の多さ、コードの量、文書の量は、価値ではありません。
2. **行うことは1つです。** 設定した条件で Coverity から警告を取得し、CID ごとに、修正コードと、修正しない場合の逸脱コメントを出力します。この目的に必要でない機能は、追加しません。
3. **4つの段階は、どれも単独で使えます。** 1段階目はスキルと MCP、2段階目はエージェント1つ、3段階目はマルチエージェント、4段階目は画面です。下の段階は、上の段階を必要としません。
4. **リポジトリと Coverity が変わるのは、利用者の OK の後だけです。** それまでの修正は、リポジトリの外の作業用コピーで行います。Coverity に書き込むツールは、事前に許可しません。
5. **認証キーは、チャット、ログ、結果フォルダー、設定ファイルのどこにも残しません。**
6. **規模に上限を設けます。** コード、テスト、文書、設定キー、コマンドの数の上限を仕様書に定め、テストで確認します。追加するときは、同じだけ削除できないかを先に検討します。
7. **文書と画面の文は、利用者の言葉で書きます。** プラグインが行うことと、利用者が行うことを先に書きます。内部の名前や、行わないことの列挙で説明しません。
8. **確認した事実だけを書きます。** 実機で確認していないことは、確認していないと書きます。

GitHub Copilot CLI 用のプラグインです。開発中の品質の確認に Claude Code を使いますが、利用者向けの機能と文書は Copilot CLI だけを対象にします。
