# ステップ2：Coverity に接続して、1件のトリアージを任せる

**所要時間**：30分（うち接続設定が20分）　**必要なもの**：[ステップ1](1-skill.md) を終えていること、Coverity Connect のアカウントと認証キー

このステップでは、Coverity への接続を設定し、CID を伝えるだけで1件のトリアージを最後まで任せます。

## 1. 接続を設定する（リポジトリごとに最初の1回）

リポジトリで Copilot CLI を起動し、次のコマンドを入力します。

```text
/coverity-setup
```

設定は対話で進みます。AI が1つずつ質問するので、答えていくだけです。聞かれるのは次の4つです。

| 聞かれること | 例 |
| --- | --- |
| Coverity Connect の URL | `https://coverity.example.co.jp:8443` |
| プロジェクト名 | `App` |
| ストリーム名 | `app-main` |
| Coverity のユーザー名 | `yamada` |

やり取りは、次のように進みます。

```text
AI ： Coverity Connect の URL を教えてください。
あなた： https://coverity.example.co.jp:8443
AI ： プロジェクトの名前を教えてください。
あなた： App
AI ： ストリームの名前を教えてください。
あなた： app-main
AI ： 次の内容で設定ファイルを作ります。

      | 項目           | 値                                        |
      | Coverity の URL | https://coverity.example.co.jp:8443       |
      | プロジェクト    | App                                       |
      | ストリーム      | app-main                                  |
      | 最初に調べる警告 | 未分類の警告を20件まで                      |
      | 結果の出力先    | ../coverity-triage-out（リポジトリの外）     |

      この内容で作りますか？
あなた： はい
```

**認証キーだけは、チャットではなく自分のターミナルで入力します。** AI が表示するコマンドを、別のターミナルに貼り付けて実行すると、入力欄が出ます（入力した文字は表示されません）。キーをチャットに貼らないのは、会話の記録に残さないためです。

最後に AI が接続を確認し、「準備ができました」と表示されたら完了です。Copilot CLI を一度終了し、新しいターミナルから起動し直してください（保存した認証情報を読み込むためです）。

できあがるもの：

| 場所 | 内容 |
| --- | --- |
| リポジトリの `.coverity-triage/config.yaml` | 接続先と動作の設定。コミットすれば、チームの他の人は設定を作らずに済みます |
| リポジトリの `.coverity-triage/filters/` | 対象の警告を絞り込む条件（ステップ3で使います） |
| 環境変数 `COV_USER` / `COV_AUTH_KEY` | 認証情報（PC ごと） |

## 2. 接続を試す

Coverity から警告の一覧を取得してみます。

```text
ストリーム app-main の、Impact が High の警告を一覧にして
```

CID、チェッカー、ファイルの一覧が返ってくれば、接続できています。この中から、トリアージする CID を1つ選びます。

## 3. 作業エージェントに1件を任せる

`/agent` と入力し、一覧から `triage-worker` を選びます。続けて、CID を伝えます。

```text
CID 12345 をトリアージして
```

エージェントは、Coverity から警告の経路を取得し、コードを調べ、ステップ1で個別に頼んだ内容を一度にまとめて報告します。

```text
結論：本物のバグです。fgets() が失敗したとき、開いたファイルを閉じずに戻っています。

判定：本物のバグ（true_bug）　確信度：高　推奨：修正

根拠：
- src/reader.c:15 — fopen() でファイルを開く
- src/reader.c:19〜20 — fgets() が NULL を返すと、fclose() せずに return -1 する

修正案：
     if (fgets(out, BUF_SIZE, fp) == NULL) {
+        fclose(fp);
         return -1;
     }

逸脱コメント案（修正しない場合）：
> 本物の不具合。open_and_read()（src/reader.c:19〜20）は fgets() の失敗時に fp を閉じない。

この差分を、作業中のファイルに適用しますか？
```

## 4. 修正を適用する（任意）

差分を確認して「はい」と答えると、エージェントが作業中のファイルを修正します。「いいえ」と答えれば、差分は提案のまま残ります。

## ここまでで分かったこと

- 接続設定は `/coverity-setup` の対話で作ります。設定ファイルの書き方を覚える必要はありません。
- 2段階目では、CID を伝えるだけで、調査・修正案・逸脱コメント案が一度に得られます。
- ファイルの修正は、差分を見て同意したときだけ行われます。

---

### 補足

- **設定をあとから変える**：もう一度 `/coverity-setup` を実行し、「1回の件数の上限を 50 にして」のように頼みます。画面で変えることもできます（ステップ3の `/coverity-gui`）。
- **チームの2人目以降**：コミットされた `.coverity-triage/` を pull してから `/coverity-setup` を実行すると、認証情報の設定だけで済みます。
- **Claude Code の場合**：`claude --agent coverity-triage-kit:triage-worker` で起動して、同じように頼みます（[Claude Code ガイド](claude-code.md)）。
- **うまく接続できないとき**：`/coverity-help` に症状を伝えるか、`/coverity-selftest` で診断します。
- この段階では、Coverity への書き込みは行いません。
- エージェントの詳しい説明は、[作業エージェントの README](../../com.github.copilot/agents/triage-worker.README.markdown) にあります。
