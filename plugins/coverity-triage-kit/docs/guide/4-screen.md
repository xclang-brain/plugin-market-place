# 4段階目：Web管理画面で一括のトリアージをする

チャットで頼むと、ブラウザーの画面（Web管理画面）が開きます。画面で条件を選んで「開始する」を押すと、エージェントが警告を一括でトリアージします。
実行の様子、止める操作、結果、改善の Issue の起票も、この画面で行います。

## できること

| 渡すもの | できること |
| --- | --- |
| チャットでの頼み（「Coverity の警告をトリアージして」など） | 画面の URL が出る。画面で条件を確かめて始められる |
| 画面で選ぶ条件（条件ファイル、Impact、件数、最初に解析するか） | 条件に合う警告を、エージェントが一括で調べ、警告ごとに修正案と逸脱コメント案を作る |
| 画面の「止める」 | この実行のエージェントと、初回解析やビルドの処理を止める |
| 画面の「承認して起票する」 | その課題の案だけを、このプラグインの GitHub リポジトリに Issue として起票する |

結果（一覧、詳細レポート、差分、修正後のファイル）は、実行フォルダにできます。承認の選択と反映は、結果と設定の画面と `/coverity-apply` で行います。

## 用意するもの

1. Copilot CLI で、試験的な機能を有効にする。どちらか1つを行います。
   - 一度だけ `copilot --experimental` で起動する（有効のまま残ります）。
   - チャットで `/settings experimental on` と入力する（Copilot CLI が起動し直します）。
2. エクステンションの読み込みの確認に答える。プラグインを入れて最初に起動したとき、次の確認が出ます。
   - 「Extension "plugin:coverity-triage-kit:coverity-triage-kit" wants elevated permissions」
   - 「Yes, and always allow … in this directory」（git のフォルダでは「in this repo」）を選ぶと、次からは聞かれません。「No」を選ぶと、画面は使えません。
3. 調べたいリポジトリに、設定（Coverity の URL、条件ファイルなど）を用意する。まだなら、チャットで `/coverity-setup` と入力します。
4. 認証情報（ユーザー名と認証キー）を環境変数に入れる。入れ方は `/coverity-setup` が案内します。

## 始め方

調べたいリポジトリのフォルダで Copilot CLI を起動し、チャットで次のように頼みます。

- 「Coverity の警告をトリアージして」
- 「未処理の Coverity 警告を調べて修正案と逸脱コメントを作って」
- 「misra.yaml の条件で、High だけ、10 件だけトリアージして」

チャットに、画面の URL と、4つの注意が出ます。

1. URL をブラウザーで開き、条件を確かめて「開始する」を押す。
2. 実行中は `/clear` を使わない。
3. エージェントの確認（ツールの許可、AI クレジットの上限、質問）には、チャットで答える。
4. 任せたいツールを前もって許可するしかたは、この文書と README にある。

画面は、Copilot CLI を動かしているパソコンのブラウザーからだけ開けます。URL には、起動するたびに変わる合言葉が入っています。いつもの番号（8731）が使われているときは、空いている番号で開きます。Copilot CLI を終えると、画面も閉じます。

## 開始の前に選ぶこと

| 項目 | 最初の値 | 意味 |
| --- | --- | --- |
| 役割ごとのモデル | 統括と検証は思考力の高いモデル、作業と統合は費用の低いモデル | 統括・作業・検証・統合のエージェントが使うモデル |
| エージェントごとの思考の深さ | 変えない | 変えないときは、エージェントの定義のとおり |
| 繰り返しの上限の回数 | 設定の値（ふつうは 1） | 警告ごとに、検証で差し戻されたときに作り直す回数の上限（0〜2） |
| 条件ファイルの名前 | untriaged.yaml | 調べる警告の条件。一覧にない名前も入れられる |
| Impact で絞る | 絞らない | High・Medium・Low・Unspecified のどれかに絞る |
| 調べる件数の上限 | 空（条件ファイルの上限） | 1〜100 |
| 最初に解析するか | 設定どおり | 「する」は、ビルドして解析し、Coverity に登録してから調べる（数十分かかることがある） |

- 頼みの文は、画面にそのまま出ます。条件ファイル・Impact・件数・最初に解析するかに当たる言い方は、最初の値に入ります。それ以外の言い方は「頼みの文の「…」は使いません。条件は画面で選んでください。」と出ます。条件を画面で選び直してください。
- Copilot CLI のモデルが Auto のときは、役割ごとのモデルが効かないことがあります。実際に動いたモデルは、エージェントごとに画面に出ます。
- 実行が終わると、このチャットでほかのエージェントに設定したモデルと思考の深さの指定も消えます。
- 画面から始めると、前の実行が途中でも、聞かずに新しく始めます。途中の実行は残り、チャットの `/coverity-run` で続きから再開できます。
- 開始できなかったときは、準備の画面に戻り、理由が出ます。設定がないときは、`/coverity-setup` で準備してください。

## 実行中の見方

画面は、再読み込みしなくても更新されます。

- 今のフェーズ（計画・実行・評価）と、今の段（警告の取得、警告ごとの作業、結果の確かめなど）
- 役割ごとの枠（統括1、作業は同時に動かす数、検証1、統合1）：担当している作業、状態、選んだモデルと実際に動いたモデル。終わったエージェントは「これまでのエージェント」に畳んであります。
- エージェントのあいだのデータの受け渡しの図
- 作業ごとの様子：作業、段、経過時間、作り直しの回数、状態。10 分（初回解析は 30 分）動きがない作業には「⚠ 停止?」が出ます。
- 重大なエラーと注意、最近の動き（新しい順に5行）、初回解析の進み具合、全体の進み具合
- 検証の結果：評価基準（C-01〜C-28）ごとの合格と不合格の数

エージェントが確認を求めると、画面に「チャットで確認を待っています」と、何の確認か（役割、種類、コマンドや場所）が出ます。答えはチャットでします。画面からは答えられません。

統括エージェントが、実行が終わる前に止まったときは、同じ実行フォルダの続きから2回まで自動で始め直します。始め直したことは「最近の動き」に出ます。

## 止める

画面の「止める」を押すと、この実行のエージェントと、初回解析やビルドの処理が止まります。10 秒ほどで、画面が終了の表示になります。チャットのほかの作業は止まりません。

止まらなかったエージェントや処理は、「止まっていないもの」に、止め方と一緒に出ます。エージェントは、ツールを使えないようにしてあります。止めるには、チャットで Esc を2回押すか、Copilot CLI を終えてください。

止めた実行は、チャットの `/coverity-run` で続きから再開できます。

## 結果を見る

終わると、画面に次が出ます。

- 終わった理由

  | 理由 | どういうときか |
  | --- | --- |
  | すべて合格した | すべての警告を処理し、確かめがすべて合格した（条件に合う警告がなかったときも） |
  | 上限の回数に達した | 作り直しの上限で「要確認」が残った、または処理できなかった警告がある |
  | ユーザーが止めた | 「止める」を押した |
  | 途中で終わった | 一括実行が続けられなかった、統括エージェントが途中で終えた、統括エージェントの失敗、チャットからの中断、AI クレジットの上限、`/clear` で切れた、エクステンションの再起動 |

- 実行全体のまとめ、件数と承認の内訳、一覧（確信度の低い順）、処理できなかった作業
- 各エージェントの最後の返事（畳んであります）
- 検証の結果（評価基準ごとの合否、警告ごとの合否と指摘）
- 結果と設定の画面へのリンク：確信度がいちばん低い警告の詳細レポート・差分・修正後のファイルと、承認の画面

承認の選択（修正・逸脱・却下・反映しない）と逸脱コメントの手直しは、リンク先の画面の「結果」で行い、`/coverity-apply` で反映します。結果と設定の画面は、あとからチャットの `/coverity-gui` でも開けます。

## 課題と Issue の起票

終わった後、課題の一覧（失敗した処理、詰まったエージェント、データの流れ）と、このプラグインを改善する Issue の案が並びます。最後まで動いた実行では、統括エージェントが振り返って足した課題も並びます。止めた実行と途中で終わった実行では、課題を洗い出すためにエージェントを動かしません。

案ごとの「承認して起票する」を押すと、その案だけが起票されます。起票には、次が要ります。

1. gh（GitHub の公式のコマンド）を入れ、`gh auth login` でログインする。
2. 起票先のリポジトリに、Issue を書き込めるアカウントであること。

起票できないときは、案は並んだままで、起票できるようにする手順が出ます。起票していない案は、次にチャットで頼んだときの準備の画面の「前の実行の結果」で見られます。

## 実行中に気をつけること

- 実行中は、チャットで `/clear` をしないでください。画面の更新が止まり、実行が途中で切れます。`/clear` の後にもう一度頼むと、前の実行が途中で切れたことが出ます。
- 実行中にもう一度チャットで頼むと、今の画面の URL と「いまの実行が終わるまで、新しい作業は始められません。」が出ます。条件を変えて頼み直すときは、画面で止めてから、もう一度チャットで頼んでください。
- 終わった知らせがチャットに来ても、結果は画面にあります。

## 任せたいツールを前もって許可する

実行フォルダはリポジトリの外にあるので、エージェントが書き込むたびに、Copilot CLI が許可を求めます。夜通し動かすときは、開始の前に次のどちらかをしておくと、確認で止まりません。

- チャットで `/add-dir "<実行フォルダの置き場所>"` と入力し、最初の確認で「このセッションでは許可」を選ぶ。実行フォルダの置き場所は、準備の画面の「実行フォルダの置き場所」に出ています。
- Copilot CLI を、許可を付けて起動し直す。

```text
# Windows（PowerShell）
copilot --add-dir "C:\coverity-triage-out" --allow-tool 'shell(uv:*)' --allow-tool write --allow-tool 'coverity-connect'
# Linux（bash）
copilot --add-dir "$HOME/coverity-triage-out" --allow-tool 'shell(uv:*)' --allow-tool write --allow-tool 'coverity-connect'
```

## うまく始まらないとき

チャットで頼んでも画面の URL が出ないときは、エクステンションが読み込まれていません。原因は次の3つのどれかです。

| 原因 | 直し方 |
| --- | --- |
| 試験的な機能が無効 | `copilot --experimental` で起動するか、チャットで `/settings experimental on` と入力する |
| 読み込みの確認で「No」を選んだ | Copilot CLI を終えて起動し直し、確認で「Yes」を選ぶ |
| `/extensions mode` が Disabled | チャットで `/extensions mode` と入力し、Load & Augment を選ぶ（Disabled は次の起動にも残ります） |

ほかに：

- 画面に「サーバーにつながりません」と出る：Copilot CLI を終えたか、`/clear` をしました。チャットでもう一度頼み、新しい URL を開いてください。
- 画面に「この画面の URL が正しくないか、古くなっています」と出る：チャットに出た最新の URL を開いてください。
- 開始すると「実行フォルダを作れませんでした」と出る：理由のとおりに設定を直します。設定がないときや直すときは、`/coverity-setup` を使います。困ったときは `/coverity-help` に聞いてください。

## 元のプラグインとの違い

使い方は、元のプラグイン coverity-warning-triage と同じです。部品を分けて、どれも単独で使えるようにしたため、次が違います。

- 繰り返しの上限は、警告ごとの作り直しの回数の上限（0〜2）です。元は、実行全体の繰り返しの回数（既定 3）でした。
- 画面から始めた実行では、結果の確かめ（検証エージェント）がいつも動きます。
- 役割ごとのモデルは、警告ごとのエージェント（作業・検証・統合）に効きます。
- 一覧の「承認」の列は、一覧を作ったときの値です。今の値は、結果と設定の画面で見ます。
- 結果と設定の画面は `/coverity-gui` で開きます。
