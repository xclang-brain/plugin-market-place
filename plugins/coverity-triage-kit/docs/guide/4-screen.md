# ステップ4：Web管理画面で一括トリアージを実行する

**所要時間**：最初の準備に10分　**必要なもの**：[ステップ3](3-batch.md) を終えていること、GitHub Copilot CLI

ステップ3では、条件をチャットに書いて実行しました。このステップでは、ブラウザーの画面で条件を選び、進み具合を見ながら実行します。エージェントごとの動きが見えるので、時間のかかる実行や、チームでの確認に向いています。

## 1. 画面の機能を有効にする（最初の1回）

Web管理画面は、Copilot CLI の試験的機能（エクステンション）で動きます。

1. `copilot --experimental` で起動します（一度指定すれば、以後は不要です）。
2. 起動時に次の確認が表示されたら、「Yes, and always allow … in this directory」を選びます。

   ```text
   Extension "plugin:coverity-triage-kit:coverity-triage-kit" wants elevated permissions
   ```

## 2. 画面を開く

リポジトリで Copilot CLI を起動し、チャットで頼みます。

```text
Coverity の警告をトリアージして
```

チャットに URL が表示されるので、ブラウザーで開きます。条件を添えて頼むと、画面の初期値に反映されます。

```text
misra.yaml の条件で、High だけ、10 件だけトリアージして
```

## 3. 条件を選んで開始する

準備の画面で条件を確認し、「開始する」を押します。最初は、既定のまま開始して構いません。

| 項目 | 初期値 | 内容 |
| --- | --- | --- |
| 条件ファイル | `untriaged.yaml` | 対象の警告の条件（[条件の指定](conditions.md)） |
| Impact | 絞らない | High・Medium・Low・Unspecified で絞り込む |
| 件数の上限 | 20 | 1〜100 |
| 最初に解析するか | 設定どおり | 「する」を選ぶと、ビルド・解析して Coverity に登録してから調べる |
| 役割ごとのモデル | 統括・検証は高性能、作業・統合は低コスト | 各エージェントが使う AI モデル |
| 繰り返しの上限 | 1 | 検証で差し戻された警告を作り直す回数（0〜2） |

## 4. 進み具合を見る

開始すると、画面が自動で更新されます。

- **全体の進み具合**：処理済みの件数と、今のフェーズ（計画・実行・評価）
- **エージェントの状態**：統括・作業・検証・統合の各エージェントが、今どの警告を処理しているか
- **警告ごとの状態**：調査中・修正案の作成中・完了など。10分動きがないと「⚠ 停止?」と表示されます
- **エラーと注意**：赤は対処が必要なもの、黄は注意

エージェントが許可や回答を求めているときは、画面に「チャットで確認を待っています」と表示されます。チャットに戻って答えてください。

途中でやめるときは、画面の「止める」を押します。止めた実行は、あとで `/coverity-run 前回の続きから` で再開できます。

## 5. 結果を確認して反映する

実行が終わると、結果の画面に切り替わります。

- 件数、推奨の内訳、警告の一覧（確信度の低い順）
- 検証の結果（評価基準ごとの合否）
- 結果を確認する画面へのリンク

ここから先は、ステップ3と同じです。リンク先の画面（`/coverity-gui` と同じもの）で警告ごとに「修正」「逸脱」などを選び、`/coverity-apply` で反映します。

## 6. 改善の Issue を起票する（任意）

結果の画面の下に、実行中に見つかった課題（失敗した処理など）と、このプラグインへの改善 Issue の案が表示されます。案ごとの「承認して起票する」を押すと、その案だけが GitHub（xclang-brain/plugin-market-place）に起票されます。

起票には、`gh` コマンドのインストールと `gh auth login` が必要です。

## ここまでで分かったこと

- 4段階目は、3段階目の一括トリアージに、条件の選択と進み具合の表示の画面を加えたものです。
- 結果の確認と反映は、3段階目と同じ手順（`/coverity-gui` → `/coverity-apply`）です。

これでチュートリアルは終わりです。日常の運用で必要になる情報は、[README の文書一覧](../../README.md#文書) から探せます。

### 補足

- **実行中は `/clear` を使わないでください。** 画面の更新が止まり、実行が中断されます。
- **実行中にもう一度チャットで頼んだ場合**：実行中の画面の URL が表示されます。条件を変えてやり直すときは、画面で止めてから頼み直します。
- **無人で実行する場合**：途中で許可の確認に止まらないよう、[事前に許可を設定します](operation.md#一括トリアージの前にツールを許可しておく)。
- **画面を開ける場所**：Copilot CLI を動かしている PC のブラウザーだけです。Copilot CLI を終了すると、画面も閉じます。
- **URL が表示されないとき**：エクステンションが読み込まれていません。原因と対処は [運用ガイド](operation.md#うまく動かないとき) にあります。
- **統括エージェントが途中で止まった場合**：同じ実行の続きから、自動で2回まで再開します。
- **モデルの指定**：Copilot CLI のモデルが Auto のときは、役割ごとの指定が効かないことがあります。実際に使われたモデルは、画面に表示されます。
- **終了の理由**：「すべて合格した」「上限の回数に達した」（要確認の警告や、処理できなかった警告が残った）「ユーザーが止めた」「途中で終わった」のいずれかが表示されます。
