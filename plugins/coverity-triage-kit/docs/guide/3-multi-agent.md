# 3. 複数のエージェントに任せる

**所要時間**：操作は5分　**前提**：[準備](../../README.md#準備最初の1回) が済んでいること

複数のエージェントが並列に処置し、同じ原因の CID を1つにまとめ、別のエージェントがすべての結果を検証して、[2. すべての警告を任せる](2-agent.md) と同じ出力を、より高い品質で作成します。統合と検証の時間が加わるため、見本の警告（6件と18件）では、2段階目のほうが早く終わりました。入力するものは、起動するエージェントの名前が違うだけです。

## 1. エージェントを起動して依頼する

```shell
copilot --agent coverity-triage-kit:triage-orchestrator
```

```text
条件に合う警告をすべて処置して
```

統括エージェントが、次の順に進めます。

| 順 | 行われること |
| --- | --- |
| 1. 並列に処置する | 複数のエージェントが、同時に別々の CID を処置します。同時に動かす数は、設定の `parallel`（最初は3）です |
| 2. 同じ原因の CID をまとめる | 1つの修正ですべて解消できる CID を、1つにまとめます。一覧では「20004（同じ原因: 20005, 20006）」と表示されます |
| 3. すべての結果を検証する | 処置したエージェントとは別のエージェントが、判定・修正コード・逸脱コメントをコードと照合します。問題が見つかった結果は、1回作り直します |

## 2. 一覧を確認して、OK を出す

一覧の形と「OK」の出し方は、2段階目と同じです。検証の結果は、選択と備考に表れます。

| CID | 判定 | 確信度 | 修正コード | 逸脱コメント | 選択 | 備考 |
| --- | --- | --- | --- | --- | --- | --- |
| 20004（同じ原因: 20005, 20006） | 本物のバグ | 高 | src/reader.c | 本物のバグ。… | 修正を取り込む | |
| 20003 | 本物のバグ | 中 | src/reader.c | 本物のバグ。… | 何もしない | 検証で要確認のため |

「検証で要確認のため」は、コードを読むだけでは結論が出ず、人の確認が必要だと検証で判断された CID です。`summary.md` の「検証の指摘」を読み、採用するなら「20003 は修正、ほかは OK」のように答えます。

中断したときの再開、続きの警告の処置、席を離れて実行するときの起動方法は、[2段階目](2-agent.md#中断したとき) と同じです（エージェントの名前だけを `triage-orchestrator` に変えます）。
