# 変更履歴

利用者から見て変わったことを書きます。新しい版が上です。

## 0.2.0（2026-11-09）

Claude Code でも使えるようにしました。GitHub Copilot CLI での使い方は変わりません（エージェントの説明の言葉が少し変わっただけです）。

### Claude Code で使える

- 同じプラグインを、Claude Code にも入れられます（`claude plugin install coverity-triage-kit@plugin-market-place`）。リポジトリの一番上に、Claude Code 用のマーケットプレイスの一覧を足しました。
- 1〜3段階目（スキル、MCP サーバー、作業エージェント、統括エージェントでの一括のトリアージ）が使えます。4段階目の Web管理画面は、Copilot CLI だけです。
- 呼び方、前もって許可するしかた、認証情報の渡し方は、README の「Claude Code で使う」にあります。部品だけを `.claude/agents/` と `.claude/skills/` に取り出す手順は、各エージェントの README にあります。
- 困ったとき・自己診断・一括実行の許可の案内・画面の入口のスキルが、Claude Code で動いているときは Claude Code の言葉で答えます（Copilot CLI での振る舞いは同じ）。自己診断は、Claude Code では Web管理画面の確かめを skip にします。画面の入口のスキルは、Claude Code では画面を開かず、統括エージェントでの始め方を伝えます。
- 夜通し動かすときは、起動のときに `claude --add-dir … --allowedTools …` で許可しておくのが確実です。チャットでするときは、`/add-dir` に加えて、`/permissions` で `uv` のコマンド・`Write`・`Edit`・Coverity から読む4つのツールを許可します。`Write` と `Edit` の許可は、セッションのすべてのファイルに効きます。
- 作業エージェントは、`claude --agent coverity-triage-kit:triage-worker` で起動したときに、差分を見せて、同意したときだけファイルを直します。名前を挙げて頼んだときは、差分を案として返すだけです。
- 反映（`/coverity-triage-kit:coverity-apply`）は、`--agent` を付けずに起動した Claude Code で行います。

### エージェントを作り直した

- 4つのエージェント（作業・統括・検証・統合）を、Claude Code の形で作り直し、Copilot CLI の定義も同じ中身にそろえました。使う部品の表と決まりは同じで、道具の言葉だけがツールごとに違います。
- 作業エージェントは、頼みの文が指示ファイル（作業用のコピーと結果のファイルを示したもの）を指すときだけ、ほかのエージェントからの頼みとして動きます。それ以外は、利用者との会話として動きます。作業中のファイルを直す同意は、利用者からだけ受け取ります。

## 0.1.0（2026-11-08）

最初の版です。元のプラグイン coverity-warning-triage の使い方を引き継ぎ、部品を1つずつ取り出しても使えるように作り直しました。

### 4つの段階で使える

- 1段階目：スキル1つ、または MCP サーバー1つで、1つの仕事ができます。チェッカーの見方、1件の警告の真偽の調査、修正、逸脱コメント、結果の記録、結果の確かめ、同じ原因の統合、準備、一括実行、反映、結果と設定の画面、Coverity Connect との通信です。スキルは、フォルダだけをコピーしても（名前を変えても）使えます。
- 2段階目：作業エージェント1つで、1件の警告（CID）のトリアージを最後まで行えます。チャットで頼むだけで動きます。
- 3段階目：統括・作業・検証・統合のエージェントで、条件に合う警告を一括でトリアージします。Web管理画面は要りません。`/agent` で統括エージェントを選ぶか、`/coverity-run` で始めます。
- 4段階目：Web管理画面で、元のプラグインと同じように、開始の設定・監視・止める・結果の確認・Issue の起票ができます。チャットで「Coverity の警告をトリアージして」と頼みます。

### 元のプラグインとの違い

- 繰り返しの上限は、警告ごとの作り直しの回数の上限（0〜2）になりました。元のプラグインは、実行全体を繰り返す回数（既定 3）でした。
- 画面から始めた実行では、結果の確かめ（検証エージェント）がいつも動きます。
- 画面で役割ごとに選んだモデルが、警告ごとのエージェント（作業・検証・統合）に効きます。
- 一覧（summary.html）の「承認」の列は、一覧を作ったときの値です。今の値は、結果と設定の画面で見ます。
- 結果と設定の画面は `/coverity-gui` で開きます。困ったとき（`/coverity-help`）からも開けます。
- エージェントはプラグインと一緒に入ります。サブエージェントを Copilot の設定のフォルダに置く手順はなくなりました。
- 元のプラグインの実行フォルダは一覧に出ますが、続きからはできず、反映もしません。
- `/coverity-setup` は、画面で準備する道を出しません。Coverity と通信する部品の用意は、README の「準備」の2で済ませておきます。
- Issue の起票先は、エクステンションの `defaults.json` の `issueRepo` です。画面に起票先を示し、案の本文は、認証情報・ユーザ名・ホスト名・メールアドレス・IP アドレスを伏せてから見せます。
- 夜通し動かすときの許可の案内は、Coverity から読むツールだけを前もって許可します。書き戻すツールは、反映のときにいつも確認が出ます。
- MCP サーバー、エージェント、エクステンションのツール、記録の置き場所の名前は、元のプラグインと重なりません。スキルの名前（`/coverity-run` など）は同じなので、元のプラグインとは、どちらか一方だけを入れてください。

### 試験

- モデルを使わない試験を、プラグインのフォルダで `python3 tests/run.py`（Windows では `py -3 tests/run.py`）で動かせます。部品ごとの試験、構造、取り決めの一致、独立性、模擬の Coverity との結合、文書、画面の試験です。
