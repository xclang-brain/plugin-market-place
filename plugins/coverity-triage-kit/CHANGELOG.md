# 変更履歴

利用者から見て変わったことを書きます。新しい版が上です。

## 0.2.0（2026-11-09）

エージェントの定義を作り直したので、エージェントの動作が少し変わったところがあります（下の「エージェントを作り直した」）。GitHub Copilot CLI でのインストール方法・呼び出し方・許可の方法は変わりません。

### エージェントを作り直した

- 4つのエージェント（作業・統括・検証・統合）の定義を作り直しました。使うスキルと MCP サーバー、動作の決まりは変わりません。
- 作業エージェントは、頼みの文が指示ファイル（作業用のコピーと結果のファイルを示したもの）を指すときだけ、ほかのエージェントからの頼みとして動きます。それ以外は、利用者との会話として動きます。作業中のファイルを直す同意は、利用者からだけ受け取ります。

### そのほかの修正

- 一括実行：途中の実行があるとき、頼みの文が「前回の続きから」を求めていれば、聞かずに再開します。`tick` の待ちは `tick` 自身がします（既定 20 秒、`sleep` などのコマンドで待たない）。理由や本文を渡す引数は `'…'` で囲みます（`"…"` の中の `$` や `` ` `` が展開されないように）。
- 自己診断：2-7（書き戻しを断る）で、許可の確認を断って呼べなかったときを「断った」と数えず、要確認にします。2-7 と 3-4 で、対象のリポジトリ（`repo_root`）を渡します。ツールが一覧に見えないときは、ツールを探すツールがあれば探してから、ないと決めます。
- 画面の入口：画面のツールがなかった後に、利用者が表の部品を自分で呼んだときは、その部品の手順に従います。統括エージェントが一括の実行を進めているときは、このスキルは何もしません。

## 0.1.0（2026-11-08）

最初の版です。

### 4つの段階で使える

- 1段階目：スキル1つ、または MCP サーバー1つで、1つの仕事ができます。チェッカーの見方、1件の警告の真偽の調査、修正、逸脱コメント、結果の記録、結果の確かめ、同じ原因の統合、準備、一括実行、反映、結果と設定の画面、Coverity Connect との通信です。スキルは、フォルダだけをコピーしても（名前を変えても）使えます。
- 2段階目：作業エージェント1つで、1件の警告（CID）のトリアージを最後まで行えます。チャットで頼むだけで動きます。
- 3段階目：統括・作業・検証・統合のエージェントで、条件に合う警告を一括でトリアージします。Web管理画面は要りません。`/agent` で統括エージェントを選ぶか、`/coverity-run` で始めます。
- 4段階目：Web管理画面で、開始の設定・監視・止める・結果の確認・Issue の起票ができます。チャットで「Coverity の警告をトリアージして」と頼みます。

### 試験

- モデルを使わない試験を、プラグインのフォルダで `python3 tests/run.py`（Windows では `py -3 tests/run.py`）で動かせます。部品ごとの試験、構造、取り決めの一致、独立性、模擬の Coverity との結合、文書、画面の試験です。
