# CERT C / C++ の見方

Coverity の CERT の警告（名前に `CERT` と規則の番号 `EXP34-C`・`ERR33-C` などが入るもの）の見方です。CERT の規則の多くは、セキュリティの弱点（CWE）に当たります。逸脱コメントのヒントの名前と場所は例なので、実際に読んだ場所に置き換えます。

## 考え方

- **判断の鍵は、攻撃者が入力を制御できる経路かどうか。** ★ の行に届く値の出どころ（外の入力、ファイル、通信、設定の値）をたどり、信用できない値が届くかを確かめる。
- 判定の目安：
  - 信用できない値が、確かめなしで ★ に届く → `true_bug`（攻撃や壊れたデータで起こりうる。優先して直す）。
  - 内部で作った値だけが届き、その値の範囲では問題が起きない（あふれない、範囲に収まる）→ `false_positive`。
  - 問題は起きないが、規則の違反（確かめのない書き方など）は残る → 逸脱するなら、逸脱コメントで外から届かない理由を説明する。
  - 内部の値でも問題が起きうる → `true_bug`。
- CERT の規則には優先度の水準（L1 が最も高く、L2、L3）がある。L1 の規則（STR31-C、MEM30-C など）で `true_bug` なら、修正を強く勧める。
- 多くの規則は標準チェッカーと同じ中身なので、その見方も使う（標準チェッカーの資料の同じ名前の項目）。

## 入力の出どころのたどり方

1. ★ の行の値（添字、長さ、ポインタ）が、どの変数から来るかを、代入をさかのぼってたどる。
2. 関数の引数なら、呼び出し元をすべて検索し、それぞれの値の出どころをたどる。
3. 出どころが次のどれかなら、信用できない値として扱う：`read`・`recv`・`fread`・`fgets` などで読んだデータ、通信のフレーム、ファイルの中身、`getenv`、コマンドラインの引数、外の機器のレジスタ、利用者が変えられる設定。
4. 出どころから ★ までに、範囲の確かめ（上限と下限の両方。符号付きなら負も）があるかを見る。

## EXP33-C

- **求めること**：値を入れる前のメモリを読まない。
- **見方**：UNINIT と同じ。出力引数で初期化する関数が、失敗のときも値を入れるかを確かめる。
- **直し方**：宣言で初期化するか、値を入れない経路で入れる。
- **判定**：値の入らない経路で読むなら `true_bug`。

## EXP34-C

- **求めること**：NULL のポインタを参照しない。
- **見方**：NULL_RETURNS・FORWARD_NULL と同じ。NULL になる条件が、外の要因（メモリ不足、ファイルがない、通信の失敗）で起こりうるかを見る。
- **直し方**：参照の前に `!= NULL` で確かめ、まわりのエラーの返し方にする。
- **判定**：NULL のまま参照に届く経路があれば `true_bug`。

## INT30-C

- **求めること**：符号なしの整数の計算で、回り込み（wrap-around）を起こさない。
- **誤検知・意図になりやすい形**：回り込みが設計どおり（ハッシュ、チェックサム、回る数え（カウンタ）、時刻の差の計算）。値の範囲で回り込まない。
- **確かめ方**：計算に入る値の範囲を出どころまでたどり、最大・最小の値で計算してみる。回り込んだ値を大きさや添字に使うかを見る（使えば危ない）。
- **直し方**：計算の前に確かめる（`if (a > UINT32_MAX - b)`、引き算なら `if (a < b)`）。
- **判定**：回り込んだ値で範囲の外を触る・確保が小さくなるなら `true_bug`。設計どおりの回り込みなら `intentional`。

## INT31-C

- **求めること**：整数の変換で、値を失ったり、符号を取り違えたりしない。
- **よくある形**：広い型から狭い型への代入（`uint8_t x = u32;`）、負の値を符号なしへ（`size_t n = len;` で len が負）、`getchar()` の戻り値を `char` に入れて `EOF` と比べる。
- **確かめ方**：変換の前の値の範囲が、変換の後の型に収まるかを出どころまでたどる。
- **直し方**：変換の前に範囲を確かめる。変数の型を合わせる（外から見える仕様に当たるなら避ける）。
- **判定**：収まらない値が届けば `true_bug`。範囲が保証されていれば `false_positive`。

## INT32-C

- **求めること**：符号付きの整数の計算で、あふれを起こさない（C では未定義の動き）。
- **確かめ方**：計算に入る値の範囲を出どころまでたどる。外から来た値の掛け算・足し算に多い。
- **直し方**：計算の前に上限・下限を確かめる。広い型で計算して範囲を確かめる。
- **判定**：あふれる値が届けば `true_bug`。範囲で決してあふれなければ `false_positive`。

## INT33-C と INT34-C

- INT33-C：0 で割らない（DIVIDE_BY_ZERO と同じ）。`%` も同じ。符号付きの `INT_MIN / -1` もあふれる。
- INT34-C：負の量や、型の幅以上の量でシフトしない（BAD_SHIFT、MISRA の Rule 12.2 と同じ）。
- 判定は、問題の値が届くかで決める。

## ARR30-C

- **求めること**：範囲の外を指すポインタや添字を作らない・使わない。
- **見方**：OVERRUN と同じ。添字の出どころが外の入力かを特に見る（通信のフレームの長さ、ファイルの中の数）。
- **直し方**：使う前に、添字を 0 以上、大きさ未満に確かめる。根の原因（大きさのマクロ）があれば1か所で直す。
- **判定**：範囲の外の値が届けば `true_bug`。

## ARR38-C

- **求めること**：ライブラリの関数（`memcpy`・`memset`・`fread` など）に、範囲の外を触らせる大きさを渡さない。
- **見方**：BUFFER_SIZE と同じ。大きさの引数と、書き込み先・読み出し元の大きさを比べる。
- **直し方**：大きさを書き込み先の `sizeof` で限る。外から来た長さは、先に確かめる。
- **判定**：大きさが超えうるなら `true_bug`。

## STR31-C

- **求めること**：文字列を入れる場所に、文字と終端の `'\0'` が入る大きさを用意する。
- **見方**：STRING_OVERFLOW と同じ。`strcpy`・`sprintf`・`gets` に、長さの分からない文字列（外の入力）を渡していないか。
- **直し方**：長さを渡す関数（`snprintf` など）にし、切れたときの扱いをまわりに合わせる。
- **判定**：入りきらない長さが届けば `true_bug`（L1）。

## STR32-C

- **求めること**：終端の `'\0'` のない文字の並びを、文字列として関数に渡さない。
- **よくある形**：`strncpy` で大きさいっぱいにコピーして、終端を入れないまま `strlen`・`printf("%s")` に渡す。読んだデータ（`fread`、`read`）をそのまま文字列として使う。
- **直し方**：コピーや読み込みの後に、必ず終端を入れる。
- **判定**：終端のないまま渡る経路があれば `true_bug`。

## MEM30-C

- **求めること**：解放したメモリを触らない。
- **見方**：USE_AFTER_FREE と同じ。
- **判定**：解放後に触る経路があれば `true_bug`（L1）。

## MEM31-C

- **求めること**：確保したメモリを、要らなくなったら解放する。
- **見方**：RESOURCE_LEAK と同じ。所有権の移動を確かめる。
- **判定**：解放されない経路があれば `true_bug`。終了まで持つ設計なら `intentional`。

## MEM34-C

- **求めること**：動的に確保したメモリだけを解放する（自動変数・静的な変数・ずらしたポインタを `free` しない）。
- **確かめ方**：`free` に渡すポインタの出どころを、確保した行までたどる。
- **判定**：確保していないものを解放する経路があれば `true_bug`。

## MEM35-C

- **求めること**：オブジェクトに十分な大きさを確保する。
- **よくある形**：`malloc(sizeof(p))`（ポインタの大きさ）、`malloc(n * size)` のあふれ、終端の1バイトの足し忘れ。
- **見方**：SIZEOF_MISMATCH・INTEGER_OVERFLOW と同じ。
- **直し方**：`sizeof(*p)` を使う。掛け算の前にあふれを確かめる。
- **判定**：確保が足りなくなる経路があれば `true_bug`。

## FIO42-C

- **求めること**：開いたファイルを、要らなくなったら閉じる。
- **見方**：RESOURCE_LEAK と同じ。エラーの経路の途中の `return` に多い。
- **直し方**：まわりの後始末（`goto cleanup` など）に合わせて閉じる。
- **判定**：閉じない経路があれば `true_bug`。

## FIO47-C

- **求めること**：正しい書式の文字列を使う（`%d` に `long` を渡すなど、書式と引数の型・数を合わせる）。
- **確かめ方**：書式と引数を1つずつ並べ、型（`size_t` は `%zu`、`uint32_t` は `PRIu32`）と数を比べる。書式の文字列が外から来ないか（書式の攻撃）も見る。
- **直し方**：書式を引数の型に合わせる。
- **判定**：合わなければ `true_bug`（表示が崩れるだけに見えても、未定義の動き）。

## ERR33-C

- **求めること**：標準ライブラリの関数が返すエラーを確かめて扱う。
- **見方**：
  - 失敗したときに、後の処理がどうなるかを確かめる。失敗のまま進んで、データを失う・壊れた値を使うなら、直す。
  - 無視して問題ない理由を説明できれば逸脱、説明できなければ修正（既存のエラーの扱いに合わせる）。
  - 例：読むだけで開いたファイルの `fclose` の失敗は、書き残しのデータがないので失っても困らないことが多い。書き込んだファイルの `fclose` の失敗は、データが書けていないことがあるので確かめる。
  - 失敗しても困らないことを示すために `(void)` を付けて無視するのは、規則の例外として扱われる書き方（まわりにその書き方があるか見る）。
- **直し方**：戻り値を確かめ、まわりのエラーの返し方にする。無視してよいなら `(void)` を付ける。
- **判定**：無視して問題が起きうるなら `true_bug`。無害で、理由を言い切れるなら `intentional`（逸脱）。

## DCL・ENV・POS のヒント

| 規則 | 求めること | 同じ見方 |
|---|---|---|
| DCL30-C | 自動変数のアドレスを、その変数より長く使わない | RETURN_LOCAL、MISRA Rule 18.6 |
| DCL31-C | 使う前に宣言する（暗黙の宣言をしない） | MISRA Rule 17.3 |
| DCL37-C | 予約された名前を宣言・定義しない | MISRA Rule 21.1・21.2 |
| DCL40-C | 同じ関数・変数を、合わない型で宣言しない | MISRA Rule 8.3・8.4 |
| ENV30-C | `getenv` などが返した文字列を書き換えない | |
| ENV32-C | 終了のときに呼ぶ関数（`atexit` で登録）は、ふつうに戻る | |
| ENV33-C | `system()` を呼ばない（命令の差し込みを防ぐ） | 引数が外から来るかを特に見る |
| ENV34-C | `getenv`・`strerror` などが返したポインタを、次の呼び出しの後まで持たない | |
| POS30-C | `readlink()` の結果に終端を入れる | STR32-C |
| POS34-C | `putenv()` に自動変数のアドレスを渡さない | DCL30-C |
| POS35-C | シンボリックリンクの確かめと使う間の競合を避ける | |
| POS36-C・POS37-C | 権限を手放す順（グループの後にユーザー）と、手放せたかの確かめ | |
| POS39-C | 機械の間でデータを送るとき、バイトの順を正しく変える（`htons`・`ntohl`） | |
| POS51-C | 鍵を取る順を決めて、デッドロックを避ける | LOCK |
| POS54-C | POSIX の関数のエラーを確かめる | ERR33-C |

## CERT C++ のヒント

- 名前は `EXP53-CPP` のように `-CPP` で終わる。中身は C の規則と同じ考え方のものが多い。
- EXP53-CPP（値を入れる前のメモリを読まない）は EXP33-C、MEM50-CPP（解放した後に触らない）は MEM30-C、MEM51-CPP（`new` と `delete`、`new[]` と `delete[]` を対にする）は確保と解放の組み合わせを見る。
- ERR50-CPP（いきなり終わらせない）・ERR51-CPP（すべての例外を受け止める）は UNCAUGHT_EXCEPT と同じ見方。
- CTR50-CPP（コンテナの添字を範囲に収める）は ARR30-C と同じ見方。

## 逸脱コメントのヒント

- 外から届かないことが理由なら、出どころと確かめの場所を書く。
  - 「誤検知。len は内部の表 frame_def（src/proto.c:12）の定数からだけ作られ、外の入力は届かないため、範囲の外を読むことはない。」
- 無視してよいエラーなら、無視しても困らない理由を書く。
  - 「意図的。fp は読むだけで開いたファイル（src/cfg.c:40）で、fclose() が失敗しても失うデータはなく、戻り値を見ないのは設計どおりである。」
- 設計どおりの回り込み（INT30-C）なら、その設計を書く。
  - 「意図的。seq は 0〜65535 を回る通し番号で（src/link.c:22 のコメント）、回り込みは設計どおりである。」
- 条件を付けないと言えない（「外から長さが来ない場合は」）ときは、言い切れないので、推奨を修正にする。
