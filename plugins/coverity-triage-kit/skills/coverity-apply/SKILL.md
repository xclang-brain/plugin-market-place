# 修正の取り込みと逸脱コメントの登録

処置済みの CID の一覧を示し、利用者が OK と答えた後に、CID ごとの選択（修正を取り込む／逸脱コメントを登録する／何もしない）のとおりに、修正をリポジトリに取り込み、逸脱コメントを Coverity に登録します。利用者のリポジトリと Coverity が変わるのは、OK の後だけです。利用者には、日本語で伝えます。

## 1. 一覧を示して、1回だけ質問する

```
uv run --native-tls --quiet "<このスキルのフォルダー>/scripts/apply.py" plan --repo "<リポジトリ>"
```

`<リポジトリ>` は、git または svn の作業ツリーの最上位フォルダーです。コマンドは JSON を1つ返します。このスキルのコマンドは、1回の呼び出しで1行だけ、書かれている全文を、パスも省略せずに実行します（シェルの変数、`;` や `&&`、パイプ、`cd` を使ったコマンドは、実行が許可されません）。

- 最初は、推奨の選択が入っています（確信度が低い CID などは「何もしない」）。画面で選んだ内容（`decisions.json`）があれば、それが入ります。以前にチャットで指定して OK と答えた選択も、そのまま入ります（備考は「チャットで指定」）。
- 利用者が CID の選択を変更したとき（「20003 は逸脱、20007 は何もしない」）は、応答の `to_change` のコマンドの `--set <CID>=<fix|deviation|none>` を、変更する CID ごとの `--set`（修正は `fix`、逸脱は `deviation`、何もしないは `none`。この例では `--set 20003=deviation --set 20007=none`）に書き換えて実行します。`after_ok` のコマンドは、回答に OK も含まれていたときだけ、その新しい応答のものを実行します。`to_change` には、この会話でそれまでに指定された変更が入っています（一覧をまだ示していないときは、上のコマンドに `--set` を付けます）。
- `table` をそのまま表示します。`summary_file` が `null` でないときは、「CID ごとの修正コードと根拠は <summary_file> にあります」と伝えます。
- `question` を1回だけ質問して、回答を待ちます（`next` は空です。`after_ok` のコマンドは、利用者が OK と答えた後に実行します）。`question` がないときは、`message` を伝えて終了します。
- `ok` が `false` のときは、`error`（`problems` があれば、その内容も）を利用者に伝えます。`problems` を自分で訂正できるとき（統合先の CID を指定する、など）は、`--set` を訂正して、もう一度実行します。
- 利用者に質問できないとき（対話のない実行など）は、`table` を表示して終了します。取り込みと登録は、利用者が OK と答えた後に行います。

## 2. 回答のとおりに実行する

| 回答 | 行うこと |
| --- | --- |
| 「OK」 | 一覧を示した `plan` の応答の、`after_ok` のコマンド（`apply`）を実行します |
| 変更と OK（「20003 は逸脱、ほかは OK」） | `to_change` のコマンドを、`--set 20003=deviation` に書き換えて実行します。OK は得ているので、その新しい応答の `after_ok` のコマンド（`apply`）を、そのまま実行します |
| 変更だけ（「20003 は逸脱にして」） | `to_change` のコマンドを、同じように書き換えて実行し、`table` を表示して、もう一度質問します |

`apply` の応答の `changed` が `true` のときは、一覧を表示した後に、結果または選択が変更されています。`next` のコマンド（`plan`）を実行し、`table` を表示して、もう一度質問します。

## 3. Coverity に登録して、結果を報告する

`apply` の応答の `call` にあるツール（`coverity_update_triage`）を、`arguments` のとおりに呼び出します（`call` が空のときは、登録するものはありません）。呼び出すときに、Copilot CLI が許可の確認を表示します。ツールの応答の `done` が `false` のときは、同じ引数でもう一度呼び出します。続けて、次を報告します。

- `message`
- git：ブランチ名（`git.branch`）と、プルリクエストのタイトル（`git.pr.title`）、作成用の URL（`git.pr.compare_url`。URL がないときは、本文 `git.pr.body`）。svn：変更したファイル（`svn.files`）
- Coverity に登録した CID（ツールの応答の `written`）
- 取り込めなかった修正（`fixes.failed`）と、登録できなかった CID（ツールの応答の `failed`）。それぞれ理由を添えます
- `git.push_error` があるときは、その内容。「修正を取り込んで」と入力すると、もう一度 push します
- ツールの呼び出しが許可されなかったとき、またはエラーになったときは、その内容と、報告の最後に、`if_not_called` の文を、文字を変えずに書きます（利用者が次に入力する文が入っています）
