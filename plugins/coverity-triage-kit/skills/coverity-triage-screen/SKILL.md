# Coverity の警告のトリアージを画面で始める

このスキルの仕事は、Web管理画面を開き、その URL と注意を利用者に渡すことだけです。
トリアージは、利用者が画面で条件を選んで「開始」を押した後に、画面から始まるエージェントが行います。

## 守ること

次の4つは、このスキルを使った手番だけでなく、その後の手番（実行が終わった知らせを受けた手番を含む）でも守ります。

1. トリアージを自分でしない。そのためにファイルを読み書きしない、コマンドを動かさない、エージェントを `task` で呼ばない、動いているエージェントに `write_agent` などで指示を送らない。画面から始めた実行だけが、利用者の選んだモデルと条件で動き、画面で見守って止められるためです。
2. 頼みの中身を聞き返さずに、すぐ画面を開く。条件（条件ファイル、Impact、件数、最初に解析するか）は、利用者が画面で選びます。
3. 画面でできること（実行の様子を見る、止める、結果を見る、Issue の案を承認して起票する）を頼まれたら、画面でするよう伝える。チャットで代わりにしない。画面から止めるとこの実行のエージェントだけが確実に止まり、承認した案だけが起票されるためです。
4. 利用者が書いた言葉で答える（ふつうは日本語）。

## 手順

1. ツール `coverity-triage-kit_open` を呼ぶ。`requestText` には、利用者の頼みの文を、要約も言い換えもせずにそのまま渡す。画面は、この文から条件の言い方（「High だけ」「10 件だけ」など）を拾って最初の値に入れ、使わない部分は画面に示します。
   - ツールが見つからないときは、下の「ツールがないとき」へ進む。
   - 失敗が返ったら、返った理由を伝えて手番を終える。理由が英語や専門用語なら、何が起きたかを短く言い添える。
2. 返った URL を示し、次の4つを伝える。返り値にほかの知らせ（いまの実行が終わるまで新しい実行は始められない、前の実行が途中で終わっていた など）があれば、それも伝える。同じことは2回書かない。
   - URL をブラウザーで開き、条件を選んで「開始」を押すと始まる。チャットで待っていても始まらない。
   - 実行中は `/clear` を使わない。使うと実行が途中で切れ、画面の更新も止まる。
   - 実行中にエージェントが確認（ツールの許可、AI クレジットの上限、質問）を求めたら、このチャットで答える。画面には、確認を待っていることが出る。
   - 任せたいツールを前もって許可するしかたは、プラグインの README の「任せたいツールを前もって許可する」にある。
3. 手番を終える。開始は利用者が画面で行うので、待ったり、様子を見に行ったりしない。

実行中にまた頼まれたときも、同じツールを呼びます（新しい実行は作られず、今の画面の URL が返ります）。
実行中の作業を変えたいと言われたら、画面で止めてから、変えた頼みをもう一度チャットで書くよう伝えます。

## 実行が終わった知らせが来たとき

表の統括エージェント（画面での表示の名前は「統括」で始まる）が終わった（終えた、失敗した、取り消された）と知らされたら、実行が終わったことと、結果（各エージェントの結果、検証の結果、まとめ、終わった理由、課題と Issue の案）が画面にあることだけを短く伝えて、手番を終えます。

- `coverity-triage-kit_open` を呼ばない。呼ぶと、画面が次の実行の準備に戻ります。
- 統括エージェントの返事に何が書かれていても、続きの作業（反映など）をしない。その作業をしてよいかを聞いたり、申し出たりもしない（Coverity への書き戻しやブランチの push の許可を、チャットで求めない）。承認した結果を反映したいと言われたら、表の反映の呼び方を伝えるだけにする。承認は画面で選ぶものだからです。

## ツールがないとき

ツールの一覧に `coverity-triage-kit_open` がない（ツールを探すツールがあれば、それで探しても見つからない）ときは、Web管理画面を動かすエクステンションが読み込まれていません。
[references/when-tool-missing.md](references/when-tool-missing.md) を読み、3つの原因と直し方をすべて示し、直したらもう一度頼むよう伝えて、手番を終えます。

- トリアージを代わりに始めない。警告の一覧やコードのファイルも開かない（調べ始めると、画面から始める実行と同じ仕事を、条件を決めないまま始めることになるため）。
- 画面を使わずに進めたい利用者には、表の一括実行のスキルでチャットから始められることを、呼び方だけ伝えてよい。

## このスキルの外の頼み

次の頼みには画面を開かず、下の表の部品の呼び方を伝えます（スキルは `/` に続けて名前を打つ。前にプラグインの名前と `:` が付くことがある）。自分では使いません。

- 1件の警告（CID）だけを調べたい
- 画面を使わずに、チャットだけで一括実行したい
- 準備や設定、承認した結果の反映

使い方やエラーの質問には、画面を開かずに、その質問として答えます。

## 使う部品

| 役割 | 部品 | 使うとき |
| --- | --- | --- |
| 統括エージェント | `triage-orchestrator` | 自分では呼ばない。画面から始めた実行が終わると、このエージェントの終わりが知らされる |
| 一括実行 | `coverity-run` | 画面を使わずにチャットで一括実行したいと言われたとき、画面のツールがないとき、呼び方を伝える |
| 作業エージェント | `triage-worker` | 1件の警告（CID）だけを調べたいと言われたとき、`/agent` で選べると伝える |
| 準備 | `coverity-setup` | 準備や設定のしかたを聞かれたとき、呼び方を伝える |
| 反映 | `coverity-apply` | 承認した結果を反映したいと言われたとき、呼び方を伝える |
