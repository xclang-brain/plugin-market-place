# code-fix（修正案の作り方）

## 何をするか

Coverity の警告を直す修正案を、決まりに沿って作るスキルです。

- 最小の変更にする（警告の経路を断つのに要る場所だけ）
- 外から見える仕様（関数の引数・戻り値、公開のヘッダ、大域の変数）を変えない
- 新しい MISRA・CERT の違反を作らない
- まわりの書き方（字下げ、名前、エラーの扱い、文字コード、改行）に合わせる

チャットでは、差分を示し、同意を得てから作業中のファイルを直します。作業用のコピーのフォルダを渡されたときは、そのフォルダだけを直します。
最新のコードでもう直っていれば何も変えず、そのことを伝えます。決まりの中で直せないときは、決まりを超えた修正と、超えた決まり・影響を受ける呼び出し元を示します。
Coverity には何も書き込みません。

## 必要なもの

- 直したいリポジトリのコード
- 警告の情報：CID、チェッカー、ファイルと行。あれば警告経路と、真偽の調べの結果
- スクリプトはありません。このフォルダだけで動きます。
- Coverity から警告経路を取れる道具（MCP サーバーなど）があれば、警告経路を自動で取ります。

## 置き方

このフォルダだけを、次のどれかにコピーします（フォルダの名前は変えても使えます）。

- 作業フォルダの `.github/skills/code-fix/`（GitHub Copilot CLI）
- `~/.copilot/skills/code-fix/`（GitHub Copilot CLI、すべての作業フォルダ）

## 呼び方

チャットで、警告の情報を添えて頼みます。AI がこのスキルを選びます（`/code-fix` でも呼べます）。

- 「この警告を直して：CID 41001、NULL_RETURNS、src/store.c の 27 行」
- 「CID 12345 の修正案の差分だけ見せて」
- 「誤検知だけど、警告が消えるように直したい」

AI は差分と、直した内容の1行と、影響を示し、「この差分で直してよいですか？」と聞きます。同意すると、示した差分のとおりに直します。

ほかのエージェントから、作業用のコピーのフォルダと結果の書き先を書いた頼み（指示ファイル）で呼ばれたときは、聞かずに、そのフォルダだけを直し、示された形で結果を返します。

## 設定

設定のファイルはありません。調べたいリポジトリに `.coverity-triage/knowledge.md` があれば、エラーの扱いの決まりなど、プロジェクトの知識として読みます。

## 結果の見方

| 項目 | 中身 |
|---|---|
| 差分 | リポジトリの一番上からの相対パスの unified diff（チャットのとき） |
| 直した内容（summary） | 1行の要約 |
| 影響（impact） | どの条件で何が変わるか、影響の範囲。決まりを超えたときは、影響を受ける呼び出し元のすべて |
| 超えた決まり（exceeded_constraints） | 守れなかった決まりと理由。ふつうは空 |
| 最新で直っている（already_fixed_on_latest） | 真なら何も変えていない。直っている場所も示す |
| Classification / Action / Severity | Bug / Fix Required / 警告の Impact に合わせた重さ（High は Major、Medium は Moderate、Low は Minor） |

チャットでは、差分と、直した内容・影響（決まりを超えたときは、その決まり）を、ふつうの言葉で返します（項目の名前は、ファイルに書くときに使います）。

注釈（`/* coverity[<タグ>:FALSE] 誤検知。… */` など）は、注釈を入れるフォルダを渡されて頼まれたときだけ入れます。

## うまくいかないとき

| 起きたこと | 直し方 |
|---|---|
| 差分が示されたが、ファイルが変わっていない | 同意するまで変えない決まりです。「この差分で直して」と答える |
| 差分が大きい・関係のない行も変わっている | 「警告の行だけを最小に直して」と頼み直す |
| 「決まりを超えます」と言われた | 示された、超えた決まりと影響を受ける呼び出し元を見て、直すか、逸脱にするかを決める |
| 「最新のコードでもう直っています」と言われた | 示された場所を確かめる。Coverity の解析が古いことが多い |
| 日本語の注釈が文字化けする | ファイルの文字コード（UTF-8 か Shift_JIS か）を伝え、その文字コードで直すよう頼む |

## テストの動かし方

このフォルダで動かします。

```
# Windows（PowerShell）
py -3 -B -m unittest discover -s tests
# Linux（bash）
python3 -B -m unittest discover -s tests
```

`tests/test_skill_files.py` が、SKILL.md の形、リンク、試験の課題の形を確かめます。

実際のモデルで解かせる試験の課題は `evals/` にあります（skill-creator の形。スキルありとなしを比べて採点します）。
