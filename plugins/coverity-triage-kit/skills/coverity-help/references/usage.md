## できること

- Coverity Connect の警告（C / C++、標準・MISRA・CERT）を、AI が1件ずつ下調べする。
- 警告ごとに、本物のバグかの見立て、確信度（高・中・低）、**修正案と逸脱コメント案の両方**を作る。
- 人は一覧を見て、修正か逸脱かを決める（承認）。承認したものだけが反映される。
- 人が承認して反映するまで、作業中のファイルも Coverity のトリアージ（分類・コメント）も変わらない。修正案は、結果の置き場所に作るコピーの上で作る。例外は初回解析（オプション）だけ。

AI がしないこと：修正か逸脱かを決める、承認していないものの反映、svn のコミット。

## 4つの段階

どの段階も、上の段階なしで使えます。

| 段階 | 使うもの | できること | 頼み方の例 |
| --- | --- | --- | --- |
| 1 | スキル1つ、または Coverity との通信の部品 | 1つの仕事 | 「MISRA 10.4 の警告はどう見ればいい？」「CID 12345（NULL_RETURNS、src/foo.c の 120 行）の警告が本物か調べて」「この警告を直して」「この警告の逸脱コメントを書いて」「この結果を確かめて」「この3件、同じ原因ならまとめて」「ストリーム app-main の High の警告を一覧にして」 |
| 2 | 作業エージェント | 1件の警告（CID）のトリアージを最後まで | `/agent` で作業エージェントを選び「CID 20001 をトリアージして」 |
| 3 | 一括実行のスキルか統括エージェント | 条件に合う警告の一括のトリアージ（画面なし） | 一括実行のスキルを `/` で呼び、「High だけ」「misra.yaml」「10 件だけ」「最初に解析して」「解析はしないで」を添える。または `/agent` で統括エージェントを選び「Coverity の警告をトリアージして」 |
| 4 | Web管理画面 | 画面で条件を選び、監視し、結果を見る | チャットで「Coverity の警告をトリアージして」 |

- 段階1のスキルは、ふつうの文で頼めば AI が選びます。結果はチャットに返り、頼まない限りファイルを作らず、Coverity にも書き込みません。
- 4段階目には、Copilot CLI の試験的な機能（エクステンション）が要ります。読み込まれていないときの直し方は troubleshooting.md の「画面が開かない」。
- 表の頼み方は Copilot CLI での言葉です。Claude Code では1〜3段階目を使えます（4段階目はありません）。呼び方は下の「Claude Code で使う」。

## 用意するもの

- git か svn のリポジトリ（調べたいコード）
- Coverity Connect のアカウントと認証キー（環境変数 `COV_USER` / `COV_AUTH_KEY`。チャットには書かない）
- uv（スクリプトと Coverity との通信の部品を動かす）。なければ準備のスキルが入れ方を示す
- 初回解析とビルドでの検証を使うときだけ：`cov-build`・`cov-analyze`・`cov-commit-defects`

準備（設定ファイル、条件ファイル、認証情報、接続の確かめ）は、準備のスキルで対話しながら行います。

## 一括のトリアージの流れ

次の順に進みます。設定で使わない段は飛ばします。

1. 初回解析（オプション）：開いているフォルダをビルド・解析し、Coverity サーバーに登録する
2. 警告の取得：条件に合う警告を Coverity から取る
3. 警告経路の取得：警告ごとに、問題が起きる道筋を取る
4. グループ分け：同じチェッカーで、同じマクロ・同じファイルと関数・同じファイルと行の警告を、1つのグループ（10件まで）にする。ID は CID か `G1`、`G2`…
5. 警告ごとの作業：作業エージェントが、1件（1グループ）ずつ調べて、修正案と逸脱コメント案を作る（同時に設定 `parallel` の数まで）
6. 同じ原因の統合（オプション）
7. 結果の確かめ（オプション）：差し戻しは作業エージェントが作り直す
8. ビルドでの検証（オプション）
9. 一覧と承認の案ができる

- 次に何をするかは、一括実行のスキルのスクリプトが決めます。チャットの AI（統括エージェント）は、その指示に従ってエージェントを呼ぶだけで、コードを読みません。
- 始めたら、終わるまで人に質問しません。始める前に、許可の与え方を1回だけ示します（下の「許可を前もって与える」）。
- どれかの AI が失敗しても、ほかの警告の処理は続きます。処理できなかった警告は一覧に出て、再開したときにやり直します。
- 結果の置き場所は `<output_dir>/<YYYYmmdd-HHMMSS>/`（実行フォルダ）。`output_dir` はリポジトリの外（既定 `../coverity-triage-out`）。

## エージェントの役割

| 役割 | 仕事 |
| --- | --- |
| 統括エージェント | 一括実行のスクリプトの指示に従い、作業・確かめ・統合のエージェントを呼ぶ。ファイルを直さない |
| 作業エージェント（作業役） | 1件（1グループ）を調べ、修正案と逸脱コメント案を作る。自分の結果の合否は決めない |
| 検証エージェント（検証役） | 結果を評価基準（C-01〜C-28）ごとに確かめ、合格・要確認・差し戻しを返す。結果を直さない |
| 統合エージェント（統合役） | 同じ原因の警告の結果を1つにまとめる計画を書く |

## 画面

画面は2つあります。どちらも、Copilot CLI を動かしているマシンのブラウザーだけで開けます。

- **Web管理画面**（4段階目）：チャットで「Coverity の警告をトリアージして」と頼むと開く。開始の前に、役割ごとのモデル、思考の深さ、作り直しの上限（0〜2）、条件ファイル、Impact、件数（1〜100）、最初に解析するかを選ぶ。実行中は、エージェントの枠、計画・実行・評価のどれか、作業ごとの様子、エラー、最近の動き、全体の進みが出る。「止める」で、この実行だけを止める。終わると、結果、検証の結果、まとめ、終わった理由、課題と Issue の案が出る。Copilot CLI を終えると、画面も終わる。
- **結果と設定の画面**：結果と設定の画面のスキルで開く（「画面を開いて」）。区分は、監視・結果・設定。結果で承認を選び、逸脱コメントを手直しする。設定で、設定・条件ファイル・知識・グループにしない CID を直す。2時間使わないと止まり、画面の「サーバを止める」でも止まる。止めても、実行フォルダのファイルと設定は消えない。

実行中にエージェントが確認（ツールの許可、AI クレジットの上限、質問）を求めたら、チャットで答えます。画面からは答えません。実行中は `/clear` を使いません（実行が途中で切れ、画面の更新も止まります）。

## 一覧と詳細レポートの読み方

実行フォルダの `summary.html`（一覧）は、確信度の低い順に並びます。

| 列 | 意味 |
| --- | --- |
| 承認 | 一覧を作ったときの承認（AI の推奨が最初から入っている）。今の値は結果と設定の画面で見る |
| ID | CID か、グループの `G1（3 件）` |
| 推奨 | 修正 / 逸脱 |
| 確信度 | 高：根拠がすべてコードで確かめられた／中：一部に推定がある／低：コードだけでは決められない。作業・確かめ・ビルドでの検証のいちばん低いもの（上がることはない） |
| 見立て | 判断の決め手の1行 |
| 詳細 | 詳細レポート `cid/<ID>.html` |

- 詳細レポートの順：結論 → 警告の概要 → 真偽の根拠 → 案A: 逸脱 → 案B: 修正（差分）→ 処理情報。
- 差分は `patches/<ID>-fix.patch`、修正後のファイルは `fixed/<ID>/fix/<パス>`。
- 確信度が「高」で見立てに納得できれば、そのまま承認してよい。「中」「低」は「真偽の根拠」を見る。
- 一覧と詳細レポートは表示だけ。書き換えても承認は変わらない。

## 承認

結果と設定の画面の「結果」で選びます。実行フォルダの `approvals.json` に保存されます（警告の一覧の行で選ぶとすぐ、1件の詳細では「保存」を押したとき）。

| 値 | 反映すると |
| --- | --- |
| 修正 | git：ブランチ `coverity-fix/cid-<CID>`（グループは `coverity-fix/<実行の日時>-G<n>`）を push し、プルリクエストを作る／svn：作業コピーに差分を当てる（コミットは人）。Coverity には書かない |
| 逸脱 | Coverity に分類（Classification / Action / Severity）と逸脱コメントを書き戻す |
| 却下 | 何もしない。グループなら、次の実行から1件ずつ調べる |
| 反映しない | 今回は反映しない（後で選べる） |

- 終わった作業だけ承認できる。統合か確かめを使う実行では、一覧ができるまで承認できない。
- 逸脱コメントを直すときは、詳細の欄で直して保存する（「AI の案に戻す」で戻せる）。

## 反映

反映のスキルで行います。Claude Code では、`--agent` を付けずに起動したセッションで行います（下の「Claude Code で使う」）。

- 実行を指定しなければ、いちばん新しい実行が対象。件数と ID を見せ、同意を得てから反映する。
- 逸脱の書き戻しの前に、件数・内容・確認の文字列が示される。確認の文字列が内容と合わなければ、何も書き込まれない。
- 途中で失敗しても、もう一度反映すると残りだけを行い、二重に書き込まない。
- プルリクエストは、使える道具で作る。作れないときは、作るための URL かブランチの名前を示す。GitHub のトークンは聞かない。

## 統合と確かめ（オプション）

どちらも既定では使いません（設定 `agents.integration`・`agents.review`）。使うと時間が延び、一覧ができるまで承認を選べません。

- 統合：同じ原因の作業を、新しい作業 `G<番号>` に1つにまとめる。まとめるのは原因が1つのものだけ。
- 確かめ：結果を1件ずつ、評価基準ごとに確かめる。

| 確かめの結果 | 意味 |
| --- | --- |
| 合格 | 直す点がない |
| 要確認 | 人に確かめてほしい点がある。確信度に上限が付く |
| 差し戻し | 作業エージェントが作り直す（警告ごとに `agents.max_rework` 回まで。既定 1、0〜2）。作り直しても残った指摘は要確認になる |
| 未検証 | 確かめられなかった。確信度は作業エージェントのまま |

Web管理画面から始めた実行では、確かめがいつも動きます。

## 初回解析とビルドでの検証（オプション）

- 初回解析（`verify.initial`）：警告を取る前に、開いているフォルダをビルド → `cov-analyze` → `cov-commit-defects` で Coverity サーバーに登録する。数十分かかることがある。失敗したら、トリアージを始めずに止まる。認証キーは環境変数 `COVERITY_PASSPHRASE` でだけ渡す。その実行だけ変えるときは「最初に解析して」「解析はしないで」。
- ビルドでの検証（`verify.default`：`none` / `build` / `build+analyze`）：修正案をビルド（と解析）で確かめる。問題のある修正は確信度 低になる。サーバーには登録しない。
- どちらも、ビルドのコマンド（`verify.build_command` など）が要る。準備のスキルで、試しのビルドをしてから保存できる。

## 再開

- 途中で止まった実行があると、一括実行のスキルは「前回の実行（日時・条件）が途中です。続きから再開しますか？」と聞く。終わった警告は飛ばし、途中とエラーの分だけやり直す。再開のときは、初回解析の有無を変えられない。
- Web管理画面から始めたときは、途中の実行があっても聞かずに新しく始める。途中の実行は残り、一括実行のスキルで再開できる。

## プロジェクトの知識

`.coverity-triage/knowledge.md` は、AI が調べる前に読む知識です。3つの見出しの下に、1行に1つ書きます。書き方は settings.md の「知識のファイル」。

- 知識とコードが食い違うと、AI はコードを優先し、そのことを結果に書く。古くなった知識は消す。
- オプション `options.knowledge_suggestions` を true にすると、反映の後、人が推奨を変えた点から知識の候補が示される。

## 許可を前もって与える

夜通しの実行で、始めた後に許可の確認で止まらないようにします。どちらか1つを行います。

1. チャットで `/add-dir "<output_dir>"` を打ち、最初の確認で「このセッションでは許可」を選ぶ（シェルの `uv`、ファイルの書き込み、Coverity との通信のツール）。
2. Copilot CLI を、次のように起動し直す（`<登録名>` は Coverity との通信の部品の名前）。

```text
copilot --add-dir "<output_dir>" --allow-tool 'shell(uv:*)' --allow-tool write --allow-tool '<登録名>(<読むツール>)' …
```

   読むツール（接続の確かめ・警告の検索・警告の詳細・反映の確かめ）ごとに `--allow-tool '<登録名>(<そのツールの名前>)'` を並べます（ツールの名前は、一括実行が示す許可の案内か、Coverity との通信の部品の README にあります）。書き戻すツールは前もって許可しません。反映のときに確認が出ます。サーバーの名前だけの `--allow-tool '<登録名>'` は、書き戻すツールまで許可するので使わない。

## Claude Code で使う

同じプラグインを Claude Code にも入れられます。1〜3段階目（スキル、Coverity との通信の部品、作業エージェント、一括のトリアージ）が使えます。4段階目の Web管理画面は GitHub Copilot CLI だけの機能で、Claude Code にはありません。

### 入れ方

```text
claude plugin marketplace add <マーケットプレイスのリポジトリ>
claude plugin install <プラグインの名前>@<マーケットプレイスの名前>
```

- Claude Code の中では、`/plugin marketplace add …` と `/plugin install …` でも入れられます。入れた後は、Claude Code を起動し直します。
- `<プラグインの名前>` は、このスキルの名前の前に付いている名前（`<プラグインの名前>:<スキル>`）。正確なコマンドは、プラグインの README の「Claude Code で使う」にあります。
- Coverity との通信の部品は、プラグインが登録します。`/mcp` で `plugin:<プラグインの名前>:<登録名>` が出れば、読み込まれています。
- 設定は、Copilot CLI と同じく、調べたいリポジトリの `.coverity-triage/` に置きます（準備のスキルで作る）。
- 調べたいリポジトリのフォルダで起動します。プラグインのフォルダそのものを作業フォルダにして起動しない（プラグインの MCP サーバーの登録が、そのフォルダの設定としても読まれ、動かない登録が1つ増える）。

### 段階ごとの呼び方

| 段階 | 呼び方 |
| --- | --- |
| 1 | スキルは `/<プラグインの名前>:<スキル>`（ほかに同じ名前がなければ `/<スキル>` でも）。ふつうの文で頼めば、AI が選ぶこともある |
| 2 | 作業エージェントの名前を挙げて頼む（「<作業エージェント> エージェントで CID 12345 をトリアージして」。`@` で選んでもよい）。または `claude --agent <プラグインの名前>:<作業エージェント>` で起動して頼む |
| 3 | `claude --agent <プラグインの名前>:<統括エージェント>` で起動して「High だけトリアージして」と頼む。または一括実行のスキルを `/` で呼ぶ（会話の主役が一括実行のスキルの手順に従い、作業・検証・統合のエージェントを呼ぶ） |
| 4 | 使えない。「Coverity の警告をトリアージして」と頼んでも、画面は開かない |

- 名前を挙げて（か `@` で）頼むと、作業エージェントは、会話の中から呼ばれたエージェント（サブエージェント）として動きます。サブエージェントは利用者に質問できないので、修正の差分を案として返すだけで、作業中のファイルは直しません。差分を見せ、同意を得てから作業中のファイルを直す流れは、`claude --agent <プラグインの名前>:<作業エージェント>` で起動したときだけです。
- 作業エージェントが質問したいのに、質問の道具がないときは、聞くことを返事に書いて止まる。チャットで答えると続きをする。
- 統括エージェントが呼んだエージェントは、裏で動くことがある。終わると、結果が知らせとして届く。
- 反映（反映のスキル）は、`--agent` を付けずに起動したふつうのセッションでします。統括エージェントで起動したセッションには、ファイルを書く道具も、反映の確かめと書き戻しの道具もありません。

### 許可（夜通し動かすとき）

一括のトリアージは、始めたら終わるまで質問しません。裏で動くエージェントは確認を出せないことがあり、前もって許可していないツールを使えずに止まります。始める前に、どちらか1つをします。夜通しの実行には、2 の起動のしかたが確実です。

1. チャットで `/add-dir "<output_dir>"` を打ち、出た確認で、このセッションのあいだの許可を選ぶ。`/add-dir` だけでは足りません（フォルダが加わるだけで、ファイルの書き込みもツールも許可されない）。続けて `/permissions` で、`Bash(uv run *)`、ファイルの書き込みの `Write` と `Edit`、Coverity から読む4つのツール（接続の確かめ・警告の検索・警告の詳細・反映の確かめ。名前は 2 と同じ形）を許可する（スキルの許可は Copilot CLI の書き方なので、Claude Code では前もって許可しないと毎回確認が出る）。書き戻すツールは許可しない。
2. Claude Code を、次のように起動し直す。

```text
claude --add-dir "<output_dir>" --allowedTools "Bash(uv run *)" "Write" "Edit" "mcp__plugin_<プラグインの名前>_<登録名>__<読むツール>" …
```

   読むツール（接続の確かめ・警告の検索・警告の詳細・反映の確かめ）ごとに、`mcp__plugin_<プラグインの名前>_<登録名>__<そのツールの名前>` を並べます（部品を取り出して手で登録したときは `mcp__<登録名>__<そのツールの名前>`）。3段階目を `--agent` で始めるときは、後ろに `--agent <プラグインの名前>:<統括エージェント>` を足します。書き戻すツールは前もって許可しません。サーバーの名前だけの `mcp__plugin_<プラグインの名前>_<登録名>` も、書き戻すツールまで許可するので使わない。反映のときに確認が出ます。

- `Write` と `Edit` の許可は、このセッションのどのファイルにも効きます。書き込みを実行フォルダだけにしているのは、エージェントの決まりです。
- 一括実行のスキルも、始める前に、この2つのしかたを実行フォルダの場所を入れて示します。

### 認証情報

Copilot CLI と同じ環境変数（`COV_USER` / `COV_AUTH_KEY`、プロキシを使うときは `HTTPS_PROXY` / `NO_PROXY`）に入れてから、Claude Code を起動します。プラグインが、この4つを Coverity との通信の部品に渡します。入れていない変数は、空として渡り、ないものとして扱われます。設定ファイルとチャットには書きません。
