# うまくいかないとき

| 起きたこと | 直し方 |
|---|---|
| 「設定ファイルがありません」 | `.coverity-triage/config.yaml` を用意します（準備の手順があれば、それで作れます）。始めません |
| 「設定に直すところがあります」 | `problems` の行（「config.yaml の parallel: 8 以下にしてください」など）を利用者に伝えます。設定を直したら、もう一度始めます |
| 「実行フォルダの置き場所がリポジトリの中です」 | 設定 `output_dir` をリポジトリの外（既定はリポジトリの隣の `coverity-triage-out`）にします |
| 「条件ファイルが見つかりません」 | `filters` に出る名前から選びます。名前は `.yaml` を省いてもかまいません |
| 「条件ファイルには、ストリームを 1 つだけ書いてください」 | 条件ファイルの `streams` を 1 つにします |
| 「作業用のコピーのパスが … 240 文字を超えます」（Windows） | 設定 `output_dir` を短いパス（例 `C:/cov-out`）にします（作業用のコピーに入るファイル、つまりバージョン管理しているファイルだけで数えます） |
| tick が `stop: true`（警告を取得できませんでした） | Coverity に届くか、認証キーの期限が切れていないか、条件のストリームが合っているかを確かめるよう伝えます。直したら `resume` で再開できます |
| tick が `stop: true`（初回解析に失敗しました） | `initial-status` の `log_tail` の要点を伝えます。ビルドの設定（`verify.build_command` など）を直したら `resume` で再開できます（初回解析をやり直します） |
| tick が `stop: true`（作業用のコピーを用意できない） | git / svn のエラーを伝えます。ディスクの空き、パスの長さ、リポジトリの状態を直したら `resume` で再開できます |
| 役のエージェントがない | `--failed <task> --reason "その役のエージェントがない"` で知らせ、どの役のエージェントを入れればよいかを伝えます。汎用のエージェントには頼みません |
| 許可の確認で止まる | 始める前に示した `permission_steps` のどちらかを行うよう伝えます |
| 「別の形で作られたものです」（`foreign: true`） | 別の版や元の道具で作った実行です。見ることはできますが、続きからはできません。新しく始めます |
| 「別の版のスクリプトで作られました」 | 実行フォルダの形が変わった版のスクリプトで作った、前の実行です。続きからはできません。新しく始めます |
| 「承認のファイル … が壊れているため、書き換えません」 | 人が選んだ承認を消さないため、止めています。示されたファイルを利用者に直してもらうか、選んだ承認が要らなければ消してもらってから、もう一度 `summary` を動かします。AI がファイルを書き換えません |
| 「task が分かりません」 | actions の `task` を、そのまま（印も付けて）渡します |
| 一覧の `run_checks` に `ok: false` がある | `detail` を伝えます。C-24（作業中のファイルが変わった）のときは、実行の間に誰かが変えていないか確かめるよう伝えます |

- どのエラーでも、スクリプトの外で同じことを手でしません（実行フォルダのファイルを書き換えるなど）。
- 実行の記録は、実行フォルダの `operations.log`（1 行に 1 つの JSON。認証情報は `****`）にあります。
