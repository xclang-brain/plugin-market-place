# 逸脱コメントの例

よい例と、だめな例の直し方です。どの「よい例」と「直す」も、確かめのスクリプトを通ります。

## よい例

チェッカーごとの例です。理由 → 根拠の場所 の順で、条件を付けずに言い切っています。

NULL_RETURNS（呼び出し元の保証）

> 誤検知。find_entry() は NULL を返しうるが、唯一の呼び出し元 load_table()（src/table.c:88）が直前に key を登録しているため、この呼び出しで NULL が返ることはない。

RESOURCE_LEAK（所有権が移る）

> 誤検知。open_log() で得た fp は構造体 ctx->log に入れて返しており（src/log.c:41）、閉じるのは close_ctx()（src/log.c:97）の役目なので、ここで漏れることはない。

OVERRUN（添字の範囲）

> 誤検知。index は呼び出し元 parse_header()（src/reader.c:55〜60）で 0〜7 に制限しており、8 要素の配列 buf の外を読むことはない。

UNINIT（出力引数での初期化）

> 誤検知。value は get_config()（src/config.c:30）が戻り値 0 のときに必ず書き込む出力引数で、戻り値が 0 でないときは src/main.c:52 で使う前に戻っている。

MISSING_BREAK（意図したフォールスルー）

> 意図的。case STATE_INIT から case STATE_RUN へのフォールスルーは、初期化のあと続けて実行を始める設計（src/fsm.c:120 のコメントに記載）であり、break の書き忘れではない。

DEADCODE（構成で使う分岐）

> 意図的。この分岐は BOARD_REV が 2 の構成で使うもので（include/board.h:15）、今の構成で実行されないのは設計どおりである。

MISRA C-2012 Rule 11.4（ハードウェアのレジスタ）

> 意図的。整数からポインタへの変換は、データシートで決まったレジスタの番地 0x40021000 を読むためのもので（src/hw/clock.c:23）、変換した値はこの番地にだけ使っている。

CERT ERR33-C（戻り値を使わない）

> 意図的。printf の戻り値は、表示に失敗してもこのデバッグ出力の後の処理に影響しないため、使っていない（src/debug.c:64）。

本物の不具合だが、今は実行されない

> 本物の不具合。v1 形式の読み込みは今の製品では無効（include/features.h:31）で、この処理は実行されない。

> 本物の不具合。src/legacy/v1_reader.c はビルドの対象から外してあり（CMakeLists.txt:40）、製品に入らない。

本物の不具合で、直さない理由を言い切れない（推奨は修正にする）

> 本物の不具合。src/reader.c:42 で fgets の戻り値を確かめずに使っており、直さない理由は説明できない。

## だめな例と直し方

条件や但し書き（「ただし」）

- だめ：本物の不具合。ただし、v1 形式の読み込みは今の製品では無効（include/features.h:31）で、この処理は実行されない。
- 直す：本物の不具合。v1 形式の読み込みは今の製品では無効（include/features.h:31）で、この処理は実行されない。

限定の言い方（「〜の場合に限り」）

- だめ：誤検知。count が 0 の場合に限り items は読まれないので問題ない。
- 直す：誤検知。count は唯一の呼び出し元 flush_queue()（src/queue.c:41）で 1 以上に決まっており、items が空のまま読まれることはない。

推量（「おそらく」）

- だめ：誤検知。呼び出し元で NULL を除いているので、おそらく問題にならない。
- 直す：誤検知。呼び出し元 open_session()（src/net/session.c:120）で NULL を除いてから渡しているため、NULL を参照することはない。

依頼・推奨

- だめ：誤検知。呼び出し元で NULL を除いている（src/a.c:10）。念のため確認してください。
- 直す：誤検知。呼び出し元で NULL を除いている（src/a.c:10）ため、NULL を参照することはない。

調べた過程を書いている

- だめ：誤検知。解析したリビジョンが分からなかったが、手元のコードでは src/a.c:10 で NULL を除いている。
- 直す：誤検知。呼び出し元 init()（src/a.c:10）で NULL を除いてから渡しているため、NULL を参照することはない。

判定区分がない・書式を使っている

- だめ：`find_slot()` の戻り値は呼び出し元で確かめているので NULL にならない。
- 直す：誤検知。find_slot() の戻り値は呼び出し元 open_session()（src/net/session.c:120）で確かめているため、NULL のまま使われることはない。

長すぎる（200文字を超える）

- だめ：誤検知。この警告は find_slot() が NULL を返す経路を指しているが、find_slot() を呼んでいるのは open_session() と open_admin() と open_debug() の3か所で、open_session() は src/net/session.c:120 で、open_admin() は src/net/session.c:210 で、open_debug() は src/net/session.c:305 で、それぞれ戻り値が NULL かどうかを確かめてから使っており、NULL のときはどれもエラーの値を返して処理をやめるので、NULL を参照することはなく、警告の経路は実際には通らない。
- 直す：誤検知。find_slot() の呼び出し元3か所（src/net/session.c:120、210、305）はどれも NULL を確かめてから使っており、NULL を参照することはない。
