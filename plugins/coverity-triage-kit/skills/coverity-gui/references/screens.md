## 監視のタブ

実行フォルダのファイル（`run.json`、`items/<ID>/progress.json`、`operations.log`、`analysis/status.json`、`jobs/`）を読むだけで、何も書かない。開いている間、2 秒ごとに新しくなる（タブを見ていないあいだは止まる）。

- 上の図：メインの AI（一括のトリアージを進める AI）と、その指示で動く枠。初回解析（initial）、作業役（worker。同時に動く数だけ）、統合役（integrator）、確かめの検証役（reviewer）。使っていないものは出ない。
- 枠の状態：▶ 動いている／⚠ 停止?／✖ エラー／✔ 終わった／空き・待ち。色だけでなく記号と文字でも示す。
- 「⚠ 停止?」：10 分動きがない作業（初回解析は 30 分）。修正用のコピーを用意している作業には出ない。チャットで確認（許可や質問）を待っていないか見てもらう。
- 作業ごとの様子：作業（CID か G1 などのグループ）、状態、段（コードを読む・真偽を判断・修正を作る・逸脱を書く・結果を書く）、経過時間、作り直しの回数。
- 重大なエラー：赤は重大（作業が止まった、初回解析の失敗、認証の失敗などで実行が止まっている、など）、黄は注意。押すと詳しい内容が開く。実行が止まっているときは、その理由を出す（原因を直して再開すると消える）。
- 最近の動き：`operations.log` の新しい順。
- 全体の進み具合：処理した作業 / 全体。

## 結果のタブ

- 実行の一覧：新しい順。進み具合と状態（途中・一覧あり・止めた・別の形の実行）。
- 警告の一覧：確信度の低い順。列は 承認・ID（チェッカー）・推奨・確信度・見立て・状態。グループは「G1（3 件）」。確信度は、作業役・確かめ・ビルドでの検証のいちばん低いもの。
- 承認：修正／逸脱／却下／反映しない。選ぶとすぐ `approvals.json` に保存され、推奨から変えた行に「✎ 推奨から変更」が出る。
  - 承認できるのは、調べ終わった作業だけ。処理できなかった作業は、理由が出る。
  - 統合か確かめを使う実行では、一覧（`summary.html`）ができるまで承認を選べない（結果が変わることがあるため）。
  - もう反映した作業の承認を変えると、反映したものは元に戻らないと知らせる。
- 詳細：左に詳細レポート、右に承認と逸脱の内容（Classification・Action・Severity・逸脱コメント）。「保存」で保存、「AI の案に戻す」で AI の案を入れ直す。空の欄は保存できない。逸脱コメントが 200 文字を超えると、保存はするが注意が出る（逸脱コメントは 200 文字以内の決まり。反映するとその文のまま Coverity に書き込むので、縮めて保存し直す）。
- 差分ファイルと修正後のファイル：名前を押すと詳細レポートの欄に出る（差分は色つき、ファイルは行番号つき）。↗ で新しいタブに開く。
- 一覧のページと詳細レポートは、作ったときの承認を示す。今の承認は、この画面で見る（画面はレポートを書き直さない）。
- 別の形で作られた実行（ほかの道具や前の版の実行）は、見るだけ。承認は選べない。

## 設定のタブ

`.coverity-triage/` の次のファイルを読み書きする。保存の前に、変える項目の表（今 → 保存後）を見せる。

| 区分 | 中身 |
| --- | --- |
| 基本設定 | Coverity の URL、最初の条件のプロジェクトとストリーム（最初だけ）、取り込み先のブランチ（git）、結果を置く場所（リポジトリの外）、認証情報 |
| オプション設定 | アノテーション・1 つのブランチにまとめる・知識の追記の提案・効果測定の記録・Markdown、統合と検証（差し戻しの上限 0〜2）、ビルドでの検証と初回解析、詳細設定（上限の件数、同時に調べる数 1〜8 など） |
| 条件 | `filters/*.yaml`。ストリームは 1 つだけ。チェッカーは `*` が使える。条件は少なくとも 1 つ残す |
| 知識 | `knowledge.md` |
| グループ化しない CID | `no-grouping.yaml` の `cids` |

- `config.yaml` と条件ファイルは、変えた値の行だけを書き換え、人が書いた注釈を元の場所に残す。ファイルにない項目は、既定の値から変えたときだけ足す。画面が知らない項目は、そのまま残す。
- 注釈を元の場所に残せない書き方（`|`・`>` で何行かにわたる値、`&`・`*` の使い回し）のファイルでは、保存の前に「このファイルでは、注釈は動いたり消えたりします」と知らせる。やめることもできる。続けると、値は正しく保存される。
- 認証情報：保存できるのは Windows だけ（ユーザーの環境変数）。認証キーの値は画面に出さない（設定済みかどうかだけ）。ユーザ名と認証キーの環境変数は別の名前にする。ほかの OS では、環境変数を自分で設定する。
- 読めないファイル（UTF-8 でない、YAML の書式の誤り、型の違う値）は、画面に既定の値を出し、何を直せばよいかを日本語で示す。`knowledge.md` が読めないときは、画面からは保存しない。
- バージョン管理の種類（git か svn）は、フォルダから決まるので変えられない。

## サーバと合言葉

- 127.0.0.1 だけで待ち受ける。URL の `?t=…` が合言葉で、最初に開いたときにブラウザーのクッキーに入り、アドレス欄からは消える。
- リポジトリごとに 1 つ。もう一度開くと使い回す。スクリプトが新しくなっていれば、古いサーバを止めて起動し直す。
- 止まるのは、「サーバを止める…」を押したとき、止めるコマンドを動かしたとき、2 時間使われなかったとき。止まっても、動いている一括のトリアージは止まらない。
- サーバの場所の記録は、ホームフォルダの `.<このスキルのフォルダの名前>/` にある（本人だけが読める）。

## うまくいかないとき

| 起きたこと | 直し方 |
| --- | --- |
| 「この画面は、画面を開くコマンドが示したアドレスで開いてください」 | 合言葉のない URL か、止まったサーバの URL。開くコマンドをもう一度動かし、新しい URL を開く |
| 「画面のサーバが止まっています」 | 2 時間使われなかったか、止めた。開くコマンドをもう一度動かす |
| 「画面のサーバを起動できませんでした」 | 出力の `log_tail` を見る。uv が動くか（`uv --version`）、ホームフォルダに書けるかを確かめる |
| ブラウザーが開かない | 出力の `url` を、この PC のブラウザーで開く（ほかの PC からは開けない） |
| 実行が一覧に出ない | `config.yaml` の `output_dir`（結果を置く場所）の中の `<年月日-時分秒>` のフォルダだけが出る。`note` に置き場所が出る |
| 「run.json を読めません」 | 実行フォルダの `run.json` が壊れている。一覧の下に、読めない実行として出る |
| 承認を選べない | 統合か確かめを使う実行で、一覧がまだない。一括のトリアージが終わるのを待つ |
| 認証情報を保存できない | Windows 以外では保存しない。環境変数（既定 `COV_USER` と `COV_AUTH_KEY`）を自分で設定する |
