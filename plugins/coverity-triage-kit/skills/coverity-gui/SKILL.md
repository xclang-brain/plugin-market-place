# 結果と設定の画面

調べるリポジトリごとに、この PC だけで開けるローカルの画面（127.0.0.1）を開く。
画面は切り離したサーバで動き、開いたコマンドが終わっても動き続ける（「サーバを止める」を押すまで止まらない）。
同じリポジトリでもう一度開くと、動いているサーバを使い回す。

画面のタブ：

| タブ | できること |
| --- | --- |
| 監視 | 実行中の AI の動き（役割ごとの枠の図）、作業ごとの段・経過時間・作り直し、「⚠ 停止?」（10 分動きがない作業。初回解析は 30 分）、重大なエラー、最近の動き。2 秒ごとに新しくなる |
| 結果 | 実行の一覧 → 警告の一覧（確信度の低い順）。一覧の行で承認を選ぶと、すぐ `approvals.json` に保存。詳細（1 件の画面）では、承認と逸脱コメントなどを直して「保存」を押すと保存（押すまでは保存されない）。AI の案に戻す、差分と修正後のファイルを見る |
| 設定 | `.coverity-triage/` の設定・条件・知識・グループにしない CID。保存の前に変更の表を見せ、`config.yaml` の注釈は元の場所に残す |

詳しい画面の中身と、うまくいかないときの直し方は [references/screens.md](references/screens.md) にある（利用者に画面のことを聞かれたときに読む）。

## 手順

1. 何をするかを一言伝える（例：「結果の画面を開きます」）。
2. リポジトリ（`.coverity-triage/` がある、git か svn の一番上のフォルダ）を決める。ふつうは今の作業フォルダ。実行フォルダ（`<output_dir>/<年月日-時分秒>/`）の話なら、その場所も決める。
3. 次のコマンドを動かす（スクリプトは読まずに動かす）。

   ```text
   uv run --native-tls --quiet "<このスキルのフォルダ>/scripts/gui.py" open --repo "<リポジトリ>"
   ```

   頼みに合わせて引数を足す：

   | 頼み | 足す引数 |
   | --- | --- |
   | 設定を直したい（既定） | なし、または `--view settings` |
   | 実行の様子を見たい | `--run "<実行フォルダ>"`（監視のタブが開く） |
   | 結果を見たい・承認を選びたい | `--run "<実行フォルダ>" --view summary` |
   | 1 件の詳細・逸脱コメントを直したい | `--run "<実行フォルダ>" --item <ID>`（ID は CID か G1 など） |

   ブラウザーを開かずに URL だけがほしいと頼まれたとき（ほかのエージェントや画面から頼まれたときなど）は、`--no-browser` を足す。

4. 出力（JSON 1 つ）を見て伝える。
   - `ok: true`：`url` を伝える。`browser_opened` が false なら「この PC のブラウザーで、この URL を開いてください」と添える。`note` があれば、その内容も伝える。
   - `ok: false`：`error`（と `problems`）を、平易な言葉でそのまま伝える。同じことを別のやり方（ファイルを手で書き換えるなど）でしない。
5. 必要なら、次のことだけを短く伝える。
   - 承認の保存は、選ぶ場所で違う。警告の**一覧の行**で選ぶと、すぐ保存される。**詳細**（`--item` で開く 1 件の画面）では、承認も逸脱コメントなども、直したあと「保存」を押したときに、まとめて保存される（押すまでは「● 保存していない変更があります」と出て、保存されない）。`--item` で開いたときは、「承認を選び、逸脱コメントを確かめてから『保存』を押してください」と伝える。はじめは AI の推奨が入っている。
   - 承認を確かめたら、チャットで「承認を反映して」と頼む（反映の手順を持つスキルがあれば、それで反映する）。
   - 統合か確かめを使う実行では、一覧（summary.html）ができるまで承認を選べない。

画面のサーバを止めるよう頼まれたら、次を動かす（画面の右上のメニューの「サーバを止める…」でも止まる）。

```text
uv run --native-tls --quiet "<このスキルのフォルダ>/scripts/gui.py" stop --repo "<リポジトリ>"
```

## 守ること

- `approvals.json` と `.coverity-triage/` のファイルは、利用者が画面で直す。AI は直さない（承認は人が決める）。
- 認証情報をチャットで聞かない。認証キーは、Windows では画面の「基本設定」で入れてもらい、ほかの OS では環境変数に自分で設定してもらう。キーがチャットに貼られたら使わず、作り直しを頼む。
- 画面の URL には合言葉（`?t=…`）が入っている。ほかの人や記録に渡さない。開けるのは、この PC のブラウザーだけ。
- 一覧（summary.html）と詳細レポートには、作ったときの承認が出る。今の承認は画面で見る。レポートを作り直さない。
