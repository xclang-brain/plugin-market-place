# CERT C / C++ の観点

Coverity の CERT の警告（名前に `CERT` と規則の番号 `EXP34-C`・`ERR33-C` などを含むもの）の観点をまとめています。CERT の規則の多くは、セキュリティ上の弱点（CWE）に対応します。「問題の行」は、警告経路の main のイベントの行です。逸脱コメントの例の名前と場所は例示です。実際に読んだ場所に置き換えます。

## 考え方

- **判断の鍵は、攻撃者が入力を制御できる経路かどうかである。** 問題の行に到達する値の出所（外部の入力、ファイル、通信、設定値）をたどり、信頼できない値が到達するかを確認する。
- 判定の目安：
  - 信頼できない値が、チェックなしで問題の行に到達する → `true_bug`（攻撃や破損したデータで起こりうる。優先して修正する）。
  - 内部で生成した値だけが到達し、その値の範囲では問題が起きない（オーバーフローしない、範囲に収まる）→ `false_positive`。
  - 問題は起きないが、規則の違反（チェックのない書き方など）は残る → 逸脱するなら、外部から到達しない理由を逸脱コメントで説明する。
  - 内部の値でも問題が起きうる → `true_bug`。
- CERT の規則には、優先度のレベル（L1 が最も高く、L2、L3 と続く）がある。L1 の規則（STR31-C、MEM30-C など）で `true_bug` なら、修正を強く推奨する。
- 多くの規則は標準チェッカーと同じ内容なので、その観点も使う（[standard.md](standard.md) の同じ名前の項目）。

## 入力元のたどり方

1. 問題の行の値（添字、長さ、ポインタ）がどの変数から来るかを、代入をさかのぼってたどる。
2. 関数の引数なら、呼び出し元をすべて検索し、それぞれの値の出所をたどる。
3. 出所が次のいずれかなら、信頼できない値として扱う：`read`・`recv`・`fread`・`fgets` などで読み込んだデータ、通信のフレーム、ファイルの内容、`getenv`、コマンドライン引数、外部機器のレジスタ、利用者が変更できる設定値。
4. 出所から問題の行までの間に、範囲のチェック（上限と下限の両方。符号付きなら負の値も）があるかを確認する。

## EXP33-C

- **要求**：未初期化のメモリを読まない。
- **観点**：UNINIT と同じ。出力引数を初期化する関数が、失敗のときも値を書き込むかを確認する。
- **修正**：宣言で初期化するか、値が代入されない経路で代入する。
- **判定**：値が代入されない経路で読むなら `true_bug`。

## EXP34-C

- **要求**：NULL ポインタを参照しない。
- **観点**：NULL_RETURNS・FORWARD_NULL と同じ。NULL になる条件が、外部の要因（メモリ不足、ファイルがない、通信の失敗）で起こりうるかを確認する。
- **修正**：参照の前に `!= NULL` でチェックし、周囲と同じ方法でエラーを返す。
- **判定**：NULL のまま参照に到達する経路があれば `true_bug`。

## INT30-C

- **要求**：符号なし整数の演算で、ラップアラウンドを起こさない。
- **誤検知・意図的になりやすいパターン**：ラップアラウンドが設計どおりである（ハッシュ、チェックサム、循環するカウンタ、時刻の差の計算）。値の範囲から、ラップアラウンドしない。
- **確認方法**：演算に使う値の範囲を出所までたどり、最大値・最小値で計算する。ラップアラウンドした値を、サイズや添字に使用するかを確認する（使用すれば危険である）。
- **修正**：演算の前にチェックする（`if (a > UINT32_MAX - b)`、減算なら `if (a < b)`）。
- **判定**：ラップアラウンドした値で範囲外にアクセスする・確保するサイズが小さくなるなら `true_bug`。設計どおりのラップアラウンドなら `intentional`。

## INT31-C

- **要求**：整数の変換で、値が失われたり、符号が誤って解釈されたりしないようにする。
- **よくあるパターン**：広い型から狭い型への代入（`uint8_t x = u32;`）、負の値の符号なしへの変換（`size_t n = len;` で len が負）、`getchar()` の戻り値を `char` に代入して `EOF` と比較する。
- **確認方法**：変換前の値の範囲が、変換後の型に収まるかを、出所までたどる。
- **修正**：変換の前に範囲をチェックする。または、変数の型を合わせる（外部仕様の変更になるなら避ける）。
- **判定**：収まらない値が到達すれば `true_bug`。範囲が保証されていれば `false_positive`。

## INT32-C

- **要求**：符号付き整数の演算で、オーバーフローを起こさない（C では未定義動作）。
- **確認方法**：演算に使う値の範囲を、出所までたどる。外部から入力された値の乗算・加算に多い。
- **修正**：演算の前に上限・下限をチェックする。または、広い型で計算してから範囲をチェックする。
- **判定**：オーバーフローする値が到達すれば `true_bug`。範囲から決してオーバーフローしなければ `false_positive`。

## INT33-C と INT34-C

- INT33-C：0 で除算しない（DIVIDE_BY_ZERO と同じ）。`%` も同じ。符号付きの `INT_MIN / -1` もオーバーフローする。
- INT34-C：負のシフト量や、型のビット幅以上のシフト量でシフトしない（BAD_SHIFT、MISRA の Rule 12.2 と同じ）。
- 判定は、問題になる値が到達するかで決める。

## ARR30-C

- **要求**：範囲外を指すポインタや添字を作らない・使わない。
- **観点**：OVERRUN と同じ。添字の出所が外部の入力かどうかを特に確認する（通信フレームの長さ、ファイルの中の数値）。
- **修正**：使用する前に、添字が 0 以上、サイズ未満であることをチェックする。根本原因（サイズのマクロ）があれば、1か所で修正する。
- **判定**：範囲外の値が到達すれば `true_bug`。

## ARR38-C

- **要求**：ライブラリ関数（`memcpy`・`memset`・`fread` など）に、範囲外にアクセスさせるサイズを渡さない。
- **観点**：BUFFER_SIZE と同じ。サイズの引数と、書き込み先・読み出し元のサイズを比較する。
- **修正**：サイズを、書き込み先の `sizeof` で制限する。外部から入力された長さは、先にチェックする。
- **判定**：サイズが超えうるなら `true_bug`。

## STR31-C

- **要求**：文字列の格納先に、文字と終端の `'\0'` が収まるサイズを確保する。
- **観点**：STRING_OVERFLOW と同じ。`strcpy`・`sprintf`・`gets` に、長さが不明な文字列（外部の入力）を渡していないかを確認する。
- **修正**：長さを渡す関数（`snprintf` など）に置き換え、切り詰められたときの扱いを周囲に合わせる。
- **判定**：収まらない長さが到達すれば `true_bug`（L1）。

## STR32-C

- **要求**：終端の `'\0'` がない文字の並びを、文字列として関数に渡さない。
- **よくあるパターン**：`strncpy` でサイズいっぱいにコピーし、終端を書き込まないまま `strlen`・`printf("%s")` に渡す。読み込んだデータ（`fread`、`read`）を、そのまま文字列として使用する。
- **修正**：コピーや読み込みの後に、必ず終端を書き込む。
- **判定**：終端がないまま渡される経路があれば `true_bug`。

## MEM30-C

- **要求**：解放したメモリにアクセスしない。
- **観点**：USE_AFTER_FREE と同じ。
- **判定**：解放後にアクセスする経路があれば `true_bug`（L1）。

## MEM31-C

- **要求**：確保したメモリを、不要になったら解放する。
- **観点**：RESOURCE_LEAK と同じ。所有権の移動を確認する。
- **判定**：解放されない経路があれば `true_bug`。終了まで保持する設計なら `intentional`。

## MEM34-C

- **要求**：動的に確保したメモリだけを解放する（自動変数、静的変数、先頭からずらしたポインタを `free` しない）。
- **確認方法**：`free` に渡すポインタの出所を、確保した行までたどる。
- **判定**：確保していないものを解放する経路があれば `true_bug`。

## MEM35-C

- **要求**：オブジェクトに対して、十分なサイズを確保する。
- **よくあるパターン**：`malloc(sizeof(p))`（ポインタのサイズ）、`malloc(n * size)` のオーバーフロー、終端の1バイトの加算漏れ。
- **観点**：SIZEOF_MISMATCH・INTEGER_OVERFLOW と同じ。
- **修正**：`sizeof(*p)` を使う。乗算の前にオーバーフローをチェックする。
- **判定**：確保するサイズが不足する経路があれば `true_bug`。

## FIO42-C

- **要求**：開いたファイルを、不要になったら閉じる。
- **観点**：RESOURCE_LEAK と同じ。エラーの経路の途中にある `return` に多い。
- **修正**：周囲の後処理（`goto cleanup` など）に合わせて閉じる。
- **判定**：閉じない経路があれば `true_bug`。

## FIO47-C

- **要求**：正しい書式文字列を使う（`%d` に `long` を渡すなどを避け、書式と引数の型・個数を一致させる）。
- **確認方法**：書式と引数を1つずつ対応させ、型（`size_t` は `%zu`、`uint32_t` は `PRIu32`）と個数を比較する。書式文字列が外部から入力されないか（書式文字列攻撃）も確認する。
- **修正**：書式を引数の型に合わせる。
- **判定**：一致しなければ `true_bug`（表示が乱れるだけに見えても、未定義動作である）。

## ERR33-C

- **要求**：標準ライブラリの関数が返すエラーを検出し、処理する。
- **観点**：
  - 失敗したときに、後の処理がどうなるかを確認する。失敗したまま処理が進み、データを失う・不正な値を使用するなら、修正する。
  - 無視しても問題がない理由を説明できれば逸脱、説明できなければ修正（既存のエラー処理に合わせる）。
  - 例：読み取り専用で開いたファイルの `fclose` の失敗は、未書き込みのデータがないので、問題にならないことが多い。書き込んだファイルの `fclose` の失敗は、データが書き込まれていないことがあるので、チェックする。
  - 失敗しても問題がないことを示すために `(void)` を付けて無視するのは、規則の例外として扱われる書き方である（周囲にその書き方があるかを確認する）。
- **修正**：戻り値をチェックし、周囲と同じ方法でエラーを返す。無視してよいなら `(void)` を付ける。
- **判定**：無視すると問題が起きうるなら `true_bug`。無害で、その理由を断定できるなら `intentional`（逸脱）。

## DCL・ENV・POS の補足

| 規則 | 要求 | 同じ観点の項目 |
|---|---|---|
| DCL30-C | 自動変数のアドレスを、その変数の寿命より長く使わない | RETURN_LOCAL、MISRA Rule 18.6 |
| DCL31-C | 使用する前に宣言する（暗黙の宣言をしない） | MISRA Rule 17.3 |
| DCL37-C | 予約済みの識別子を宣言・定義しない | MISRA Rule 21.1・21.2 |
| DCL40-C | 同じ関数・変数を、互換性のない型で宣言しない | MISRA Rule 8.3・8.4 |
| ENV30-C | `getenv` などが返した文字列を書き換えない | |
| ENV32-C | 終了時に呼び出される関数（`atexit` で登録）は、通常どおりに戻る | |
| ENV33-C | `system()` を呼び出さない（コマンドインジェクションを防ぐ） | 引数が外部から入力されるかを特に確認する |
| ENV34-C | `getenv`・`strerror` などが返したポインタを、次の呼び出しの後まで保持しない | |
| POS30-C | `readlink()` の結果に終端を書き込む | STR32-C |
| POS34-C | `putenv()` に自動変数のアドレスを渡さない | DCL30-C |
| POS35-C | シンボリックリンクのチェックと使用の間の競合状態を避ける | |
| POS36-C・POS37-C | 権限を放棄する順序（グループの後にユーザー）と、放棄できたことの確認 | |
| POS39-C | 異なるシステムの間でデータを送るとき、バイトオーダーを正しく変換する（`htons`・`ntohl`） | |
| POS51-C | ロックを取得する順序を決めて、デッドロックを避ける | LOCK |
| POS54-C | POSIX の関数のエラーをチェックする | ERR33-C |

## CERT C++ の補足

- 名前は `EXP53-CPP` のように `-CPP` で終わる。内容は、C の規則と同じ考え方のものが多い。
- EXP53-CPP（未初期化のメモリを読まない）は EXP33-C、MEM50-CPP（解放後にアクセスしない）は MEM30-C と同じ観点で確認する。MEM51-CPP（`new` と `delete`、`new[]` と `delete[]` を対応させる）は、確保と解放の組み合わせを確認する。
- ERR50-CPP（プログラムを突然終了させない）・ERR51-CPP（すべての例外を捕捉する）は UNCAUGHT_EXCEPT と同じ観点で確認する。
- CTR50-CPP（コンテナの添字を範囲内にする）は ARR30-C と同じ観点で確認する。

## 逸脱コメントの例

- 外部から到達しないことが理由なら、値の出所とチェックの場所を書く。
  - 「誤検知。len は内部のテーブル frame_def（src/proto.c:12）の定数だけから生成され、外部の入力は到達しないため、範囲外を読むことはない。」
- 無視してよいエラーなら、無視しても問題がない理由を書く。
  - 「意図的。fp は読み取り専用で開いたファイル（src/cfg.c:40）で、fclose() が失敗しても失われるデータはなく、戻り値を参照しないのは設計どおりである。」
- 設計どおりのラップアラウンド（INT30-C）なら、その設計を書く。
  - 「意図的。seq は 0〜65535 を循環するシーケンス番号で（src/link.c:22 のコメント）、ラップアラウンドは設計どおりである。」
- 条件を付けないと説明できない（「外部から長さが入力されない場合は」）ときは、断定できないので、推奨を修正にする。
