- 回ごとに、採点の担当の指摘で、スキルと課題を直した。採点基準は回ごとに厳しくしたので（スキルなしでも通る基準を、差の出るものに直した）、回をまたいだ数字の比べ方には注意。
- EVAL で見つかって直した、スキルの中身の主な誤り：
  - MISRA 10.4 の資料：小さい符号なしの型の式（`uint16_t` の `a - b` は int に格上げされる）では、`0` を `0U` にすると結果が変わる（`(a - b) > 0` は偽、`(a - b) > 0U` は真）。条件演算子に `0U` を使うと、式の型が unsigned int になる。
  - 準備と反映：表や件数を見せることと、書く・反映することを同じ手番で行うと、見せずに書くことがあった。見せたら手番を終えて同意を待つ決まりにした。
  - 結果と設定の画面：詳細では「保存」を押すまで保存されないことを、案内していなかった。
  - 逸脱コメント：「と思います」などの推量、「前提」「場合は」「見直すこと」などの条件や依頼を、決まりの確かめで断っていなかった。
  - 一括実行：進み具合を、段の名前（judge など）のまま伝えていた。
- 3回目で見つかって、その後に直したこと（3回目の数字は、直す前のもの）：
  - 自己診断：結果のフォルダをリポジトリの中に作ることがあった。返事に「未実施」の数がなかった。社内の Coverity への書き戻しを頼まれたとき、② の見本で確かめることを申し出ていなかった。
  - 画面の入口：ツールの一覧に画面を開くツールが見えないとき、探さずに「ない」と言っていた。
  - 同じ原因の統合：まとめる・まとめないの判断に、確信度を付けていなかった。差分を試すために、一時的なコピーを作っていた。

## Claude Code のプラグインとして動かして見つけ、直したこと

Claude Code の定義（`agents/*.md`）を、本物のプラグインとして動かしたとき（11-09）に見つけたこと。

- **スキルと参照資料が許可で断られた。** 最初の流しで、3段階目の作業役が参照資料を読めずに止まった（default 3/4、full 2/4）。Claude Code 2.1.319 では、許可（`allowed-tools`）を持つスキルは使う前に確認が出る。入れたプラグインのフォルダ（`~/.claude/plugins/cache/…`）はリポジトリの外なので、参照資料を読むたびにも確認が出る。裏で動くエージェントと `claude -p` は、どちらも断る。GitHub から入れたプラグインで同じことを確かめ、`Skill(coverity-triage-kit:*)` と、このプラグインのフォルダを読むだけの `Read(…)` を、利用者に勧める許可と一括実行の案内に足した。
- **書く許可を実行フォルダだけにした。** `Edit(//<実行フォルダ>/**)` は Write にも効き、ほかの場所（調べているリポジトリ）に書くときは確認が出ることを確かめ、素の `Write`・`Edit` の代わりにした。EVAL も同じ許可で動かし（`acceptEdits` を外した）、3段階目のすべての変種が合格した。
- **グループの欄を省いた。** 2段階目の brief-group で、作業役が、外す CID がないときに `group_excluded_cids` を省いた。指示ファイルに「すべて同じ原因なら空の配列 [] にする」と足した。
- **確かめの道具の誤り。** 2段階目の user-20001 で、「逸脱コメント案（推奨は修正なので参考です。…）：」のように見出しの補足が長く、逸脱コメント案を見つけられなかった。道具を直した。
- plugin-dev の skill-reviewer（4つのスキル）と plugin-validator の指摘は、別のエージェントが1つずつ確かめてから直した（設計書 3.5、変更履歴 0.2.0）。plugin-validator は合格（`claude plugin validate` も、プラグインとマーケットプレイスの一覧の両方で合格。アイコンがないという注意だけ）。

- 一括実行・結果と設定の画面・反映・同じ原因の統合のスキルは、課題が2つずつしかない。
- 11-09 の直しの後に流し直したのは、2〜4段階目のすべてと、変えた4つのスキル（困ったとき・一括実行・自己診断・画面の入口）の課題。ほかの10のスキルの課題は、11-08 の3回目のまま。

- Copilot CLI でしか確かめられないこと（設計書 9.4）。
