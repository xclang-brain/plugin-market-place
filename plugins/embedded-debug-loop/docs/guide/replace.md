# スキルと作業エージェントを置き換える

スキルか作業エージェントを置き換えると、統括エージェント（`orchestrator`）・検証エージェント（`verifier`）・Web管理画面を変えずに、別の方法や別の機器で使えます。
作業の方法が違うときはスキルを、機器の種類が違うときは作業エージェント（`device-worker`）を置き換えます。

## スキルを置き換える

新しいスキルは、次の約束を守ります。
「役割」は、作業エージェントの「使うスキル」の表の役割（ビルドなど）です。

| 約束 | 内容 |
| --- | --- |
| 頼まれること | 作業エージェントから、役割の作業と、設定の確認を頼まれる |
| 返すもの | 作業では、成否・起きたこと・ログの場所。設定の確認では、抜けや誤り（できれば、機器に接続できるかも試す） |
| 設定 | 設定が要るなら、`README.md` に設定ファイルの場所・作り方・項目の意味を書く。形式（YAML・INI・JSON など）も項目の名前も自由。項目のすぐ上に説明のコメントを書くと、設定のスキルがそれを読んで質問する |
| コマンド | `SKILL.md` のコマンドは、Windows の PowerShell でも動く書き方にする |
| 独立 | 要るファイルは、スキルのフォルダに置く。ほかのスキルやエージェントを前提にしない |

### 同じ名前で置き換える（元のスキルは隠れる）

1. 新しいスキルを、作業フォルダ（ふつうは、Copilot CLI を起動したフォルダ）の `.github/skills/<元のスキルの名前>/` に置きます。`SKILL.md` の `name:` も同じにします。
2. Copilot CLI を起動したまま置いたときは、`/skills reload` を実行します。
3. `/skills list` で、そのスキルが「project」の下に出ることを確認します。
4. 元のスキルの設定ファイルは、作業フォルダの `.<スキルの名前>/` にあります。新しいスキルが同じフォルダを使うなら、項目が違うので消します。
5. `/agent` で作業エージェントを選び、「<スキルの名前> を設定したい」と頼みます。質問に答えると、作業エージェントが最後に設定を確認します。

### 別の名前で足す（元のスキルも残す）

1. 新しいスキルを、作業フォルダの `.github/skills/<新しい名前>/` に置きます。`SKILL.md` の `name:` も同じにします。
2. 「同じ名前で置き換える」の 2〜3 で、読み込まれたことを確認します。
3. 作業エージェントをコピーし、「使うスキル」の表を新しい名前に書き換えます（次の節）。
4. `/agent` でコピーした作業エージェントを選び、「<新しい名前> を設定したい」と頼みます。

設定のスキルを置き換えるときは、設定するほかのスキルも同じ `.github/skills/` に置きます。
プラグインの外の設定のスキルからは、プラグインの中のスキルが見えないためです。

## 作業エージェントを置き換える

作業エージェントの定義をコピーして書き換えます。
新しい作業エージェントは、統括エージェントとの次の約束を守ります。

| 場面 | 約束 |
| --- | --- |
| ほかのエージェントから呼ばれたとき（ask_user が使えないか、頼みが「これは準備の確認です」か「あなたは作業役です」で始まる） | 利用者に質問せず、頼まれたことだけをする |
| 準備の確認 | 作業はしない。1行目に「準備：できている」か「準備：できていない」と書き、続けて設定の要約と、足りないもの（直し方つき）を書く |
| 試行 | 1回だけ作業し、合否は判断しない。進めなくなったら止める。変えたこと、手順ごとの「できた／できなかった（理由）」、ログの要点、ログの場所（絶対パス）、気づいたことを返す |

手順：

1. インストールしたプラグインの `device-worker.agent.md` を、作業フォルダの `.github/agents/<新しい名前>.agent.md` にコピーします。
   - Windows での場所：`%USERPROFILE%\.copilot\installed-plugins\plugin-market-place\embedded-debug-loop\com.github.copilot\agents\`
   - [GitHub](https://github.com/xclang-brain/plugin-market-place/tree/main/plugins/embedded-debug-loop/com.github.copilot/agents) のものを使うときは、インストールしたバージョンと同じものにします。
2. コピーしたファイルの、次の所をいつも書き換えます。
   - 「使うスキル」の表：使うスキルの名前（前に `<プラグインの名前>:` は付けない）。そのスキルも作って置きます。
   - ファイルの中の `device-worker`：新しい名前。「device-worker · plugin」は「<新しい名前> · project」にします。
   - 「変えてよいもの」の「このプラグインのファイル」：「このエージェントのファイル」。
3. 機器が違うときは、次も書き換えます。
   - 先頭の `description` と最初の段落（`---` で囲んだ先頭の情報の後の、最初の文）：何をするエージェントか。Web管理画面で選ぶときに、この説明が出ます。
   - 作業の言葉（「ビルド」「転送」など）、例、「調べ方のこつ」：その機器に合う内容。返事の形の行の名前（ビルド・転送・ログ取得など）も変えてかまいません。
4. ほかのエージェントから呼ばれたときの決まり（上の表）は変えません。言い回しは変えてかまいません。
5. `/agent` で新しいエージェントを選び、「設定を確認して」と頼みます。使うスキルごとに確認の結果が出れば、単体で動いています。
6. 3段階目で使うときは、統括エージェントへの最初の依頼に「作業エージェントは <新しい名前> で」と書きます。統括エージェントは、この作業エージェントで準備を確認し、作業フォルダの設定に残します。
   一度使った後は、Web管理画面の「設定」でも替えられます。
