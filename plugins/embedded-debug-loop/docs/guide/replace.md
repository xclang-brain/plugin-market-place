# スキルと作業エージェントを置き換える

スキルか作業エージェント（`device-worker`）を置き換えると、別の方法や、別の機器・作業で使えます。
統括エージェント（`orchestrator`）・検証エージェント（`verifier`）・Web管理画面は変えません。

## スキルを置き換える

作業の方法が違うときは、スキルを置き換えます。
新しいスキルは、次の約束を守ります。

| 約束 | 内容 |
| --- | --- |
| 頼まれること | 作業エージェントの[「使うスキル」の表](../../com.github.copilot/agents/README.markdown#使うスキル)にある役割の作業と、設定の確認 |
| 返すもの | 作業では、成否・起きたこと・ログの場所。設定の確認では、抜けや誤り（できれば、実際に使えるかも試す） |
| 設定 | 要るなら、`README.md` に設定ファイルの場所・作り方・項目の意味を書く。形式（YAML・INI・JSON など）と項目の名前は自由 |
| 設定の書き方 | 設定のスキル（「使うスキル」の表の「設定」）が読める形で書く。書き方は、そのスキルの README にある |
| コマンド | `SKILL.md` のコマンドは、Windows の PowerShell でも動くようにする（ヒアドキュメント・`source`・`$(…)` を使わない）。Python は、Windows では `py -3`（なければ `python`）、ほかは `python3` で呼ぶ |
| 独立 | 要るファイルは、スキルのフォルダに置く。ほかのスキルやエージェントを前提にしない |

設定のスキルを置き換えたら、ほかのスキルも同じ `.github/skills/` に置きます。
プラグインの中のスキルは、置き換えた設定のスキルからは見つかりません。

### 同じ名前で置き換える（元のスキルは隠れる）

1. 新しいスキルを、作業フォルダ（ふつうは、Copilot CLI を起動したフォルダ）の `.github/skills/<元のスキルの名前>/` に置きます。`SKILL.md` の `name:` も同じにします。
2. Copilot CLI を起動したまま置いたときは、`/skills reload` を実行します。
3. `/skills list` で、そのスキルが「project」の下に出ることを確認します。
4. 新しいスキルの設定ファイルが、元のスキルのものと同じパスなら、元の設定ファイルを消します（項目が違うため）。元のパスは、元のスキルの README にあります。
5. `/agent` で作業エージェントを選び、「<元のスキルの名前> を設定したい」と頼みます。質問に答えると、最後に作業エージェントが設定を確認します。

### 別の名前で足す（元のスキルも残す）

1. 新しいスキルを、作業フォルダの `.github/skills/<新しいスキルの名前>/` に置きます。`SKILL.md` の `name:` も同じにします。
2. 「同じ名前で置き換える」の 2〜3 で、読み込まれたことを確認します。
3. 次の節の手順 1〜4 で作業エージェントをコピーし、「使うスキル」の表のスキル名を、新しいスキルの名前に替えます。
   コピーの `description` には、元との違い（使うスキルなど）を書きます。
4. `/agent` でコピーした作業エージェントを選び、「<新しいスキルの名前> を設定したい」と頼みます。質問に答えた後、新しいスキルの確認の結果が出れば完了です。
5. 3段階目で使うときは、次の節の手順 6 のとおり、最初の依頼に作業エージェントの名前を書きます。

## 作業エージェントを置き換える

機器の種類や作業の対象が違うとき（例：機器を使わず、PC でテスト用にビルドして動かす）は、作業エージェントを置き換えます。
新しい作業エージェントは、統括エージェントとの次の約束を守ります。

| 場面 | 約束 |
| --- | --- |
| ほかのエージェントから呼ばれたとき（質問のツール ask_user が使えないか、依頼が「これは準備の確認です」か「あなたは作業役です」で始まる） | 利用者に質問せず、頼まれたことだけをする |
| 準備の確認 | 作業はしない。1行目に「準備：できている」か「準備：できていない」と書き、続けて設定の要約と、足りないもの（直し方つき）を書く |
| 試行 | 1回だけ作業し、合否は判断しない。進めなくなったら止める。変えたこと、手順ごとの「できた／できなかった（理由）」、ログの要点、ログの場所（絶対パス）、気づいたことを返す |

手順：

1. インストールしたプラグインの `device-worker.agent.md` を、作業フォルダの `.github/agents/<エージェントの名前>.agent.md` にコピーします。
   - Windows での場所：`%USERPROFILE%\.copilot\installed-plugins\plugin-market-place\embedded-debug-loop\com.github.copilot\agents\`
   - プラグインを更新したら、コピーし直して、手順 2〜3 をやり直します（コピーは古いまま残ります）。
2. コピーしたファイルの次の箇所は、必ず書き換えます。
   - 「使うスキル」の表に、使うスキルの名前を書きます（前に `<プラグインの名前>:` は付けません）。新しい名前のスキルは、作って `.github/skills/` に置きます。
   - ファイルの中の `device-worker` を、<エージェントの名前> に替えます。「· plugin」は「· project」に替えます。
   - 「変えてよいもの」の「このプラグインのファイル」を、「このエージェントのファイル」に替えます。
3. 機器の種類や作業の対象が違うときは、次も書き換えます。
   - 先頭の `description` と、`---` の後の「あなたは、…」から箇条書きの終わりまでを、新しいエージェントの説明にします。`description` は、Web管理画面で選ぶときに出ます。
   - 作業の言葉、例、「調べ方のこつ」を、その作業に合わせます。返事の項目の名前も変えてかまいません。
4. 上の表の約束は変えません（言い回しは変えてかまいません）。
5. `/agent` で新しいエージェントを選び、「設定を確認して」と頼みます。使うスキルごとに確認の結果が出れば、単体で使えます。
6. 3段階目で使うときは、統括エージェントへの最初の依頼に「作業エージェントは <エージェントの名前> で」と書きます。
   2回目からは、Web管理画面の「設定」でも替えられます。
