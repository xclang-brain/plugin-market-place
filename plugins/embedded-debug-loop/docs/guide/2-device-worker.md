# 作業エージェントを使う（2段階目）

作業エージェント（`device-worker`）は、組み込み機器の作業を受け持つ AI です。
チャットで頼むと、ソースを直し、スキルでビルド・転送・ログ取得をして、不具合を直します。
Web管理画面やほかのエージェントは使いません。

頼めるのは、セットアップ、不具合の調査と修正、ビルド・転送・ログ取得を1回だけ動かすこと、設定の確認です。

## 始め方

1. プロジェクトのフォルダで、Copilot CLI を起動します。
2. `/agent` で、一覧から `device-worker · plugin` を選びます（正式な名前は `embedded-debug-loop:device-worker`）。
3. チャットで頼みます。頼み方は、下の「頼めること」を見てください。

- 作業の途中で、Copilot CLI がコマンドの実行やファイルの変更の許可を求めます。答えるまで、作業は止まります。
- 許可の確認を減らしたいときは、確認の画面で、そのセッションのあいだ同じ種類の操作を許す選択肢を選びます。
- `/clear` を実行すると、エージェントの選択が既定（Default）に戻ります。続けて使うときは、もう一度 `/agent` で選びます。

## 頼めること

### セットアップ

ビルド・転送・ログ取得のスキルの設定ファイルに、値を書き込みます。

```text
セットアップしたい
```

1. 作業エージェントが、ビルド・転送・ログ取得のスキルの設定ファイルを用意します。
2. 設定のスキル（`setup`）が、空の必須の項目を1つずつ質問します。選択肢から選ぶか、値を書いて答えます。
3. 残りの項目の表が出て、今の値のままでよいかを聞かれます。直す項目があれば、「直す項目を選ぶ」を選びます。
4. 作業エージェントが、3つのスキルで設定を確認し、結果を伝えます。転送とログ取得では、機器に接続できるかも確認します。

次の3つの項目は、2 では質問されません。機器で使うときは、3 で「直す項目を選ぶ」を選んで値を書きます。

- `sdk_env`（ビルド）：SDK の環境設定ファイル
- `file_mode`（転送）：送った後にファイルに付ける権限（例：755）
- `commands`（ログ取得）：機器で実行するコマンド

一部だけを直したいときは、「転送の設定だけ直したい」のように頼みます。

### 不具合の調査と修正

```text
sensor_app を機器で動かすと、AVG=3 と出ます。正しくは AVG=25 です。原因を調べて直してください。
```

作業エージェントは、次の順に進めます。

1. 合格の条件を決めます。依頼に期待する結果（例：「正しくは AVG=25」）があれば、それを合格の条件にして伝えます。なければ質問します。
2. 設定がそろっているかと、機器に接続できるかを確認します。確認の結果（使う機器・ポート・コンパイラー）を伝えます。足りなければ、セットアップをするかを聞きます。
3. 今のソースのまま、ビルド → 転送 → ログ取得をして、症状を確認します。
4. 原因の見当をつけてソースを直し、ビルド → 転送 → ログ取得をします。この1回分を「試行」と呼びます。ログを見て、直ったかを判断します。
5. 直るまで、4 を繰り返します。上限は、依頼に書かなければ 5 回です。
6. 結論、試行ごとの表、ログの場所を報告します。

依頼には、次のことを書くとよいです。

- 合格の条件（例：「ログに AVG=25 と出る」）
- 繰り返しの上限（例：「3回まで」）
- 守ること（例：「main.c は変えないで」）

### ほかの依頼

| 頼み | 作業エージェントがすること |
| --- | --- |
| 「ビルドして、機器で動かして、ログを見せて」 | ビルド・転送・ログ取得を1回だけして、結果とログを見せる |
| 「転送の設定を確かめて」 | 転送のスキルで、設定と機器への接続を確認する |

## 質問されるとき

作業エージェントは、チャットに選択肢つきの質問を出します。
主に次のときに質問します。

- 合格の条件が分からないとき
- 設定が足りないとき
- 転送やログ取得が失敗したとき。同じ操作は繰り返しません。起きたことと、確認するとよいこと（電源、ケーブル、設定）を伝えて、どうするかを聞きます。
- デバッグ用に足した出力を、最後に残すか消すかを決めるとき

## 変えるもの・変えないもの

- 作業エージェントが変えるのは、プロジェクトのフォルダの中のソースだけです。変えてはいけないファイルは、依頼に書いてください。
- スキルの設定ファイルは、セットアップであなたが答えたときだけ変えます。
- プラグインのファイルと、スキルのファイルは変えません。

## 統括エージェントから呼ばれたとき

3段階目では、統括エージェント（`orchestrator`）が、この作業エージェントを呼んで作業を依頼します。
このときは質問をせず、依頼されたこと（準備の確認か、1回の試行）だけをします。結果は決まった形で報告します。
合否は、検証エージェント（`verifier`）が確認します。
3段階目の使い方は、[統括エージェントと Web管理画面](3-orchestrator.md) を見てください。
