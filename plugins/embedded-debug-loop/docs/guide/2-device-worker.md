# 作業エージェントを使う（2段階目）

作業エージェント（`embedded-debug-loop:device-worker`）は、組み込み機器の作業を受け持つ AI です。
ソースを直し、スキルでビルド・転送・ログ取得をして、不具合を直します。
Web管理画面やほかのエージェントは使いません。チャットだけで使えます。

## 始め方

1. プロジェクトのフォルダで、Copilot CLI を起動します。
2. `/agent` と打ち、一覧から `embedded-debug-loop:device-worker` を選びます。
3. チャットで頼みます。

作業の途中で、Copilot CLI が、コマンドの実行やファイルの変更を許可するかを聞いてきます。答えるまで、作業は止まります。

## 頼めること

### セットアップ

```text
セットアップしたい
```

1. 作業エージェントが、ビルド・転送・ログ取得のスキルの設定ファイルを用意します。
2. 設定のスキルで、項目を1つずつ質問します。選択肢から選ぶか、値を書いて答えます。
3. 最後に、3つのスキルで設定を確かめ、結果を伝えます（機器につながるかも試します）。

一部だけを直したいときは、「転送の設定だけ直したい」のように頼みます。

### 不具合の調査と修正

```text
sensor_app を機器で動かすと、AVG=3 と出ます。正しくは AVG=25 です。原因を調べて直してください。
```

作業エージェントは、次のように進めます。

1. 合格の条件を決めます。依頼に書いていなければ、質問します。
2. 設定がそろっているかを確かめます。足りなければ、セットアップをするか聞きます。
3. 今のソースのまま、ビルド → 転送 → ログ取得をして、症状を確かめます。
4. 原因の見当をつけてソースを直し、ビルド → 転送 → ログ取得をします（この1回分を「試行」と呼びます）。ログで、直ったかを判断します。
5. 直るまで、4 を繰り返します（上限は、依頼に書かなければ 5 回）。
6. 結論、試行ごとの表、ログの場所を報告します。

依頼に書くとよいこと：

- 合格の条件（例：「ログに AVG=25 と出る」）
- 繰り返しの上限（例：「3回まで」）
- 守ること（例：「main.c は変えないで」）

### ほかの依頼

- 「ビルドして、機器で動かして、ログを見せて」：1回だけ動かして、ログを見せます。
- 「転送の設定を確かめて」：転送のスキルで、設定と接続を確かめます。

## 質問のされ方

作業エージェントは、質問するとき、チャットの質問の画面（選択肢つき）を出します。
次のようなときに質問します。

- 合格の条件が分からないとき
- 設定が足りないとき
- ビルド・転送・ログ取得が、何度も同じ理由で失敗するとき（電源やケーブルを確かめてほしいとき）
- デバッグ用に足した出力を、最後に残すか消すかを決めるとき

## 変えるもの・変えないもの

- 変えるのは、プロジェクトのフォルダの中のソースだけです。変えてはいけないファイルは、依頼に書いてください。
- スキルの設定ファイルは、セットアップで、あなたが答えたときだけ変えます。
- プラグインのファイルは変えません。

## 統括エージェントから呼ばれたとき

3段階目では、統括エージェントが、この作業エージェントを作業役として呼びます。
そのときは、質問をせず、頼まれた1回の試行だけをして報告します。合否は、検証エージェントが確かめます。
