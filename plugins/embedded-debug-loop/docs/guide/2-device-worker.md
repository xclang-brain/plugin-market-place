# 作業エージェントを使う（2段階目）

作業エージェント（`device-worker`）は、組み込み機器の不具合を直す AI です。Web管理画面は使わず、チャットだけで使えます。
ソースを直し、スキルでビルド・転送・ログ取得をして、直ったかをログで確認します。

## 始め方

1. プロジェクトのフォルダで、Copilot CLI を起動します。
2. `/agent` で `device-worker · plugin` を選びます（正式な名前は `embedded-debug-loop:device-worker`）。「Selected custom agent: device-worker」と出れば選べています。
3. チャットで依頼します。

`/clear` の後は、もう一度 `/agent` で選びます。

## 依頼できること

### セットアップ

```text
セットアップしたい
```

作業エージェントの質問に答えて、ビルド・転送・ログ取得の設定を埋めます。最後に、設定と機器への接続が確認されます。
手順と、機器で動かすときに入れる項目（`sdk_env`・`file_mode`・`commands`）は、[README の「最初に設定する」](../../README.md#最初に設定する) にあります。
一部だけ直すときは、「転送の設定だけ直したい」のように依頼します。

### 不具合の調査と修正

```text
sensor_app を機器で動かすと、AVG=3 と出ます。正しくは AVG=25 です。原因を調べて直してください。
```

依頼には、合格の条件（例：「ログに AVG=25 と出る」）、試行の上限（例：「3回まで」）、守ること（例：「main.c は変えないで」）も書けます。
作業エージェントは、次の順に進めます。

1. 合格の条件を決めて伝えます。
2. 設定と機器への接続を確認し、使う機器・ポート・コンパイラーを伝えます。
3. 今のソースのまま動かして、症状を確認します。
4. 試行：ソースを直し、ビルド → 転送 → ログ取得をして、ログで直ったかを判断します。
5. 直るまで試行を繰り返します（上限は 5 回。依頼に書けば、その回数）。
6. 結論（直ったか、原因、変えたところ）、試行ごとの結果の表、ログの場所を報告します。

### ほかの依頼

- 「ビルドして、機器で動かして、ログを見せて」：1回だけ動かして、結果とログを見せます。
- 「転送の設定を確認して」：転送のスキルで、設定と機器への接続を確認します。

## 質問されるとき

次のようなときに質問が出ます。選択肢を選ぶか、文を入力して答えます。

- 合格の条件が分からない
- 設定が足りない（セットアップをするか）
- 転送やログ取得が失敗した（同じ操作は繰り返さず、電源・ケーブル・設定の確認を勧めます）
- デバッグ用に足した出力（printf など）を、終わりに残すか消すか

## 変えるもの・変えないもの

- 変えるのは、作業フォルダ（ふつうは、Copilot CLI を起動したフォルダ）の中のソースと、セットアップで答えた設定の値だけです。
- プラグインとスキルのファイルは変えません。
- 変えてはいけないファイルは、依頼に書いてください。

## 統括エージェントから呼ばれたとき

3段階目では、統括エージェント（`orchestrator`）に呼ばれ、質問をせずに準備の確認か1回の試行だけをします。
直ったかは、検証エージェント（`verifier`）が確認します（[3段階目のガイド](3-orchestrator.md)）。
