# スキルを単体で使う（1段階目）

ビルド、機器への転送、機器のログ取得、設定の4つのスキルがあります。
どれも、それだけで使えます。ほかのスキルやエージェントは要りません。

## 呼び方

Copilot CLI のチャットで、コマンドを打ちます。続けて、頼みを書き足してもかまいません。

```text
/embedded-debug-loop:cross-compile
/embedded-debug-loop:deploy 設定を確かめて
/embedded-debug-loop:log-capture
/embedded-debug-loop:setup
```

コマンドを打たなくても、頼みの内容がスキルの説明に合えば、AI がスキルを選んで使うこともあります。

## ビルド・転送・ログ取得のスキルに頼めること

3つのスキルには、同じ3つのことを頼めます。

| 頼み | すること |
| --- | --- |
| 「ビルドして」などの作業の頼み（何も書かないときも） | 作業をして、結果とログの場所を伝える |
| 「設定ファイルの場所を教えて」 | 設定ファイルの場所を伝える。まだなければ作る |
| 「設定を確かめて」 | 設定の抜けや誤りを調べる。機器につながるかも試す |

## 設定ファイル

- 置き場所：プロジェクトのフォルダの `.embedded-debug-loop/<スキルの名前>.yaml`
- 初めて使うとき、スキルが設定ファイルを作ります。中身は空の項目と説明です。
- 項目の意味は、ファイルの中で各項目の上に書いてあります。
- 直接書き換えても、設定のスキル（`/embedded-debug-loop:setup`）で埋めてもかまいません。
- パスワードは、ファイルに書く代わりに、環境変数で渡せます（`〜_env` の項目に、環境変数の名前を書きます）。
- 作業のログは、`.embedded-debug-loop/logs/` にたまります。

## ビルド：cross-compile

機器向けにビルドします。ビルドの前に、SDK の環境設定ファイルを読み込みます。

| 項目 | 意味 | 例 |
| --- | --- | --- |
| `source_dir` | ビルドするフォルダ | `.` |
| `sdk_env` | SDK の環境設定ファイル。空なら読み込まない | `/opt/poky/4.0/environment-setup-cortexa7t2hf-neon-poky-linux-gnueabi` |
| `build_command` | ビルドのコマンド | `make` |
| `clean_command` | ビルドの前の片付け。空ならしない | `make clean` |
| `outputs` | ビルドでできるファイル（必須） | `["sensor_app"]` |
| `timeout_seconds` | 待つ最長の秒数 | `600` |

ビルドが終わると、できたファイル（種類と大きさ）を伝えます。
失敗したときは、エラーの行を抜き出して伝えます。

## 機器への転送：deploy

FTP で、ファイルを機器へ送ります。送った後に、権限とサム値も整えます。

| 項目 | 意味 | 例 |
| --- | --- | --- |
| `host` | 機器の IP アドレスかホスト名（必須） | `192.168.1.50` |
| `port` | FTP のポート | `21` |
| `user` / `password` | FTP のユーザー名とパスワード | `root` |
| `password_env` | パスワードを入れた環境変数の名前（あればこちらを使う） | `BOARD_FTP_PASSWORD` |
| `passive` | パッシブモードを使うか | `true` |
| `files` | 送るファイル（必須） | `["sensor_app"]` |
| `remote_dir` | 機器の送り先のフォルダ（必須） | `/opt/sensor` |
| `file_mode` | 送った後に付ける権限。空なら変えない | `"755"` |
| `checksum` | サム値の付け方（none / crc32 / sum32） | `crc32` |
| `checksum_suffix` | サム値のファイルの名前の後ろに付ける文字 | `.sum` |
| `timeout_seconds` | 待つ最長の秒数 | `30` |

- FTP で送ると、実行の権限が外れます。`file_mode` で付け直します。
- `checksum` を決めると、ファイルごとにサム値のファイル（例：`sensor_app.sum`）を作り、一緒に送ります。
- 送った後に、機器の上の大きさが手元と同じかを確かめます。

## 機器のログ取得：log-capture

シリアルコンソールで機器にログインし、コマンドを動かして、出力を記録します。

| 項目 | 意味 | 例 |
| --- | --- | --- |
| `port` | シリアルポート（必須） | `/dev/ttyUSB0` |
| `baud` | 通信の速さ | `115200` |
| `login_user` / `login_password` | ログインのユーザー名とパスワード。ユーザー名が空ならログインしない | `root` |
| `login_password_env` | パスワードを入れた環境変数の名前 | |
| `prompt` | シェルのプロンプトの終わり（正規表現） | `[#$] $` |
| `commands` | 機器で順に動かすコマンド。空なら出力を記録するだけ | `["run-app /opt/sensor/sensor_app"]` |
| `command_timeout_seconds` | 1つのコマンドの出力を待つ最長の秒数 | `30` |
| `listen_seconds` | コマンドの後に、さらに記録する秒数 | `0` |
| `logout` | 終わったらログアウトするか | `true` |

- 記録したログは、そのまま全部をファイルに残します。チャットには、コマンドごとの出力の終わりのほうを示します。
- 1回だけ別のコマンドを動かしたいときは、頼みに書いてください（例：「`dmesg` を動かしてログを取って」）。

## 設定：setup

設定ファイルの項目を、対話しながら埋めます。

1. どの設定ファイルを埋めるかを聞きます（`.embedded-debug-loop/` の中から選べます）。
2. 項目ごとに、説明と例を示して聞きます。空の必須の項目から聞きます。
3. 答えをファイルに書き込み、最後に一覧で見せます。パスワードは表示しません。

設定のスキルは、ファイルの中の説明だけを頼りに進めます。どのスキルの設定ファイルでも使えます。

## うまくいかないとき

| 伝えられること | 確かめること |
| --- | --- |
| 設定の項目が空です | 設定ファイルの該当の項目を埋める |
| FTP でつながりません | 機器の電源、LAN のケーブル、`host` と `port` |
| ログインできません | ユーザー名とパスワード |
| シリアルポートから応答がありません | ケーブル、機器の電源、`port` と `baud` |
| シリアルポートを開けません | ほかのソフトが使っていないか、ポートの権限 |
