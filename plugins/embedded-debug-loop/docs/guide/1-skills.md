# スキルを単体で使う（1段階目）

ビルド、機器への転送、機器のログ取得、設定の4つのスキルがあります。
どれも、それだけで使えます。ほかのスキルやエージェントは要りません。

## 呼び方

Copilot CLI のチャットで、コマンドを打ちます。
コマンドの後ろに、やってほしいことを続けて書くこともできます（例：`/embedded-debug-loop:deploy 設定を確かめて`）。

```text
/embedded-debug-loop:cross-compile
/embedded-debug-loop:deploy
/embedded-debug-loop:log-capture
/embedded-debug-loop:setup
```

コマンドを打たなくても、依頼の内容がスキルの説明に合えば、AI がスキルを選んで使うこともあります。

## ビルド・転送・ログ取得のスキルにできること

3つのスキルは、どれも次の3つのことができます。

| 依頼の仕方 | すること |
| --- | --- |
| コマンドだけを打つ。または「ビルドして」などと頼む | 作業をして、結果とログの場所を伝える |
| 「設定ファイルの場所を教えて」と頼む | 設定ファイルの場所を伝える。まだなければ作る |
| 「設定を確かめて」と頼む | 設定の抜けや誤りを調べる。ビルドは SDK とコンパイラーがあるかを、転送とログ取得は機器につながるかも試す |

## 設定ファイル

- 置き場所：プロジェクトのフォルダ（Copilot CLI を起動したフォルダ）の `.embedded-debug-loop/<スキルの名前>.yaml`
- 初めて使うと、スキルは設定ファイルを作って止まり、まだ空の必須の項目を伝えます。
  - 必須の項目は空です。ほかの項目には、よく使う値（例：`port: 21`、`baud: 115200`）が入っています。
  - 項目を埋めてから、もう一度頼みます。
- 項目の意味は、ファイルの中で、各項目のすぐ上に書いてあります。
- 直接書き換えても、設定のスキル（`/embedded-debug-loop:setup`）で質問に答えて埋めてもかまいません。
- 作業のログは、`.embedded-debug-loop/logs/` にたまります。

### パスワードを環境変数で渡す

パスワードは、ファイルに書かずに、環境変数で渡せます。

1. `password_env`（転送）や `login_password_env`（ログ取得）に、環境変数の名前を書きます（例：`BOARD_FTP_PASSWORD`）。
2. Copilot CLI を起動する前に、同じ端末で値を入れます（例：`export BOARD_FTP_PASSWORD=…`）。

## ビルド：cross-compile

機器向けにビルドします。ビルドの前に、SDK の環境設定ファイルを読み込みます。

| 項目 | 意味 | 例 |
| --- | --- | --- |
| `source_dir` | ビルドするフォルダ | `.` |
| `sdk_env` | SDK の環境設定ファイル。空なら読み込まない | `/opt/poky/4.0/environment-setup-cortexa7t2hf-neon-poky-linux-gnueabi` |
| `build_command` | ビルドのコマンド | `make` |
| `clean_command` | ビルドの前に片付けるコマンド。空なら片付けない | `make clean` |
| `outputs` | ビルドでできるファイル。ビルドするフォルダからの相対パス（必須） | `["sensor_app"]` |
| `timeout_seconds` | ビルドを待つ最長の秒数。過ぎたらビルドを止める | `600` |

- ビルドが終わると、できたファイル（種類と大きさ）を伝えます。
- 失敗したときは、エラーの行を抜き出して伝えます。
- ソースが変わっていないと、make はファイルを作り直しません。そのときは「前のビルドのまま」と伝えます。毎回作り直すには、`clean_command` に `make clean` を書きます。

## 機器への転送：deploy

FTP で、ファイルを機器へ送ります。送った後に、実行の権限を付けます。
サム値（チェックサム）のファイルを作って、一緒に送ることもできます。

| 項目 | 意味 | 例 |
| --- | --- | --- |
| `host` | 機器の IP アドレスかホスト名（必須） | `192.168.1.50` |
| `port` | FTP のポート | `21` |
| `user` / `password` | FTP のユーザー名とパスワード | `root` |
| `password_env` | パスワードを入れた環境変数の名前（あれば、こちらを使う） | `BOARD_FTP_PASSWORD` |
| `passive` | パッシブモードを使うか | `true` |
| `files` | 送るファイル。プロジェクトのフォルダからの相対パス（必須） | `["sensor_app"]` |
| `remote_dir` | 機器の送り先のフォルダ（必須） | `/opt/sensor` |
| `file_mode` | 送った後に付ける権限。空なら変えない | `"755"` |
| `checksum` | サム値の種類（none / crc32 / sum32）。none なら作らない | `crc32` |
| `checksum_suffix` | サム値のファイルの名前の後ろに付ける文字 | `.sum` |
| `timeout_seconds` | 機器の応答を待つ最長の秒数 | `30` |

- FTP で送ると、実行の権限が外れます。`file_mode` で付け直します。
- `checksum` を none 以外にすると、ファイルごとにサム値のファイル（例：`sensor_app.sum`）を作り、同じフォルダへ一緒に送ります。中身は、16進数8桁（小文字）と改行です。
- 送った後に、機器に届いたファイルのサイズが、PC のファイルと同じかを確かめます（機器の FTP サーバーがサイズの問い合わせに答えるときだけ）。

## 機器のログ取得：log-capture

シリアルコンソールで機器にログインし、コマンドを動かして、出力を記録します。

| 項目 | 意味 | 例 |
| --- | --- | --- |
| `port` | シリアルポート（必須） | `/dev/ttyUSB0` |
| `baud` | ボーレート。機器の設定と同じ値にする | `115200` |
| `login_user` / `login_password` | ログインのユーザー名とパスワード。ユーザー名が空ならログインしない | `root` |
| `login_password_env` | パスワードを入れた環境変数の名前 | |
| `prompt` | シェルのプロンプトの終わり（正規表現） | `[#$] $` |
| `commands` | 機器で順に動かすコマンド | `["/opt/sensor/sensor_app"]` |
| `command_timeout_seconds` | 1つのコマンドの出力を待つ最長の秒数。過ぎたら Ctrl-C を送って止める | `30` |
| `listen_seconds` | コマンドの後に、さらに記録する秒数 | `0` |
| `logout` | 終わったらログアウトするか | `true` |

- `commands` が空なら、コマンドは動かさず、`listen_seconds` の秒数だけ出力を記録します（このときは `listen_seconds` を 1 以上にします）。
- 記録したログは、全部をファイルに残します。チャットには、コマンドごとの出力の最後の 60 行を示します。
- その回だけ別のコマンドを動かしたいときは、依頼に書きます（例：「`dmesg` を動かしてログを取って」）。
- 終わらないプログラムを見るときは、`command_timeout_seconds` を、見たい長さの秒数にします。時間が来ると止めますが、それまでの出力は記録されます。

## 設定：setup

設定ファイルの項目を、質問に答えながら埋めます。

- 設定のスキルは、設定ファイルを作りません。初めてのときは、先に各スキルに「設定ファイルの場所を教えて」と頼んでファイルを作るか、作業エージェントに「セットアップしたい」と頼みます。
- 設定のスキルは、ファイルの中の説明だけを頼りに進めます。どのスキルの設定ファイルでも使えます。

進み方：

1. どの設定ファイルを埋めるかを聞きます（`.embedded-debug-loop/` の中から選べます）。
2. 必須なのに空の項目を、1つずつ、説明と例を示して聞きます。選択肢から選ぶか、値を書いて答えます。
3. 残りの項目は表で見せ、「今の値のままにする」「1つずつ確かめる」「直す項目を選ぶ」から選んでもらいます。
4. 答えをファイルに書き込み、最後に一覧で見せます。パスワードは「＊＊＊」と伏せます。

パスワードの項目では、渡し方を選べます。おすすめは、環境変数か、自分でファイルを書き換える方法です。
チャットで入力すると、値が Copilot CLI の画面と記録に残ります。

## うまくいかないとき

| 伝えられること | 確かめること |
| --- | --- |
| 設定の項目が空です | 設定ファイルの、その項目を埋める |
| FTP でつながりません | 機器の電源、LAN のケーブル、`host` と `port` |
| ログインできません | ユーザー名とパスワード（環境変数で渡すときは、Copilot CLI を起動した端末にあるか） |
| シリアルポートから応答がありません | ケーブル、機器の電源、`port` と `baud` |
| シリアルポートを開けません | ほかのソフトが使っていないか、ポートの権限 |
