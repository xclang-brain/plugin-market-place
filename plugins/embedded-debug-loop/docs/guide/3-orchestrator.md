# 統括エージェントと Web管理画面（3段階目）

直してほしいことを頼むと、統括エージェント（`orchestrator`）が、計画 → 作業 → 評価の「試行」を、合格するか上限に達するまで繰り返します。
作業は作業エージェントが、合否の判定は検証エージェント（`verifier`）がします。設定・進み具合・結果は、ブラウザーの Web管理画面で見られます。

## 準備

使う作業エージェントを、単体で使える状態にしておきます（セットアップを済ませておきます）。

## 使い方

1. `/agent` を入力し、一覧から `orchestrator` を選びます。
2. 直してほしいことを頼みます。

   ```text
   sensor_app を動かすと AVG=3 と出ます。正しくは AVG=25 です。直してください。
   ```

   合格の条件（例では「正しくは AVG=25」）が書かれていなければ、統括エージェントが質問します。
3. 準備の確認が終わると、チャットに URL が出ます。Copilot CLI と同じ PC のブラウザーで開きます。
4. 「設定」タブで、頼む作業・合格の条件・作業エージェントの準備を確かめて、「開始」を押します。
5. チャットに質問や許可の確認が出たら、チャットで答えます。
6. 終わると、チャットと「結果」タブに結論が出ます。

作業エージェントを選ぶときは、最初の依頼に「作業エージェントは <名前> で」と書きます。書かなければ、既定の作業エージェントを使います。Web管理画面の「設定」でも替えられます。

## Web管理画面

### 設定

| 欄 | 意味 |
| --- | --- |
| 頼む作業 | チャットで頼んだ内容。ここで直せる |
| 合格の条件 | 1行に1つ。検証エージェントは、この条件で合否を決める |
| 繰り返しの上限 | 試行の最大回数。作業フォルダごとに保存される |
| 使うエージェント | 作業エージェントと検証エージェント。替えたら、「開始」の後に準備を確かめ直す |
| モデル・考える深さ | 「既定」なら、エージェントの定義のとおり |

- 「作業エージェントの準備」には、作業エージェントが返した設定の要約が出ます。「できていない」なら、書かれた直し方で直します。
- 「保存」は設定だけを保存し、「開始」は保存してから始めます。実行中は変えられません。
- 作業エージェントが使う設定は、この画面にはありません。作業エージェントで変えます。

### 実行のようす

- 構成図：動いているエージェントが強調表示されます。
- 試行ごとのカード：計画、作業の報告、評価（条件ごとの合否）が並びます。
- 通知：エージェントがチャットで質問や許可を求めると、画面の上に出ます。
- 「くわしい記録」：実行したコマンド、読んだり直したりしたファイル、使ったスキルが、新しい順に出ます。
- 「止める」：動いているエージェントがその場で止まり、実行が終わります。

### 結果

上から、結論、合格の条件と最後の評価、試行ごとのまとめ、振り返り（このプラグイン自身の改善点）が出ます。前の実行の結果は、「これまでの実行」から開けます。

| 結論 | 意味 |
| --- | --- |
| 成功 | すべての条件に合格した |
| 失敗 | 上限の回数まで試したが、合格しなかった |
| 途中で止めた | 「止める」を押した。または Copilot CLI が途中で終わった |
| 人の判断が必要 | 作業を進められず、質問に「ここで終える」と答えた |

## 注意

- AI はソースを直接書き換え、自動では元に戻しません。始める前にコミットしておくと、`git diff` で確かめて戻せます。
- 結論の最後に、この実行で変えたファイルの一覧が出ます。コマンドで変わったファイルは出ません。
- 実行中は、チャットでほかのエージェントに替えても、ファイルの編集・コマンド・スキルは使えません。使うときは、先に「止める」を押します。

## 改善点を Issue にする

振り返りに改善点があると、統括エージェントが Issue にするかを聞きます。
Issue は、配布元のリポジトリ（xclang-brain/plugin-market-place）に、利用者の GitHub のアカウントで公開されます。作った人は Issue を消せません。

1. 「する」と答えると、統括エージェントが題と本文を見せます。社外に出してはいけない情報がないかを確かめます。
2. Copilot CLI が、Issue を作るツールを使ってよいかを確かめます。よければ許可します。

`gh` がないか、ログインしていないときは、チャットに題・本文と作成ページの URL が出ます。その URL を開き、題と本文を貼り付けます。

## うまくいかないとき

| 起きること | すること |
| --- | --- |
| `/agent` の一覧に `orchestrator` がない | プラグインがインストールされているかを確かめる（[インストール](../../README.md#インストール)） |
| URL が出ない。統括エージェントが「画面を開けない」「ツールがない」と言う | Web管理画面は、Copilot CLI の試験的な機能（エクステンション）で動く。`/experimental on` を実行するか、`copilot --experimental` で起動し直す |
| 起動時のエクステンションの確認で「No」を選んだ | Copilot CLI を起動し直し、「Yes」を選ぶ |
| 「この画面のサーバーとつながりません」と出る | Copilot CLI を閉じたか、起動し直したときに出る。統括エージェントに最初の依頼をもう一度送り、新しい URL を開く |
| 「この画面の URL が正しくないか、古くなっています」と出る | チャットに出た、いちばん新しい URL を開く |
| ほかの PC のブラウザーで開けない | Copilot CLI を動かしている PC で開く |
