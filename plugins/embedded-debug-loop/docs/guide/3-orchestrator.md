# 統括エージェントと Web管理画面（3段階目）

統括エージェント（`orchestrator`）は、直してほしいことを頼まれると、「試行」を繰り返します。
合格の条件をすべて満たすか、試行の回数が上限に達すると終わります。
設定・進み具合・結果は、ブラウザーの Web管理画面で見られます。

1回の試行は、次の3つの工程です。

- 計画：統括エージェントが、何を試すかを決めます。
- 作業：作業エージェントが、計画どおりに1回作業します。
- 評価：検証エージェント（`verifier`）が、ログなどを読み、条件ごとに合否を判定します。

## 準備

- 使う作業エージェントを、単体で使える状態にしておきます。
- Web管理画面は、Copilot CLI のエクステンションで動きます。Copilot CLI 1.0.105 では、既定で読み込まれます。
  - `/extensions` を実行し、エクステンションのモードが「Disabled」なら「Load & Augment」に変えます。
  - 1.0.105 より古いバージョンでは、会話を始める前に `/settings experimental on` を実行します。Copilot CLI が再起動し、今の会話は消えます。

## 進め方

1. `/agent` で `orchestrator · plugin`（正式な名前は `embedded-debug-loop:orchestrator`）を選びます。
2. 直してほしいことを頼みます。

   ```text
   sensor_app を動かすと AVG=3 と出ます。正しくは AVG=25 です。直してください。
   ```

   作業エージェントを選ぶときは、依頼に「作業エージェントは <名前> で」と書きます。
   選んだ作業エージェントは、その会話のあいだ使います。
   書かなければ、既定の作業エージェントを使います。
3. 依頼に合格の条件（例では「正しくは AVG=25」）がなければ、統括エージェントが質問します。
4. 作業エージェントが、準備ができているかを確認します（ソースは変えません）。終わると、チャットに URL が出ます。
5. URL（`http://127.0.0.1:…`）を、Copilot CLI と同じ PC のブラウザーで開きます。
6. 「設定」タブで、頼む作業や合格の条件を確認し、必要なら直します。
7. 「作業エージェントの準備」が「できている」ことを確認します。「できていない」なら、書かれた直し方で直します。
8. 「開始」を押します。準備を直したり、作業エージェントを替えたりした後は、準備を確認し直してから始まります。進み具合は「実行のようす」タブに出ます。
9. チャットに質問や許可の確認が出たら、チャットで答えます。
10. 終わると、チャットと「結果」タブに結論が出ます。

- `/clear` を実行すると、エージェントの選択が既定（Default）に戻ります。もう一度 `/agent` で選びます。
- ほかのエージェントを選んでいても、「開始」を押すと統括エージェントに切り替わります。

## Web管理画面

### 設定

| 欄 | 意味 |
| --- | --- |
| 頼む作業 | チャットで頼んだ内容。ここで直せる |
| 合格の条件 | 1行に1つ。検証エージェントは、この条件で合否を決める |
| 繰り返しの上限 | 試行の最大回数 |
| 作業エージェント › 使うエージェント | 作業をするエージェント。2回目からは、ここでも替えられる |
| 作業エージェント › モデル・考える深さ | 「既定」なら、エージェントの定義のとおり |
| 検証エージェント › 使うエージェント | 合否を確認するエージェント |
| 検証エージェント › モデル・考える深さ | 作業エージェントの欄と同じ |

- 統括エージェントのモデルは、チャットで選んだモデル（`/model`）です。
- 「作業エージェントの準備」には、作業エージェントが返した設定の要約が出ます。
- 「保存」は設定だけを保存し、「開始」は保存してから始めます。
- 実行中は、設定を変えられません。
- モデル・考える深さ・繰り返しの上限は、作業フォルダごとに保存されます。使うエージェントは保存しません（毎回、既定から始まります）。`/cd` で移ったフォルダに設定がなければ、既定を使います。
- 保存先は `%USERPROFILE%\.copilot\plugin-data\embedded-debug-loop\settings.json` です（COPILOT_HOME があれば `%COPILOT_HOME%\plugin-data\…`、Linux では `~/.copilot/plugin-data/…`）。実行の記録は、同じフォルダの `runs/` にあります。
- 作業の設定は、この画面にはありません。使う作業エージェントで変えます。

### 実行のようす

- 構成図：動いているエージェントが強調表示されます。
- 試行ごとのカード：計画、作業の報告、評価（条件ごとの合否）が並びます。
- 通知：エージェントがチャットで質問や許可を求めると、画面の上に出ます。
- 「くわしい記録」：実行したコマンド、読んだり直したりしたファイル、使ったスキルが、新しい順に出ます。

「止める」を押すと、動いているエージェントがその場で止まり、実行が終わります。

- 結論に、止めた工程と、途中で変えたファイルの一覧が出ます。一覧には、コマンドで変わったファイルは出ません。
- 変えたファイルは、自動では元に戻りません。
- 構成図の欄では、止めた工程に「途中で止めた」と出ます。

### 結果

上から、結論、合格の条件と最後の評価、試行ごとのまとめ、振り返り（このプラグイン自身の改善点）が出ます。
前の実行の結果は、「これまでの実行」から開けます。

| 結論 | 意味 |
| --- | --- |
| 成功 | すべての条件に合格した |
| 失敗 | 上限の回数まで試したが、合格しなかった |
| 途中で止めた | 「止める」を押した |
| 人の判断が必要 | 作業を進められず、質問に「ここで終える」と答えた |

## 改善点を Issue にする

振り返りに改善点があると、統括エージェントが Issue にするかを質問します。
作成先は、配布元のリポジトリ（xclang-brain/plugin-market-place）です。

1. 振り返りに、社外に出してはいけない情報がないかを確認します。
2. 「する」と答えます。統括エージェントが `gh` コマンドで Issue を作ります。

`gh` がないか、ログインしていないときは、チャットに題・本文と作成ページの URL が出ます。その URL を開き、題と本文を貼り付けます。

## うまくいかないとき

| 起きること | すること |
| --- | --- |
| URL が出ない。統括エージェントが「画面を開けない」「ツールがない」と言う | エクステンションが読み込まれているかを確認する（[準備](#準備)） |
| 起動時のエクステンションの確認で「No」を選んだ | Copilot CLI を起動し直し、「Yes」を選ぶ |
| 「この画面のサーバーとつながりません」と出る（Copilot CLI を閉じたか、再起動したとき） | 統括エージェントに最初の依頼をもう一度送り、新しい URL を開く |
| 「この画面の URL が正しくないか、古くなっています」と出る | チャットに出た、いちばん新しい URL を開く |
| ほかの PC のブラウザーで開けない | Copilot CLI を動かしている PC で開く |
