# 統括エージェントと Web管理画面（3段階目）

統括エージェント（`embedded-debug-loop:orchestrator`）は、作業を計画→作業→評価（PDS サイクル）で進める AI です。

- 計画：統括エージェントが、この試行で何を試すかを決めます。
- 作業：作業エージェントが、計画どおりに1回作業します。
- 評価：検証エージェントが、合格の条件ごとに結果を確かめます。

ようすと結果は、ブラウザーの Web管理画面で見られます。

## 準備

1. Copilot CLI の試験的な機能を有効にします。チャットで次を打ちます（Copilot CLI が再起動します）。

   ```text
   /settings experimental on
   ```

2. 起動のとき、「Extension "plugin:embedded-debug-loop:…" wants elevated permissions」と聞かれたら、許可します。
3. 機器の設定がまだなら、先に作業エージェントでセットアップをします（[作業エージェントを使う](2-device-worker.md)）。

## 進め方

1. `/agent` で `embedded-debug-loop:orchestrator` を選びます。
2. 直してほしいことを頼みます。

   ```text
   sensor_app を機器で動かすと AVG=3 と出ます。正しくは AVG=25 です。直してください。
   ```

3. 合格の条件が頼みに書かれていなければ、統括エージェントが質問します。
4. 統括エージェントが、作業エージェントに準備の確認を頼み、Web管理画面の URL を示します。
5. URL をブラウザーで開き、設定と「作業エージェントの準備」を確かめて、「開始」を押します。
6. 統括エージェントが試行を始めます。チャットで質問されたら、チャットで答えます。
7. 終わると、チャットに結論が出ます。Web管理画面の「結果」でも見られます。

## Web管理画面

### 設定

| 項目 | 意味 |
| --- | --- |
| 頼む作業 | チャットで頼んだ内容。ここで直せます |
| 合格の条件 | 1行に1つ。検証エージェントは、この条件で合否を決めます |
| 繰り返しの上限 | 試行の最大の回数 |
| 作業エージェント | 作業をするエージェント。別の機器向けのエージェントに替えられます |
| 作業エージェントのモデル・考える深さ | 空（既定）なら、エージェントの定義のとおり |
| 検証エージェントのモデル・考える深さ | 同上 |

- 統括エージェントのモデルは、チャットで選んだモデル（`/model`）です。
- 「作業エージェントの準備」には、作業エージェントが返した設定の要約が出ます。機器の設定は、ここで見られます。
- 機器の設定を変えるときは、`/agent` で作業エージェントを選び、「セットアップしたい」と頼みます。
- 開始の後も、設定は見られます（変えられません）。

### 実行のようす

- 構成の図：統括エージェントが、作業エージェントと検証エージェントを呼ぶ形です。いま動いているエージェントが目立ちます。
- 試行ごとのカード：計画・作業の報告・評価（条件ごとの合格・不合格）が並びます。
- チャットが質問や許可を待っているときは、上に知らせが出ます。
- 「止める」で、実行を止められます。
- 「くわしい記録」を開くと、エージェントが使った道具の記録を見られます。

### 結果

- 最初に結論が出ます。
- 次に、試行ごとの表（計画・作業・評価）が出ます。
- 最後に、振り返り（このプラグインの改善点）が出ます。
- 前の実行の結果も、一覧から開けます。

## 改善の Issue

振り返りで改善点が見つかると、統括エージェントが、Issue にするかを質問します。
「する」と答えると、`gh` コマンドで起票します。`gh` がないときは、起票の文と URL を示します。

## 作業エージェントを替える

設定の「作業エージェント」で、別のエージェントを選べます。
統括エージェントと検証エージェントは、機器のことを知りません。作業エージェントには、ふつうの文で頼むだけです。
そのため、同じ頼み方に応えられる作業エージェントなら、別の機器向けのものに替えても動きます。
作り方は [スキルと作業エージェントの置き換え](replace.md) にあります。
