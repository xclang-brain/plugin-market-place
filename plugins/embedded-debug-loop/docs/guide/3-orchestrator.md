# 統括エージェントと Web管理画面（3段階目）

統括エージェント（`orchestrator`）は、直してほしいことを頼まれると、「試行」を繰り返して直します。
1回の試行では、計画・作業・評価を順に行います。
合格の条件（何が確認できれば直ったとするか）をすべて満たすか、試行の回数が上限に達すると終わります。
設定・進み具合・結果は、ブラウザーの Web管理画面で見られます。

| 工程 | 担当 | すること |
| --- | --- | --- |
| 計画 | 統括エージェント | この試行で何を試すかを決める |
| 作業 | 作業エージェント（`device-worker`） | 計画どおりに1回作業する |
| 評価 | 検証エージェント（`verifier`） | ログなどのファイルを読み、合格の条件ごとに合否を判定する |

## 準備

3段階目では、Web管理画面を動かすために、Copilot CLI のエクステンションを使います。
始める前に、次の3つを済ませます。

### エクステンションを読み込む

Copilot CLI 1.0.105 では、エクステンションは既定で読み込まれます。
読み込まれているかは、次の手順で確認します。

1. チャットで `/extensions` を実行します。
2. エクステンションのモードが「Disabled」なら、その画面で「Load & Augment」に変えます。モードが「Load & Augment」になっていれば完了です。

1.0.105 より古いバージョンでは、`/settings experimental on` でエクステンションを読み込みます。
このコマンドを実行すると、Copilot CLI が再起動し、今の会話は消えます。
会話を始める前に、チャットで `/settings experimental on` を実行します。

### 起動時の確認に答える

Copilot CLI を起動（または再起動）すると、次の確認が出ます。

| 確認 | 答え |
| --- | --- |
| フォルダを信頼するか | 信頼する |
| 「Extension "plugin:embedded-debug-loop:embedded-debug-loop" wants elevated permissions」 | 「1. Yes」を選ぶ。このフォルダで毎回聞かれたくなければ、「2. Yes, and always allow …」を選ぶ |

- 同じ確認が、続けて2回出ることがあります。2回とも同じように答えます。
- 「No」を選んだときは、Copilot CLI を起動し直して、もう一度答えます。

### ビルド・転送・ログ取得を設定する

まだ設定していなければ、先に作業エージェントでセットアップします。
方法は [作業エージェントを使う](2-device-worker.md) を見てください。

## 進め方

始める前に、機器の電源を入れ、LAN ケーブルとシリアルケーブルを接続しておきます。
統括エージェントは、合格の条件を決めた後、作業エージェントに準備を確認させます。
準備の確認では、設定がそろっているかと、機器に接続できるかを調べます。ソースは変えません。

1. チャットで `/agent` を実行し、一覧から `orchestrator · plugin` を選びます。
2. 直してほしいことを、チャットで頼みます。

   ```text
   sensor_app を機器で動かすと AVG=3 と出ます。正しくは AVG=25 です。直してください。
   ```

   別の作業エージェントを使うときは、依頼に「作業エージェントは <名前> で」と書きます。
   書かなければ、作業フォルダ（Copilot CLI を起動したフォルダ）で前に選んだ作業エージェントを使います。
   その作業フォルダで初めて使うときは、`device-worker` を使います。
3. 依頼に合格の条件（上の例では「正しくは AVG=25」）が書かれていなければ、統括エージェントが質問します。質問に答えます。
4. 統括エージェントが、作業エージェントに準備を確認させます。チャットに Web管理画面の URL が出るまで待ちます。
5. URL を、Copilot CLI を動かしている PC のブラウザーで開きます。URL は `http://127.0.0.1:…` で始まります。
6. 「設定」タブで、頼む作業・合格の条件などの設定を確認します。必要なら直します。
7. 同じタブの「作業エージェントの準備」が「できている」になっていることを確認します。「できていない」なら、[準備が「できていない」と出たとき](#準備ができていないと出たとき) に進みます。
8. 「開始」を押します。統括エージェントが試行を始めます。進み具合は「実行のようす」タブで見られます。
9. チャットに質問や許可の確認が出たら、チャットで答えます。
10. 終わると、チャットに結論が出ます。結論は、Web管理画面の「結果」タブでも見られます。

- 一覧の `orchestrator · plugin` の正式な名前は、`embedded-debug-loop:orchestrator` です。
- `/clear` を実行すると、エージェントの選択が既定（Default）に戻ります。続けて使うときは、もう一度 `/agent` で選びます。
- 「開始」を押したときに、チャットで統括エージェントを選んでいなくてもかまいません。Web管理画面が、チャットのエージェントを統括エージェントに切り替えてから、開始の知らせを送ります。

### 準備が「できていない」と出たとき

作業エージェントでセットアップしてから、もう一度頼みます。
「できていない」の間は、「設定」タブの上に警告が出ます。
セットアップせずに「開始」を押すこともできます。そのときは、統括エージェントが準備を確認し直してから始めます。

1. チャットで `/agent` を実行し、`device-worker · plugin` を選びます。別の作業エージェントを使っているときは、そのエージェントを選びます。
2. 「セットアップしたい」と頼みます。
3. セットアップが終わったら、`/agent` で `orchestrator · plugin` に戻します。
4. 最初の依頼を、もう一度送ります。
5. チャットに出た URL を開き、「作業エージェントの準備」が「できている」になったことを確認します。
6. 「開始」を押します。

## Web管理画面

Web管理画面には、「設定」「実行のようす」「結果」の3つのタブがあります。

### 設定

依頼の内容と、使うエージェントを確認します。必要なら、ここで変えます。

| 欄 | 意味 |
| --- | --- |
| 頼む作業 | チャットで頼んだ内容。ここで直せる |
| 合格の条件 | 1行に1つ書く。検証エージェントは、この条件で合否を決める |
| 繰り返しの上限 | 試行の最大回数 |
| 作業エージェント › 使うエージェント | 作業をするエージェント。別の機器向けのエージェントに替えられる |
| 作業エージェント › モデル・考える深さ | 作業エージェントが使うモデルと、考える深さ（AI が答える前にどれだけ考えるか）。「既定（エージェントの定義のまま）」なら、エージェントの定義ファイル（`*.agent.md`）に書かれたとおりに動く |
| 検証エージェント › 使うエージェント | 合否を確認するエージェント |
| 検証エージェント › モデル・考える深さ | 検証エージェントが使うモデルと、考える深さ。選び方は作業エージェントと同じ |

- 統括エージェントのモデルは、チャットで選んだモデル（`/model`）です。
- 「作業エージェントの準備」には、作業エージェントが返した設定の要約が出ます。機器の IP アドレスやシリアルポートなどを、ここで確認できます。
- ビルド・転送・ログ取得の設定を変えるときは、`/agent` で作業エージェントを選び、「セットアップしたい」と頼みます。
- 「保存」は、開始せずに設定だけを保存します。「開始」は、保存してから始めます。
- 実行中は、設定を見られますが、変えられません。終わると、また変えられます。

Web管理画面の設定は、作業フォルダごとに保存されます。

- 作業フォルダは、Copilot CLI を起動したフォルダです。`/cd` で変えると、変えた先のフォルダの設定を使います。
- まだ保存していないフォルダでは、既定の設定を使います。
- 保存される項目は、使うエージェント・モデル・考える深さ・繰り返しの上限です。
- 保存先は、作業フォルダの中ではなく、`~/.copilot/plugin-data/embedded-debug-loop/settings.json` です。実行の記録は、同じフォルダの `runs/` にあります。
- ビルド・転送・ログ取得の設定は、これとは別です。スキルごとの `config.yaml` に保存されます（例：作業フォルダの `.cross-compile/config.yaml`）。

### 実行のようす

実行中の進み具合を見られます。

- 構成図：統括エージェントが、作業エージェントと検証エージェントを呼び出す関係の図です。いま動いているエージェントが強調表示されます。
- 試行ごとのカード：計画、作業の報告、評価（条件ごとの合格・不合格）が並びます。
- 通知：エージェントがチャットで質問したり、コマンドの許可を求めたりすると、画面の上に通知が出ます。答えは、チャットで入力します。
- 「くわしい記録」：エージェントが実行したコマンド、読んだファイル、直したファイル、使ったスキルの記録です。開くと、新しいものから順に表示されます。

#### 実行を止める

実行を止めるときは、「止める」を押します。動いているエージェントがその場で止まり、この実行は終わります。

- 結論に、どこで止めたかが出ます（例：「試行 1 の作業の途中で止めました」）。
- 結論には、エージェントが途中で変えたファイルの一覧も出ます。出るのは、ファイルを編集するツール（`edit`・`create`・`apply_patch`）で変えたファイルだけです。コマンドで変わったファイルは出ません。
- 変えたファイルは、自動では元に戻りません。必要なら、自分で戻します。
- 「いまのようす」の計画・作業・評価の並びでは、止めた工程に「途中で止めた」と出ます。

### 結果

終わった実行の結論とまとめを見られます。上から次の順に出ます。

1. 結論
2. 合格の条件と、最後の評価
3. 試行ごとのまとめ：各試行の計画・作業・評価をまとめた表
4. 振り返り：このプラグイン自身の改善点（頼み方、エージェントの動き、画面など）

結論には、次のどれかが付きます。

| 表示 | 意味 |
| --- | --- |
| 成功 | すべての条件に合格した |
| 失敗 | 上限の回数まで試したが、合格しなかった |
| 途中で止めた | 「止める」を押した |
| 人の判断が必要 | 作業を進められなくなり、統括エージェントの質問に、チャットで「ここで終える」と答えた |

前の実行の結果も、「これまでの実行」の一覧から開けます。

## 改善点を Issue にする

振り返りで改善点が見つかると、統括エージェントが、Issue にするかを質問します。
Issue には、振り返りの改善の案が書かれます。作成先は、このプラグインの配布元のリポジトリ（xclang-brain/plugin-market-place）です。

- 「する」と答える前に、「結果」タブの振り返りに、社外に出してはいけない情報が入っていないかを確認してください。
- 「する」と答えると、統括エージェントが `gh` コマンドで Issue を作ります。
- `gh` がインストールされていないときや、ログインしていないときは、自分で Issue を作ります。チャットに、Issue の題と本文、Issue 作成ページの URL が出ます。その URL を開き、題と本文を貼り付けます。

## 作業エージェントを替える

設定の「作業エージェント › 使うエージェント」で、別のエージェントを選べます。
別の機器向けの作業エージェントに替えても、統括エージェントと検証エージェントはそのまま使えます。理由は次の2つです。

- 統括エージェントと検証エージェントには、機器のことが書かれていません。
- 統括エージェントは、作業エージェントにふつうの文で頼むだけです。

ただし、替える作業エージェントは、準備の確認と1回の試行の依頼に、決まった形で答える必要があります。
答える形と作り方は、[スキルと作業エージェントを置き換える](replace.md) を見てください。

## うまくいかないとき

| 起きること | すること |
| --- | --- |
| URL が出ない。統括エージェントが、Web管理画面を開けない、またはツールが見つからないと言う | [エクステンションを読み込む](#エクステンションを読み込む) の手順で、読み込まれているかを確認する。起動時の確認では「Yes」を選ぶ |
| 画面に「この画面のサーバーとつながりません」と出る（Copilot CLI を閉じたか、再起動したとき） | 統括エージェントに最初の依頼をもう一度送り、チャットに出た新しい URL を開く |
| 画面に「この画面の URL が正しくないか、古くなっています」と出る | チャットに出た、いちばん新しい URL を開く |
| ほかの PC のブラウザーで開けない | Copilot CLI を動かしている PC のブラウザーで開く（Web管理画面は、その PC からしか開けない） |
