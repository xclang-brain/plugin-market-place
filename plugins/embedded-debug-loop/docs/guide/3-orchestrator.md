# 統括エージェントと Web管理画面（3段階目）

統括エージェント（`embedded-debug-loop:orchestrator`）は、計画 → 作業 → 評価 を1回の「試行」として、合格するか、上限の回数に達するまで繰り返す AI です。

- 計画：統括エージェントが、この試行で何を試すかを決めます。
- 作業：作業エージェントが、計画どおりに1回作業します。
- 評価：検証エージェントが、合格の条件ごとに、ログなどのファイルを読んで結果を確かめます。

設定・進み具合・結果は、ブラウザーの Web管理画面で見られます。

## 準備

3段階目は、Web管理画面を動かすために、Copilot CLI のエクステンションを使います。

1. Copilot CLI 1.0.105 では、エクステンションは既定で読み込まれます。読み込まれないときは、チャットで `/extensions` と打ち、エクステンションの使い方（モード）が「Disabled」になっていないかを確かめます。「Disabled」なら、その画面で「Load & Augment」に変えます。それより古い版の Copilot CLI では、チャットで `/settings experimental on` と打ちます（Copilot CLI が再起動し、今の会話は消えます）。
2. 起動（または再起動）の後に、次の確認が出ます。
   - フォルダを信頼するかを聞かれたら、信頼します。
   - 「Extension "plugin:embedded-debug-loop:embedded-debug-loop" wants elevated permissions」と聞かれたら、「1. Yes」を選びます。このフォルダで毎回聞かれたくなければ、「2. Yes, and always allow …」を選びます。同じ確認が続けて2回出ることがあります。
   - 「No」を選んだときは、Copilot CLI を起動し直して、もう一度答えます。
3. ビルド・転送・ログ取得の設定がまだなら、先に作業エージェントでセットアップをします（[作業エージェントを使う](2-device-worker.md)）。

`/clear` を打つと、エージェントの選択が既定（Default）に戻ります。続けて使うときは、もう一度 `/agent` で選びます。

## 進め方

0. 機器の電源を入れ、LAN とシリアルのケーブルをつないでおきます（統括エージェントが、頼んだ直後に機器につながるかを確かめるためです）。
1. `/agent` と打ち、一覧から `orchestrator · plugin` を選びます（正式な名前は `embedded-debug-loop:orchestrator`）。
2. 直してほしいことを頼みます。

   ```text
   sensor_app を機器で動かすと AVG=3 と出ます。正しくは AVG=25 です。直してください。
   ```

   - 別の作業エージェントを使うときは、依頼に「作業エージェントは <名前> で」と書きます。書かなければ、前にこのフォルダで選んだもの（初めてなら device-worker）を使います。
3. 合格の条件が依頼に書かれていなければ、統括エージェントが質問します。
4. 統括エージェントが作業エージェントに、設定がそろっているかと、機器につながるかを確かめさせます（ソースは変えません）。
5. 終わると、統括エージェントが Web管理画面の URL をチャットに出します。
6. URL（`http://127.0.0.1:…` で始まります）を、Copilot CLI を動かしている PC のブラウザーで開きます。
7. 設定と「作業エージェントの準備」を確かめて、「開始」を押します。
8. 統括エージェントが試行を始めます。チャットで質問や許可の確認が出たら、チャットで答えます。
9. 終わると、チャットに結論が出ます。Web管理画面の「結果」でも見られます。

### 準備が「できていない」と出たとき

1. `/agent` で `device-worker · plugin` を選び、「セットアップしたい」と頼みます。
2. 終わったら、`/agent` で `orchestrator · plugin` に戻し、最初の依頼をもう一度送ります。
3. 「作業エージェントの準備」が「できている」になったのを確かめて、「開始」を押します。

「できていない」の間は、設定の画面の上に警告が出ます。「開始」は押せます。
「できていない」のまま「開始」を押すと、統括エージェントが準備を確かめ直してから始めます。

「開始」を押すと、チャットで選んでいるエージェントが統括エージェントでなければ、Web管理画面が統括エージェントに切り替えてから、開始の知らせを送ります。

## Web管理画面

### 設定

| 欄 | 意味 |
| --- | --- |
| 頼む作業 | チャットで頼んだ内容。ここで直せます |
| 合格の条件 | 1行に1つ。検証エージェントは、この条件で合否を決めます |
| 繰り返しの上限 | 試行の最大の回数 |
| 作業エージェント › 使うエージェント | 作業をするエージェント。別の機器向けのエージェントに替えられます |
| 作業エージェント › モデル・考える深さ | 「既定（エージェントの定義のまま）」なら、定義のとおり。考える深さは、AI が答える前にどれだけ考えるかです |
| 検証エージェント › 使うエージェント | 合否を確かめるエージェント |
| 検証エージェント › モデル・考える深さ | 作業エージェントと同じ |

- 統括エージェントのモデルは、チャットで選んだモデル（`/model`）です。
- 「作業エージェントの準備」には、作業エージェントが返した設定の要約が出ます。機器の IP アドレスやシリアルポートなどは、ここで見られます。
- ビルド・転送・ログ取得の設定を変えるときは、`/agent` で作業エージェントを選び、「セットアップしたい」と頼みます。
- 「保存」は、開始せずに設定だけを残します。「開始」を押すと、保存してから始めます。
- Web管理画面の設定（使うエージェント・モデル・考える深さ・繰り返しの上限）は、`~/.copilot/plugin-data/embedded-debug-loop/settings.json` に保存します。ビルド・転送・ログ取得の設定（`.embedded-debug-loop/`）とは別のものです。実行の記録は、同じフォルダの `runs/` にあります。
- Web管理画面の設定は、作業フォルダごとに保存します。作業フォルダは、Copilot CLI を起動したフォルダです（`/cd` で変えると、そのフォルダの設定になります）。別のフォルダでは、そのフォルダの設定か、まだ保存していなければ既定の設定を使います。
- 実行中は、設定を見られますが、変えられません。終わると、また変えられます。

### 実行のようす

- 構成の図：統括エージェントが、作業エージェントと検証エージェントを呼ぶ形です。いま動いているエージェントが目立ちます。
- 試行ごとのカード：計画・作業の報告・評価（条件ごとの合格・不合格）が並びます。
- エージェントがチャットで質問したり、コマンドの許可を求めたりしているときは、画面の上に知らせが出ます。答えは、チャットで入力します。
- 「止める」を押すと、動いているエージェントがその場で止まり、この実行は終わります。
  - 結論に、どこで止めたか（例：「試行 1 の作業の途中で止めました」）と、途中で変えたファイルの一覧が出ます。一覧に出るのは、エージェントがファイルを直すツールで変えたものだけです（コマンドで変わったファイルは出ません）。変えたファイルは、元に戻しません。
  - 止めた段には、「途中で止めた」と出ます。
- 「くわしい記録」を開くと、エージェントが動かしたコマンド、読んだり直したりしたファイル、使ったスキルを、新しい順に見られます。

### 結果

- 最初に結論が出ます。結論には、次のどれかが付きます。
  - 成功：すべての条件に合格した。
  - 失敗：上限の回数まで試したが、合格しなかった。
  - 途中で止めた：「止める」を押した。
  - 人の判断が必要：作業が進めなくなり、チャットで「ここで終える」を選んだ。
- 次に、試行ごとの表（計画・作業・評価）が出ます。
- 最後に、振り返り（このプラグインの改善点）が出ます。
- 前の実行の結果も、一覧から開けます。

## 改善の Issue

振り返りで改善点が見つかると、統括エージェントが、Issue にするかを質問します。

- 「する」と答えると、`gh` コマンドで、このプラグインの配布元のリポジトリ（xclang-brain/plugin-market-place）に Issue を作ります。社外に出してはいけない情報が入っていないかを確かめてから答えてください。
- `gh` がないときや、ログインしていないときは、Issue の題と本文と、作成のページの URL をチャットに出します。

## 作業エージェントを替える

設定の「作業エージェント › 使うエージェント」で、別のエージェントを選べます。
統括エージェントと検証エージェントには、機器のことが書かれていません。作業エージェントには、ふつうの文で頼むだけです。
そのため、準備の確認と1回の試行に、決まった形で答える作業エージェントなら、別の機器向けのものに替えても動きます。
作り方は [スキルと作業エージェントの置き換え](replace.md) にあります。

## うまくいかないとき

| 起きること | すること |
| --- | --- |
| URL が出ない。統括エージェントが、Web管理画面を開けない、またはツールが見つからないと言う | `/extensions` でエクステンションが動いているかを確かめる（古い版では `/settings experimental on`）。起動の後の確認で「Yes」を選ぶ |
| 画面に「サーバーとつながりません」と出る | Copilot CLI を閉じたか、再起動しました。統括エージェントにもう一度頼み、新しい URL を開く |
| 画面に「URL が正しくない」と出る | チャットに出た、いちばん新しい URL を開く |
| ほかの PC のブラウザーで開けない | Web管理画面は、Copilot CLI を動かしている PC からしか開けません |
