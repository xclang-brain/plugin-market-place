# embedded-debug-loop 仕様書

この文書は、利用者から見た振る舞いを決める。しくみは [設計書](../design/design.md)、上位の決まりは [憲章](../constitution.md) にある。

- バージョン：0.3.0

## 1. 目的

AI が、組み込み機器の C/C++ の不具合を調べて直す。
ソースの修正 → ビルド → 転送 → ログ取得 を繰り返す。

## 2. 3つの段階

| 段階 | 部品 | 呼び方 |
| --- | --- | --- |
| 1 | スキル：cross-compile、deploy、log-capture、setup | `/embedded-debug-loop:<スキル>` か、AI が選ぶ |
| 2 | 作業エージェント（`device-worker`） | `/agent` で選ぶ |
| 3 | 統括エージェント（`orchestrator`）、検証エージェント（`verifier`）、Web管理画面 | `/agent` で統括エージェントを選ぶ |

- REQ-001：どの段階も、上の段階なしで使える。エクステンションが要るのは3段階目だけ（1・2段階目は `extensions.mode` が `disabled` でも動く）。
- REQ-002：機器ごとに違うもの（ビルド・転送・ログ取得の方法と設定）は、1・2段階目にだけ置く。
- REQ-003：作業エージェントの定義には、スキルの名前と役割だけを書く。「使うスキル」の表の名前を変えれば、別のスキルを使える。
- REQ-004：4つのスキルは、互いを前提にしない。1つを置き換えても、ほかは変わらない。
- REQ-005：3段階目の作業エージェントは、依頼に名前を書いて選ぶ（例：「作業エージェントは <名前> で」）。
  - 統括エージェントは、最初の準備の確認から、その作業エージェントを使う。
  - 選んだ名前は、作業フォルダ（ふつうは、Copilot CLI を起動したフォルダ）ごとに保存される。名前を書かなければ、保存した名前（なければ既定の `device-worker`）を使う。
  - Web管理画面の「設定」でも替えられる。替えたら、「開始」の後に準備を確認し直す。
  - 統括エージェントは、作業エージェントにふつうの文だけで依頼する。
- REQ-006：利用者の PC は Windows。すべての部品が Windows で動く。Linux でも動く。
- REQ-007：各部品の使い方は、その部品の README にだけ書く。
  - スキルは `skills/<名前>/README.md`、作業エージェントは `com.github.copilot/agents/README.markdown`、3段階目は `docs/guide/3-orchestrator.md`。
  - 上の段の文書（プラグインの README、作業エージェントの README の統括・検証エージェントの部分、3段階目のガイド、置き換えのガイド）には、下の段の中身（スキルの名前、転送やログ取得の方法、設定の項目と手順）を、例としても書かない。
  - 下の段の部品を置き換えても、上の段の文書は直さずに済む。

## 3. 1段階目：スキル

### 3.1 共通

- REQ-101：ビルド・転送・ログ取得のスキルは、次の依頼に応える。
  - 作業：作業をして、成否、起きたこと、ログの場所を伝える。
  - 設定の確認：抜けと誤りを伝える。転送とログ取得は機器への接続も、ビルドはコマンドとコンパイラーの有無も確認する。作業フォルダにファイルを作らない（設定ファイルがなければ、ないと伝える）。
  - 設定ファイルの用意：なければ、説明つきのひな形から作り、場所を伝える。
- REQ-102：この3つのスキルは、設定（YAML）を作業フォルダの `.<スキルのフォルダ名>/config.yaml` に置く。
- REQ-103：設定ファイルの各項目のすぐ上に、意味を日本語のコメントで書く。必須なら「（必須）」と書く。
- REQ-104：パスワードは、設定ファイルか環境変数で渡す。結果にもログにも出さない。ただし、設定ファイルの行が読めないときは、その行をエラーメッセージに出すことがある。
  - setup は、チャットで入れた値が画面と記録に残ると伝え、環境変数か、ファイルに直接書く方法を勧める。
- REQ-105：失敗したら、起きたことと確認すべきことを、平易な文で伝える。
- REQ-106：ビルド・転送・ログ取得は、作業のログを `.<スキルのフォルダ名>/logs/` に残す。
- REQ-107：機器に接続できないときは、やり直さずに終える。
- REQ-108：どのスキルも、そのフォルダだけで完結する。
  - プラグインなしで、フォルダだけを作業フォルダの `.github/skills/<名前>/` か `~/.copilot/skills/<名前>/` にコピーしても使える。呼び方は `/<名前>`。
  - 名前は SKILL.md の `name:` で決まる。変えるときは、フォルダ名も同じにする（設定とログのフォルダ名になる）。
  - 中の説明だけで分かり、そのとおりに動く。
  - テスト（`tests/`）と `README.md` を持つ。README には、何をするか、必要なもの、置き方、呼び方、設定ファイル（あれば）、結果とログの見方、うまくいかないとき、テストの動かし方を書く。
  - 設定ファイルを持つスキルは、README に、その場所・作り方・項目の意味を書く。setup は、これを読んで設定を案内する。
- REQ-109：どのスキルも Windows で動く。
  - スクリプトは Python 3.8 以上で動き、利用者は追加のものをインストールしない（log-capture は pyserial 3.5 を同梱する）。
  - SKILL.md のコマンドは、PowerShell（Windows）でも bash でも動く書き方にする。Python は、Windows では `py -3`（なければ `python`）、ほかでは `python3` で呼ぶ。
  - スクリプトの結果は、PowerShell で読んでも文字化けしない（くわしくは[設計書](../design/design.md)の 3.8）。設定ファイルとログは UTF-8 で書く。

### 3.2 cross-compile（ビルド）

- REQ-111：SDK の環境設定ファイルを読み込み、設定ファイルのコマンド（例：make）でビルドする。
  - 読み込みとビルドに使うシェルは、設定で選べる（`auto`・`cmd`・`powershell`・`bash`）。`auto` は、Windows では `cmd`、ほかでは `bash`。
  - 時間切れで止めるときは、ビルドの子のプロセスまで止める。
- REQ-112：ビルドの後、指定したファイルの有無を確認し、種類とサイズを伝える。更新されていなければ、前のビルドのままだと伝える（失敗にしない）。
- REQ-113：失敗したら、エラーの行を抜き出して伝える。

### 3.3 deploy（転送）

- REQ-121：設定ファイルで指定したファイルを、FTP で機器の指定のフォルダに送る。フォルダがなければ作る。
- REQ-122：送ったファイルに、指定の権限（例：755）を付ける。
- REQ-123：サム値（チェックサム）の種類に crc32 か sum32 を指定すると、ファイルごとのサム値のファイルも送る。
- REQ-124：送った後、機器でのサイズが PC と同じかを確認する。FTP サーバーがサイズを返さなければ、確認できなかったと伝える。

### 3.4 log-capture（ログ取得）

- REQ-131：シリアルポート（Windows では `COM3` など、Linux では `/dev/ttyUSB0` など）で機器のコンソールに接続し、必要ならログインする。
  - ポートが見つからないときは、PC にあるポートを候補として伝える。
- REQ-132：設定ファイルのコマンドを順に実行し、プロンプトが戻るまでの出力を記録する。依頼で指定すれば、その回だけ別のコマンドを実行する。
- REQ-133：コマンドを実行せず、指定の秒数（設定ファイルか依頼）だけ出力を記録することもできる。
- REQ-134：応答がないときは、ケーブルと電源を確認するよう伝える。

### 3.5 setup（設定）

- REQ-141：利用者が使うスキルの設定を、そのスキルの README と設定ファイルを読んで、利用者に質問しながら埋める。どのスキルでも設定できる（今のスキルの名前・項目・置き場所を前提にしない）。
  - 設定するスキルは、頼みにある名前で決める。なければ、スキルを探して候補を示し、ask_user で選んでもらう。
  - スキルを探す場所と順は、作業フォルダとその上のフォルダ（project）、`<COPILOT_HOME（なければ ~/.copilot）>/skills/` など（personal）、setup の隣のフォルダ（sibling）。同じ名前なら、先に見つかったものを使う（Copilot CLI と同じ）。くわしい場所は[設計書](../design/design.md)の 3.3。
  - 利用者にも呼び出し元にも、設定ファイルのパスを指定させない。
  - 自分の設定ファイルもログも持たない。
- REQ-142：スキルごとに README.md（なければ SKILL.md）を読み、設定ファイルの有無・場所・作り方・項目の意味を知る。書いていないことは推測しない。
- REQ-143：項目は、利用者に聞いて埋める。設定ファイルがなければ、先に README に書かれた方法で作る。
  - 聞く順は、形式によらず同じ。利用者が項目を名指ししたら、その項目だけを聞いて終える。そうでなければ、まず必須で空の項目、次にコメントに「必ず」とある空の項目を、1つずつ聞く。ほかの項目は、今の値のままでよいかをまとめて聞く。
  - 項目のすぐ上に説明のコメントがある YAML なら、項目ごとに説明と例を示す。
  - そうでない形式なら、README の説明をもとに、聞いた値をファイルに書く。
  - どちらも、コメントの行と項目の順を変えずに書き込む。質問には ask_user を使う。
- REQ-144：最後に、スキルごとに埋めた結果を表で見せる（パスワードはマスクする）。

## 4. 2段階目：作業エージェント

- REQ-201：チャットの依頼だけで動く。Web管理画面とほかのエージェントは使わない。
- REQ-202：セットアップでは、次の順に進める。
  1. 設定のスキルに、使うスキルの名前（「使うスキル」の表の名前）を渡して、設定を頼む。設定ファイルの場所は渡さない。
  2. ビルド・転送・ログ取得のスキルで、設定を確認する。
- REQ-203：不具合の調査と修正では、次の順に進める。
  1. 合格の条件を決める。依頼になければ質問する。
  2. 今の症状を確認する。
  3. 修正 → ビルド → 転送 → ログ取得 → 合否の判断 を繰り返す（1回を試行と呼ぶ）。
  4. 直るか、上限（既定 5 回）に達したら終える。
- REQ-204：質問には ask_user を使う。
- REQ-205：機器に接続できないときは、繰り返さず、起きたことを伝えてどうするかを聞く。
- REQ-206：終わったら、結論、試行ごとの表、ログの場所を報告する。
- REQ-207：ほかのエージェントからの依頼では、質問も合否の判断もしない。準備の確認か1回の試行だけをし、[設計書](../design/design.md)の 3.5 の形で報告する。
- REQ-208：直すのは作業フォルダのソースだけ。スキルの設定ファイルは、セットアップで利用者が答えた値を書くときだけ変える。

## 5. 3段階目：統括エージェントと Web管理画面

### 5.1 流れ

- REQ-301：依頼に合格の条件がなければ、統括エージェントが ask_user で聞く。
- REQ-302：統括エージェントは、Web管理画面を起動し、作業エージェントに準備の確認を依頼してから、URL を伝える。
- REQ-303：Web管理画面の「開始」を押すと、統括エージェントが試行を始める。ほかのエージェントが選ばれていれば、エクステンションが先に統括エージェントに切り替える。
- REQ-304：試行ごとに、計画の記録 → 作業エージェントへの依頼 → 検証エージェントの判定 → 評価の記録 の順に進める。
- REQ-305：合格の条件をすべて満たすか、上限に達したら終える。作業エージェントが進めなくなったら、ask_user で聞く。
- REQ-306：統括エージェントは、ファイルを直さず、コマンドも実行しない。「開始」の後にファイルの編集・コマンド・スキルのツールを呼ぶと、エクステンションが拒否する（[設計書](../design/design.md)の 3.6）。
- REQ-307：検証エージェントは、作業の報告にあるファイルを読み、合格の条件ごとに判定する。ファイルは直さない。
- REQ-308：終えるときは、結論と振り返りを記録する。改善点を Issue にするかを ask_user で聞き、「する」なら作る。
- REQ-309：作業の報告を受けた試行では、作業を依頼し直さない（エクステンションも拒否する）。続けるときは、次の試行の計画から始める。

### 5.2 Web管理画面

- REQ-311：Copilot CLI を動かす PC（127.0.0.1）からだけ開ける。URL には、起動ごとに作るトークンが入る。
- REQ-312：「設定」画面には、次の項目を置く。
  - 頼む作業、合格の条件、繰り返しの上限
  - 作業エージェントと検証エージェントそれぞれの、使うエージェント、モデル、考える深さ
- REQ-313：「設定」画面に、準備の確認の結果をそのまま見せる。機器の設定は、ここで見る。
- REQ-314：「開始」の後も、設定を見られる（変えられない）。
- REQ-315：「実行のようす」画面には、次のものを置く。
  - エージェントの構成図（動いているものを目立たせる）
  - 試行ごとの計画・作業の報告・評価
  - 質問や許可を待つときの知らせ
  - 「止める」ボタン
  - 使ったツールなどの一覧（「くわしい記録」を開いたときだけ）
- REQ-316：「結果」画面には、結論・合格の条件と最後の評価・試行ごとの表・振り返りを、この順に見せる。前の実行の結果も開ける。
- REQ-317：「止める」を押すと、エクステンションが統括エージェントの応答を止める。その後は、結論と振り返りを記録するツールだけを通す。
- REQ-318：幅 390 px でも横にはみ出さない。ライトモードとダークモードの両方で読める。

### 5.3 記録

- REQ-321：エクステンションは、実行ごとに、設定・試行の経過・エージェントの動きを `<COPILOT_HOME または ~/.copilot>/plugin-data/embedded-debug-loop/` に残す。
