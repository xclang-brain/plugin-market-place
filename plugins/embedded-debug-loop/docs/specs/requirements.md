# embedded-debug-loop 仕様書

- 版：0.2.0
- この文書は、利用者から見た embedded-debug-loop の振る舞いを決める。中のしくみは [設計書](../design/design.md) に書く。
- 決まりの大もとは [憲章](../constitution.md) にある。

## 1. 目的

組み込み機器の C/C++ の不具合を、AI が調べて直す。
AI は、ソースの修正 → ビルド → 機器への転送 → 機器のログ取得 を繰り返す。

## 2. 3つの段階

| 段階 | 部品 | 利用者の使い方 |
| --- | --- | --- |
| 1 | スキル：cross-compile、deploy、log-capture、setup | コマンド `/embedded-debug-loop:<スキル>`、または AI が選んで使う |
| 2 | 作業エージェント：device-worker | `/agent` で選び、チャットで頼む |
| 3 | 統括エージェント：orchestrator、検証エージェント：verifier、Web管理画面 | `/agent` で統括エージェントを選び、チャットで頼む |

- REQ-001：どの段階も、それより上の段階なしで使える。3段階目だけは、Copilot CLI のエクステンションが読み込まれている必要がある。1段階目と2段階目は、エクステンションを読み込まない設定（`extensions.mode` が disabled）でも使える。
- REQ-002：機器に固有のこと（ビルド・転送・ログ取得のやり方と、その設定）は、2段階目と1段階目だけが持つ。3段階目は持たない。
- REQ-003：作業エージェントの定義には、使うスキルの名前と役割だけを書く。定義の「使うスキル」の表で、スキルの名前を書き替えるだけで、別のスキルを使える。
- REQ-004：4つのスキルは、互いを知らず、頼り合わない。どれか1つを替えても、ほかのスキルは変わらない。
- REQ-005：3段階目では、使う作業エージェントを、Web管理画面の設定の画面で選ぶ。統括エージェントは、作業エージェントと、ふつうの文の依頼だけでやり取りする。

## 3. 1段階目：スキル

### 3.1 共通

- REQ-101：ビルド・転送・ログ取得のスキルは、次の3つの頼みに応える。
  - 作業：作業をして、できたかどうか、何が起きたか、ログの場所を伝える。
  - 設定ファイルの場所：場所を伝える。なければ、説明つきのひな形から作る。
  - 設定の確認：設定の抜けと誤りを伝える。転送とログ取得のスキルは、機器につながるかも試す。ビルドのスキルは、ビルドのコマンドとコンパイラーがあるかを試す。
- REQ-102：設定は、スキルごとに1つの YAML ファイルに持つ。置き場所は、作業フォルダの `.embedded-debug-loop/<スキルの名前>.yaml`。作業フォルダは、スクリプトを動かしたときの今のフォルダ（ふつうは、Copilot CLI を起動したプロジェクトのフォルダ）。
- REQ-103：設定ファイルの各項目のすぐ上に、項目の意味を日本語で書く。欠かせない項目には「（必須）」と書く。
- REQ-104：パスワードは、設定ファイルに書くか、環境変数で渡す。スキルは、パスワードを結果や記録に出さない。設定のスキルは、チャットで入力すると値が画面と記録に残ることを伝え、環境変数か、利用者が自分でファイルに書く方法を勧める。
- REQ-105：失敗したときは、何が起きたかと、何を確かめればよいかを、利用者に分かる文で伝える。
- REQ-106：作業のログを、`.embedded-debug-loop/logs/` にファイルで残す。
- REQ-107：つながらないときに、同じことを何度も繰り返さない。

### 3.2 cross-compile（ビルド）

- REQ-111：SDK の環境設定ファイルを読み込んでから、設定ファイルに書いたコマンド（例：make）でビルドする。
- REQ-112：ビルドの後に、設定ファイルに書いたファイルができたかを確かめ、ファイルの種類と大きさを伝える。ビルドの前から変わっていなければ、前のビルドのままだと伝える（失敗にはしない）。
- REQ-113：失敗したときは、エラーの行を抜き出して伝える。

### 3.3 deploy（機器への転送）

- REQ-121：FTP で、設定ファイルに書いたファイルを、機器の設定ファイルに書いたフォルダへ送る。フォルダがなければ作る。
- REQ-122：送った後に、設定ファイルに書いた権限（例：755）を付ける。
- REQ-123：設定ファイルでサム値の種類（crc32 か sum32）を選ぶと、ファイルごとにサム値のファイルを作り、一緒に送る。
- REQ-124：送った後に、機器に届いたファイルのサイズが、PC のファイルと同じかを確かめる。FTP サーバーがサイズの問い合わせに応じないときは、確かめずに、そのことを伝える。

### 3.4 log-capture（機器のログ取得）

- REQ-131：シリアルポートで機器のコンソールにつなぎ、必要ならログインする。
- REQ-132：設定ファイルに書いたコマンドを順に動かし、プロンプトが戻るまでの出力を記録する。その回だけ、設定と違うコマンドを動かすこともできる。
- REQ-133：コマンドを動かさずに、設定ファイルに書いた秒数のあいだ、出力を記録するだけのこともできる。
- REQ-134：応答がないときは、ケーブルと電源を確かめるよう伝える。

### 3.5 setup（設定）

- REQ-141：設定ファイル（YAML）の項目を、利用者に聞きながら埋める。どのファイルを埋めるかは、渡されたファイルで決まる。渡されなければ、`.embedded-debug-loop/` の中から利用者が選ぶ。設定ファイルは作らない。
- REQ-142：質問は、選択肢つきの質問の画面（ask_user）で聞く。項目の説明と例を示す。空の必須の項目から聞く。
- REQ-143：ファイルの中の説明だけを頼りに進める。ほかのスキルのことは知らない。
- REQ-144：書き込むときは、説明の行と項目の順を崩さない。最後に、埋めた結果を一覧で見せる（パスワードは伏せる）。

## 4. 2段階目：作業エージェント

- REQ-201：`/agent` で選ぶと、チャットの頼みだけで動く。Web管理画面とほかのエージェントは使わない。
- REQ-202：「セットアップしたい」と頼まれたら、次のとおり進める。
  1. ビルド・転送・ログ取得のスキルに、設定ファイルを用意してもらう。
  2. 設定のスキルを使い、利用者に聞きながら設定ファイルを埋める。
  3. 3つのスキルに、設定を確かめてもらう。
- REQ-203：不具合の調査と修正を頼まれたら、次のとおり進める。
  1. 合格の条件を決める。依頼になければ質問する。
  2. 今の症状を確かめる。
  3. 直す → ビルド → 転送 → ログ取得 → 判断 を繰り返す。
  4. 直るか、上限（既定 5 回）に達したら終える。
- REQ-204：質問は、必ず ask_user で聞く。
- REQ-205：転送やログ取得がつながらないときは、繰り返さずに、起きたことを伝えて、どうするかを聞く。
- REQ-206：終わったら、結論、試行ごとの表、ログの場所を報告する。
- REQ-207：ほかのエージェントから作業役として頼まれたときは、質問せず、頼まれたこと（準備の確認、または1回の試行）だけをして、決まった形で報告する。合否は判断しない。
- REQ-208：直すのは、プロジェクトのソースだけ。スキルの設定ファイルは、利用者がセットアップで決めたときだけ変える。

## 5. 3段階目：統括エージェントと Web管理画面

### 5.1 流れ

- REQ-301：`/agent` で統括エージェントを選び、チャットで頼む。合格の条件が頼みになければ、ask_user で聞く。
- REQ-302：統括エージェントは、Web管理画面を開き、作業エージェントに準備の確認を頼み、URL を利用者に伝える。
- REQ-303：利用者が Web管理画面で「開始」を押すと、統括エージェントが試行を始める。
- REQ-304：試行ごとに、統括エージェントが計画を記録し、作業エージェントに1回の作業を頼み、検証エージェントに合否を確かめさせ、評価を記録する。
- REQ-305：すべて合格するか、上限に達すると終える。作業エージェントが進めなくなったときは、ask_user で利用者に聞く。
- REQ-306：統括エージェントは、ファイルを直したり、コマンドを動かしたりしない。定義の `tools` で、使えるツールを、エージェントを呼ぶ・読む・探す・質問・記録だけにする。「開始」の後は、エクステンションも、統括エージェントのファイルを直すツール・コマンドのツール・スキルのツールの使用を断る。
- REQ-309：試行の作業が報告された後に続けるときは、試行の番号を進め、計画から始める。同じ試行で作業を頼み直さない（エクステンションも断る）。
- REQ-307：検証エージェントは、合格の条件ごとに、報告に書かれたファイルを読んで判定する。成果物は直さない。
- REQ-308：終えるとき、結論と振り返りを記録する。改善点があれば、Issue にするかを ask_user で聞き、「する」なら起票する。

### 5.2 Web管理画面

- REQ-311：自分の PC（127.0.0.1）からだけ開ける。URL に、その場かぎりの合言葉が入る。
- REQ-312：設定の画面に置く項目：頼む作業、合格の条件、繰り返しの上限。作業エージェントと検証エージェントのそれぞれについて、使うエージェント、モデル、考える深さ（AI が答える前にどれだけ考えるか）。機器に固有の項目は置かない。
- REQ-313：設定の画面に、作業エージェントが返した「準備の確認」の内容を、そのまま見せる。機器の設定は、ここで見られる。
- REQ-314：開始の後も、設定を見られる（変えられない）。
- REQ-315：実行のようすの画面：エージェントの構成の図（いま動いているものが目立つ）、試行ごとの計画・作業の報告・評価、質問や許可を待っているときの知らせ、止めるボタン。ツールの使用の記録は、「くわしい記録」を開いたときだけ見せる。
- REQ-316：結果の画面：最初に結論、次に試行ごとの表、最後に振り返り。前の実行の結果も開ける。
- REQ-317：「止める」を押すと、統括エージェントのいまの応答を止め、その後のツールの使用を断る（終わりの記録のツールだけは通す）。
- REQ-318：幅 390 px の画面でも、横にはみ出さずに見られる。明るい表示と暗い表示の両方で読める。

### 5.3 記録

- REQ-321：実行ごとに、設定、試行の記録、エージェントの動きの記録を、Copilot CLI のプラグインのデータのフォルダに残す。振り返りに使う。
