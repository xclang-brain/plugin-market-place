# embedded-debug-loop 仕様書

この文書は、利用者から見た振る舞いを決める。しくみは [設計書](../design/design.md)、上位の決まりは [憲章](../constitution.md) にある。

- バージョン：0.4.0

## 1. 目的

AI が、組み込み機器の C/C++ の不具合を調べて直す。
ソースの修正 → ビルド → 転送 → ログ取得 を繰り返す。

## 2. 3つの段階

| 段階 | 部品 | 呼び方 |
| --- | --- | --- |
| 1 | スキル（`skills/` の下のフォルダ） | `/embedded-debug-loop:<スキル>` か、AI が選ぶ |
| 2 | 作業エージェント（`com.github.copilot/agents/` の、統括・検証のほかのエージェント） | `/agent` で選ぶ |
| 3 | 統括エージェント（`orchestrator`）、検証エージェント（`verifier`）、Web管理画面 | `/agent` で統括エージェントを選ぶ |

- REQ-001：どの段階も、上の段階なしで使える。エクステンションが要るのは3段階目だけ（1・2段階目は `extensions.mode` が `disabled` でも動く）。
- REQ-002：機器ごとに違うもの（作業の方法と設定）は、1・2段階目にだけ置く。
- REQ-003：作業エージェントの定義は、使うスキルの名前を「使うスキル」の一覧にだけ書く。スキルが何をするか、いつ使うかは書かない（各スキルの description に任せる）。
  - スキルを足す・消す・置き換えるときに、作業エージェントで直すのは、この一覧だけで済む。
  - 作業エージェントの使い方の文書は、スキルの名前を書かず、定義の一覧を案内する。その作業エージェントのことだけを書く（作業エージェントを置き換えるときは、定義と使い方の文書を丸ごと替える）。
- REQ-004：スキルは、互いを前提にしない。スキルを足す・消す・置き換えても、ほかのスキルは変わらない。
- REQ-005：3段階目の作業エージェントは、依頼に名前を書いて選ぶ（例：「作業エージェントは <名前> で」）。
  - 統括エージェントは、最初の準備の確認から、その作業エージェントを使う。
  - 選んだ名前は、その会話のあいだ使う。保存はしない（部品を替えたとき、前の名前が残らないように）。名前を書かなければ、既定（`defaults.json` の `worker`）を使う。
  - 使えるエージェントにない名前や、2つ以上に当たる名前なら、使えるエージェントを示して選び直してもらう。
  - Web管理画面の「設定」でも替えられる。替えたら、「開始」の後に準備を確認し直す。
  - 統括エージェントは、作業エージェントにふつうの文だけで依頼する。
- REQ-006：利用者の PC は Windows。すべての部品が Windows で動く。Linux でも動く。
- REQ-007：各部品の使い方は、その部品の使い方の文書にだけ書く。
  - スキルは `skills/<名前>/README.md`、作業エージェントは `docs/guide/2-<作業エージェントの名前>.md`、3段階目は `docs/guide/3-orchestrator.md`。
  - 部品（スキルと作業エージェント）を足す・消す・置き換える手順（プラグインの設計変更）は、開発者向けの `docs/replace.md` にだけ書く。利用者は、新しいバージョンを入れ直すだけなので、利用者向けの文書には書かない。手順書には、直す所が分かるように、今の部品の名前を例として書く。
  - 上の段の文書（プラグインの README、3段階目のガイド）には、下の段の中身（スキルの名前、転送やログ取得の方法、設定の項目と手順）を、例としても書かない。
  - 下の段の部品を置き換えても、上の段の文書は直さずに済む。

## 3. 1段階目：スキル

### 3.1 共通

- REQ-101：設定を持つスキルは、次の依頼に応える。
  - 作業：作業をして、成否、起きたこと、ログの場所を伝える。
  - 設定の確認：抜けと誤りを伝える。できれば、実際に使えるか（機器への接続、コマンドの有無など）も確認する。作業フォルダにファイルを作らない（設定ファイルがなければ、ないと伝える）。
  - 設定ファイルの用意：なければ、説明つきのひな形から作り、場所を伝える。
- REQ-102：設定を持つ作業のスキルは、設定ファイルを作業フォルダの `.<スキルのフォルダ名>/` に置く。形式と項目の名前は、スキルが決める。
- REQ-103：設定ファイルの各項目のすぐ上に、意味を日本語のコメントで書く。必須なら「（必須）」と書く。
- REQ-104：パスワードは、設定ファイルか環境変数で渡す。結果にもログにも出さない。ただし、設定ファイルの行が読めないときは、その行をエラーメッセージに出すことがある。
  - 設定のスキルは、チャットで入れた値が画面と記録に残ると伝え、環境変数か、ファイルに直接書く方法を勧める。
- REQ-105：失敗したら、起きたことと確認すべきことを、平易な文で伝える。
- REQ-106：作業のスキルは、作業のログを `.<スキルのフォルダ名>/logs/` に残す。
- REQ-107：機器に接続できないときは、やり直さずに終える。
- REQ-108：どのスキルも、そのフォルダだけで完結する。
  - プラグインなしで、フォルダだけを作業フォルダの `.github/skills/<名前>/` か `~/.copilot/skills/<名前>/` にコピーしても使える。呼び方は `/<名前>`。
  - 名前は SKILL.md の `name:` で決まる。変えるときは、フォルダ名も同じにする（設定とログのフォルダ名になる）。
  - 中の説明だけで分かり、そのとおりに動く。
  - テスト（`tests/`）と `README.md` を持つ。README には、何をするか、必要なもの、置き方、呼び方、設定ファイル（あれば）、結果とログの見方、うまくいかないとき、テストの動かし方を書く。
  - 設定ファイルを持つスキルは、README に、その場所・作り方・項目の意味を書く。設定のスキルは、これを読んで設定を案内する。
- REQ-109：どのスキルも Windows で動く。
  - スクリプトは Python 3.8 以上で動き、利用者は追加のものをインストールしない（要るものは、スキルのフォルダの `scripts/vendor/` に同梱する）。
  - テストに要るパッケージは、スキルのフォルダの `tests/requirements.txt` に書く。
  - SKILL.md のコマンドは、PowerShell（Windows）でも bash でも動く書き方にする。Python は、Windows では `py -3`（なければ `python`）、ほかでは `python3` で呼ぶ。
  - スクリプトの結果は、PowerShell で読んでも文字化けしない（くわしくは[設計書](../design/design.md)の 3.8）。設定ファイルとログは UTF-8 で書く。

### 3.2 各スキル

- REQ-110：各スキルの振る舞い（何をするか、設定の項目、コマンド）は、そのスキルの README と SKILL.md に書く。この仕様書には、スキルの名前と中身を書かない。スキルを足す・消す・置き換えても、仕様書は直さない。
- REQ-111：設定のスキルは、名前を渡されたスキルの README と設定ファイルを読み、利用者に質問しながら設定を埋める。特定のスキルの名前・項目・置き場所を前提にしない。利用者にも呼び出し元にも、設定ファイルのパスを指定させない。
  - 設定するのは、Copilot CLI が使うスキルである。同じ名前のスキルがいくつかあるときも、Copilot CLI が使うほうを設定する。
  - スキルの名前を渡されなければ、Copilot CLI で使えるスキルの中から、利用者に選んでもらう。

## 4. 2段階目：作業エージェント

- REQ-201：チャットの依頼だけで動く。Web管理画面とほかのエージェントは使わない。
- REQ-202：セットアップでは、次の順に進める。
  1. 使うスキルのうち、設定を受け持つスキルを使い、その説明に従う。なければ、そのことを伝える。
  2. 機器で試すスキルで、設定を確認する。
- REQ-203：不具合の調査と修正では、次の順に進める。
  1. 合格の条件を決める。依頼になければ質問する。
  2. 今の症状を確認する。
  3. 修正 → スキルで機器で試す（ビルドから、機器で動かしてログを取るまで）→ 合否の判断 を繰り返す（1回を試行と呼ぶ）。
  4. 直るか、上限（既定 5 回）に達したら終える。
- REQ-204：質問には ask_user を使う。
- REQ-205：機器に接続できないときは、繰り返さず、起きたことを伝えてどうするかを聞く。使うスキルに、そのときに使うもの（description にそう書かれたもの）があれば、それを使ってから、1回だけやり直す。使う前に利用者に確かめるかは、そのスキルが決める。
- REQ-206：終わったら、結論、試行ごとの表、ログの場所を報告する。
- REQ-207：ほかのエージェントからの依頼では、頼みの文に書かれた手順と返事の形に従う。質問と合否の判断をしないことも、頼みの文で伝える（[設計書](../design/design.md)の 3.5）。
- REQ-208：直すのは作業フォルダのソースだけ。スキルの設定ファイルは、自分の判断で変えない。

## 5. 3段階目：統括エージェントと Web管理画面

### 5.1 流れ

- REQ-301：依頼に合格の条件がなければ、統括エージェントが ask_user で聞く。
- REQ-302：統括エージェントは、Web管理画面を起動し、作業エージェントに準備の確認を依頼してから、URL を伝える。
- REQ-303：Web管理画面の「開始」を押すと、統括エージェントが試行を始める。ほかのエージェントが選ばれていれば、エクステンションが先に統括エージェントに切り替える。
- REQ-304：試行ごとに、計画の記録 → 作業エージェントへの依頼 → 検証エージェントの判定 → 評価の記録 の順に進める。
- REQ-305：合格の条件をすべて満たすか、上限に達したら終える。作業エージェントが進めなくなったら、ask_user で聞く。
  - エクステンションは、すべての条件の評価がそろい、検証エージェントを呼んだ試行でだけ「合格」を受け付ける。最後の評価がすべて合格でなければ「成功」で終えさせない。
- REQ-306：統括エージェントは、ファイルを直さず、コマンドも実行しない。「開始」の後にファイルの編集・コマンド・スキルのツールを呼ぶと、エクステンションが拒否する（[設計書](../design/design.md)の 3.6）。「開始」の後に頼めるのは、作業エージェントと検証エージェントだけ。
- REQ-307：検証エージェントは、作業の報告にあるファイルを読み、合格の条件ごとに判定する。ファイルは直さない。
- REQ-308：終えるときは、結論と振り返りを記録する。改善点を Issue にするかを ask_user で聞き、「する」なら、題と本文を利用者に見せてから作る。作る前に、Copilot CLI の許可の確認を通す。作った Issue は、その実行の記録に残す。
- REQ-309：作業の報告を受けた試行では、作業を依頼し直さない（エクステンションも拒否する）。続けるときは、次の試行の計画から始める。

### 5.2 Web管理画面

- REQ-311：Copilot CLI を動かす PC（127.0.0.1）からだけ開ける。URL には、起動ごとに作るトークンが入る。
  - 開いた後は、アドレスバーからトークンを消す。
  - 設定の保存・開始・止めるは、この画面から送ったものだけを受ける（同じ PC のほかの画面からの操作を断る）。
- REQ-312：「設定」画面には、次の項目を置く。
  - 頼む作業、合格の条件、繰り返しの上限
  - 作業エージェントと検証エージェントそれぞれの、使うエージェント、モデル、考える深さ
  - 保存するのは、作業フォルダごとの繰り返しの上限だけ。使うエージェント・モデル・考える深さは、その会話のあいだだけ使う（部品を替えたとき、前の値が残らないように）。
- REQ-313：「設定」画面に、準備の確認の結果をそのまま見せる。機器の設定は、ここで見る。
- REQ-314：「開始」の後も、設定を見られる（変えられない）。
- REQ-315：「実行のようす」画面には、次のものを置く。
  - エージェントの構成図（動いているものを目立たせる）
  - 試行ごとの計画・作業の報告・評価
  - 質問や許可を待つときの知らせ
  - 「止める」ボタン
  - 使ったツールなどの一覧（「くわしい記録」を開いたときだけ）
- REQ-316：「結果」画面には、結論・合格の条件と最後の評価・試行ごとの表・振り返りを、この順に見せる。前の実行の結果も開ける。
  - 評価のない条件も、「評価なし」として見せる。
  - 結論には、どの終わり方でも、その実行で変えたファイルの一覧を足す。
- REQ-317：「止める」を押すと、エクステンションが統括エージェントの応答を止める。その後は、結論と振り返りを記録するツールだけを通す。
- REQ-318：幅 390 px でも横にはみ出さない。ライトモードとダークモードの両方で読める。

### 5.3 記録

- REQ-321：エクステンションは、実行ごとに、設定・試行の経過・エージェントの動き・変えたファイルを `<COPILOT_HOME または ~/.copilot>/plugin-data/embedded-debug-loop/` に残す。
  - 記録は、本人だけが読める権限で作る（Linux）。
  - Copilot CLI が実行の途中で終わったときは、次に起動したときに、その実行を「途中で止めた」として閉じる。
