# 部品を変える（プラグインの設計変更）

このプラグインのスキルを足す・消す・置き換えるときと、作業エージェントを置き換えるときの手順です。プラグインのソース（このリポジトリの `plugins/embedded-debug-loop/`）を直す開発者向けです。
利用者は、プラグインをアンインストールして、新しいバージョンを入れ直すだけです。部品の名前や設定の項目が変わったときは、入れ直したあとに設定もやり直します。

どの部品も、ほかの部品の中身を前提にしない作りです。統括エージェント（`orchestrator`）・検証エージェント（`verifier`）・Web管理画面・3段階目のガイド・プラグインの README は、直しません。
パスは、プラグインのフォルダからの相対パスです。

## スキルを足す

1. `skills/<名前>/` に、新しいスキルを置きます（[新しいスキルが守ること](#新しいスキルが守ること)）。`SKILL.md` の `name:` は、フォルダの名前と同じにします。
2. 作業エージェントの定義（`com.github.copilot/agents/` の `.agent.md`）と README（同じフォルダの `README.markdown`）の「使うスキル」の表に、役割と名前の行を足します。2つの表は同じにします。
3. 作業エージェントの定義に、そのスキルをいつ使うかを書きます。役割を並べて書いてある所（説明、セットアップ、準備の確認、試行の報告の形など）にも、新しい役割を足します。
4. [テストと CI](#テストと-ci) を直します。
5. [仕上げ](#仕上げ)に進みます。

## スキルを消す

1. `skills/<名前>/` を消します。
2. 作業エージェントの定義と README の「使うスキル」の表から、その行を消します。
3. 作業エージェントの定義から、その役割を使う手順を消します。役割を並べて書いてある所からも消します。
4. [テストと CI](#テストと-ci) を直します。
5. [仕上げ](#仕上げ)に進みます。

## スキルを置き換える

[スキルを消す](#スキルを消す)と[スキルを足す](#スキルを足す)を、続けて行います。
役割が同じなら、作業エージェントの定義で直すのは「使うスキル」の表だけです。

## 作業エージェントを置き換える

1. `com.github.copilot/agents/` の作業エージェントの定義を、新しいもの（`<名前>.agent.md`）に替えます。
   - 定義の中で自分の名前を書く所（準備の確認の返事で、セットアップの頼み方を案内する所）も、新しい名前にします。
   - 元の定義を残すと、利用者は両方から選べます。
2. 同じフォルダの `README.markdown` を、新しい作業エージェントの名前と使い方に書き替えます。「統括エージェントと検証エージェント」の節は残します。
   README は `.md` にしません。`agents/` の `.md` は、エージェントの定義として読み込まれます。
3. 使うスキルが違うときは、上の手順でスキルを足す・消す・置き換えます。
4. 既定の作業エージェントの名前（`com.github.copilot/extensions/embedded-debug-loop/defaults.json` の `worker`）を、`embedded-debug-loop:<新しい名前>` にします。
5. [テストと CI](#テストと-ci) を直します。
6. [仕上げ](#仕上げ)に進みます。

## テストと CI

テストと CI には、今の部品の名前と作りが書いてあります。部品を変えたら、次を直します。
古いままでも不合格にならない所があるので、テストが通っただけでは足りません。

| ファイル | 直す所 |
| --- | --- |
| `tests/independence/test_independence.py` | `SKILL_NAMES`（すべてのスキルの名前）と `WORK_SKILLS`（設定のスキルのほかのスキルの名前と、そのスクリプトの名前）。足したスキルは、ここに書かないと確認されない |
| 同上 | 作業エージェントの定義のファイル名と、作業エージェントの名前 |
| 同上 | 今のスキルの作りを前提にしたテスト。作業のスキルのコマンドの名前、設定ファイルとひな形の名前と形式、設定のスキルのスクリプトとコマンド、置き換えのテストで例に使うスキルの名前 |
| `tests/extension/independence.test.mjs` | `FORBIDDEN`（Web管理画面に書いてはいけない言葉）の、スキルと作業エージェントの名前 |
| リポジトリ直下の `.github/workflows/` にある、このプラグインの CI の定義 | スキルのテストに要るパッケージ（`pip install` の行）。設定のスキルを Windows の PowerShell で動かすジョブ |

`tests/run.py` と、CI でスキルのテストを動かすジョブは、`skills/` の下からスキルを探すので、直しません。

## 仕上げ

1. 古い名前で検索し、直し残しがないことを確認します。

   ```text
   git grep -n "<古い名前>"
   ```

2. 仕様書と設計書を直します。スキルの一覧と数、役割の一覧、そのスキルの節、構成図、作業のスキルの共通の作り（設定ファイルの形式、コマンドの名前）、作業エージェントの名前が書いてあります。
3. 役割を足したり消したりしたときは、プラグインの説明も直します（`plugin.json`、リポジトリ直下の `.github/plugin/marketplace.json` と `README.md`）。
   憲章（`docs/constitution.md`）の第1条にも役割があります。憲章を変えるときは、憲章の改訂として扱います。
4. バージョンを上げます。次の5か所にあります。
   - `plugin.json`
   - 仕様書と設計書の先頭
   - リポジトリ直下の `.github/plugin/marketplace.json`
   - リポジトリ直下の `README.md` の表
5. テストを実行し、すべて合格することを確認します。Node.js が要ります。

   ```text
   # Windows（PowerShell）
   py -3 tests\run.py
   # Linux（bash）
   python3 tests/run.py
   ```

6. push し、GitHub Actions のテスト（Windows と Linux）が合格することを確認します。
7. マージしたら、Copilot CLI でプラグインをアンインストールしてインストールし直し、新しい部品で動くことを確認します。

   ```text
   /plugin uninstall embedded-debug-loop
   /plugin install embedded-debug-loop@plugin-market-place
   ```

## 新しいスキルが守ること

| 約束 | 内容 |
| --- | --- |
| 頼まれること | 作業エージェントの[「使うスキル」の表](../com.github.copilot/agents/README.markdown#使うスキル)にある役割の作業と、設定の確認 |
| 返すもの | 作業では、成否・起きたこと・ログの場所。設定の確認では、抜けや誤り（できれば、実際に使えるかも試す） |
| 設定 | 要るなら、`README.md` に設定ファイルの場所・作り方・項目の意味を書く。形式（YAML・INI・JSON など）と項目の名前は自由 |
| 設定の書き方 | 設定のスキル（「使うスキル」の表の「設定」）が読める形で書く。書き方は、そのスキルの README にある |
| コマンド | `SKILL.md` のコマンドは、Windows の PowerShell でも動くようにする（ヒアドキュメント・`source`・`$(…)` を使わない）。Python は、Windows では `py -3`（なければ `python`）、ほかは `python3` で呼ぶ |
| 独立 | 要るファイルは、スキルのフォルダに置く。ほかのスキルやエージェントを前提にしない。README とテストも、フォルダの中に置く |

設定のスキルを置き換えるときは、新しいスキルが次のことをできるようにします。

- 渡されたスキルの名前から、そのスキルの README と設定ファイルを見つける。プラグインの中では、ほかのスキルは同じ `skills/` の下にある。
- ほかのスキルの設定ファイルを、今の書き方のまま読む。書き方を変えるなら、ほかのスキルの設定ファイルも直す。

## 新しい作業エージェントが守ること

統括エージェントとの約束は、次のとおりです（言い回しは変えてかまいません）。

| 場面 | 約束 |
| --- | --- |
| ほかのエージェントから呼ばれたとき（質問のツール ask_user が使えないか、依頼が「これは準備の確認です」か「あなたは作業役です」で始まる） | 利用者に質問せず、頼まれたことだけをする |
| 準備の確認 | 作業はしない。1行目に「準備：できている」か「準備：できていない」と書き、続けて設定の要約と、足りないもの（直し方つき）を書く |
| 試行 | 1回だけ作業し、合否は判断しない。進めなくなったら止める。変えたこと、手順ごとの「できた／できなかった（理由）」、ログの要点、ログの場所（絶対パス）、気づいたことを返す |

- 使うスキルは、定義の「使うスキル」の表（`| 役割 | スキル |`）に名前だけを書きます。スキルの中身は書きません。
- 試行の報告の行（ビルド・転送など）は、作業に合わせて変えてかまいません。統括エージェントは、行の名前を読みません。
- `description` は、Web管理画面で作業エージェントを選ぶときに出ます。
