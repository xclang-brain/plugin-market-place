# 部品を置き換える（プラグインの設計変更）

このプラグインのスキルや作業エージェントを、別のものに置き換える手順です。プラグインのソース（このリポジトリの `plugins/embedded-debug-loop/`）を直す開発者向けです。
利用者は、プラグインをアンインストールして、新しいバージョンを入れ直すだけです。部品の名前や設定の項目が変わったときは、入れ直したあとに設定もやり直します。

## 直す所

どの部品も、ほかの部品の中身を前提にしない作りです。置き換えるときに直すのは、次の所だけです。
パスは、プラグインのフォルダからの相対パスです。

| 置き換えるもの | 直す所 |
| --- | --- |
| スキル（名前はそのまま） | `skills/<名前>/` |
| スキル（名前も替える） | `skills/<新しい名前>/`、作業エージェントの「使うスキル」の表と、その README の表 |
| 作業エージェント | `com.github.copilot/agents/` にある作業エージェントの定義と README、既定の作業エージェントの名前（`com.github.copilot/extensions/embedded-debug-loop/defaults.json` の `worker`） |
| どの部品でも | テストと CI（下の表）、仕様書と設計書、バージョン |

統括エージェント（`orchestrator`）・検証エージェント（`verifier`）・Web管理画面のコード・プラグインの README・3段階目のガイドは、直しません。

テストと CI には、今の部品の名前と作りが書いてあります。置き換えたら、次も直します。

| ファイル | 書いてあること |
| --- | --- |
| `tests/independence/test_independence.py` | スキルの名前（`SKILL_NAMES`）、作業のスキルのスクリプトの名前（`WORK_SKILLS`）、作業エージェントの定義のファイル名、設定のスキルのスクリプトとコマンド。スキルの作り（`check` と `config-path` のコマンド、設定ファイルの場所、README の決まった文）も確認している |
| `tests/extension/independence.test.mjs` | Web管理画面に書いてはいけない言葉（`FORBIDDEN`）。スキルと作業エージェントの名前が入っている |
| リポジトリ直下の `.github/workflows/` にある、このプラグインの CI の定義 | 設定のスキルを Windows の PowerShell で動かすジョブ。スキルのテストに要るパッケージ（`pip install` の行） |

バージョンは、次の5か所にあります。

- `plugin.json`
- 仕様書と設計書の先頭
- リポジトリ直下の `.github/plugin/marketplace.json`
- リポジトリ直下の `README.md` の表

## 新しいスキルが守ること

| 約束 | 内容 |
| --- | --- |
| 頼まれること | 作業エージェントの[「使うスキル」の表](../com.github.copilot/agents/README.markdown#使うスキル)にある役割の作業と、設定の確認 |
| 返すもの | 作業では、成否・起きたこと・ログの場所。設定の確認では、抜けや誤り（できれば、実際に使えるかも試す） |
| 設定 | 要るなら、`README.md` に設定ファイルの場所・作り方・項目の意味を書く。形式（YAML・INI・JSON など）と項目の名前は自由 |
| 設定の書き方 | 設定のスキル（「使うスキル」の表の「設定」）が読める形で書く。書き方は、そのスキルの README にある |
| コマンド | `SKILL.md` のコマンドは、Windows の PowerShell でも動くようにする（ヒアドキュメント・`source`・`$(…)` を使わない）。Python は、Windows では `py -3`（なければ `python`）、ほかは `python3` で呼ぶ |
| 独立 | 要るファイルは、スキルのフォルダに置く。ほかのスキルやエージェントを前提にしない。README とテストも、フォルダの中に置く |

設定のスキルを置き換えるときは、新しいスキルが次のことをできるようにします。

- 渡されたスキルの名前から、そのスキルの README と設定ファイルを見つける。プラグインの中では、ほかのスキルは同じ `skills/` の下にある。
- ほかのスキルの設定ファイルを、今の書き方のまま読む。書き方を変えるなら、ほかのスキルの設定ファイルも直す。

## 新しい作業エージェントが守ること

統括エージェントとの約束は、次のとおりです（言い回しは変えてかまいません）。

| 場面 | 約束 |
| --- | --- |
| ほかのエージェントから呼ばれたとき（質問のツール ask_user が使えないか、依頼が「これは準備の確認です」か「あなたは作業役です」で始まる） | 利用者に質問せず、頼まれたことだけをする |
| 準備の確認 | 作業はしない。1行目に「準備：できている」か「準備：できていない」と書き、続けて設定の要約と、足りないもの（直し方つき）を書く |
| 試行 | 1回だけ作業し、合否は判断しない。進めなくなったら止める。変えたこと、手順ごとの「できた／できなかった（理由）」、ログの要点、ログの場所（絶対パス）、気づいたことを返す |

- 使うスキルは、定義の「使うスキル」の表（`| 役割 | スキル |`）に名前だけを書きます。スキルの中身は書きません。
- `description` は、Web管理画面で作業エージェントを選ぶときに出ます。

## スキルを置き換える

1. `skills/<名前>/` を消し、新しいスキルのフォルダを置きます。`SKILL.md` の `name:` は、フォルダの名前と同じにします。
2. 名前を替えたときは、作業エージェントの定義と README の「使うスキル」の表を直します。2つの表は同じにします。
3. テストと CI の、今のスキルの名前と作りが書いてある所を直します（[直す所](#直す所)）。
4. [仕上げ](#仕上げ)に進みます。

## 作業エージェントを置き換える

1. `com.github.copilot/agents/` の作業エージェントの定義（`<名前>.agent.md`）を、新しいものに替えます。元の定義を残すと、利用者は両方から選べます。
2. 同じフォルダの `README.markdown` を、新しい作業エージェントの使い方に書き替えます。「統括エージェントと検証エージェント」の節は残します。
   README は `.md` にしません。`agents/` の `.md` は、エージェントの定義として読み込まれます。
3. 新しい作業エージェントが使うスキルを、`skills/` に置きます（[スキルを置き換える](#スキルを置き換える)）。
4. `defaults.json` の `worker` を、`embedded-debug-loop:<新しい名前>` にします。
5. テストと CI の、今の作業エージェントの名前が書いてある所を直します（[直す所](#直す所)）。
6. [仕上げ](#仕上げ)に進みます。

## 仕上げ

1. 古い名前で検索し、直し残しがないことを確認します。

   ```text
   git grep -n "<古い名前>"
   ```

2. 仕様書と設計書を直します。
3. バージョンを上げます（[直す所](#直す所)の5か所）。
4. テストを実行し、すべて合格することを確認します。Node.js が要ります。

   ```text
   # Windows（PowerShell）
   py -3 tests\run.py
   # Linux（bash）
   python3 tests/run.py
   ```

5. push し、GitHub Actions のテスト（Windows と Linux）が合格することを確認します。
6. マージしたら、Copilot CLI でプラグインをアンインストールしてインストールし直し、新しい部品で動くことを確認します。

   ```text
   /plugin uninstall embedded-debug-loop
   /plugin install embedded-debug-loop@plugin-market-place
   ```
