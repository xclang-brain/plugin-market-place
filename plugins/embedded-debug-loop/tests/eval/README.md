# EVAL（エージェントが不具合を直せるかの試験）

実際のモデルで課題を解かせ、合否の基準で採点します。エージェントの定義・スキル・モデルを変えたときに流し、前の結果と比べます。
AI クレジットを使います。

| 課題 | 中身 |
| --- | --- |
| `T-01/` | センサーの値の平均が AVG=3 と出る（正しくは 25）。合計を 8 ビットの変数で足しているため、あふれる |

各課題の `eval.json` に、頼みの文（`prompt`）・作業フォルダに置くファイル（`inputs`）・合否の基準（`criteria`）があります。
`inputs` には、今のスキルの設定ファイルも入っています。スキルを替えたときは、設定ファイルも替えます。

## 模擬の機器

機器の代わりに、この PC の上で FTP サーバーとコンソール（本物の bash）を動かします。Linux か macOS で動きます。
課題を流す前に起動し、終わるまで動かしておきます。

```
pip install pyftpdlib
python3 tests/eval/device_sim.py --root /tmp/device
```

課題の設定ファイルは、FTP を 127.0.0.1:2121、コンソールを `socket://127.0.0.1:2323` として書いてあります。
課題ごとに、`--root` のフォルダは空にしてから始めます。

## 流し方

plugin-creator を入れた Copilot CLI で、embedded-debug-loop の試験を頼みます。

手で流すときは、次のとおりにします。

1. 空のフォルダに、課題の `inputs/` の中身をコピーします。
2. そのフォルダで Copilot CLI を起動し、`/agent` で作業エージェントを選びます（3段階目を試すときは統括エージェント）。
3. `prompt` の文を送ります。質問には、ふつうの利用者として答えます。
4. 終わったら、`criteria` の基準で採点します。結果は、モデル・版・日付と一緒に残します。
