# クロスコンパイル

ビルドの方法は、作業フォルダの `.<このスキルのフォルダの名前>/config.yaml` に書きます。
各項目の意味は、ファイルの中のコメントにあります。

## コマンド

作業フォルダで実行します。`<python>` は、Windows では `py -3`（なければ `python`）、ほかでは `python3` です。

| すること | コマンド |
| --- | --- |
| ビルドする | `<python> <このスキルのフォルダ>/scripts/build.py run` |
| 設定を確かめる（ビルドせず、ファイルも作らない） | `<python> <このスキルのフォルダ>/scripts/build.py check` |
| 設定ファイルを作る・場所を返す・足りない項目を足す | `<python> <このスキルのフォルダ>/scripts/build.py config-path` |

- 作業フォルダが今のフォルダと違うときは、`--workdir <フォルダ>` を付けます。
- run は、設定の timeout_seconds（既定 600 秒）まで終わらないことがあります。終わるまで待ちます。
- 設定ファイルを作ったり書き換えたりするのは、頼まれたときだけです。

## 結果

標準出力に JSON を1つ返します。
`message` は結果の要約、`problems` は設定や PC の準備の問題、`notes` は注意、`log` はログの場所です。

- 成功したら、`outputs` のファイル（場所・大きさ・種類）と、使ったコンパイラーを伝えます。
  `stale_outputs` のファイルは今回作り直されていないので、ソースの変更が入っていないかもしれません。
- ビルドに失敗したら、`error_lines`（なければ `tail`）の主な行を示します。`timed_out` が true なら時間切れです。
