# deploy：機器にファイルを送るスキル

GitHub Copilot CLI で使うスキルです。
このフォルダだけで動きます。

## 何をするスキルか

PC にあるファイルを、FTP で組み込み機器に送ります。

- 送った後に、ファイルの権限を変えられます（例：755。実行できるようにする）。
- サム値のファイルを作って、一緒に送れます。
  サム値は、ファイルが壊れていないかを機器で確かめるための値です。
- 送った後に、機器のファイルの大きさが PC と同じかを確かめます。

送り先や送るファイルは、設定ファイルに書きます。

## 必要なもの

- PC の OS：Linux
- Python 3.8 以上。標準の部品だけで動くので、ほかに入れるものはありません。
- GitHub Copilot CLI
- 機器の準備
  - 機器で FTP サーバーが動いていること。
  - PC から、機器の IP アドレス（かホスト名）につながること。
  - FTP のユーザー名とパスワード。そのユーザーが、送り先のフォルダに書き込めること。
  - 権限を変えるなら、FTP サーバーが権限の変更（`SITE CHMOD`）を受け付けること。
  - 大きさを確かめるには、FTP サーバーが大きさの問い合わせ（`SIZE`）に答えること。
    答えないときは、確かめずに送ります。

## 置き方

このフォルダを、次のどちらかに写します。

- その作業フォルダだけで使う：`<作業フォルダ>/.github/skills/deploy/`
- 自分のどの作業フォルダでも使う：`~/.copilot/skills/deploy/`

Copilot CLI を起動したまま写したときは、`/skills reload` を実行します。

名前を変えて写すこともできます。
そのときは、フォルダの名前と、`SKILL.md` の `name:` を同じ名前にします。
Copilot CLI は、`name:` の名前でスキルを呼ぶためです。

## 呼び方

`/deploy` の後に、頼みたいことを書きます。

| 頼めること | 例 |
| --- | --- |
| ファイルを機器に送る | `/deploy 機器に送って` |
| 設定ファイルの場所を知る・用意する | `/deploy 設定ファイルはどこ？`<br>`/deploy 設定ファイルを用意して` |
| 設定を確かめる（機器に FTP でログインできるかも試す。ファイルは送らない） | `/deploy 設定を確かめて` |

はじめて使うときの流れです。

1. `/deploy 設定ファイルを用意して` と頼みます。ひな形から設定ファイルができます。
2. 設定ファイルの `host`・`files`・`remote_dir` を書きます。
3. `/deploy 設定を確かめて` と頼みます。
4. `/deploy 機器に送って` と頼みます。

プラグインに入れて配られているときは、`/<プラグインの名前>:<スキル名>` でも呼べます。

### コマンドで直接動かすとき

作業フォルダで、次のように実行します。
`~/.copilot/skills/` に置いたときは、パスをそちらに変えます。

```sh
python3 .github/skills/deploy/scripts/deploy.py config-path   # 設定ファイルの場所（なければ作る）
python3 .github/skills/deploy/scripts/deploy.py check         # 設定を確かめる
python3 .github/skills/deploy/scripts/deploy.py run           # 機器に送る（run は省略できる）
```

- 作業フォルダを変えるとき：`--workdir <フォルダ>`
- 別の設定ファイルを使うとき：`--config <ファイル>`

## 設定ファイル

### 置き場所

```
<作業フォルダ>/.deploy/config.yaml
```

- 作業フォルダは、コマンドを動かした今のフォルダです（ふつうは Copilot CLI を動かしているフォルダ）。
  上のフォルダは探しません。別のフォルダで動かすと、そこに新しい設定ファイルができます。
  作業フォルダは `--workdir` で変えられます。
- `.deploy` は、このフォルダの名前の前に点を付けた名前です。
  名前を変えて写したときは、`.<変えた名前>` になります。
- このスキルをどこに置いても、設定と記録は作業フォルダの中にできます。
- 設定ファイルがないときは、ひな形（このフォルダの `config-template.yaml`）から作ります。
- `.deploy` フォルダには `.gitignore`（中身は `*`）も作ります。
  設定（パスワード）や記録を、git に入れないためです。
- スキルを新しくして、ひな形に項目が増えたときは、足りない項目を設定ファイルの最後に足します。
  値はひな形のままです。ほかの所は変えません。

設定ファイルは、直接書き直してかまいません。
各項目の意味は、項目のすぐ上のコメントにも書いてあります。
1行に「名前: 値」を1つ書きます。入れ子の書き方は使えません。
リストは `["a", "b"]` の形で書きます。

### 項目

| 項目 | 意味 | ひな形の値 | 例 |
| --- | --- | --- | --- |
| `host` | 機器の IP アドレスかホスト名（必須） | 空 | `"192.168.1.50"` |
| `port` | FTP サーバーのポート番号 | `21` | `21` |
| `user` | FTP でログインするユーザー名。空なら anonymous（名前なしのログイン） | `"root"` | `"root"` |
| `password` | FTP でログインするパスワード | 空 | ― |
| `password_env` | パスワードを入れた環境変数の名前（「パスワードを環境変数で渡す」を見てください） | 空 | `"DEVICE_FTP_PASSWORD"` |
| `passive` | パッシブモード（データを送る接続を PC の側から張るやり方）で送るか。送る途中で止まるときは `false` を試す | `true` | `false` |
| `files` | 送るファイル（必須）。作業フォルダからの相対パス。絶対パスも書ける | `[]` | `["my_app"]`<br>`["build/my_app", "conf/my_app.conf"]` |
| `remote_dir` | 機器の送り先のフォルダ（必須）。なければ作る | 空 | `"/opt/myapp"` |
| `file_mode` | 送った後に付ける権限（8進数）。空なら付けない | 空 | `"755"` |
| `checksum` | サム値の種類。`none`（作らない）・`crc32`・`sum32` | `"none"` | `"crc32"` |
| `checksum_suffix` | サム値のファイルの名前の末尾に付ける文字 | `".sum"` | `".sum"` |
| `timeout_seconds` | 機器の応答を待つ最長の秒数 | `30` | `60` |

`file_mode` について：
FTP で送ったファイルは、ふつうは実行できない権限になります。
機器でプログラムを実行するなら、`755` などを書いてください。

サム値について：

- `crc32` は CRC-32 です。`sum32` は、全バイトを足した値の下位32ビットです。
- サム値のファイルの中身は、16進数8桁（小文字）と改行です。例：`cbf43926`
- サム値のファイルは、送るファイルと同じフォルダに送ります。
  `my_app` なら、`my_app.sum` です。

### パスワードを環境変数で渡す

パスワードを設定ファイルに書きたくないときは、環境変数で渡せます。

1. 設定ファイルに、環境変数の名前を書きます。

   ```yaml
   password: ""
   password_env: "DEVICE_FTP_PASSWORD"
   ```

2. Copilot CLI を起動する前に、その環境変数を設定します。

   ```sh
   export DEVICE_FTP_PASSWORD='機器のパスワード'
   copilot
   ```

- その環境変数があれば、`password` より優先します。
- 環境変数がなく、`password` に値があれば、`password` を使います。
- どちらもなければ、設定の問題として知らせます。

パスワードは、画面にも記録のファイルにも出しません。
ただし、設定ファイルの書き方の誤り（閉じていない `"` など）を知らせるときは、その行の中身をそのまま見せます。

## 結果とログの見方

### 結果

Copilot が、結果をふつうの言葉で伝えます。
送れたときは、送ったファイル、機器の送り先、権限、サム値を短い表で伝えます。

コマンドで直接動かしたときは、結果が JSON で1つだけ出ます。
途中のようすは、標準エラー（JSON とは別の出力）に出ます。
各行の頭は `[deploy]` です（名前を変えて写したときは、変えた名前）。

JSON の主な項目です。

| 項目 | 中身 |
| --- | --- |
| `skill` | このフォルダの名前（名前を変えて写したときは、変えた名前） |
| `ok` | うまくいったら `true` |
| `message` | 何が起きたかの説明。失敗したときは、原因と確かめること |
| `files` | 送ったファイルごとの結果。`local`（PC のファイル）、`remote`（機器の場所）、`size`（大きさ）、`remote_size`（機器での大きさ）、`mode`（付けた権限。付けていなければ null）、`checksum`（サム値）、`checksum_file`（機器のサム値のファイル）、`checksum_local_file`（PC に残したサム値のファイル） |
| `remote_dir` | 機器の送り先のフォルダ |
| `created_dirs` | 機器に新しく作ったフォルダ |
| `notes` | 知らせ（例：機器が大きさの問い合わせに答えない） |
| `problems` | 設定の問題（check では、ログインできない理由も入る） |
| `summary` | check のときの設定のまとめ。パスワードは `＊＊＊` で伏せる |
| `config` | 設定ファイルの場所 |
| `added` | 設定ファイルに足した項目 |
| `log` | 記録のファイル（ログ）の場所 |

`config-path` のときは、`config`（場所）、`created`（いま作ったら `true`）、`missing`（必須なのに空の項目）、`added` が出ます。
項目を足したときは `message`、設定ファイルが読めないときは `problems` も出ます。

終了コードは、0 がうまくいった、1 が送れなかった（思わぬエラーで止まったときも 1）、2 が設定やコマンドの書き方に問題があった、です。
`check` でログインできないときも 2 です。
`config-path` は、設定ファイルが読めないときも 0 です（理由は `problems` に出ます）。

### ログ

`run` と `check` は、動くたびに記録のファイル（ログ）を1つ作ります。

```
<作業フォルダ>/.deploy/logs/deploy-YYYYmmdd-HHMMSS.log
```

- 名前を変えて写したときは、`.deploy` も、名前の頭の `deploy` も、変えた名前になります。
- 同じ秒に2回以上動かしたときは、名前の後ろに `-2` などが付きます。
- 各行の頭に、日時があります。
- 機器の FTP サーバーの答えや、失敗したときの詳しいことも書きます。
- サム値のファイルは、PC にも残します。
  場所は、記録のファイルと同じ名前の後ろに `-checksums` を付けたフォルダです（例：`.deploy/logs/deploy-YYYYmmdd-HHMMSS-checksums/`）。
- 古い記録は、自動では消えません。要らなければ消してかまいません。

## うまくいかないとき

`message` に、原因と確かめることが書いてあります。
くわしくは、記録のファイルを見てください。

| こう言われたら | 確かめること |
| --- | --- |
| 「FTP でつながりません（接続が拒否されました）」 | 機器の電源。機器の FTP サーバーが動いているか |
| 「FTP でつながりません（N 秒待っても応答がありません）」 | 機器の電源とケーブル。`host` の IP アドレス |
| 「FTP でつながりません（機器までの経路がありません）」 | ケーブル、`host` の IP アドレス、PC のネットワークの設定 |
| 「ホスト名 … が見つかりません」 | `host` |
| 「ログインできません（ユーザー名かパスワードが違います）」 | `user`、`password`、`password_env` |
| 「機器が断りました」 | `user` に書き込む権限があるか。`remote_dir` が正しいか |
| 「機器の空き容量が足りません」 | 機器の空き容量 |
| 「権限を … に変えられません」 | FTP サーバーが権限の変更（`SITE CHMOD`）を受け付けるか |
| 送る途中で止まる・「ファイルを送るための接続が拒否されました」 | `passive` を変えて試す（`true` ⇔ `false`） |
| 「大きさ … が、PC のファイル … と合いません」 | 機器の空き容量とケーブル。もう一度送る |
| 「送るファイル … が見つかりません」 | ファイルができているか。`files` のパス |
| 「設定に直すところが N 件あります」 | 設定ファイルを直す。各項目の意味はコメントにある |
| 機器でプログラムを実行できない | `file_mode` が空でないか（`755` などを書く） |
| 「思わぬエラーで止まりました」 | 記録のファイル |

「大きさは確かめていません」は、エラーではありません。
機器の FTP サーバーが大きさの問い合わせに答えないので、確かめずに送った、という知らせです。

## 試験の動かし方

このフォルダで、次の1つのコマンドを実行します。

```sh
python3 -m unittest discover -s tests
```

- 試験は、一時フォルダの中で動きます。本物の機器は要りません。
- 一部の試験は、試験の中で FTP サーバーを立てます。それには `pyftpdlib` が要ります（試験のときだけ。ふだん使うときは要りません）。
  - `pyftpdlib` が読み込めないときは、その試験だけ飛ばします（skipped と出ます）。
  - `pyftpdlib` を置いたフォルダは、環境変数 `DEPLOY_TEST_PYLIB` で指定できます（`:` 区切りで複数）。
  - 入れ方の例です（このフォルダの外の `/tmp/pylib` に入れます）。

    ```sh
    python3 -m pip install --target /tmp/pylib pyftpdlib
    DEPLOY_TEST_PYLIB=/tmp/pylib python3 -m unittest discover -s tests
    ```

- 試験のコマンドは、`tests/__pycache__` を残します。要らなければ消してかまいません。
  残したくないときは、`python3 -B -m unittest discover -s tests` とします。
