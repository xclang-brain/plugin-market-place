# deploy：機器にファイルを送るスキル

PC にあるファイルを、FTP で組み込み機器に送る GitHub Copilot CLI のスキルです。このフォルダだけで動きます。
設定ファイルに送り先と送るファイルを書いて、`/deploy 機器に送って` と入力します。

## できること

- 設定ファイルに書いたファイルを、機器のフォルダに送る。
- 送った後に、機器のファイルのサイズが PC と同じかを確認する。
- 送った後に、ファイルの権限を変更する（例：755）。
- サム値（チェックサム）のファイルを作って一緒に送る。機器での破損の確認に使う。

## 必要なもの

- Windows の PC（Linux でも動きます）
- Python 3.8 以上（追加のインストールは要りません）
- GitHub Copilot CLI
- 機器の FTP サーバーと、送り先のフォルダに書き込めるユーザー（ユーザー名・パスワード）
- PC から、機器の IP アドレスかホスト名に接続できること
- FTP サーバーが `SITE CHMOD`（権限の変更）と `SIZE`（サイズの確認）に対応していること。`SIZE` がなければ、確認せずに送ります

Windows では GitHub Actions でテストしています（Copilot CLI との組み合わせは未確認）。

## インストールする

プラグインと一緒にインストールしたときは、この手順は要りません。

1. このフォルダを、次のどちらかにコピーします。
   - 1つの作業フォルダ（ふつうは、Copilot CLI を起動したフォルダ）で使う：`<作業フォルダ>/.github/skills/deploy/`
   - すべての作業フォルダで使う：`%USERPROFILE%\.copilot\skills\deploy\`（Linux では `~/.copilot/skills/deploy/`）
2. Copilot CLI を起動したままコピーしたときは、`/skills reload` を実行します。
3. `/skills list` に `deploy` が出れば完了です。

フォルダの名前を変えてコピーするときは、`SKILL.md` の `name:` も、フォルダと同じ名前に変えます。
呼び出しは `/<新しい名前>`、設定とログのフォルダは `.<新しい名前>/`、ログファイルの名前の先頭は `<新しい名前>-` になります。

## 使い方

1. `/deploy 設定ファイルを作って` と入力します。設定ファイルがなければ作られ、場所が表示されます。
2. 設定ファイルに、必須の `host`・`files`・`remote_dir` を書きます。必要なら `user`・`password` も書きます（[項目](#項目)）。
3. `/deploy 設定を確認して` と入力します。FTP でログインできるかも試します（ファイルは送りません）。「… に FTP でログインできました」と出れば、準備完了です。「ただし、」の後に注意が出たら、その内容を確認します。
4. `/deploy 機器に送って` と入力します。送ったファイル・送り先・権限・サム値の表が出れば完了です。

- プラグインに入れて配られているときは、`/<プラグインの名前>:<スキル名>` で呼びます。

## 設定ファイル

場所は `<作業フォルダ>/.deploy/config.yaml` です。
親フォルダはさかのぼって探しません。

設定ファイルがなければ、ひな形（このフォルダの `config-template.yaml`）から作ります。
`.deploy/` には `.gitignore`（中身は `*`）も作り、パスワードやログを Git から外します。
設定の確認では、ファイルを作りません。設定ファイルも変更しません。
スキルの更新でひな形に項目が増えたら、送るときと設定の確認で、足りない項目を注意として知らせます。
`/deploy 足りない項目を足して` と入力すると、足りない項目をひな形の値で設定ファイルの最後に追加します。

各項目の説明は、設定ファイルのコメントにもあります。

- 文字コードは UTF-8 で保存します。
- 1行に「名前: 値」を1つ書きます。入れ子は使えません。リストは `["a", "b"]` と書きます。
- Windows のパスは、`/` で区切るか（`"C:/work/my_app"`）、`'` で囲みます（`'C:\work\my_app'`）。`"` で囲むと、`\t` や `\n` がタブや改行になります。

### 項目

| 項目 | 意味 | ひな形の値 |
| --- | --- | --- |
| `host` | 機器の IP アドレスかホスト名（必須）。例：`"192.168.1.50"` | 空 |
| `port` | FTP のポート番号 | `21` |
| `user` | FTP のユーザー名。空なら anonymous でログインする | `"root"` |
| `password` | FTP のパスワード。`user` を書いたら、必ず書く（`password_env` で渡すときは空） | 空 |
| `password_env` | パスワードを入れた環境変数の名前（[下記](#パスワードを環境変数で渡す)） | 空 |
| `passive` | パッシブモードを使うか | `true` |
| `files` | 送るファイル（必須）。作業フォルダからの相対パスか絶対パス。例：`["build/my_app", "conf/my_app.conf"]` | `[]` |
| `remote_dir` | 機器の送り先のフォルダ（必須）。なければ作る。`/` で区切る。例：`"/opt/myapp"` | 空 |
| `file_mode` | 送った後に設定する権限（8進数）。空なら設定しない。機器で実行するなら `"755"` などにする | 空 |
| `checksum` | サム値の種類。`none`（作らない）・`crc32`（CRC-32）・`sum32`（全バイトを足した値の下位32ビット） | `"none"` |
| `checksum_suffix` | サム値のファイルの名前の末尾に付ける文字（`.sum` なら `my_app.sum`）。`/`・`\`・`:` などは使えない | `".sum"` |
| `timeout_seconds` | 機器の応答を待つ最長の秒数 | `30` |

サム値のファイルの中身は、16進数8桁（小文字）と改行（LF）です（例：`cbf43926`）。送るファイルと一緒に `remote_dir` に送ります。

### パスワードを環境変数で渡す

1. 設定ファイルの `password_env` に、環境変数の名前（例：`DEVICE_FTP_PASSWORD`）を書きます。
2. Copilot CLI を起動する前に、同じ端末でその環境変数を設定します。
   - Windows（PowerShell）：`$env:DEVICE_FTP_PASSWORD = '機器のパスワード'`
   - Linux（bash）：`export DEVICE_FTP_PASSWORD='機器のパスワード'`

環境変数は `password` より優先します。
どちらもなければ、設定の問題として知らせます。

パスワードは、画面にもログにも出しません。
ただし、`password` の行の書き方に誤り（閉じていない `"` など）があると、パスワードを含むその行がエラーメッセージに出ます。

## 結果とログ

### スクリプトの出力

標準出力に、結果の JSON が1つ出ます。
途中経過は、標準エラー出力に `[deploy]`（このフォルダの名前）で始まる行で出ます。
Windows では、コンソールの文字コード（日本語の Windows では cp932 など）で書きます。

`run` と `check` の JSON の主な項目です。

| 項目 | 内容 |
| --- | --- |
| `ok` | 成功したら `true` |
| `message` | 結果の説明。失敗したときは、原因と確認する点 |
| `problems` | 設定の問題（`check` では、ログインできない理由も） |
| `notes` | エラーではない注意（設定ファイルに足りない項目があることなど） |
| `summary` | `check` の設定のまとめ（パスワードは `＊＊＊` でマスク） |
| `remote_dir`・`created_dirs` | 送り先・機器に新しく作ったフォルダ |
| `config`・`log`・`skill` | 設定ファイル・ログ（`run` だけ）の場所、このフォルダの名前 |
| `files` | ファイルごとの結果。`local`・`remote`（PC・機器のファイル）、`size`・`remote_size`（そのバイト数）、`mode`（設定した権限。なければ null）、`checksum`（サム値）、`checksum_file`・`checksum_local_file`（機器・PC のサム値のファイル） |

`config-path` の JSON は、`config`（場所）、`created`（今回作ったら `true`）、`missing`（必須なのに空の項目）、`added`（設定ファイルに追加した項目）です。
項目を追加したら `message`、設定ファイルを読めなければ `problems` も出ます。

終了コードは次のとおりです。

- 0：成功
- 1：送れなかった（予期しないエラーを含む）
- 2：設定かコマンドの書き方の問題（`check` でログインできないときを含む）

`config-path` は、設定ファイルを読めないときも 0 です。

### ログ

`run` は、実行するたびに次のログファイルを作ります。

```
<作業フォルダ>/.deploy/logs/deploy-YYYYmmdd-HHMMSS.log
```

- FTP サーバーの応答や、失敗の詳細も書きます。
- サム値のファイルは、ログと同じフォルダの `deploy-YYYYmmdd-HHMMSS-checksums/` にも残します。
- 古いログは、自動では削除されません。

## うまくいかないとき

メッセージに、原因と確認する点があります。詳しくは、ログ（`check` では標準エラー出力）を見ます。

| 症状・メッセージ | 対処 |
| --- | --- |
| `/deploy` が出てこない | 置き場所と、`name:` がフォルダの名前と同じかを確認し、`/skills reload` を実行する |
| 「FTP でつながりません（接続が拒否されました）」 | 機器の電源と、FTP サーバーが動いているかを確認する |
| 「FTP でつながりません（N 秒待っても応答がありません）」 | 機器の電源とケーブル、`host` の IP アドレスを確認する |
| 「FTP でつながりません（機器までの経路がありません）」 | ケーブル、`host` の IP アドレス、PC のネットワーク設定を確認する |
| 「ホスト名 … が見つかりません」 | `host` のホスト名を確認する |
| 「ログインできません（ユーザー名かパスワードが違います）」 | `user`・`password`・`password_env` を確認する |
| 「機器が断りました」 | `user` の書き込み権限と、`remote_dir` を確認する |
| 「機器の空き容量が足りません」 | 機器の空き容量を確認する |
| 「権限を … に変えられません」 | FTP サーバーが `SITE CHMOD` に対応しているかを確認する |
| 送る途中で止まる・「ファイルを送るための接続が拒否されました」 | `passive` を切り替える（`true` ⇔ `false`）。`false` なら PC のファイアウォールも確認する |
| 「大きさ … が、PC のファイル … と合いません」 | 機器の空き容量とケーブルを確認し、送り直す |
| 「送るファイル … が見つかりません」 | ファイルができているかと、`files` のパスを確認する |
| 「設定ファイルがありません」 | `/deploy 設定ファイルを作って` と入力する |
| 「設定ファイルに、項目 … がありません」 | `/deploy 足りない項目を足して` と入力する |
| 「設定に直すところが N 件あります」 | 設定ファイルを直す |
| 機器でプログラムを実行できない | `file_mode` に `"755"` などを書く |
| 「思わぬエラーで止まりました」 | ログを見る |
| 「大きさは確かめていません」 | エラーではない（FTP サーバーが `SIZE` に未対応） |

## スクリプトを直接実行する

作業フォルダをカレントディレクトリにして、次のように実行します。

```
# Windows（PowerShell）
py -3 <このフォルダ>/scripts/deploy.py <サブコマンド>
# Linux（bash）
python3 <このフォルダ>/scripts/deploy.py <サブコマンド>
```

`<このフォルダ>` は、このフォルダのパスです（例：`.github/skills/deploy`）。`py` がないときは `python` を使います。

`<サブコマンド>` は次のどれかです。

- `run`：機器に送る（サブコマンドを省略したときも `run`）
- `config-path`：設定ファイルの場所を表示する（なければ作る。足りない項目を追加する）
- `check`：設定を確認する（ファイルを作らず、設定ファイルも変更しない）

次のオプションを付けられます。

- `--workdir <フォルダ>`：作業フォルダを指定する（既定はカレントディレクトリ）
- `--config <ファイル>`：別の場所の設定ファイルを使う

## テストを実行する

このフォルダで、次を実行します。

```
# Windows（PowerShell）
py -3 -m unittest discover -s tests
# Linux（bash）
python3 -m unittest discover -s tests
```

最後に `OK` と出れば成功です。実機は要りません。

FTP サーバーを起動するテストには `pyftpdlib` が要ります。なければ、そのテストはスキップされます。
`--target` で別の場所にインストールしたときは、その場所を環境変数 `DEPLOY_TEST_PYLIB` に設定します（複数なら Windows では `;`、Linux では `:` で区切る）。

```
# Windows（PowerShell）
py -3 -m pip install --target "$env:TEMP\pylib" pyftpdlib
$env:DEPLOY_TEST_PYLIB = "$env:TEMP\pylib"
# Linux（bash）
python3 -m pip install --target /tmp/pylib pyftpdlib
export DEPLOY_TEST_PYLIB=/tmp/pylib
```

`__pycache__` を残さないときは、`-B` を付けます（例：`py -3 -B -m unittest discover -s tests`）。
