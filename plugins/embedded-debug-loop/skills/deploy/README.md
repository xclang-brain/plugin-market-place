# deploy：機器にファイルを送るスキル

PC にあるファイルを、FTP で組み込み機器に送る GitHub Copilot CLI のスキルです。
動かすのに必要なファイルは、すべてこのフォルダに入っています。
設定ファイルに送り先と送るファイルを書いて、`/deploy 機器に送って` と入力します。

## できること

- 設定ファイルに書いたファイルを、機器の送り先のフォルダに送る。
- 送った後に、機器のファイルのサイズが PC と同じかを確認する。
- 送った後に、ファイルの権限を変更する（例：755 にして、実行できるようにする）。
- 機器でファイルが壊れていないかを確認できるように、サム値（チェックサム）のファイルを作り、一緒に送る。

権限の変更は、設定ファイルに `file_mode` を書いたときだけ行います。
サム値のファイルは、`checksum` を `crc32` か `sum32` にしたときだけ作ります。

## 必要なもの

- PC の OS：Linux
- Python 3.8 以上（標準ライブラリだけで動きます。追加のインストールは不要です）
- GitHub Copilot CLI
- 機器の準備
  - 機器で FTP サーバーが動いていること。
  - PC から、機器の IP アドレスかホスト名に接続できること。
  - FTP のユーザー名とパスワード。そのユーザーが、送り先のフォルダに書き込めること。
  - 権限を変更するときは、FTP サーバーが `SITE CHMOD` コマンドに対応していること。
  - サイズを確認するときは、FTP サーバーが `SIZE` コマンドに対応していること。
    対応していないときは、サイズを確認せずに送ります。

## インストールする

1. このフォルダを、次のどちらかにコピーします。
   - 1つの作業フォルダ（Copilot CLI を起動するフォルダ）だけで使う：`<作業フォルダ>/.github/skills/deploy/`
   - 自分のすべての作業フォルダで使う：`~/.copilot/skills/deploy/`
2. Copilot CLI を起動したままコピーしたときは、`/skills reload` を実行します。
3. Copilot CLI で `/deploy` と入力します。このスキルが候補に出れば、インストールは完了です。

別の名前でコピーするときは、フォルダの名前と `SKILL.md` の `name:` を、その名前にそろえます。
呼び出すときは、`/<その名前>` と入力します。

## 使い方

`/deploy` の後に、してほしいことを書きます。

| したいこと | 入力の例 |
| --- | --- |
| ファイルを機器に送る | `/deploy 機器に送って` |
| 設定ファイルの場所を知る・設定ファイルを用意する | `/deploy 設定ファイルはどこ？`<br>`/deploy 設定ファイルを用意して` |
| 設定を確認する。機器に FTP でログインできるかも試す（ファイルは送らない） | `/deploy 設定を確かめて` |

プラグインに入れて配られているときは、`/<プラグインの名前>:<スキル名>` でも呼べます。

### はじめて使うとき

1. `/deploy 設定ファイルを用意して` と入力します。
   このフォルダの `config-template.yaml`（ひな形）から設定ファイルが作られ、その場所が表示されます。
2. 設定ファイルに、必須の `host`・`files`・`remote_dir` を書きます。
   ログインに使う `user` と `password`（または `password_env`）も、必要に応じて書きます。
   項目の意味は、下の「[項目](#項目)」を見てください。
3. `/deploy 設定を確かめて` と入力します。「設定に問題はありません」と表示されれば、準備は完了です。
4. `/deploy 機器に送って` と入力します。送ったファイルと送り先の表が表示されれば、完了です。

### スクリプトを直接実行する

Copilot CLI を使わずに、スクリプトを直接実行することもできます。
作業フォルダで、次のコマンドを実行します。
`~/.copilot/skills/` に置いたときは、パスを `~/.copilot/skills/deploy/scripts/deploy.py` に変えます。

```sh
python3 .github/skills/deploy/scripts/deploy.py config-path   # 設定ファイルの場所を表示する（なければ作る）
python3 .github/skills/deploy/scripts/deploy.py check         # 設定を確認する
python3 .github/skills/deploy/scripts/deploy.py run           # 機器に送る（run は省略できる）
```

次のオプションを、コマンドの後に付けられます。

- 作業フォルダを指定する：`--workdir <フォルダ>`
- 別の設定ファイルを使う：`--config <ファイル>`

例：

```sh
python3 .github/skills/deploy/scripts/deploy.py check --workdir <フォルダ>
```

## 設定ファイル

### 場所

```
<作業フォルダ>/.deploy/config.yaml
```

- 作業フォルダは、コマンドを実行したフォルダ（カレントディレクトリ）です。ふつうは、Copilot CLI を実行しているフォルダです。
- 設定ファイルは、親フォルダまでさかのぼって探しません。別のフォルダで実行すると、そのフォルダに新しい設定ファイルが作られます。
- 作業フォルダは、`--workdir` で変更できます。
- `.deploy` というフォルダ名は、スキルのフォルダ名（`deploy`）の前に `.` を付けたものです。
  別の名前でコピーしたときは、`.<その名前>` になります。
- このスキルをどこに置いても、設定ファイルとログは作業フォルダの中に作られます。

### 自動で作成・更新されるもの

- 設定ファイルがないときは、ひな形（このフォルダの `config-template.yaml`）から作られます。
- `.deploy` フォルダには、`.gitignore`（中身は `*`）も作られます。
  これで、パスワードを書いた設定ファイルやログが、Git にコミットされません。
- スキルを新しいバージョンに更新すると、ひな形に項目が増えることがあります。
  そのときは、次にスクリプトを実行したときに、足りない項目が設定ファイルの最後に追加されます。
  追加された項目の値は、ひな形のままです。すでにある部分は変わりません。

### 書き方

設定ファイルは、直接編集してかまいません。
各項目の意味は、項目のすぐ上のコメントにも書いてあります。
書き方の決まりは、次のとおりです。

- 1行に「名前: 値」を1つ書きます。
- インデントで階層を作る書き方（入れ子）は使えません。
- リストは `["a", "b"]` の形で書きます。

### 項目

| 項目 | 意味 | ひな形の値 | 例 |
| --- | --- | --- | --- |
| `host` | 機器の IP アドレスかホスト名（必須） | 空 | `"192.168.1.50"` |
| `port` | FTP サーバーのポート番号 | `21` | `21` |
| `user` | FTP でログインするユーザー名。空なら anonymous（匿名）でログインする | `"root"` | `"root"` |
| `password` | FTP でログインするパスワード | 空 | ― |
| `password_env` | パスワードを入れた環境変数の名前（「[パスワードを環境変数で渡す](#パスワードを環境変数で渡す)」を参照） | 空 | `"DEVICE_FTP_PASSWORD"` |
| `passive` | `true` なら、パッシブモード（データ転送用の接続を PC から開始する方式）を使う。送る途中で止まるときは `false` を試す | `true` | `false` |
| `files` | 送るファイル（必須）。作業フォルダからの相対パスか、絶対パスで書く | `[]` | `["my_app"]`<br>`["build/my_app", "conf/my_app.conf"]` |
| `remote_dir` | 機器の送り先のフォルダ（必須）。なければ作る | 空 | `"/opt/myapp"` |
| `file_mode` | 送った後に設定する権限（8進数）。空なら設定しない | 空 | `"755"` |
| `checksum` | サム値の種類。`none`（作らない）・`crc32`・`sum32` | `"none"` | `"crc32"` |
| `checksum_suffix` | サム値のファイルの名前の末尾に付ける文字 | `".sum"` | `".sum"` |
| `timeout_seconds` | 機器の応答を待つ最長の秒数 | `30` | `60` |

#### 権限（`file_mode`）

FTP で送ったファイルは、ふつうは実行できない権限になります。
機器でプログラムを実行するときは、`755` などを書きます。

#### サム値（`checksum`）

- `crc32` は CRC-32 です。`sum32` は、全バイトを足した値の下位32ビットです。
- サム値のファイルの中身は、16進数8桁（小文字）と改行です。例：`cbf43926`
- サム値のファイルは、送るファイルと一緒に、機器の送り先のフォルダ（`remote_dir`）に送ります。
  たとえば `checksum_suffix` が `.sum` なら、`my_app` のサム値のファイルは `my_app.sum` です。

### パスワードを環境変数で渡す

パスワードを設定ファイルに書きたくないときは、環境変数で渡せます。

1. 設定ファイルの `password_env` に、環境変数の名前を書きます。

   ```yaml
   password: ""
   password_env: "DEVICE_FTP_PASSWORD"
   ```

2. Copilot CLI を起動する前に、その環境変数を設定します。

   ```sh
   export DEVICE_FTP_PASSWORD='機器のパスワード'
   copilot
   ```

`password_env` を書いたときは、使うパスワードが次のとおりに決まります。

- その環境変数があれば、環境変数の値を使います。`password` より優先します。
- 環境変数がなく、`password` に値があれば、`password` を使います。
- どちらもなければ、設定の問題として知らせます。

パスワードは、画面にもログにも出しません。
ただし、設定ファイルの書き方の誤り（閉じていない `"` など）は例外です。
エラーメッセージに、その行の内容がそのまま表示されます。
`password` の行に誤りがあると、パスワードも表示されます。

## 結果とログ

### 結果

Copilot CLI から使ったときは、Copilot が結果を文章で説明します。
送れたときは、送ったファイル・機器の送り先・権限・サム値を、短い表にして示します。

スクリプトを直接実行したときは、標準出力に結果の JSON が1つだけ出ます。
途中経過は、標準エラー出力に出ます。
途中経過の各行の先頭は `[deploy]` です（別の名前でコピーしたときは、その名前）。

`run` と `check` の結果の JSON には、主に次の項目があります。

| 項目 | 内容 |
| --- | --- |
| `skill` | このフォルダの名前（別の名前でコピーしたときは、その名前） |
| `ok` | 成功したら `true` |
| `message` | 結果の説明。失敗したときは、原因と、確認する点も入る |
| `files` | 送ったファイルごとの結果（下の表） |
| `remote_dir` | 機器の送り先のフォルダ |
| `created_dirs` | 機器に新しく作ったフォルダ |
| `notes` | エラーではない注意（例：機器の FTP サーバーが `SIZE` コマンドに対応していない） |
| `problems` | 設定の問題（`check` では、ログインできない理由も入る） |
| `summary` | `check` のときの設定のまとめ。パスワードは `＊＊＊` でマスクする |
| `config` | 設定ファイルの場所 |
| `added` | 設定ファイルに追加した項目 |
| `log` | ログファイルの場所 |

`files` の中の、ファイルごとの項目です。

| 項目 | 内容 |
| --- | --- |
| `local` | PC のファイル |
| `remote` | 機器のファイル |
| `size` | PC のファイルのサイズ（バイト） |
| `remote_size` | 機器のファイルのサイズ（バイト） |
| `mode` | 設定した権限。設定していなければ null |
| `checksum` | サム値 |
| `checksum_file` | 機器のサム値のファイル |
| `checksum_local_file` | PC に残したサム値のファイル |

`config-path` の結果には、次の項目が出ます。

- `config`：設定ファイルの場所
- `created`：今回作ったときは `true`
- `missing`：必須なのに空の項目
- `added`：設定ファイルに追加した項目
- `message`：追加した項目の説明（項目を追加したときだけ）
- `problems`：設定ファイルを読めない理由（読めないときだけ）

終了コードは、次のとおりです。

| 終了コード | 意味 |
| --- | --- |
| 0 | 成功した |
| 1 | 送れなかった。予期しないエラーで止まったときも 1 |
| 2 | 設定かコマンドの書き方に問題がある。`check` でログインできないときも 2 |

`config-path` は、設定ファイルを読めないときも 0 を返します（理由は `problems` に出ます）。

### ログ

`run` と `check` は、実行するたびにログファイルを1つ作ります。

```
<作業フォルダ>/.deploy/logs/deploy-YYYYmmdd-HHMMSS.log
```

- 別の名前でコピーしたときは、`.deploy` も、ファイル名の先頭の `deploy` も、その名前になります。
- 同じ秒に2回以上実行したときは、ファイル名の後ろに `-2` などが付きます。
- 各行の先頭に、日時があります。
- 機器の FTP サーバーの応答や、失敗したときの詳細も書きます。
- サム値のファイルは、PC にも残します。
  場所は、ログファイルの名前の `.log` を `-checksums` に替えたフォルダです（例：`.deploy/logs/deploy-YYYYmmdd-HHMMSS-checksums/`）。
- 古いログは、自動では削除されません。不要なら削除してかまいません。

## うまくいかないとき

まず、表示されたメッセージを見てください。原因と、確認する点が書いてあります。
スクリプトを直接実行したときは、結果の JSON の `message` に出ます。
詳しい内容は、ログファイルにあります。

| 症状・メッセージ | 対処 |
| --- | --- |
| `/deploy` が出てこない | フォルダの置き場所を確認する。フォルダの名前と `SKILL.md` の `name:` が同じかを確認する。そのあと `/skills reload` を実行する |
| 「FTP でつながりません（接続が拒否されました）」 | 機器の電源が入っているか、機器の FTP サーバーが動いているかを確認する |
| 「FTP でつながりません（N 秒待っても応答がありません）」 | 機器の電源とケーブルを確認する。`host` の IP アドレスが正しいかを確認する |
| 「FTP でつながりません（機器までの経路がありません）」 | ケーブル、`host` の IP アドレス、PC のネットワーク設定を確認する |
| 「ホスト名 … が見つかりません」 | `host` のホスト名が正しいかを確認する |
| 「ログインできません（ユーザー名かパスワードが違います）」 | `user`・`password`・`password_env` を確認する |
| 「機器が断りました」 | `user` に書き込み権限があるか、`remote_dir` が正しいかを確認する |
| 「機器の空き容量が足りません」 | 機器の空き容量を確認する |
| 「権限を … に変えられません」 | FTP サーバーが `SITE CHMOD` コマンドに対応しているかを確認する |
| 送る途中で止まる・「ファイルを送るための接続が拒否されました」 | `passive` を切り替えて試す（`true` ⇔ `false`） |
| 「大きさ … が、PC のファイル … と合いません」 | 機器の空き容量とケーブルを確認して、もう一度送る |
| 「送るファイル … が見つかりません」 | ファイルができているかを確認する。`files` のパスが正しいかを確認する |
| 「設定に直すところが N 件あります」 | 設定ファイルを直す。各項目の意味は、項目のすぐ上のコメントに書いてある |
| 機器でプログラムを実行できない | `file_mode` が空でないかを確認する（`755` などを書く） |
| 「思わぬエラーで止まりました」 | ログファイルで詳しい内容を確認する |

「大きさは確かめていません」と表示されても、エラーではありません。
機器の FTP サーバーが `SIZE` コマンドに対応していないので、サイズを確認しなかったという意味です。

## テストを実行する

このフォルダで、次のコマンドを実行します。

```sh
python3 -m unittest discover -s tests
```

最後に `OK` と表示されれば、テストは通っています。
テストは、一時フォルダの中で動きます。実機は不要です。

FTP サーバーを起動するテストには、`pyftpdlib` が必要です。スキルを使うだけなら不要です。
`pyftpdlib` を読み込めないときは、そのテストだけがスキップされます（`skipped` と表示されます）。

`pyftpdlib` を使って、すべてのテストを実行する手順です。

1. このフォルダの外（例：`/tmp/pylib`）に、`pyftpdlib` をインストールします。

   ```sh
   python3 -m pip install --target /tmp/pylib pyftpdlib
   ```

2. インストールしたフォルダを環境変数 `DEPLOY_TEST_PYLIB` で指定して、テストを実行します。

   ```sh
   DEPLOY_TEST_PYLIB=/tmp/pylib python3 -m unittest discover -s tests
   ```

`DEPLOY_TEST_PYLIB` には、`:` で区切って、複数のフォルダを指定できます。

テストを実行すると、`tests/__pycache__` が残ります。不要なら削除してかまいません。
残したくないときは、`python3 -B -m unittest discover -s tests` で実行します。
