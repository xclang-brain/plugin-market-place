# 機器にファイルを送る

送り先（機器のアドレス・ユーザー・フォルダ）と送るファイルは、作業フォルダの `.<このスキルのフォルダの名前>/config.yaml` に書きます。
各項目の意味は、ファイルの中のコメントにあります。

## コマンド

作業フォルダで実行します。`<python>` は、Windows では `py -3`（なければ `python`）、ほかでは `python3` です。

| すること | コマンド |
| --- | --- |
| 機器に送る | `<python> <このスキルのフォルダ>/scripts/deploy.py run` |
| 設定を確かめる（FTP でログインできるかも試す。送らず、ファイルも作らない） | `<python> <このスキルのフォルダ>/scripts/deploy.py check` |
| 設定ファイルを作る・場所を返す・足りない項目を足す | `<python> <このスキルのフォルダ>/scripts/deploy.py config-path` |

- 作業フォルダが今のフォルダと違うときは、`--workdir <フォルダ>` を付けます。
- 設定ファイルを作ったり書き換えたりするのは、頼まれたときだけです。
- つながらないときは、同じコマンドを繰り返しません。`message` にある原因と確かめることを伝えて終えます。

## 結果

標準出力に JSON を1つ返します。
`message` は結果の要約、`problems` は設定の問題、`notes` は注意、`log` はログの場所です。

- 送れたら、`files` のファイルごとに、機器の送り先・権限・サム値を伝えます。
  `mode` が null のファイルには権限を付けていません。そのときの権限は、機器の FTP サーバーが決めます。
- 設定を見せるときは、パスワードを伏せます（`summary` では伏せてあります）。
