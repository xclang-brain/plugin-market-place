# deploy：機器にファイルを送る

## 何をするスキルか

PC にあるファイルを、FTP で組み込み機器に送ります。
送った後に、ファイルの権限を変えられます（例：755）。
サム値のファイルを作って、一緒に送ることもできます。
サム値は、ファイルが壊れていないかを機器で確かめる値です。

送り先や送るファイルは、設定ファイルに書きます。
設定ファイルは、作業フォルダの `.embedded-debug-loop/deploy.yaml` です。
作業フォルダは、ふつうは今のフォルダです。
`.embedded-debug-loop` フォルダを新しく作るときは、中に `.gitignore`（中身は `*`）も作ります。設定やログを git に入れないためです。

## 頼まれ方と、すること

このスキルのフォルダを `<このスキルのフォルダ>` と書きます。
コマンドは、作業フォルダで実行します。

### (a) 「機器に送って」「デプロイして」と頼まれたとき

```
python3 <このスキルのフォルダ>/scripts/deploy.py run
```

設定ファイルのとおりに、ファイルを機器に送ります。

### (b) 設定ファイルの場所を聞かれたとき・用意するよう頼まれたとき

```
python3 <このスキルのフォルダ>/scripts/deploy.py config-path
```

設定ファイルの場所を出します。
なければ、ひな形から作ります（`created` が true）。
`missing` には、必須なのにまだ空の項目が並びます。

### (c) 設定を確かめるよう頼まれたとき

```
python3 <このスキルのフォルダ>/scripts/deploy.py check
```

設定の中身を確かめます。
機器に FTP でログインできるかも試します。
ファイルは送りません。

### 付けられるもの

- 作業フォルダが今のフォルダと違うとき：`--workdir <フォルダ>`
- 設定ファイルが別の場所にあるとき：`--config <ファイル>`

## 結果の伝え方

コマンドは、結果を JSON で1つだけ出します。

- `message` を、そのまま利用者に伝えます。
- `notes` があれば、それも伝えます。
- 記録のファイルの場所（`log`）を伝えます。

### 送れたとき

見分け方：`ok` が true です。

- `files` の中身を短い表で伝えます。
  送ったファイル、機器の送り先、権限、サム値です。

### 設定を確かめたとき（check）

- `summary` の主な設定を、短い表で伝えます。
- パスワードは、空なら「（空）」、空でなければ「＊＊＊」と書きます。

### 設定に問題があるとき

見分け方：`problems` に文が入っています。

- 問題を1つずつ並べて伝えます。
- 設定ファイルの場所（`config`）を伝えます。
- 設定ファイルは、利用者が直接書き直してよいと伝えます。
- 各項目の意味は、項目のすぐ上のコメントに書いてあると伝えます。

### 送れなかったとき

見分け方：`ok` が false で、`problems` がありません。

- `message` に、原因と確かめることが書いてあります。
- くわしくは、記録のファイルにあると伝えます。

## 守ること

- 頼まれないかぎり、設定ファイルを書き換えません。
- つながらないときに、何度もやり直しません。
  やり直さずに、`message` を伝えて終えます。どうするかは、頼んだ側か利用者が決めます。
- パスワードを画面に出しません。JSON の中でも伏せてあります。
  設定ファイルの中身を見せるときも、パスワードは伏せます。
- スクリプトの終了コードは、利用者に伝えません。
