# log-capture：シリアルコンソールの記録

GitHub Copilot CLI で使うスキルです。
このフォルダだけで動きます。

## 何をするスキルか

- PC から、機器のシリアルコンソールにつなぎます。
- 機器がログインを求めたら、設定のユーザー名とパスワードでログインします。
- 設定したコマンドを、機器のシェルで順に実行します。
- 各コマンドの出力と、機器での終了コード（コマンドの終わり方を表す数）を返します。
- 機器から届いた文字は、すべてログのファイルに残します。
- コマンドを実行せず、決めた秒数だけ出力を記録することもできます。

## 必要なもの

- Linux の PC。
- Python 3.8 以上。標準の部品だけで動きます。pyserial などは要りません。
- GitHub Copilot CLI。
- 機器と PC をつなぐシリアルのケーブル（USB シリアル変換器など）。
  PC では `/dev/ttyUSB0` や `/dev/ttyACM0` のような名前で見えます。
- シリアルポートを開く権限。
  多くの Linux では、今のユーザーを `dialout` グループに入れます。
  `sudo usermod -aG dialout $USER` を実行し、PC にログインし直します。
- 機器の側：シリアルコンソールでシェル（sh や bash）が使えること。
  終了コードを読むのに、シェルの `$?` を使います。

## 置き方

このフォルダを、次のどちらかに写します。

- 作業フォルダの `.github/skills/log-capture/`（その作業フォルダだけで使う）
- `~/.copilot/skills/log-capture/`（どの作業フォルダでも使う）

例：

```
mkdir -p .github/skills
cp -r log-capture .github/skills/log-capture
```

Copilot CLI を起動したまま写したときは、Copilot CLI で `/skills reload` を実行します。

名前を変えて写すこともできます。
そのときは、フォルダの名前と、`SKILL.md` の先頭にある `name:` を、同じ名前に変えます。
Copilot CLI は、`name:` の名前でスキルを呼ぶためです。
設定とログのフォルダの名前も、新しい名前に合わせて変わります（下の「設定ファイル」を見てください）。

## 呼び方

Copilot CLI で、`/log-capture` の後に、頼みたいことを書きます。

頼めることは、作業・設定ファイルの場所・設定の確認です。

| 頼むこと | 例 |
| --- | --- |
| 作業（コマンドを実行して出力を記録する） | `/log-capture 機器で /opt/myapp/my_app を動かして、出力を見せて` |
| 作業（出力を記録するだけ） | `/log-capture 機器の出力を 30 秒記録して` |
| 設定ファイルの場所を聞く・用意する | `/log-capture 設定ファイルはどこ？` |
| 設定の確認（機器につながるか、ログインできるか） | `/log-capture 設定を確かめて` |

- 作業のとき、ふつうは設定の `commands` を実行します。
  頼んだ文にコマンドを書けば、今回だけそのコマンドを実行します。
- 設定の確認では、機器のシェルでコマンドは実行しません。
- プラグインに入れて配られているときは、`/<プラグインの名前>:<スキル名>` でも呼べます。

スクリプトを直接動かすこともできます。作業フォルダで、次のように実行します。

```
python3 .github/skills/log-capture/scripts/capture.py run
python3 .github/skills/log-capture/scripts/capture.py run --command "/opt/myapp/my_app"
python3 .github/skills/log-capture/scripts/capture.py run --listen-only 30
python3 .github/skills/log-capture/scripts/capture.py config-path
python3 .github/skills/log-capture/scripts/capture.py check
```

- `--command` は、何回でも書けます。設定の `commands` の代わりに実行します。
- `--listen-only 秒数` は、コマンドを実行せず、その秒数だけ記録します。
- `--workdir フォルダ` で、作業フォルダを変えられます（ふつうは今のフォルダ）。
- `--config ファイル` で、別の場所の設定ファイルを使えます。

## 設定ファイル

### 置き場所

- 作業フォルダの `.log-capture/config.yaml` です。
  作業フォルダは、ふつうは Copilot CLI で作業している今のフォルダです。
- 名前を変えて写したときは、`.<新しい名前>/config.yaml` です。
- 初めて使うときに、このフォルダの `config-template.yaml`（ひな形）を写して作ります。
- 同じフォルダに `.gitignore`（中身は `*`）も作ります。設定やログを git に入れないためです。
- スキルを新しくして、ひな形に項目が増えたときは、足りない項目をファイルの最後に足します。
  値はひな形のままです。ほかの所は変えません。

各項目の意味は、ファイルの中でも、項目のすぐ上のコメントに書いてあります。
ファイルは、自分で直接書き換えてかまいません。

### 項目

| 項目 | 意味 | 例 |
| --- | --- | --- |
| `port` | 機器につながるシリアルポート（必須） | `"/dev/ttyUSB0"` |
| `baud` | シリアルの速さ（ボーレート）。機器と同じ値にする | `115200` |
| `login_user` | ログインするユーザー名。空ならログインしない | `"root"` |
| `login_password` | ログインのパスワード。なければ空のまま | `""` |
| `login_password_env` | パスワードを入れた環境変数の名前 | `"DEVICE_PASSWORD"` |
| `prompt` | シェルのプロンプトの終わりに合う正規表現。空なら `[#$] $` | `"[#$] $"` |
| `commands` | 機器のシェルで、並べた順に実行するコマンド | `["/opt/myapp/my_app"]` |
| `command_timeout_seconds` | 1つのコマンドを待つ最長の秒数。過ぎたら Ctrl-C を送って止める | `30` |
| `listen_seconds` | コマンドの後に、さらに出力を記録する秒数。0 なら記録しない | `10` |
| `logout` | 終わったらログアウトする（`exit` を送る）か。自分でログインしたときだけ送る | `true` |

- `commands` が空なら、コマンドは実行せず、`listen_seconds` の秒数だけ記録します。
  そのときは `listen_seconds` を 1 以上にします。
- 書き方は、1行に「項目: 値」です。文字は `"…"` で囲みます。
  `\` を使う正規表現は、`'…'`（シングルクォート）で囲みます。
- `[#$] $` は、「# 」か「$ 」で終わるプロンプトに合います。

### パスワードを環境変数で渡す

パスワードをファイルに書きたくないときは、環境変数を使います。

1. 設定ファイルに、環境変数の名前を書きます。

   ```
   login_password: ""
   login_password_env: "DEVICE_PASSWORD"
   ```

2. Copilot CLI を起動する前に、その環境変数にパスワードを入れます。

   ```
   export DEVICE_PASSWORD='機器のパスワード'
   copilot
   ```

- 環境変数があれば、`login_password` より優先します。
- 環境変数がなく、`login_password` も空なら、設定の問題として止まります。
- パスワードは、結果にもログにも出しません。設定の要点では「＊＊＊」と表します。

## 結果とログの見方

### 結果

Copilot CLI が、結果を言葉で伝えます。

- 何が起きたか（失敗のときは、考えられる原因と、確かめること）。
- コマンドごとの出力。長いときは最後の 60 行だけです。全部はログにあります。
- 機器での終了コード。0 なら、コマンドはふつうに終わっています。
  0 以外なら、機器でコマンドがうまく動いていないかもしれません。
- 時間内に終わらず、Ctrl-C で止めたコマンド。それまでの出力は残ります。
- 実行しなかったコマンド（途中で止まったとき）。
- ログのファイルの場所。

スクリプトを直接動かしたときは、標準出力に JSON を1つ出します。
主な項目は次のとおりです。

| 項目 | 意味 |
| --- | --- |
| `ok` | うまくいったか |
| `message` | 何が起きたかの文 |
| `commands` | コマンドごとの `command`（コマンド）、`output`（出力）、`exit_code`（機器での終了コード。分からなければ null）、`timed_out`（時間切れで止めたか）、`truncated`（出力を最後の 60 行に切ったか） |
| `listen` | コマンドの後や、記録だけのときに記録した出力 |
| `not_run` | 実行しなかったコマンド |
| `problems` | 設定の問題（直すところ） |
| `summary` | 設定の要点（check のとき。パスワードは伏せる） |
| `config` | 設定ファイルの場所 |
| `log` | ログのファイルの場所 |
| `added` | 設定ファイルに足した項目 |

スクリプトの終わりのコードは、0 が成功、1 が作業の失敗、2 が設定の問題です。
check は、問題があれば 2 です。

### ログ

- 場所は、作業フォルダの `.log-capture/logs/` です。
- 名前は `log-capture-年月日-時分秒.log` です（例：`log-capture-20261105-143000.log`）。
  名前を変えて写したときは、頭が新しい名前になります。
- `#` で始まる最初の行に、シリアルポートと、実行するコマンドを書きます。
- その後に、機器から届いた文字を、そのまま書きます。色の制御文字も残ります。
- 各コマンドの出力の後に、「（終了コード：0）」のような行を書きます。
  読めなかったときは「（終了コード：読めませんでした）」です。
- 最後に、結果の文を書きます。

## うまくいかないとき

| 出てきた文 | 確かめること |
| --- | --- |
| シリアルポート … が見つかりません | ケーブルがつながっているか。`port` が正しいか。文の最後に、PC で見つかったポートが出ます |
| シリアルポート … を開く権限がありません | 今のユーザーを `dialout` グループに入れ、PC にログインし直す |
| シリアルポート … は、ほかのプログラムが使っています | minicom や screen などの端末ソフトを閉じる |
| … はシリアルポートではありません | `port` が正しいか |
| シリアルポート … から応答がありません | ケーブルと、機器の電源 |
| 文字は届きますが、ログインの求めも、シェルのプロンプトも出ません | `baud` が機器と同じか。`prompt` が機器のプロンプトに合うか。機器で前のプログラムが動いたままでないか |
| ログインできませんでした | `login_user` と、パスワード（`login_password` か環境変数） |
| ログインの後、シェルのプロンプトが出ません | `prompt` が機器のプロンプトに合うか |
| 環境変数 … がありません | Copilot CLI を起動する前に、その環境変数にパスワードを入れたか |
| … 秒で終わらなかったため、Ctrl-C で止めました | 長く動くプログラムなら、`command_timeout_seconds` を見たい長さの秒数にする |
| Ctrl-C を送ってもプロンプトが戻りませんでした | 機器のコンソールでプログラムを止めるか、機器の電源を入れ直す |
| やりとりが、途中で切れました | USB ケーブルが抜けていないか |
| 設定ファイルの … 行目が読めません | その行の書き方。文字を `"…"` で囲んでいるか |
| 実行するコマンド（commands）が空で、記録する秒数（listen_seconds）も 0 です | `commands` を書くか、`listen_seconds` を 1 以上にする |
| baud（シリアルの速さ）の … は使えません | 9600、38400、57600、115200 などの、決まった速さを書く |
| 終了コードが「読めませんでした」になる | 機器のシェルで `$?` が使えるか（fish などでは使えません） |

## 試験の動かし方

このフォルダで、次のコマンドを実行します。

```
python3 -m unittest discover -s tests
```

- 機器は要りません。機器のまねを、PC の中に作って試します。
- Linux で動かします。すべて終わるまで、2 分ほどかかります。
