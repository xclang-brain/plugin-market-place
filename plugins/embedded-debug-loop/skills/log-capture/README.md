# log-capture：シリアルコンソールの記録

機器のシリアルコンソールで、コマンドを実行して出力を記録する GitHub Copilot CLI のスキルです。このフォルダだけで動きます。

## できること

- 機器がログインを求めたらログインし、設定したコマンドを機器のシェルで順に実行する。
- コマンドごとに、出力と終了コードを返す。機器から届いた文字はログファイルに保存する。
- コマンドを実行せず、指定した秒数だけ出力を記録する。

## 必要なもの

- Windows の PC（Linux でも動きます）
- Python 3.8 以上。追加のインストールは要りません。シリアルポートを扱う pyserial 3.5 を同梱しています（BSD ライセンス。[LICENSE.txt](scripts/vendor/serial/LICENSE.txt)）。
- GitHub Copilot CLI
- 機器と PC を接続するシリアルケーブル（USB シリアル変換器など）
- 機器のシリアルコンソールで、`$?` が使えるシェル（sh や bash）
- Linux では、シリアルポートを開く権限。多くの場合、今のユーザーを `dialout` グループに追加し（`sudo usermod -aG dialout $USER`）、PC にログインし直します。

Windows では、GitHub Actions でテストを確認しています。Windows の Copilot CLI との組み合わせは、まだ確認していません。

## インストールする

1. このフォルダを、次のどちらかにコピーします。
   - 1つの作業フォルダ（ふつうは、Copilot CLI を起動したフォルダ）で使う：`<作業フォルダ>/.github/skills/log-capture/`
   - すべての作業フォルダで使う：`$env:USERPROFILE\.copilot\skills\log-capture\`（Linux では `~/.copilot/skills/log-capture/`）
2. Copilot CLI を起動したままコピーしたときは、`/skills reload` を実行します。
3. `/skills list` に `log-capture` が出れば完了です。

フォルダの名前を変えてコピーするときは、`SKILL.md` の `name:` も、フォルダと同じ名前に変えます。
呼び出しは `/<新しい名前>`、設定とログのフォルダは `.<新しい名前>/`、ログファイルの名前の先頭は `<新しい名前>-` になります。

## 使い方

1. `/log-capture 設定ファイルを作って` と入力します。設定ファイルがなければ作られ、場所が表示されます。
2. 設定ファイルの `port` に、シリアルポートを書きます。
   Windows では `COM3` の形です（番号はデバイスマネージャーで確認できます）。Linux では `/dev/ttyUSB0` の形です。
   ほかの項目も機器に合わせます。
3. `/log-capture 設定を確認して` と入力します（機器のシェルでコマンドは実行しません）。
   「… でログインできました」と出れば、設定は完了です（ログインが要らない機器では「… シェルのプロンプトを確かめました」）。
   「ただし、」の後に注意が出たら、その内容を確認します。
4. `/log-capture 機器で /opt/myapp/my_app を動かして、出力を見せて` のように依頼します。
   コマンドの出力、終了コード、ログファイルの場所が表示されます。

- 依頼の文にコマンドを書くと、今回だけ、設定の `commands` の代わりにそのコマンドを実行します。
- 記録だけするときは、`/log-capture 機器の出力を 30 秒記録して` のように依頼します。
- プラグインに入れて配られているときは、`/<プラグインの名前>:<スキル名>` でも呼べます。

## 設定ファイル

場所は `<作業フォルダ>/.log-capture/config.yaml` です。直接書き換えてかまいません。
各項目の説明は、ファイルの中のコメントにもあります。

- 設定は作業フォルダごとに別です。別のフォルダ（サブフォルダを含む）で使うと、そこに新しく作られます。いつも同じフォルダで使います。
- 設定ファイルがなければ、スキルのフォルダのひな形 `config-template.yaml` をコピーして作ります。
- `.log-capture/` に `.gitignore`（中身は `*`）がなければ作り、設定とログを git の管理対象から外します。
- check は、これらのファイルもログも作りません。
- スキルを更新してひな形の項目が増えたときは、足りない項目をひな形の値でファイルの最後に追加します。

### 項目

| 項目 | 意味 | 例 |
| --- | --- | --- |
| `port` | 機器に接続するシリアルポート（必須） | `"COM3"` |
| `baud` | シリアルの速さ（ボーレート）。機器と同じ値にする | `115200` |
| `login_user` | ログインするユーザー名。空ならログインしない | `"root"` |
| `login_password` | ログインのパスワード（なければ空） | `""` |
| `login_password_env` | パスワードを設定した環境変数の名前 | `"DEVICE_PASSWORD"` |
| `prompt` | シェルのプロンプトの終わりに一致する正規表現。空なら `[#$] $`（「# 」か「$ 」で終わる） | `"[#$] $"` |
| `commands` | 機器のシェルで順に実行するコマンド。空なら実行せず、`listen_seconds` 秒だけ記録する | `["/opt/myapp/my_app"]` |
| `command_timeout_seconds` | 1つのコマンドを待つ最長の秒数。過ぎたら Ctrl-C で止める | `30` |
| `listen_seconds` | コマンドの後に記録を続ける秒数（0 なら記録しない）。`commands` が空なら 1 以上にする | `10` |
| `logout` | 終わったら `exit` でログアウトするか（このスキルがログインしたときだけ） | `true` |

1行に「項目: 値」の形で書きます。文字列は `"…"`、`\` を使う正規表現は `'…'` で囲みます。

### パスワードを環境変数で渡す

1. 設定ファイルの `login_password_env` に、環境変数の名前（例：`"DEVICE_PASSWORD"`）を書きます。`login_password` は空にします。
2. Copilot CLI を起動する前に、同じ端末でその環境変数を設定します。
   - Windows（PowerShell）：`$env:DEVICE_PASSWORD = '機器のパスワード'`
   - Linux（bash）：`export DEVICE_PASSWORD='機器のパスワード'`

環境変数は `login_password` より優先します。
環境変数がなく、`login_password` も空なら、機器に接続せずに止まります（`login_user` が空なら止まりません）。
パスワードは、結果にもログにも出しません。設定の確認では「＊＊＊」と表示します。

## 結果とログ

- 出力が長いときは、最後の 60 行だけを表示します。すべての出力はログファイルにあります。
- 終了コードが 0 以外なら、機器でコマンドがうまく動いていない可能性があります。
- 時間切れのため Ctrl-C で止めたコマンドも、止めるまでの出力は残ります。
- 途中で止まったときは、実行しなかったコマンドも伝えます。

### スクリプトの出力

スクリプトは、標準出力に JSON を1つ出します。
Windows では、コンソールの文字コード（日本語の Windows では cp932 など）で書きます。
主な項目は次のとおりです。

| 項目 | 意味 |
| --- | --- |
| `ok` | 成功したか |
| `message` | 何が起きたかの文 |
| `commands` | コマンドごとの `command`・`output`・`exit_code`（分からなければ null）・`timed_out`（時間切れで止めたか）・`truncated`（最後の 60 行に切ったか） |
| `listen` | コマンドの後や、記録だけのときの出力 |
| `not_run` | 実行しなかったコマンド |
| `problems` | 設定の問題（check では失敗の理由も） |
| `notes` | 注意（check のとき。問題ではない） |
| `summary` | 設定の内容（check のとき。パスワードはマスクする） |
| `config`・`log` | 設定ファイル・ログファイルの場所 |
| `added` | 設定ファイルに追加した項目 |
| `created` | 設定ファイルを今回作ったか |
| `missing` | 値のない必須の項目（config-path のとき） |
| `available_ports` | PC で見つかったシリアルポート（ポートが見つからないとき） |

config-path は `config`・`created`・`missing`・`added` を出します（項目を追加したときは `message`、問題があるときは `problems` も）。

スクリプトの終了コードは、0 が成功、1 が run の失敗（接続やログインの失敗、時間切れなど）、2 が設定の問題です。
check は失敗したときも 2、config-path は設定に問題があっても 0 です。

### ログ

- ログを取るたびに、作業フォルダの `.log-capture/logs/` に、開始日時を名前にして保存します（例：`log-capture-20261105-143000.log`）。同じ秒に2つできたときは、`-2` などが付きます。
- ファイルは UTF-8 です。
- 先頭の `#` の行に、開始時刻、シリアルポート、実行するコマンドなどを書きます。
- その後に、機器から届いた文字をそのまま（色の制御文字も）書き、最後に結果の文を書きます。
- 各コマンドの出力の後に「（終了コード：0）」のような行を書きます。読み取れなかったときは「（終了コード：読めませんでした）」です。
  終了コードを調べるために送ったコマンドとその応答は、この行に置き換えます。

## うまくいかないとき

| 症状・メッセージ | 対処 |
| --- | --- |
| 設定ファイルがありません | `/log-capture 設定ファイルを作って` と依頼する |
| `/log-capture` が使えない | 置き場所と、フォルダの名前が `SKILL.md` の `name:` と同じか。直したら `/skills reload` を実行する |
| シリアルポート … が見つかりません | ケーブルと `port`。文の最後に、PC で見つかったシリアルポートが出ていれば、その中から選ぶ。1つも出ないときは、デバイスマネージャーの「ポート (COM と LPT)」に USB シリアル変換器が出ているか。出ていなければ、そのドライバーをインストールする |
| シリアルポート … は、ほかのプログラム…が使っています | 端末ソフト（Windows では Tera Term や PuTTY、Linux では minicom や screen など）を閉じる |
| シリアルポート … を開く権限がありません | Linux では、`dialout` グループに追加し、PC にログインし直す |
| … はシリアルポートではありません | `port` が正しいか |
| シリアルポート … から応答がありません | ケーブルと、機器の電源 |
| 文字は届きますが、ログインの求めも、シェルのプロンプトも出ません | `baud` が機器と同じか。`prompt` が一致するか。機器で前のプログラムが動いたままでないか |
| ログインできませんでした | `login_user` とパスワード |
| 機器がログインを求めていますが、設定の login_user … が空です | `login_user` を書く |
| ログインの後、シェルのプロンプトが出ません | `prompt` が機器のプロンプトに一致するか |
| 環境変数 … がありません | Copilot CLI を起動する前に、その環境変数を設定したか |
| … 秒で終わらなかったため、Ctrl-C で止めました | 長く動くプログラムなら、`command_timeout_seconds` を増やす |
| Ctrl-C を送ってもプロンプトが戻りませんでした | 機器でプログラムを止めるか、機器の電源を入れ直す |
| やりとりが、途中で切れました | USB ケーブルが抜けていないか |
| 設定ファイルの … 行目が読めません | その行の書き方（文字列を `"…"` で囲んでいるか） |
| 実行するコマンド（commands）が空で、記録する秒数（listen_seconds）も 0 です | `commands` を書くか、`listen_seconds` を 1 以上にする |
| baud（シリアルの速さ）の … は使えません | 9600、38400、57600、115200 などの決まった速さにする |
| 終了コードが「読めませんでした」になる | 機器のシェルで `$?` が使えるか（fish などでは使えません） |

## スクリプトを直接実行する

作業フォルダをカレントディレクトリにして、次のように実行します。

```
# Windows（PowerShell）
py -3 <このフォルダ>/scripts/capture.py <サブコマンド> [オプション]
# Linux（bash）
python3 <このフォルダ>/scripts/capture.py <サブコマンド> [オプション]
```

`<このフォルダ>` は、このフォルダのパスです（例：`.github/skills/log-capture`）。`py` がないときは `python` を使います。

`<サブコマンド>` は次のどれかです。

- `run`：機器でコマンドを実行し、出力を記録する（サブコマンドを省略したときも `run`）
- `config-path`：設定ファイルの場所を表示する（なければ作る）
- `check`：設定を確認する（ファイルは作らない）

次のオプションを付けられます。

- `--command 'コマンド'`（run のとき）：`commands` の代わりに実行する。複数指定できる。値の中の `'` は、PowerShell では `''`、bash では `'\''` と書く
- `--listen-only 秒数`（run のとき）：コマンドを実行せず、その秒数だけ記録する
- `--workdir <フォルダ>`：作業フォルダを指定する（既定はカレントディレクトリ）
- `--config <ファイル>`：別の場所の設定ファイルを使う

## テストを実行する

このフォルダで、次を実行します。

```
# Windows（PowerShell）
py -3 -m unittest discover -s tests
# Linux（bash）
python3 -m unittest discover -s tests
```

最後に `OK` と出れば成功です。
機器は要りません。TCP で接続する模擬の機器を使います（Linux では、疑似端末で接続するテストも動きます）。

`__pycache__` を残さないときは、`-B` を付けます（例：`py -3 -B -m unittest discover -s tests`）。
