# シリアルコンソールの記録

シリアルポート、ログイン、機器で実行するコマンド（commands）は、作業フォルダの `.<このスキルのフォルダの名前>/config.yaml` に書きます。
各項目の意味は、ファイルの中のコメントにあります。

## コマンド

作業フォルダで実行します。`<python>` は、Windows では `py -3`（なければ `python`）、ほかでは `python3` です。

| すること | コマンド |
| --- | --- |
| 設定の commands を機器で順に実行し、出力を記録する | `<python> <このスキルのフォルダ>/scripts/capture.py run` |
| 設定を確かめる（つないでログインまで試す。コマンドは実行せず、ファイルも作らない） | `<python> <このスキルのフォルダ>/scripts/capture.py check` |
| 設定ファイルを作る・場所を返す・足りない項目を足す | `<python> <このスキルのフォルダ>/scripts/capture.py config-path` |

run に付けられるもの：

- `--command '<コマンド>'`：設定の commands の代わりに、このコマンドを実行します（何回でも書けます）。
  値は `'…'` で囲みます。値の中の `'` は、PowerShell では `''`、bash では `'\''` と書きます。
- `--listen-only <秒>`：コマンドを実行せず、その秒数だけ出力を記録します。
- `--workdir <フォルダ>`：作業フォルダが今のフォルダと違うとき。

run は長くかかることがあります（目安：コマンドの数 ×（command_timeout_seconds ＋ 10 秒）＋ listen_seconds）。終わるまで待ちます。

設定ファイルを作ったり書き換えたりするのは、頼まれたときだけです。
つながらないときは、同じコマンドを繰り返しません。`message` にある原因と確かめることを伝えて終えます。

## 結果

標準出力に JSON を1つ返します。
`message` は結果の要約、`problems` は設定の問題、`notes` は注意、`log` はログの場所です。

`commands` には、コマンドごとの `command`・`output`・`exit_code` が入ります。

- `exit_code` は、機器でのコマンドの終了コードです（null は分からないとき）。
  0 以外なら、`ok` が true でもコマンドはうまく動いていません。そのことを伝えます。
- `timed_out` が true のコマンドは、command_timeout_seconds を過ぎたので Ctrl-C で止めました。それまでの出力は残っています。
- `truncated` が true なら、`output` は最後の 60 行だけです。全部はログにあります。
- `not_run` は、実行しなかったコマンドです。

設定を見せるときは、パスワードを伏せます（`summary` では伏せてあります）。
