# setup：YAML の設定ファイルを対話で埋めるスキル

YAML の設定ファイルの項目を、1つずつ質問して埋める GitHub Copilot CLI のスキルです。このフォルダだけで動きます。
このフォルダをコピーして、`/setup 設定ファイルを埋めて` と入力します。

## 何をするスキルか

- 項目の意味は、コメント（`#` の行）だけから読み取ります。
- 書き換えるのは値だけです。コメントと項目の並びは変えず、項目の追加や削除もしません。
- ログを含め、新しいファイルやフォルダは作りません。設定した値で何かを実行することもしません。
- このスキル自体の設定は要りません。

## 必要なもの

- Linux の PC（動作確認は Linux だけ）
- Python 3.8 以上（標準ライブラリだけで動きます）
- GitHub Copilot CLI

## インストールする

1. このフォルダを、次のどちらかにコピーします。
   - 1つの作業フォルダ（ふつうは、Copilot CLI を起動したフォルダ）で使う：その作業フォルダの `.github/skills/setup/`
   - すべての作業フォルダで使う：`~/.copilot/skills/setup/`
2. Copilot CLI を起動したままコピーしたときは、`/skills reload` を実行します。
3. `/setup` と入力して、このスキルが候補に出れば完了です。

フォルダの名前を変えてコピーするときは、`SKILL.md` の `name:` も、フォルダと同じ名前に変えます。
`tests/` はテスト用です。なくてもスキルは動きます。

## 使い方

`/setup` に続けて依頼を書きます。

| 入力の例 | スキルの動き |
| --- | --- |
| `/setup 設定ファイルを埋めて` | 候補を探し、設定するファイルを質問します |
| `/setup conf/app.yaml を設定して` | そのファイルを設定します |
| `/setup conf/app.yaml の interval_seconds を直したい` | その項目から質問します |

Esc で質問を取り消すと、そこで止まり、書き換えた項目と結果を表示します。

プラグインに入れて配られているときは、`/<プラグインの名前>:<スキル名>` でも呼べます。

## 埋められるファイル

1行に「項目: 値」を書く YAML のファイルです。入れ子（字下げした項目）には対応していません。

- 値：文字列（`"…"`・`'…'`・引用符なし）、数値、`true` / `false`、`null`、1行のリスト（`["a", "b"]`）、次の行から `  - 値` と並べたリスト
- `  - 値` のリストは、書き換えると1行のリストになります。中のコメントは、項目の下に残ります。
- 項目のすぐ上の `#` の行が、その項目の説明です。間に空行があると、説明になりません。
- 先頭の `#` の行は、ファイル全体の説明です。最初の項目との間に空行を1行入れます。

説明に次のことを書くと、扱いが変わります。

| 説明に書くこと | 意味 |
| --- | --- |
| 「必須」 | 必須の項目。空なら先に質問します。「必須ではない」なら必須になりません |
| 「必ず」 | ふつうは書く項目（必須ではない）。例の値より、自分の環境に合う値を勧めます |
| `# 例：…` の行 | 値の例。質問の選択肢に出ます。何行でも書けます |
| `# 選べる値：a / b / c` の行 | 書ける値をこの中に限ります。空を許すなら `""` も並べます。値の後ろの `（…）` は補足で、値に含めません |

例：

```yaml
# 温室の監視の設定です。

# 温室の名前（必須）。
# 例：東の温室
name: ""

# 監視の間隔（秒）。
interval_seconds: 60

# 温度の単位。
# 選べる値：c / f
unit: "c"

# 通知先のメールアドレス。
# 例：["a@example.com"]
notify_to: []

# 通知サービスのパスワード。
password: ""

# パスワードを入れる環境変数の名前。
# 例：GREENHOUSE_PASSWORD
password_env: ""
```

### パスワードなどの項目

名前に次の言葉を含む項目です（大文字と小文字は区別しない。`_env` で終わる名前は除く）。
`password`・`passwd`・`passphrase`・`secret`・`token`・`api_key`・`apikey`・`パスワード`・`暗証`

表や説明では、値を `＊＊＊` で隠します。
ただし、質問に答えて入力した値は、画面と会話の記録に残ります。
残したくないときは、環境変数で渡すか、ファイルを自分で書き換えます。

環境変数で渡せるのは、設定ファイルを読むプログラムが対応しているときだけです。
ファイルの値との優先順位も、そのプログラムが決めます。

1. ファイルに `<項目の名前>_env` という項目を用意します（例の `password_env`）。
2. 渡し方の質問で、「環境変数で渡す」を選びます。
3. 環境変数の名前を答えます。ファイルには名前だけが書き込まれます。
4. 設定が終わったら、Copilot CLI を終了します。
5. 同じ端末で値を設定します（例：`export GREENHOUSE_PASSWORD=値`）。
6. Copilot CLI を起動し直します。

## 候補のファイルの探し方

場所を指定せずに依頼すると、作業フォルダから候補を探します。

- 作業フォルダと、その下 3 階層までのフォルダを探します。例：`a/b/c/x.yaml` は探し、`a/b/c/d/x.yaml` は探しません。
- 候補は、説明のある項目を1つ以上持つ `.yaml`・`.yml` のファイルです。対応していない書き方のものは除きます。
- 名前がドットで始まるフォルダ（`.myapp/` など）の中も探します。
- 次のフォルダの中は探しません。
  - `.git`・`.hg`・`.svn`・`node_modules`・`__pycache__`・`.venv`・`venv`・`.tox`・`.mypy_cache`・`.pytest_cache`・`.ruff_cache`
  - このスキルのフォルダと、`SKILL.md` があるほかのフォルダ（中のひな形は候補に出ません）
- 候補が1つだけでも、1つもなくても、設定するファイルを質問します。ファイルの場所を入力して答えられます。

## 結果の見方

終わるとき、ファイルごとに、ファイルの場所、項目と値の表、必須なのに空の項目を表示します。
表では、空の値を（空）と表示します（パスワードなども同じ）。長い値は、真ん中を「…」で省略します。

## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| `/setup` が出てこない | フォルダの場所と、`name:` がフォルダの名前と同じかを確認し、`/skills reload` を実行します |
| 候補にファイルが出ない | 項目のすぐ上に `#` の説明があるか（空行をはさんでいないか）を確認します。探す範囲の外なら、場所を指定します |
| 「… 行目は読めません」と出る | その行を「項目: 値」の1行に直します（入れ子と複数行の値は不可。`  - 値` のリストは可） |
| 「UTF-8 の文字として読めません」と出る | UTF-8 で保存し直します |
| 値を書き込めないと表示される | 「選べる値」と型（数値・真偽値・リスト）に合う値で答え直します |
| ファイルに書き込めないと表示される | ファイルとフォルダの書き込み権限を確認します |
| 何も書き換わらない | `copilot -p` などの対話しない使い方では書き換えません。対話モードで依頼し直します |
| `python3` が見つからない | Python 3.8 以上をインストールします |

作業フォルダで次を実行すると、候補を JSON で確認できます。

```bash
python3 <このフォルダ>/scripts/config_tool.py list
```

`files` が候補、`unreadable` が対応していない書き方のため外したファイルです（理由は `error`）。

## テストを実行する

このフォルダで、次を実行します。

```bash
python3 -m unittest discover -s tests -v
```

最後に `OK` と出れば成功です。PyYAML があれば、書き換えたファイルを PyYAML でも読めるかもテストします。
`__pycache__` を残したくないときは、`python3 -B -m unittest discover -s tests -v` を実行します。
