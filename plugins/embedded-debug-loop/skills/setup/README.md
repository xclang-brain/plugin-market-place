# setup：YAML の設定ファイルを対話で埋めるスキル

GitHub Copilot CLI で使うスキルです。
このフォルダだけで動きます。

## 何をするスキルか

- YAML の設定ファイルの項目を、1つずつ質問しながら埋めます。
- 項目の意味は、ファイルの中のコメント（`#` の行）だけを頼りにします。
- 書き換えるのは値だけです。コメントと項目の並びは変えません。
- ファイルを新しく作ることはしません。項目を足したり消したりもしません。
- 設定を使って何かを動かしたり、試したりはしません。

このスキルには、自分の設定ファイルはありません。
埋めるのは、あなたが持っている YAML のファイルです。

## 必要なもの

- Linux の PC（試したのは Linux です）
- Python 3.8 以上（標準のライブラリだけで動きます。追加のインストールは要りません）
- GitHub Copilot CLI

## 置き方

1. このフォルダを、次のどちらかに写します。
   - 作業フォルダ（リポジトリ）の `.github/skills/setup/`：そのリポジトリで使えます。
   - `~/.copilot/skills/setup/`：自分のどのフォルダでも使えます。
2. Copilot CLI を起動したまま写したときは、`/skills reload` を実行します。

- 名前を変えて写すときは、フォルダの名前と、`SKILL.md` の `name:` を同じ名前にします。
  Copilot CLI は、`name:` の名前でスキルを呼ぶからです。
- `tests/` は試験のためのものです。なくてもスキルは動きます。

## 呼び方

`/setup` に続けて、頼みたいことを書きます。
ふつうの言葉で頼んでも、Copilot CLI がこのスキルを選ぶことがあります。

| 頼み方の例 | すること |
| --- | --- |
| `/setup 設定ファイルを埋めて` | 作業フォルダの中から候補のファイルを探し、どれを設定するかを聞きます |
| `/setup conf/app.yaml を設定して` | そのファイルを設定します |
| `/setup conf/app.yaml の interval_seconds を直したい` | その項目から聞きます |

質問には、選択肢を選ぶか、自分で書いて答えます。
Esc で質問を取り消すと、そこで止めて、それまでの結果を伝えます。
質問しながら進めるので、Copilot CLI の対話の画面で使います。
質問ができない使い方（`copilot -p` など）では、何も書き換えません。

プラグインに入れて配られているときは、`/<プラグインの名前>:<スキル名>` でも呼べます。

## 埋められるファイル

次の形の YAML のファイルを埋められます。

- 1行に「項目: 値」を書きます。入れ子（字下げした項目）は使えません。
- 値は、文字（`"…"`・`'…'`・囲みなし）、数、`true` / `false`、`null`、
  1行のリスト（`["a", "b"]`）、または「項目:」の次の行から `  - 値` と並べたリストです。
- `  - 値` と並べたリストを書き換えると、1行のリスト（`["a", "b"]`）の形になります。
  リストの中にあったコメントは消さずに、項目の下に `#` の行として残します。
- 項目のすぐ上の `#` の行が、その項目の説明です。空の行をはさむと、説明になりません。
- ファイルの先頭の `#` の行は、ファイルの説明です。項目とのあいだに、空の行を1行入れます。

説明の中に、次のように書くと、このスキルがそのとおりに扱います。

| 説明に書くこと | 意味 |
| --- | --- |
| 「必須」という言葉（例：`（必須）`） | 必須の項目です。空なら、先に聞きます。「必須ではない」とだけ書いた項目は、必須になりません |
| `# 例：…` の行 | 例の値です。質問の選択肢になります。何行でも書けます |
| `# 選べる値：a / b / c` の行 | この中の値しか書けません。空を許すときは `""` も並べます。値の後ろに `（…）` で書いた補足は、値に含めません |
| 「必ず」という言葉（例：`ふだんは必ず書く`） | 必須ではないが、ふつうは書く項目です。自分の値を書くよう勧めます |

例：

```yaml
# 温室の見張りの設定です。
# 見回りの間隔と、知らせの送り先を書きます。

# 温室の名前（必須）。
# 例：東の温室
name: ""

# 見回る間隔（秒）。
# 例：60
interval_seconds: 60

# 温度の単位。
# 選べる値：c / f
unit: "c"

# 知らせを送るアドレス。複数書けます。
# 例：["a@example.com"]
notify_to: []

# 知らせを送るサービスのパスワード。
password: ""

# パスワードを入れた環境変数の名前。
# 例：GREENHOUSE_PASSWORD
password_env: ""
```

### パスワードなど

- 項目の名前に、次の言葉があると、値を見せない項目になります。
  `password`・`passwd`・`passphrase`・`secret`・`token`・`api_key`・`apikey`・`パスワード`・`暗証`
  （大文字と小文字は区別しません。名前が `_env` で終わる項目は除きます）
- 見せない項目の値は、このスキルが出す表や説明では `＊＊＊` に置き換えます。空なら（空）と出します。
- ただし、質問に答えて値を書き込むと、書いた値は Copilot CLI の画面と記録に残ります。
  残したくないときは、環境変数で渡すか、ファイルを自分で書き換えます。
- 環境変数で渡すには、`<項目の名前>_env` という項目を、ファイルに置きます（上の例の `password_env`）。
  - このスキルは、その項目に、環境変数の名前だけを書きます。
  - 値は、自分で入れます。Copilot CLI を一度終え、同じ端末で `export 名前=値` を実行してから、起動し直します。
  - 環境変数をどう使うか（ファイルの値より先に使うかなど）は、そのファイルを読むプログラムが決めます。

## 候補のファイルの探し方

ファイルの場所を言わずに頼むと、作業フォルダの中から候補を探します。
作業フォルダは、今のフォルダ（ふつうは Copilot CLI を起動したフォルダ）です。

- 作業フォルダと、その下 3 段までのフォルダを探します。
  例：`a/b/c/x.yaml` は探します。`a/b/c/d/x.yaml` は探しません。
- 名前が `.yaml` か `.yml` で終わるファイルを探します。
- 項目のすぐ上に `#` の説明がある項目が、1つ以上あるファイルだけが候補になります。
- 点で始まるフォルダ（`.myapp/` など）の中も探します。
- 次のフォルダの中は探しません。
  `.git`・`.hg`・`.svn`・`node_modules`・`__pycache__`・`.venv`・`venv`・`.tox`・`.mypy_cache`・`.pytest_cache`・`.ruff_cache`、
  それと、このスキルのフォルダと、`SKILL.md` があるほかのフォルダ（スキルのフォルダ。中のひな形を、候補に出さないため）
- 書き方が読めないファイル（入れ子があるものなど）は、候補に出しません。
- 候補が1つでも、どれを設定するかを聞きます。ほかのファイルの場所を書いて答えることもできます。
- 候補が見つからないときは、ファイルの場所を聞きます。

## 結果の見方

- 終わりに、ファイルの場所と、項目と値の表を見せます。
  空の値は（空）、パスワードなどの値は `＊＊＊` と出ます。長い値は、真ん中を「…」で省きます。
- 必須なのに空のままの項目があれば、その名前を伝えます。
- このスキルは、ログのファイルを作りません。作業フォルダに、ほかのファイルやフォルダも作りません。
- ファイルは、直接書き換えてもかまいません。

## うまくいかないとき

| こんなとき | すること |
| --- | --- |
| `/setup` が出てこない | フォルダの場所と、`SKILL.md` の `name:` を確かめます。そのあと `/skills reload` を実行します |
| 候補にファイルが出ない | 項目のすぐ上に `#` の説明があるか（空の行をはさんでいないか）を確かめます。深い場所や、探さないフォルダにあるときは、ファイルの場所を言って頼みます |
| 「… 行目は読めません」と出る | 入れ子や、複数行に分けた値は読めません。その行を「項目: 値」の1行に直します |
| 「UTF-8 の文字として読めません」と出る | ファイルを UTF-8 で保存し直します |
| 値を書き込めないと言われる | 「選べる値」にない値や、種類（数・`true` か `false`・リスト）の違う値は書けません。出た文のとおりに直します |
| ファイルに書き込めないと言われる | ファイルとフォルダの書き込みの権限を確かめます |
| 何も書き換わらない | 質問ができない使い方（`copilot -p` など）になっていないかを確かめます。Copilot CLI の対話の画面で頼み直します |
| `python3` が見つからない | Python 3.8 以上を入れます |

どのファイルが候補になるかは、作業フォルダで次を実行すると分かります。結果は JSON で出ます。

```bash
python3 <このフォルダ>/scripts/config_tool.py list
```

`files` が候補のファイルです。
`unreadable` は、書き方が読めないため候補にしなかったファイルです。`error` に理由が出ます。

## 試験の動かし方

このフォルダで、次を実行します。

```bash
python3 -m unittest discover -s tests -v
```

PyYAML が入っていれば、書いたファイルがふつうの YAML として読めるかも確かめます。
入っていなければ、その試験は飛ばします。

- `__pycache__` を残したくないときは、`python3 -B -m unittest discover -s tests -v` とします。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `SKILL.md` | Copilot CLI への指示 |
| `scripts/config_tool.py` | 設定ファイルを読み書きする道具 |
| `tests/` | 試験と、試験に使う見本のファイル |
