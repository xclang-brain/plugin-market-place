# setup：スキルの設定を対話で埋めるスキル

ほかのスキルの設定ファイルを、利用者に質問しながら埋める GitHub Copilot CLI のスキルです。このフォルダだけで動きます。
設定するスキルの README か SKILL.md を読んで、設定ファイルの場所・作り方・項目の意味を調べます。
そこに説明があるスキルなら、どれでも設定できます。

## できること

- 設定するスキルを探して、どれを設定するかを質問する。
- 設定ファイルがなければ、そのスキルの README のとおりに作る。
- 必須で空の項目から1つずつ質問して、答えを書き込む。
- 終わったら、スキルごとに項目と値の表を表示する。パスワードなどの値は隠す。

書き換えるのは値だけです。コメントと項目の並びは変えません。
ただし、`  - 値` の形のリストは、書き換えると1行のリスト（`["a", "b"]`）になります。
設定した値を使った接続や動作の確認はしません。このスキル自体の設定は要りません。

## 必要なもの

- Windows の PC（Linux でも動きます）
- Python 3.8 以上（追加のインストールは要りません）
- GitHub Copilot CLI

Windows の PC での動作は、まだ確認していません。

## インストールする

1. このフォルダを、次のどちらかにコピーします。
   - 1つの作業フォルダ（ふつうは、Copilot CLI を起動したフォルダ）で使う：`<作業フォルダ>/.github/skills/setup/`
   - すべての作業フォルダで使う：`~/.copilot/skills/setup/`（Windows では `C:\Users\<ユーザー名>\.copilot\skills\setup\`）
2. Copilot CLI を起動したままコピーしたときは、`/skills reload` を実行します。
3. `/setup` と入力して、このスキルが候補に出れば完了です。

フォルダの名前を変えてコピーするときは、`SKILL.md` の `name:` も、フォルダと同じ名前に変えます。

## 使い方

Copilot CLI で「セットアップしたい」と頼むか、`/setup` に続けて依頼を書きます。

| 入力の例 | スキルの動き |
| --- | --- |
| `セットアップしたい` | 設定できるスキルを探し、どれを設定するかを質問します |
| `/setup <スキルの名前> を設定して` | そのスキルを設定します |
| `/setup <スキルの名前> の <項目の名前> を直したい` | その項目から質問します |

Esc で質問を取り消すと、そこで止まり、書き換えた項目と結果を表示します。

プラグインに入れて配られているときは、`/<プラグインの名前>:<スキル名>` でも呼べます。

## スキルの探し方

次の順に、`SKILL.md` があるフォルダを探します。名前がドットで始まるフォルダは見ません。

1. `.github/skills/`
2. `.agents/skills/`
3. `.claude/skills/`
4. `~/.copilot/skills/`（環境変数 `COPILOT_HOME` があれば、その中の `skills/`）
5. `~/.agents/skills/`
6. このフォルダの隣のフォルダ

1〜3 は、作業フォルダから上のフォルダへ、Git のリポジトリの一番上まで探します。
リポジトリの外では、ホームフォルダまで探します。
Copilot CLI の設定で足したスキルのフォルダ（`COPILOT_SKILLS_DIRS` など）は探しません。

同じ名前のスキルがあるときは、先に見つかったほうを設定します。
この順は、Copilot CLI 1.0.105 がスキルを選ぶ順と同じです。
ただし、`--plugin-dir` で読み込んだプラグインのスキルは、Copilot CLI では 4 と 5 より先に選ばれます。

## 設定されるスキルの書き方

設定されるスキルの README か SKILL.md に、次の3つを書きます。
設定ファイルの場所、作り方（コマンドか、ひな形のコピー）、項目の意味です。
書いていないことは、推測しません。

YAML の設定ファイルは、次の形で書くと、コメントも説明として読みます。

- 1行に「項目: 値」を書きます。
- 値は、文字列・数値・`true` / `false`・`null`・リスト（`["a", "b"]` か、次の行から `  - 値`）です。
- 項目のすぐ上の `#` の行は、その項目の説明です。間に空行を入れません。
- 先頭の `#` の行は、ファイル全体の説明です。最初の項目との間に空行を1行入れます。

説明に次のことを書くと、扱いが変わります。

| 説明に書くこと | 意味 |
| --- | --- |
| 「必須」 | 必須の項目。空なら先に質問します。「必須ではない」なら必須になりません |
| 「必ず」 | ふつうは書く項目（必須ではない）。例の値より、自分の環境に合う値を勧めます |
| `# 例：…` の行 | 値の例。質問の選択肢に出ます。何行でも書けます |
| `# 選べる値：a / b / c` の行 | 書ける値をこの中に限ります。空を許すなら `""` も並べます。値の後ろの `（…）` は補足です |

この形でない YAML（入れ子など）や、ほかの形式（JSON など）は、README の説明をもとに直接書き換えます。

## パスワードなどの項目

名前に次の言葉を含む項目です（大文字と小文字は区別しない。`_env` で終わる名前は除く）。
`password`・`passwd`・`passphrase`・`secret`・`token`・`api_key`・`apikey`・`パスワード`・`暗証`

表や説明では、値を `＊＊＊` で隠します。
ただし、質問に答えて入力した値は、画面と会話の記録に残ります。
残したくないときは、ファイルを自分で書き換えるか、環境変数で渡します。

環境変数で渡せるのは、設定ファイルに `<項目の名前>_env` の項目があり、そのスキルが対応しているときです。

1. 渡し方の質問で「環境変数で渡す」を選び、環境変数の名前を答えます。ファイルには名前だけが書き込まれます。
2. 設定が終わったら、Copilot CLI を終了します。
3. 同じ端末で値を設定します。PowerShell は `$env:名前 = '値'`、bash は `export 名前=値` です。
4. Copilot CLI を起動し直します。

## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| `/setup` が出てこない | フォルダの場所と、`name:` がフォルダの名前と同じかを確認し、`/skills reload` を実行します |
| 設定したいスキルが候補に出ない | そのスキルが「スキルの探し方」の場所にあるかを確認します |
| 「設定ファイルの説明がありません」と出る | そのスキルの README に、設定ファイルの場所と作り方を書きます |
| 「設定ファイルの作り方が、README と SKILL.md にありません」と出る | そのスキルの README に、作り方（コマンドか、ひな形のコピー）を書きます |
| 「UTF-8 の文字として読めません」と出る | 設定ファイルを UTF-8 で保存し直します |
| 値を書き込めないと表示される | 「選べる値」と型（数値・真偽値・リスト）に合う値で答え直します |
| ファイルに書き込めないと表示される | ファイルが読み取り専用になっていないかと、ファイルとフォルダの書き込み権限を確認します |
| 何も書き換わらない | `copilot -p` などの対話しない使い方では書き換えません。対話モードで依頼し直します |
| `py` や `python3` が見つからない | Python 3.8 以上をインストールします |

見つかるスキルは、作業フォルダで次を実行すると JSON で確認できます（Linux では `py -3` を `python3` に変えます）。
`hidden` が true のスキルは、同じ名前のスキルが先に見つかったため、設定しません。

```
py -3 <このフォルダ>/scripts/config_tool.py skills
```

## テストを実行する

このフォルダで、次を実行します（Linux では `py -3` を `python3` に変えます）。

```
py -3 -m unittest discover -s tests -v
```

最後に `OK` と出れば成功です。PyYAML があれば、書き換えたファイルを PyYAML でも読めるかもテストします。
`__pycache__` を残したくないときは、`-m` の前に `-B` を付けます。
