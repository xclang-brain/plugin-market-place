# setup：YAML の設定ファイルを対話で埋めるスキル

YAML の設定ファイルの項目を、1つずつあなたに質問して埋めるスキルです。
GitHub Copilot CLI で使います。このフォルダだけで動きます。

使い始めるときは、次のとおりに進めます。

1. このフォルダを、作業フォルダ（Copilot CLI を起動するフォルダ）の `.github/skills/setup/` にコピーします。
2. Copilot CLI で `/setup 設定ファイルを埋めて` と入力します。設定するファイルを聞く質問が出れば、使えています。

## 何をするスキルか

あなたが用意した YAML の設定ファイルに、質問の答えを書き込みます。
このスキル自体の設定は要りません。

- 項目の意味は、ファイルの中のコメント（`#` の行）だけから読み取ります。
- 書き換えるのは値だけです。コメントと項目の並びは変えません。
- 項目の追加や削除はしません。
- 新しいファイルやフォルダは作りません。ログファイルも作りません。
- 設定した値を使って何かを実行したり、動作を確認したりはしません。

スキルで設定したあとも、設定ファイルを自分で直接書き換えてかまいません。

## 必要なもの

- Linux の PC（動作確認は Linux だけで行っています）
- Python 3.8 以上（標準ライブラリだけで動きます。追加のインストールは不要です）
- GitHub Copilot CLI

## インストールする

コピー先は次の2つです。使う範囲に合わせて選びます。

| コピー先 | 使える場所 |
| --- | --- |
| 作業フォルダ（リポジトリ）の `.github/skills/setup/` | そのリポジトリの中だけ |
| `~/.copilot/skills/setup/` | どのフォルダでも（自分のユーザーアカウントだけ） |

1. このフォルダを、上の表のどちらかにコピーします。
2. Copilot CLI を起動したままコピーしたときは、`/skills reload` を実行します。
3. Copilot CLI で `/setup` と入力し、このスキルが候補に出ることを確認します。

- フォルダの名前を変えてコピーするときは、`SKILL.md` の `name:` も、フォルダと同じ名前に変えます。
  スキルを呼び出すコマンドは、`/<新しい名前>` になります。
- `tests/` はテスト用です。なくてもスキルは動きます。

## 使い方

`/setup` に続けて、依頼の内容を書きます。

| 入力の例 | スキルの動き |
| --- | --- |
| `/setup 設定ファイルを埋めて` | 作業フォルダの中から候補のファイルを探し、どれを設定するかを質問します |
| `/setup conf/app.yaml を設定して` | `conf/app.yaml` を設定します |
| `/setup conf/app.yaml の interval_seconds を直したい` | `interval_seconds` から質問します |

`/setup` を付けずにふつうの言葉で依頼しても、Copilot CLI がこのスキルを選ぶことがあります。

質問には、選択肢を選ぶか、自分で入力して答えます。
Esc で質問を取り消すと、スキルはそこで止まります。
それまでに書き換えた項目を伝えてから、「結果の見方」のとおりに結果を表示します。

このスキルは質問しながら進むため、Copilot CLI の対話モードで使います。
対話しない使い方（`copilot -p` でプロンプトを渡して実行するときなど）では、ファイルを何も書き換えません。

プラグインに入れて配られているときは、`/<プラグインの名前>:<スキル名>` でも呼べます。

## 埋められるファイル

次の形の YAML のファイルを埋められます。

- 1行に「項目: 値」を書く形です。入れ子（字下げした項目）には対応していません。
- 値に使えるのは、次のどれかです。
  - 文字列（`"…"`・`'…'`・引用符なし）
  - 数値
  - `true` / `false`
  - `null`
  - 1行のリスト（`["a", "b"]`）
  - 「項目:」の次の行から `  - 値` と並べたリスト
- `  - 値` と並べたリストを書き換えると、1行のリスト（`["a", "b"]`）の形になります。
  リストの中にあったコメントは消えず、項目の下に `#` の行として残ります。
- 項目のすぐ上の `#` の行が、その項目の説明です。間に空行があると、説明になりません。
- ファイルの先頭の `#` の行は、ファイル全体の説明になります。最初の項目との間には、空行を1行入れてください。

項目の説明に次の言葉や行を書くと、スキルの扱いが変わります。

| 説明に書くこと | 意味 |
| --- | --- |
| 「必須」という言葉（例：`（必須）`） | 必須の項目になります。値が空なら、ほかの項目より先に質問します。ただし、依頼で名前を挙げた項目が最初です。「必須ではない」と書いても、必須にはなりません |
| 「必ず」という言葉（例：`ふだんは必ず書く`） | 必須ではないが、ふつうは書く項目になります。質問では、例の値を選ぶより、自分の環境に合う値を書くよう勧めます |
| `# 例：…` の行 | 値の例として、質問の選択肢に出ます。この行は何行でも書けます |
| `# 選べる値：a / b / c` の行 | 書ける値を、この中の値に限ります。空の値を許すときは、`""` も並べます。値の後ろの `（…）` は補足として扱い、値に含めません |

例：

```yaml
# 温室の監視の設定です。
# 監視の間隔と、通知の送り先を書きます。

# 温室の名前（必須）。
# 例：東の温室
name: ""

# 監視の間隔（秒）。
# 例：60
interval_seconds: 60

# 温度の単位。
# 選べる値：c / f
unit: "c"

# 通知を送るメールアドレス。複数書けます。
# 例：["a@example.com"]
notify_to: []

# 通知を送るサービスのパスワード。
password: ""

# パスワードを設定した環境変数の名前。
# 例：GREENHOUSE_PASSWORD
password_env: ""
```

### パスワードなどの項目

パスワードなどの値は、スキルが出す表や説明では `＊＊＊` に隠します。
ただし、質問に答えて入力した値は、Copilot CLI の画面と会話の記録に残ります。
残したくないときは、環境変数で渡すか、ファイルを自分で書き換えます。

名前に次の言葉を含む項目が、パスワードなどの項目になります。大文字と小文字は区別しません。

`password`・`passwd`・`passphrase`・`secret`・`token`・`api_key`・`apikey`・`パスワード`・`暗証`

ただし、名前が `_env` で終わる項目は除きます。

環境変数をどう使うか（ファイルの値より優先するかなど）は、設定ファイルを読むプログラムが決めます。
そのプログラムが環境変数に対応していることを確認してから、次のとおりに進めます。

1. ファイルに `<項目の名前>_env` という項目を用意します（上の例の `password_env`）。
2. パスワードなどの項目の渡し方を質問されたら、「環境変数で渡す」を選びます。
3. 環境変数の名前を質問されたら、名前を答えます（例：`GREENHOUSE_PASSWORD`）。
   `<項目の名前>_env` には、その名前だけが書き込まれます。値は書き込まれません。
4. スキルの設定が終わったら、Copilot CLI を終了します。
5. 同じ端末で、手順3で答えた名前の環境変数に値を設定します（例：`export GREENHOUSE_PASSWORD=値`）。
6. Copilot CLI を起動し直します。

## 候補のファイルの探し方

ファイルの場所を指定せずに依頼すると、スキルは作業フォルダの中から候補を探します。
作業フォルダは、カレントディレクトリです（ふつうは Copilot CLI を起動したフォルダ）。

- 作業フォルダと、その下 3 階層までのフォルダを探します。
  例：`a/b/c/x.yaml` は探します。`a/b/c/d/x.yaml` は探しません。
- 名前が `.yaml` か `.yml` で終わるファイルを探します。
- 説明（項目のすぐ上の `#` の行）がある項目を、1つ以上持つファイルだけが候補になります。
- 名前がドットで始まるフォルダ（`.myapp/` など）の中も探します。
- 次のフォルダの中は探しません。
  - `.git`・`.hg`・`.svn`・`node_modules`・`__pycache__`・`.venv`・`venv`・`.tox`・`.mypy_cache`・`.pytest_cache`・`.ruff_cache`
  - このスキルのフォルダと、`SKILL.md` があるほかのフォルダ（スキルのフォルダ）。
    スキルのフォルダの中にあるひな形は、候補に出ません。
- このスキルが対応していない書き方のファイル（入れ子があるものなど）は、候補に出しません。
- 候補が1つだけのときも、設定するファイルを質問します。ほかのファイルの場所を入力して答えることもできます。
- 候補が見つからないときは、ファイルの場所を質問します。

## 結果の見方

設定を終えるとき、スキルはファイルごとに次を表示します。

- ファイルの場所
- 項目と値の表。空の値は、パスワードなどの値でも（空）と表示します。長い値は、真ん中を「…」で省略します。
- 必須なのに空のままの項目があれば、その名前

## うまくいかないとき

| 症状 | 対処 |
| --- | --- |
| `/setup` が出てこない | フォルダが「インストールする」の表のどちらかの場所にあるかを確認します。`SKILL.md` の `name:` がフォルダの名前と同じかも確認します。そのあと `/skills reload` を実行します |
| 候補にファイルが出ない | 項目のすぐ上に `#` の説明があるか（間に空行がないか）を確認します。作業フォルダから4階層以上下のフォルダや、探さないフォルダの中にあるときは、ファイルの場所を指定して依頼します |
| 「… 行目は読めません」と出る | 入れ子や、値を複数行に分ける書き方には対応していません（`  - 値` と並べたリストは書けます）。その行を「項目: 値」の1行に直します |
| 「UTF-8 の文字として読めません」と出る | ファイルを UTF-8 で保存し直します |
| 値を書き込めないと表示される | 「選べる値」にない値や、型（数値・`true` か `false`・リスト）の違う値は書けません。メッセージを読んで、書ける値で答え直します |
| ファイルに書き込めないと表示される | ファイルとフォルダの書き込み権限を確認します |
| 何も書き換わらない | 対話しない使い方（`copilot -p` など）になっていないかを確認します。Copilot CLI の対話モードで依頼し直します |
| `python3` が見つからない | Python 3.8 以上をインストールします |

候補にファイルが出ないときは、作業フォルダで次のコマンドを実行します。候補のファイルが JSON で表示されます。

```bash
python3 <このフォルダ>/scripts/config_tool.py list
```

`<このフォルダ>` は、このフォルダの場所に置き換えます（例：`.github/skills/setup`）。

- `files`：候補のファイル
- `unreadable`：対応していない書き方のため、候補から外したファイル。理由は `error` に出ます。

## テストを実行する

このフォルダで、次を実行します。

```bash
python3 -m unittest discover -s tests -v
```

最後に `OK` と表示されれば成功です。

PyYAML がインストールされていれば、スクリプトで書き換えたファイルを PyYAML でも読めるかもテストします。
インストールされていなければ、そのテストはスキップします。

`__pycache__` を残したくないときは、`python3 -B -m unittest discover -s tests -v` を実行します。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `SKILL.md` | Copilot CLI への指示 |
| `scripts/config_tool.py` | 設定ファイルを読み書きするスクリプト |
| `tests/` | テストと、テストで使うサンプルのファイル |
