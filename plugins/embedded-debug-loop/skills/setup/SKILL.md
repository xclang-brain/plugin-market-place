# 設定ファイルを対話で埋める

YAML の設定ファイルの項目を、利用者に聞きながら埋めるスキルです。
項目の意味は、ファイルの中のコメントだけを頼りにします。
コメントにないことは、説明も推測もしません。
設定を使って何かを動かしたり、試したりもしません。

## 道具

ファイルの読み書きには、このスキルの道具だけを使います。

```bash
python3 <このスキルのフォルダ>/scripts/config_tool.py <サブコマンド> ...
```

結果は、いつも JSON で返ります。
`"ok": false` のときは、`error` に理由が日本語で入ります。

| サブコマンド | すること |
| --- | --- |
| `list` | 作業フォルダの `.embedded-debug-loop/` にある設定ファイルの一覧を返す |
| `list --dir <フォルダ>` | 指定したフォルダにある設定ファイルの一覧を返す |
| `show <ファイル>` | ファイルの説明と、項目ごとの説明・今の値・例を返す |
| `set <ファイル> <項目> <値>` | 文字の値を書き込む |
| `set <ファイル> <項目> <値> --json` | 数・true か false・リストを、JSON の形で書き込む |
| `set <ファイル> <項目> --stdin` | 値を標準入力で受け取って書き込む |
| `get <ファイル> <項目>` | 1つの項目の今の値を返す |

- 作業フォルダは、今のフォルダです。違うときは `--workdir <フォルダ>` を付けます。
- `set` は、その項目の行だけを書き換えます。コメントと並びは変えません。
- `set` は、ない項目や、種類の違う値を断ります。
- パスワードなどの値は、空でなければ、結果の中で `＊＊＊` に置き換わります。
  空の値は、空のまま返ります。

`show` の結果のうち、使うものは次のとおりです。

| 名前 | 中身 |
| --- | --- |
| `header` | ファイルの先頭のコメント（何のファイルか） |
| `missing` | 必須なのに空の項目の名前の一覧 |
| `items` | 項目ごとの情報（次の表） |
| `table` | 項目と値の表。終わりの報告に、そのまま貼る。パスワードなどは伏せてある |

`items` の1つ1つには、次が入っています。

| 名前 | 中身 |
| --- | --- |
| `key` | 項目の名前 |
| `comment` | 項目の説明（項目のすぐ上のコメント） |
| `value` | 今の値 |
| `type` | 値の種類。`string`（文字）、`number`（数）、`boolean`（true か false）、`list`（リスト）、`null`（空） |
| `required` | 必須の項目なら true |
| `fill_recommended` | 必須ではないが、コメントに「必ず書く」などとある項目なら true |
| `empty` | 値が空なら true |
| `secret` | パスワードなど、見せない値なら true |
| `examples` | コメントの「例：」の値 |
| `choices` | コメントの「選べる値：」の値。あれば、この中からしか書けない |
| `env_alternative` | 同じ値を環境変数で渡すための項目の名前（あるときだけ） |
| `env_for` | 環境変数の名前を書く項目なら、もとの項目の名前（あるときだけ） |
| `env_defined` | 書いてある名前の環境変数が、今のシェルにあれば true |

## 利用者に見せる言葉

- JSON の名前（`secret`、`missing`、`changed` など）は、利用者に見せません。
  ふつうの言葉で言います。
- 設定ファイルの項目の名前（`key`）は、見せてかまいません。
  利用者が、ファイルの中で探す名前だからです。
- コメントには、ファイルの中でしか通じない言い方があります。
  「下の」「上の」「このスキル」「この項目」などです。
  質問・表・説明では、そのまま使わず、名前で言い換えます。
  - 「下の xxx_env を使う」「上の値」は、その項目の名前で言います。
    例：「xxx_env を使う」「xxx の値」
  - 「この項目」は、その項目の名前（`key`）にします。
  - 「このスキル」は、`header` にある持ち主の名前にします。
    名前がなければ、「このファイルを使うもの」とします。

## 質問のしかた

利用者への質問は、必ず質問のツール（ask_user）で行います。
チャットの文で問いかけて終わらないでください。

- ask_user で、質問の文と選択肢を示して聞きます。
- 1回の質問で聞くのは、1つのことだけです。
- 質問の文は、箇条書きにせず、ふつうの文で書きます。
- 利用者は、選択肢のほかに自由に書くこともできます。
  「その他」のような選択肢は足しません。
- おすすめがあるときは、それを1番目に置き、「（おすすめ）」と付けます。

### 質問が取り消されたとき・断られたとき

利用者が質問を取り消したとき（Esc を押したとき）や、答えるのを断ったときは、次のとおりにします。

1. それ以上は聞きません。
2. それまでに書き換えた項目を伝えます。
   `set` の結果の `changed` が true だった項目です。
   なければ、「書き換えた項目はありません。」と伝えます。
3. 「7. 終わりの報告」（ファイルの場所と、値の表）をして、終えます。

## 進め方

### 1. 設定するファイルを決める

- 呼び出し元がファイルの場所を渡したら、そのファイルを渡された順に設定します。
- 渡されなかったら、`list` を実行します。
  - 一覧が空なら、「設定ファイルがまだありません。設定ファイルを用意してから、もう一度頼んでください。」と伝えます。
    そのうえで、すでにあるファイルの場所を知っているかを ask_user で聞きます。
  - ファイルが1つなら、そのファイルを設定します。
  - 2つ以上なら、どれを設定するかを ask_user で聞きます。
    - 選択肢は「ファイルの名前：説明」です。
      どちらも `list` の結果の `details`（`name` と `header`）にあります。
    - 最後に「全部」を加えます。
- 呼び出し元か利用者が、直したい項目の名前を示したときは、その項目があるファイルを先にします。
- 渡されたファイルがなければ、作りません。そう伝えて、次のファイルへ進みます。

### 2. ファイルごとに進める

ファイルは、1つずつ順に設定します。
1つのファイルについて、2〜6 を全部終えてから、次のファイルに進みます。
ほかのファイルの項目を、先にまとめて聞くことはしません。

ファイルに入るときは、`show <ファイル>` を実行します。
`header` をもとに、何のファイルかを1〜2行で伝えます。ファイルの場所も伝えます。
`header` が空なら、ファイルの名前と場所だけを伝えます。
`show` が `"ok": false` を返したら、`error` を伝え、そのファイルは飛ばします。

### 3. 聞く順番（1つのファイルの中）

1. 呼び出し元か利用者が、直したい項目の名前を示したときは、その項目から聞きます。
   そのファイルにない名前は、飛ばします。
2. 次に、必須で空の項目（`required` と `empty` がどちらも true）を、ファイルの順に聞きます。
   1 で聞いた項目は、聞きません。
3. ほかの項目をどうするかを、ask_user で1回だけ聞きます。
   まだ聞いていない項目がなければ、聞きません。
   - 聞く前に、まだ聞いていない項目の表をチャットに出します。
     列は「項目」「今の値」「説明」です。
     「説明」には、`comment` の1行目を書きます。
     空の値は「（空）」と書きます。`secret` が true でも同じです。
     `secret` が true で、空でない値は「＊＊＊」にします。
   - 質問：「ほかの N 個の項目は、今の値のままでよいですか。」
     N は、表に出した項目の数です。
   - 選択肢：「今の値のままにする」「1つずつ確かめる」「直す項目を選ぶ」
4. 「1つずつ確かめる」なら、表の項目をファイルの順に、全部聞きます。
5. 「直す項目を選ぶ」なら、どの項目かを ask_user で聞きます。
   - 選択肢は「項目の名前：説明」と、最後に「これで終わる」です。
   - 選ばれた項目を聞いたら、また同じ質問をします。「これで終わる」まで続けます。
6. `env_for` がある項目は、環境変数の名前を書く項目です。
   もとの項目の `secret` が true なら、単独では聞きません。
   もとの項目を聞くときに、一緒に扱います（「6. パスワードなど」）。

### 4. 1つの項目の聞き方

`secret` が true の項目は、ここではなく「6. パスワードなど」のとおりに聞きます。

- 質問の文は「<key>：<comment>　今の値は <value> です。」の形にします。
  - `comment` は、「利用者に見せる言葉」のとおりに言い換えてから使います。
  - 今の値が空なら「今の値は空です。」とします。
  - `type` が `list` なら「複数あるときは、「、」で区切って書いてください。」と足します。
- 選択肢は、次の順に並べます。当てはまるものだけを入れます。
  1. 「今の値のまま：<value>」（今の値が空でないとき）
  2. 書ける値。どれも「<値> と書く」の形にします（例：「my_app と書く」）。
     選ぶと、その値がそのままファイルに書かれると分かるようにするためです。
     「例：」は付けません。
     - `choices` の値。今の値と同じものは入れません。
     - `type` が `boolean` で `choices` がなければ、true と false のうち今の値でないもの。
     - `examples` の値。今の値と同じものと、`choices` にもあるものは入れません。
     - リストの値は、中の値を「、」でつないで示します（例：「a、b と書く」）。
  3. 「空のまま」（必須でなく、今の値が空のとき）
  4. 「空にする」（必須でなく、今の値が空でない、文字かリストの項目のとき）
  5. 「あとで決める」（必須で空の項目のとき）
- 「空のまま」は、書ける値より前に置きません。
- 今の値が空で、`fill_recommended` が true の項目は、`examples` の1つ目を1番目に置きます。
  それに「（おすすめ）」を付けます（例：「my_app と書く（おすすめ）」）。
  コメントに、ふだん使うには書く項目だとあるからです。
- 選択肢に、コメントにない値を足しません。値を作り出しません。
- 選択肢が1つもないときは、選択肢なしで聞きます（自由に書く答えだけになります）。

### 5. 答えを書き込む

- 「今の値のまま」「空のまま」「あとで決める」は、何も書き込みません。
- それ以外は、答えを受けたらすぐに `set` で書き込みます。
  - `type` が `string` か `null` の項目：`--json` を付けずに、答えのまま書きます。
    今の値が null の項目は、そのまま書けば、道具がコメントの「例：」を見て、数や true/false として書きます。
  - `number`・`boolean`・`list` の項目：`--json` を付けて、JSON の形で書きます。
    例：`200`、`true`、`["a", "b"]`
  - 「<値> と書く」を選んだら、`examples` か `choices` にある、その値をそのまま書きます。
  - `list` の項目で `choices` の値を1つ選んだら、その1つだけのリストにします。
  - 「空にする」は、文字の項目なら `set <ファイル> <項目> ''`、リストの項目なら `set <ファイル> <項目> '[]' --json` を実行します。
  - 自由に書かれたリストは、区切りで分けて JSON のリストにします。
    分け方に迷ったら、書く前に ask_user で確かめます。
- 値は、利用者の答えのとおりに書きます。直したほうがよさそうでも、勝手に変えません。
  気になることがあれば、書く前に ask_user で確かめます。
- 値に空白や記号があるときは、値を ' で囲みます。
  値に ' が入っているときは、`--stdin` で渡します（6 の書き方と同じ）。
- `set` が `"ok": false` を返したら、`error` を読みます。
  - `--json` の付け忘れなど、書き方の誤りなら、直して書き直します。
  - 値そのものの問題なら、`error` を利用者に伝え、同じ項目をもう一度聞きます。

### 6. パスワードなど（`secret` が true の項目）

- 答えの値は、チャットの文や表に書きません。
- 今の値は、空なら「（空）」、空でなければ「＊＊＊」と書きます。
- `get` で取り出して見せることもしません。
- まず、渡し方を ask_user で聞きます。
  - 質問：「<key>：<comment>　どの方法で渡しますか。」
    `comment` は、「利用者に見せる言葉」のとおりに言い換えてから使います。
  - `env_alternative` があるときの選択肢：
    1. 「環境変数で渡す（おすすめ。値をチャットにもファイルにも書きません）」
    2. 「自分でファイルを書き換える（値はチャットに出ません）」
    3. 「ここで入力して書き込む（入力した値は、Copilot CLI の画面と記録に残ります）」
    4. 「今のまま」（今の値が空なら「空のまま」）
  - `env_alternative` がないときは、2〜4 だけにし、2 に「（おすすめ）」を付けます。
- 「環境変数で渡す」なら：
  1. `env_alternative` の項目を、「4. 1つの項目の聞き方」で聞いて、環境変数の名前を書きます。
  2. 環境変数に値を入れるのは利用者です。次の入れ方だけを伝えます。
     「Copilot CLI を一度終え、同じ端末で `export 名前=値` を実行してから、Copilot CLI を起動し直してください。」
  3. もとの項目に値が入っていれば、消すかを ask_user で聞きます。消すなら `""` を書きます。
- 「ここで入力して書き込む」なら：
  1. 値を ask_user で聞きます。選択肢は「やめる」だけにします。
  2. 答えは、`--stdin` で渡して書き込みます。

     ```bash
     python3 <このスキルのフォルダ>/scripts/config_tool.py set <ファイル> <項目> --stdin <<'EOF'
     <答えの値>
     EOF
     ```

- 「自分でファイルを書き換える」なら、利用者が書き終えるまで待ちます。
  1. ファイルの場所と、項目の名前を伝えます。
     このとき、ほかのコマンドは実行しません。次の項目にも進みません。
  2. ask_user で「書き換えたら教えてください。」と聞きます。
     選択肢は「書き換えた」「あとでやる」の2つです。
  3. 「書き換えた」なら、`show` でファイルを読み直します。
     - その項目が空でなくなっていれば、書き換わったことを伝えて、次に進みます。
       値は見せません。
     - まだ空なら、まだ空であることを伝えて、2 をもう一度聞きます。
     - 読み直した後は、ほかの項目も、新しい `show` の値を使います。
  4. 「あとでやる」なら、次に進みます。
     その項目は、終わりの報告で「あとで書き換える項目」として伝えます。

### 7. 終わりの報告

設定を終えるときは、どんな終わり方でも、最後に必ずこの報告をします。
全部のファイルが終わったときも、途中で止めたときも同じです。
ほかのものから呼ばれて、呼び出し元がこの後に別の作業を続けるときも、省きません。

- この報告が、手番を返す前の最後のことです。
- 報告は、チャットの文として、利用者に必ず見せます。
- ファイルごとに `show` をもう一度実行し、その結果を受け取ってから報告を書きます。
- `show` と、ほかのコマンドやツールを、一緒に呼びません。
- 報告を書く前に、ほかのコマンドやツールを呼びません。

ファイルごとに、次を短く伝えます。

1. ファイルの場所
2. 項目と値の表
   - `show` の結果の `table` を、そのまま貼ります。作り直しません。
   - `table` は、空の値を「（空）」、`secret` が true で空でない値を「＊＊＊」にしてあります。
     長い値は、40 文字で切り、「…」を付けてあります。
3. 必須なのに空のままの項目（`missing`）があれば、その名前と説明
4. 「あとでやる」と答えた項目があれば、「あとで書き換える項目：<key>」
5. `env_defined` が false の項目があれば、「Copilot CLI を起動した端末には、環境変数 <名前> がありません。」
   <名前> は、その項目の値（環境変数の名前）です。
6. 最後に、次の文を添えます。
   「このファイルは、直接書き換えてもかまいません。各項目の意味は、項目のすぐ上のコメントにあります。」

## 守ること

- 値は、利用者が選んだか書いたものだけを書きます。推測で書きません。
- 設定ファイルは、`set` でだけ書き換えます。ほかの方法で書き換えません。
- ないファイルは作りません。項目を足したり消したりもしません。
- コメントにない説明はしません。意味を聞かれたら、コメントを示し、それ以上は分からないと伝えます。
- 設定を使って何かを動かしたり、試したりしません。
- 質問のツール（ask_user）が使えないときは、何も書き換えません。
  ファイルごとに、場所と、必須なのに空の項目（`missing`）を伝えて終えます。
