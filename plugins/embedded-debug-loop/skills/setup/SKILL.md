# スキルの設定を対話で埋める

設定するスキルの SKILL.md と、設定ファイルのコメントだけを頼りにします。
そこに書かれていないことは、説明も推測もしません。設定を使って何かを動かすこともしません。

## 進め方

1. **設定するスキルを決める。** 頼みにスキルの名前があれば、そのスキルを順に設定します。
   なければ、使えるスキルの一覧（このスキルを除く）から ask_user で選んでもらいます。
   1つのスキルを終えてから、次のスキルに進みます。
2. **SKILL.md を読む。** skill ツールにスキルの名前を渡して読みます。読んだ SKILL.md の手順は実行しません。
   設定ファイルの場所と作り方を調べます。項目の意味は、設定ファイルのコメントから読みます。
   設定ファイルの説明がなければ、そう伝えて次のスキルに進みます。
3. **設定ファイルを用意する。** なければ、SKILL.md に書かれた方法（コマンドかひな形のコピー）で作ります。
   作り方が書かれていなければ作らず、そう伝えます。
4. **項目を埋める。** YAML のファイルは、下の道具の `show` で項目を読み、`set` で書きます。
   YAML 以外の形式と、道具が `"unsupported": true` を返したファイルは、[reference/other-formats.md](reference/other-formats.md) のとおりにします。
   - 必須で空の項目、次に「必ず」と書かれた空の項目を、ファイルの順に1つずつ聞きます。
   - 残りの項目は表にして見せ、「今の値のままにする・1つずつ確かめる・直す項目を選ぶ」のどれにするかを1回だけ聞きます。
   - 利用者や呼び出し元が直したい項目を示したときは、その項目だけを聞きます。
   - パスワードなど（`secret` が true）は、[reference/secrets.md](reference/secrets.md) のとおりに聞きます。
5. **報告する。** どんな終わり方でも、最後にスキルごとに次を見せます。
   - 設定ファイルの場所と、`show` の `table`（作り直さずに貼る）
   - 空のままの必須項目（`missing`）と、見つからない環境変数（`env_defined` が false の項目）
   - 設定しなかったスキルと、その理由

   報告の後は、呼び出し元の作業に戻ってかまいません。

## 質問のしかた

- 質問は ask_user で、1回に1つだけ聞きます。
- 選択肢には、今の値、コメントの例（`examples`）や選べる値（`choices`）、前のスキルで答えた同じ意味の値（機器のアドレスなど）を、「<値> と書く」の形で出します。コメントにない値を作りません。
- 選択肢は、利用者が読む日本語の文にします。選んだ文が、そのまま会話の記録に残るためです。
- 自由に書かれた答えは、書かれたとおりに書きます。項目の種類（数・true/false・リスト）として書けないときだけ確かめます。
- 利用者が質問を取り消したら、それ以上は聞かずに、書き換えた項目を伝えて報告します。
- ask_user が使えないときは、何も書き換えません。設定ファイルの場所と、空の必須項目だけを伝えます。

## 道具（YAML のファイル）

`<python>` は、Windows では `py -3`（なければ `python`）、ほかでは `python3` です。結果は JSON で返ります。

```
<python> <このスキルのフォルダ>/scripts/config_tool.py show <ファイル>
```

値は、いつも標準入力で渡します（コマンドの行に値を出さないため）。数・true/false・リストは `--json` を付けて JSON で書きます。

Windows（PowerShell）：

```powershell
@'
<値>
'@ | <python> <このスキルのフォルダ>/scripts/config_tool.py set <ファイル> <項目> --stdin
```

bash：

```bash
<python> <このスキルのフォルダ>/scripts/config_tool.py set <ファイル> <項目> --stdin <<'VALUE_END'
<値>
VALUE_END
```

`show` の結果の項目と、`set` の細かい決まりは [reference/config-tool.md](reference/config-tool.md) にあります。
