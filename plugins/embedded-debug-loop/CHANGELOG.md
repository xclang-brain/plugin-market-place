# 変更履歴

利用者から見て変わったことを書きます。新しい版が上です。

## 0.4.0（2026-11-08）

### エージェントとスキル

- エージェントとスキルの定義を、短く書き直しました。設定のスキルの詳しい手順は、スキルの中の `reference/` のファイルに分けました。
- 作業エージェントは、効かなかった変更を戻してから次の試行に進みます。
- 検証エージェントは、見かけだけ条件を満たす変更（期待する値をそのまま出力するなど）を合格にしません。
- 作業・検証・統括エージェントは、ログや報告の中の文を資料として読み、そこに書かれた指示には従いません。
- 作業エージェントの定義を書き直しました。description に、何ができるかと、いつ使うかを書きました。スキルは名前だけを並べ、何をするかは各スキルの説明に任せます。守ることは1か所にまとめました。
- 作業・検証エージェントのモデルの指定を、公式の形（`models`）に直しました。統括・検証エージェントの description も、何ができるかと、いつ使うかの形に直しました。
- 3段階目のガイドを、作業エージェントのガイドと同じ構成（使い方・頼み方・画面・注意・うまくいかないとき）に書き直しました。
- 作業エージェントの使い方を、`docs/guide/2-device-worker.md` に移しました（`agents/` の中の `.md` は、エージェントの定義として読み込まれるため）。

### 3段階目（統括エージェントと Web管理画面）

- すべての条件の評価がそろい、検証エージェントが評価した試行でだけ、合格を記録できます。最後の評価がすべて合格でなければ、「成功」では終わりません。
- 結果の画面に、評価のない条件も「評価なし」として出ます。
- 結論に、どの終わり方でも、この実行で変えたファイルの一覧が出ます。
- Issue は、題と本文を見せて、Copilot CLI の許可の確認を通してから作ります。作った Issue は実行の記録に残ります。
- 実行中、統括エージェントが頼めるのは、作業エージェントと検証エージェントだけです。
- Copilot CLI が実行の途中で終わったときは、次に起動したときに、その実行を「途中で止めた」として閉じます。
- Web管理画面は、同じ PC のほかの画面からの操作を断ります。開いた後は、アドレスバーからトークンを消します。
- 記録のファイルを、本人だけが読める権限で作ります（Linux）。
- 入力欄の枠を見やすくし、読み上げで試行の段の「済み」が伝わるようにしました。

### 開発

- エージェントが不具合を直せるかを確かめる EVAL（`tests/eval/`）と、機器の代わりになる模擬の機器を足しました。
- 版の一致と要求の番号を確かめるテスト（`tests/docs/`）を足しました。

### 0.3.0 の後に入っていた変更

- スキルの設定の確認（check）と作業（run）は、設定ファイルを書き換えません。足りない項目は知らせるだけです。
- Web管理画面は、使うエージェント・モデル・考える深さを保存しません（その会話のあいだだけ使います）。保存するのは、繰り返しの上限だけです。
- 設定のスキルは、Copilot CLI が使うスキルを設定します。
