# embedded-debug-loop

組み込み機器の C/C++ の不具合を、調べて直すための GitHub Copilot CLI のプラグインです。
AI が、ソースの修正 → ビルド → 機器への転送 → 機器のログ取得 を繰り返します。

## 3つの使い方（段階）

使い方は3つあります。やりたいことに合うものを1つ選んで使います。順に進める必要はありません。
どの使い方でも、最初に設定（下の「はじめに」）が要ります。

| 段階 | 使うもの | 始め方 | 向いている場面 |
| --- | --- | --- | --- |
| 1 | スキル（ビルド・転送・ログ取得・設定） | `/embedded-debug-loop:cross-compile` などのコマンド | 1つの作業だけを AI に頼みたい |
| 2 | 作業エージェント | `/agent` で選び、チャットで頼む | 不具合の調査と修正を、チャットで任せたい |
| 3 | 統括エージェントと Web管理画面 | `/agent` で選び、チャットで頼む | 直ったかを別の AI（検証エージェント）に確かめさせたい。進み具合をブラウザーで見たい |

- 1段階目：スキルを直接使います。
- 2段階目：作業エージェントが、スキルを使って作業します。
- 3段階目：統括エージェントが、作業エージェントと検証エージェントに頼みます。設定・進み具合・結果は、Web管理画面で見ます。

## 必要なもの

- Linux の PC（ビルドに bash を、ログ取得に Linux のシリアルポートを使います）
- GitHub Copilot CLI
- Python 3.8 以上（スキルが使います。追加のパッケージは要りません）
- 機器向けのビルドの環境（例：Yocto の SDK）
- 機器で FTP サーバーが動いていること（同梱の転送のスキルを使う場合）
- PC と機器が、シリアルケーブル（例：`/dev/ttyUSB0`）でつながっていること（同梱のログ取得のスキルを使う場合）

## インストール

```sh
copilot plugin marketplace add xclang-brain/plugin-market-place
copilot plugin install embedded-debug-loop@plugin-market-place
```

## はじめに：ビルド・転送・ログ取得のやり方を設定する

最初に一度、ビルド・転送・ログ取得のやり方（SDK の場所、機器の IP アドレス、シリアルポートなど）を設定します。
プロジェクトのフォルダで Copilot CLI を起動して、次のようにします。

1. `/agent` と打ち、一覧から `device-worker · plugin`（作業エージェント。正式な名前は `embedded-debug-loop:device-worker`）を選びます。
2. 「セットアップしたい」と頼みます。
3. 作業エージェントが、項目ごとに質問します。答えると、設定ファイルに書き込みます。
4. 最後に、作業エージェントが、機器につながるかを確かめて伝えます。

- 設定ファイルは、プロジェクトのフォルダの `.embedded-debug-loop/` にできます。
- ファイルを直接書き換えてもかまいません。項目の意味は、ファイルの中の説明に書いてあります。
- パスワードが入ることがあるので、このフォルダは Git に入れないことをおすすめします。

## 1段階目：スキルを1つずつ使う

コマンドで、1つの作業だけを頼めます。

| コマンド | すること |
| --- | --- |
| `/embedded-debug-loop:cross-compile` | 機器向けにビルドする |
| `/embedded-debug-loop:deploy` | ビルドしたファイルを FTP で機器へ送る。送った後に実行の権限（例：755）を付ける。設定すれば、サム値（チェックサム）のファイルも一緒に送る |
| `/embedded-debug-loop:log-capture` | シリアルコンソールで機器のコマンドを動かし、出力を記録する |
| `/embedded-debug-loop:setup` | 設定ファイルの項目を、質問に答えながら埋める（先に設定ファイルが要ります） |

くわしくは [スキルを単体で使う](docs/guide/1-skills.md) を見てください。

## 2段階目：作業エージェントに任せる

1. `/agent` で `device-worker · plugin` を選びます。
2. 直してほしいことを、ふつうの文で頼みます。

```text
sensor_app を機器で動かすと、平均値が AVG=3 と出ます。正しくは AVG=25 です。原因を調べて直してください。
```

作業エージェントが、ビルド・転送・ログ取得を繰り返して直し、結果を報告します。
くわしくは [作業エージェントを使う](docs/guide/2-device-worker.md) を見てください。

## 3段階目：統括エージェントと Web管理画面で進める

1. Copilot CLI を起動したときに「… wants elevated permissions」と聞かれたら、「Yes」を選びます（3段階目の Web管理画面を動かすエクステンションの確認です。1段階目と2段階目だけを使うなら、「No」でもかまいません）。
2. 聞かれず、統括エージェントが URL を出せないときは、[統括エージェントと Web管理画面](docs/guide/3-orchestrator.md) の「準備」を見てください。
3. `/agent` で `orchestrator · plugin`（統括エージェント）を選び、直してほしいことを頼みます。
4. 統括エージェントがチャットに出す URL を、同じ PC のブラウザーで開きます。
5. 設定と、作業エージェントの準備の内容を確かめて、「開始」を押します。

統括エージェントが計画を立て、作業エージェントに作業を頼み、検証エージェントに合否を確かめさせます。
進み具合と結果は、Web管理画面で見られます。
くわしくは [統括エージェントと Web管理画面](docs/guide/3-orchestrator.md) を見てください。

## 機器やつなぎ方が違うとき

機器ごとのやり方は、作業エージェントとスキルにだけ書いてあります。統括エージェントと Web管理画面には書いてありません。

- ビルド・転送・ログ取得のやり方が違うときは、スキルを置き換えます。
- 別の種類の機器に使うときは、作業エージェントを置き換えます。

手順は [スキルと作業エージェントの置き換え](docs/guide/replace.md) にあります。
