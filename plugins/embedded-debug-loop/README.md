# embedded-debug-loop

組み込み機器の C/C++ の不具合を、AI が調べて直す GitHub Copilot CLI のプラグインです。
AI は、ソースの修正 → ビルド → 機器への転送 → 機器のログ取得 を繰り返します。

使い方は3段階あり、AI に任せる範囲が違います。
順に進める必要はなく、目的に合う1つを選んで使います。
どの段階でも、最初にビルド・転送・ログ取得の設定が必要です（下の「最初に設定する」）。

## 3つの段階

段階ごとに、使うものと始め方が違います。

| 段階 | 使うもの | 始め方 | 向いている場面 |
| --- | --- | --- | --- |
| 1 | スキル（ビルド・転送・ログ取得・設定） | `/embedded-debug-loop:cross-compile` などのコマンドを入力する | 1つの作業だけを AI に頼みたい |
| 2 | 作業エージェント（`device-worker`） | `/agent` で選び、チャットで頼む | 不具合の調査と修正を、チャットで任せたい |
| 3 | 統括エージェント（`orchestrator`）と Web管理画面 | `/agent` で選び、チャットで頼む | 調査と修正を任せ、直ったかは検証エージェント（`verifier`）という別の AI に確認させたい。進み具合をブラウザーで見たい |

2段階目と3段階目は、前の段階の部品を使います。

- 1段階目：スキルを直接使います。
- 2段階目：作業エージェントが、スキルを使って作業します。
- 3段階目：統括エージェントが、作業エージェントと検証エージェントに作業を依頼します。設定・進み具合・結果は、Web管理画面で見ます。

## 必要なもの

- Linux の PC（ビルドには bash、ログ取得には Linux のシリアルポートを使います）
- GitHub Copilot CLI（動作を確認したバージョン：1.0.105）
- Python 3.8 以上（スキルが使います。追加のパッケージは不要です）
- 機器向けのビルド環境（例：Yocto の SDK）
- 付属の転送スキル（`deploy`）を使う場合：
  - PC から機器に、LAN で接続できること
  - 機器で FTP サーバーが動いていること
  - 送った後に実行権限を付けるなら、FTP サーバーが権限の変更（SITE CHMOD）に対応していること
- 付属のログ取得スキル（`log-capture`）を使う場合：
  - PC と機器が、シリアルケーブルで接続されていること（PC 側の例：`/dev/ttyUSB0`）

## インストール

```sh
copilot plugin marketplace add xclang-brain/plugin-market-place
copilot plugin install embedded-debug-loop@plugin-market-place
```

インストールした後に Copilot CLI を起動すると、次の確認が出ます。

```text
Extension "plugin:embedded-debug-loop:embedded-debug-loop" wants elevated permissions
```

3段階目を使うなら「Yes」を選びます。使わないなら「No」でもかまいません。
この確認は、3段階目の Web管理画面を動かすためのものです。
「No」を選んだ後で3段階目を使うときは、Copilot CLI を起動し直して「Yes」を選びます。

## 最初に設定する

最初に一度、ビルド・転送・ログ取得の方法を設定します。
設定するのは、SDK の場所、機器の IP アドレス、シリアルポートなどです。
作業エージェントに頼むと、質問に答えながら設定できます。

次の3つの項目は必須ではないため、セットアップで個別には聞かれません。
機器でプログラムを動かすなら、手順5で、この3つを選んで値を入れます。

| 項目（設定ファイル） | 入れる値 | 空のとき |
| --- | --- | --- |
| `sdk_env`（ビルド） | SDK の環境設定ファイルのパス | PC 用のプログラムができる |
| `file_mode`（転送） | 送った後に付ける権限（例：755） | 送ったプログラムを、ふつうは機器で実行できない |
| `commands`（ログ取得） | 機器で実行するコマンド（例：`["/opt/myapp/my_app"]`） | 機器でコマンドを実行しない |

1. プロジェクトのフォルダで、Copilot CLI を起動します。
2. `/agent` と入力します。
3. 一覧から `device-worker · plugin` を選びます。
4. 「セットアップしたい」と頼みます。
5. 設定ファイル（ビルド・転送・ログ取得）ごとに、次の質問に答えます。
   1. まだ値のない必須の項目（機器の IP アドレス、送るファイル、シリアルポートなど）を、1つずつ聞かれます。順に答えます。
   2. ほかの項目の一覧が出て、今の値のままでよいかを聞かれます。「直す項目を選ぶ」を選びます。
   3. 上の表の項目を選びます。
   4. 値を入力します。
   5. 「これで終わる」を選びます。

最後に、作業エージェントが、設定と機器への接続を確認して、結果を伝えます。
問題がないと伝えられれば、設定は完了です。
問題があれば、作業エージェントが足りないものを伝え、直すかを聞きます。

### 設定ファイル

- 設定ファイルは、スキルごとに、プロジェクトのフォルダの中に作られます（`.cross-compile/config.yaml`、`.deploy/config.yaml`、`.log-capture/config.yaml`）。ログは、設定ファイルと同じフォルダの `logs/` に保存されます。
- 設定ファイルは、直接書き換えてもかまいません。項目の意味は、ファイルの中の説明に書いてあります。
- 設定ファイルとログは、Git にコミットされません。スキルが、それぞれのフォルダ（`.cross-compile/`・`.deploy/`・`.log-capture/`）に `.gitignore`（中身は `*`）を自動で作ります。設定やログには、パスワードが含まれることがあります。

### スキルのコマンドで設定する

作業エージェントを使わずに、スキルのコマンドで設定することもできます。

1. 次の3つのコマンドを、1つずつ実行します。設定ファイルの場所が表示されます。まだなければ、設定ファイルが作られます。

   ```text
   /embedded-debug-loop:cross-compile 設定ファイルの場所を教えて
   /embedded-debug-loop:deploy 設定ファイルの場所を教えて
   /embedded-debug-loop:log-capture 設定ファイルの場所を教えて
   ```

2. `/embedded-debug-loop:setup` を実行します。
3. 質問に答えて、手順1の設定ファイルに値を入れます。上の表の3つの項目（`sdk_env`・`file_mode`・`commands`）にも、値を入れます。

終わると、設定ファイルごとに、項目と値の表が表示されます。
くわしくは [スキルを単体で使う](docs/guide/1-skills.md) を見てください。

## 1段階目：スキルを1つずつ使う

コマンドで、1つの作業だけを頼めます。

| コマンド | すること |
| --- | --- |
| `/embedded-debug-loop:cross-compile` | 機器向けにビルドする |
| `/embedded-debug-loop:deploy` | ビルドしたファイルを FTP で機器へ送る。`file_mode` を設定すると、送った後にその権限（例：755）を付ける。`checksum` を設定すると、チェックサムのファイルも一緒に送る |
| `/embedded-debug-loop:log-capture` | シリアルコンソールで機器のコマンドを実行し、出力を記録する |
| `/embedded-debug-loop:setup` | 利用者に質問し、答えを設定ファイルの項目に書き込む（設定ファイルは先に作っておく） |

- 各スキルの使い方は、スキルのフォルダの中の README にあります（例：[skills/deploy/README.md](skills/deploy/README.md)）。
- スキルは、プラグインをインストールしなくても、1つずつ使えます。スキルのフォルダを、プロジェクトの `.github/skills/` などにコピーします。このときは、`/deploy` のように、プラグインの名前を付けずに呼びます。

くわしくは [スキルを単体で使う](docs/guide/1-skills.md) を見てください。

## 2段階目：作業エージェントに任せる

不具合の調査と修正を、チャットで作業エージェントに任せます。

1. `/agent` で `device-worker · plugin` を選びます。
2. 直してほしいことを、チャットに書いて頼みます。

   ```text
   sensor_app を機器で動かすと、平均値が AVG=3 と出ます。正しくは AVG=25 です。原因を調べて直してください。
   ```

作業エージェントが、ビルド・転送・ログ取得を繰り返して直し、結果を報告します。
くわしくは [作業エージェントを使う](docs/guide/2-device-worker.md) を見てください。

## 3段階目：統括エージェントに任せ、Web管理画面で見る

統括エージェントが計画を立て、作業エージェントに作業を依頼し、検証エージェントに合否を確認させます。
進み具合と結果は、Web管理画面で見られます。

機器は、依頼の前に準備しておきます。
依頼を受けるとすぐ、統括エージェントが、作業エージェントに機器への接続を確認させます。

1. 機器の電源を入れ、LAN とシリアルのケーブルを接続します。
2. `/agent` で `orchestrator · plugin` を選びます。
3. 直してほしいことを、2段階目の例のように頼みます。
4. 統括エージェントがチャットに出す URL を、同じ PC のブラウザーで開きます。
5. Web管理画面で、「設定」の内容と「作業エージェントの準備」（機器の IP アドレスやシリアルポートなど）を確認します。
6. 「開始」を押します。統括エージェントが試行を始めます。

終わると、チャットに結論が出ます。結論は、Web管理画面の「結果」でも見られます。

URL が出ないときや、Copilot CLI が 1.0.105 より古いときは、[統括エージェントと Web管理画面](docs/guide/3-orchestrator.md) の「準備」を見てください。

## ほかの環境で使う

このプラグインは、ビルドしたプログラムを FTP で機器に送り、シリアル経由でログを取得します。
方法や機器が違うときは、次の表のとおりに、スキルか作業エージェントを置き換えます。

| 環境の違い | 置き換えるもの |
| --- | --- |
| ビルド・転送・ログ取得の方法 | スキル |
| 機器の種類 | 作業エージェント |

統括エージェント・検証エージェント・Web管理画面は、置き換えずにそのまま使えます。
機器に合わせた方法は、スキルと作業エージェントの中にだけ書いてあるからです。

手順は [スキルと作業エージェントを置き換える](docs/guide/replace.md) にあります。
