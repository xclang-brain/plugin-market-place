# embedded-debug-loop

組み込み機器の C/C++ の不具合を、AI が調べて直す GitHub Copilot CLI のプラグインです。
AI は、ソースの修正 → ビルド → 機器への転送 → 機器のログ取得 を繰り返します。

使い方は3段階あり、目的に合う1つを選んで使います。
どの段階でも、最初にビルド・転送・ログ取得の設定が必要です（下の「最初に設定する」）。

## 3つの段階

段階ごとに、使うものと始め方が違います。順に進める必要はありません。

| 段階 | 使うもの | 始め方 | 向いている場面 |
| --- | --- | --- | --- |
| 1 | スキル（ビルド・転送・ログ取得・設定） | `/embedded-debug-loop:cross-compile` などのコマンドを打つ | 1つの作業だけを AI に頼みたい |
| 2 | 作業エージェント（`device-worker`） | `/agent` で選び、チャットで頼む | 不具合の調査と修正を、チャットで任せたい |
| 3 | 統括エージェント（`orchestrator`）と Web管理画面 | `/agent` で選び、チャットで頼む | 直ったかを、検証エージェント（`verifier`）という別の AI に確認させたい。進み具合をブラウザーで見たい |

- 1段階目：スキルを直接使います。
- 2段階目：作業エージェントが、スキルを使って作業します。
- 3段階目：統括エージェントが、作業エージェントと検証エージェントに作業を依頼します。設定・進み具合・結果は、Web管理画面で見ます。

## 必要なもの

- Linux の PC（ビルドに bash を、ログ取得に Linux のシリアルポートを使います）
- GitHub Copilot CLI（動作を確認したバージョン：1.0.105）
- Python 3.8 以上（スキルが使います。追加のパッケージは不要です）
- 機器向けのビルド環境（例：Yocto の SDK）
- 機器で FTP サーバーが動いていること（同梱の転送のスキルを使う場合）
  - 送った後に実行の権限を付けるなら、FTP サーバーが権限の変更（SITE CHMOD）に対応していること
- PC と機器が、シリアルケーブルで接続されていること（同梱のログ取得のスキルを使う場合。PC 側の例：`/dev/ttyUSB0`）

## インストール

```sh
copilot plugin marketplace add xclang-brain/plugin-market-place
copilot plugin install embedded-debug-loop@plugin-market-place
```

インストールした後に Copilot CLI を起動すると、次の確認が出ます。

```text
Extension "plugin:embedded-debug-loop:embedded-debug-loop" wants elevated permissions
```

この確認は、3段階目の Web管理画面を動かすためのものです。
3段階目を使うなら「Yes」を選びます。使わないなら「No」でかまいません。

## 最初に設定する

最初に一度、ビルド・転送・ログ取得の方法を設定します。
設定するのは、SDK の場所、機器の IP アドレス、シリアルポートなどです。
作業エージェントに頼むと、質問に答えるだけで設定できます。

1. プロジェクトのフォルダで、Copilot CLI を起動します。
2. `/agent` と入力し、一覧から `device-worker · plugin` を選びます。
3. 「セットアップしたい」と頼みます。
4. 空の必須の項目を1つずつ聞かれるので、答えます（機器の IP アドレス、送るファイル、シリアルポートなど）。
5. ほかの項目の表が出て、今の値のままでよいかを聞かれます。「直す項目を選ぶ」を選び、次の3つを書きます。機器で使うなら、必ず書く項目です。
   - `sdk_env`（ビルド）：SDK の環境設定ファイル。空だと、PC 用のプログラムができます。
   - `file_mode`（転送）：送った後に付ける権限（例：755）。空だと、送ったプログラムは、ふつうは機器で実行できません。
   - `commands`（ログ取得）：機器で実行するコマンド（例：`["/opt/myapp/my_app"]`）。
6. 最後に、作業エージェントが、機器に接続できるかを確認して結果を伝えます。問題がなければ、設定は完了です。

設定ファイルについて：

- 設定ファイルは、プロジェクトのフォルダに、スキルごとにできます（`.cross-compile/config.yaml`、`.deploy/config.yaml`、`.log-capture/config.yaml`）。
- 設定ファイルは、直接書き換えてもかまいません。項目の意味は、ファイルの中の説明に書いてあります。
- 設定やログには、パスワードが含まれることがあります。スキルがこれらのフォルダに `.gitignore`（中身は `*`）を自動で作るため、Git には入りません。

### スキルのコマンドで設定する

作業エージェントを使わずに、スキルのコマンドで設定することもできます。くわしくは [スキルを単体で使う](docs/guide/1-skills.md) を見てください。

1. ビルド・転送・ログ取得のスキルに、それぞれ「設定ファイルの場所を教えて」と頼みます（例：`/embedded-debug-loop:cross-compile 設定ファイルの場所を教えて`）。設定ファイルがまだなければ、作られます。
2. `/embedded-debug-loop:setup` を実行し、できた設定ファイルを埋めます。

## 1段階目：スキルを1つずつ使う

コマンドで、1つの作業だけを頼めます。

| コマンド | すること |
| --- | --- |
| `/embedded-debug-loop:cross-compile` | 機器向けにビルドする |
| `/embedded-debug-loop:deploy` | ビルドしたファイルを FTP で機器へ送る。`file_mode` を書けば、送った後にその権限（例：755）を付ける。`checksum` を設定すれば、サム値（チェックサム）のファイルも一緒に送る |
| `/embedded-debug-loop:log-capture` | シリアルコンソールで機器のコマンドを実行し、出力を記録する |
| `/embedded-debug-loop:setup` | 設定ファイルの項目を、質問に答えながら埋める（先に設定ファイルが必要） |

- 各スキルの使い方は、フォルダの中の README にあります（例：[skills/deploy/README.md](skills/deploy/README.md)）。
- スキルは、フォルダだけでも使えます。フォルダをプロジェクトの `.github/skills/` などにコピーすれば、プラグインをインストールしなくても使えます。このときは、`/deploy` のように、プラグインの名前を付けずに呼びます。

くわしくは [スキルを単体で使う](docs/guide/1-skills.md) を見てください。

## 2段階目：作業エージェントに任せる

不具合の調査と修正を、チャットで作業エージェントに任せます。

1. `/agent` で `device-worker · plugin` を選びます。
2. 直してほしいことを、ふつうの文で頼みます。

   ```text
   sensor_app を機器で動かすと、平均値が AVG=3 と出ます。正しくは AVG=25 です。原因を調べて直してください。
   ```

作業エージェントが、ビルド・転送・ログ取得を繰り返して直し、結果を報告します。
くわしくは [作業エージェントを使う](docs/guide/2-device-worker.md) を見てください。

## 3段階目：統括エージェントと Web管理画面で進める

統括エージェントが計画を立て、作業エージェントに作業を依頼し、検証エージェントに合否を確認させます。
進み具合と結果は、Web管理画面で見られます。

統括エージェントは、依頼を受けた直後に、機器に接続できるかを作業エージェントに確認させます。そのため、先に機器を準備しておきます。

1. 機器の電源を入れ、LAN とシリアルのケーブルを接続します。
2. `/agent` で `orchestrator · plugin` を選びます。
3. 直してほしいことを頼みます。
4. 統括エージェントがチャットに出す URL を、同じ PC のブラウザーで開きます。
5. 設定と、作業エージェントの準備の内容を確認して、「開始」を押します。

URL が出ないときは、[統括エージェントと Web管理画面](docs/guide/3-orchestrator.md) の「準備」を見てください。
Copilot CLI のバージョンが古いときも、同じ所を見てください。

## 環境が違うとき

環境が違うときは、スキルか作業エージェントを置き換えます。
機器ごとの方法は、スキルと作業エージェントにだけ書いてあります。統括エージェントと Web管理画面には書いてありません。

| 環境の違い | 置き換えるもの |
| --- | --- |
| ビルド・転送・ログ取得の方法 | スキル |
| 機器の種類 | 作業エージェント |

手順は [スキルと作業エージェントを置き換える](docs/guide/replace.md) にあります。
