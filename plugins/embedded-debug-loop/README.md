# embedded-debug-loop

組み込み機器の C/C++ の不具合を、調べて直すための GitHub Copilot CLI のプラグインです。
AI が、ソースの修正 → ビルド → 機器への転送 → 機器のログ取得 を繰り返します。

## 3つの段階

使い方は3段階あります。どの段階も、それだけで使えます。

| 段階 | 使うもの | 使い方 | 向いている場面 |
| --- | --- | --- | --- |
| 1 | スキル（ビルド・転送・ログ取得・設定） | `/embedded-debug-loop:cross-compile` などのコマンド | 1つの作業だけを AI に頼みたい |
| 2 | 作業エージェント | `/agent` で選び、チャットで頼む | 不具合の調査と修正を、チャットで任せたい |
| 3 | 統括エージェントと Web管理画面 | `/agent` で選び、チャットで頼む | 計画と評価を分けて進め、ようすをブラウザーで見たい |

```text
3段階目  統括エージェント ──（ふつうの文で頼む）──┬─▶ 作業エージェント（2段階目）
         Web管理画面（設定・ようす・結果）         └─▶ 検証エージェント
2段階目  作業エージェント ──（スキルを使う）──▶ 1段階目のスキル
1段階目  ビルド / 機器への転送 / 機器のログ取得 / 設定
```

- 機器に固有のこと（ビルドの仕方、転送の仕方、ログの取り方）は、作業エージェントとスキルだけが知っています。
- 統括エージェントと Web管理画面は、機器のことを知りません。作業エージェントを替えれば、別の機器でも使えます。

## 必要なもの

- GitHub Copilot CLI
- Python 3.8 以上（スキルが使います。追加のパッケージは要りません）
- 機器向けのビルドの環境（例：Yocto の SDK）
- 機器への FTP の接続と、シリアルポートの接続（今のスキルの場合）
- 3段階目だけ：Copilot CLI の試験的な機能（エクステンション）を有効にすること

## インストール

```sh
copilot plugin marketplace add xclang-brain/plugin-market-place
copilot plugin install embedded-debug-loop@plugin-market-place
```

## はじめに：機器の設定をする

最初に一度、機器の設定をします。プロジェクトのフォルダで Copilot CLI を起動して、次のようにします。

1. `/agent` と打ち、`embedded-debug-loop:device-worker`（作業エージェント）を選びます。
2. 「セットアップしたい」と頼みます。
3. 作業エージェントが、項目ごとに質問します。答えると、設定ファイルに書き込みます。

設定ファイルは、プロジェクトのフォルダの `.embedded-debug-loop/` にできます。
ファイルを直接書き換えてもかまいません。項目の意味は、ファイルの中の説明に書いてあります。
パスワードが入るので、このフォルダは Git に入れないことをおすすめします。

## 1段階目：スキルを1つずつ使う

コマンドで、1つの作業だけを頼めます。

| コマンド | すること |
| --- | --- |
| `/embedded-debug-loop:cross-compile` | 機器向けにビルドする |
| `/embedded-debug-loop:deploy` | ビルドしたファイルを機器へ送る（FTP。権限とサム値も整える） |
| `/embedded-debug-loop:log-capture` | シリアルコンソールで機器のコマンドを動かし、出力を記録する |
| `/embedded-debug-loop:setup` | 設定ファイルの項目を、対話しながら埋める |

くわしくは [スキルを単体で使う](docs/guide/1-skills.md) を見てください。

## 2段階目：作業エージェントに任せる

1. `/agent` で `embedded-debug-loop:device-worker` を選びます。
2. 直してほしいことを、ふつうの文で頼みます。

```text
sensor_app を機器で動かすと、平均値が AVG=3 と出ます。正しくは AVG=25 です。原因を調べて直してください。
```

作業エージェントが、ビルド・転送・ログ取得を繰り返して直し、結果を報告します。
くわしくは [作業エージェントを使う](docs/guide/2-device-worker.md) を見てください。

## 3段階目：統括エージェントと Web管理画面で進める

1. Copilot CLI の試験的な機能を有効にします（チャットで `/settings experimental on`）。
2. `/agent` で `embedded-debug-loop:orchestrator` を選びます。
3. 直してほしいことを、ふつうの文で頼みます。
4. 統括エージェントが示す URL を、ブラウザーで開きます。
5. 設定と、作業エージェントの準備の内容を確かめて、「開始」を押します。

統括エージェントが、計画を立て、作業エージェントに作業を頼み、検証エージェントに合否を確かめさせます。
ようすと結果は、Web管理画面で見られます。
くわしくは [統括エージェントと Web管理画面](docs/guide/3-orchestrator.md) を見てください。

## 機器やつなぎ方が違うとき

- ビルド・転送・ログ取得のやり方が違うときは、スキルを置き換えます。
- 別の種類の機器に使うときは、作業エージェントを置き換えます。

手順は [スキルと作業エージェントの置き換え](docs/guide/replace.md) にあります。
